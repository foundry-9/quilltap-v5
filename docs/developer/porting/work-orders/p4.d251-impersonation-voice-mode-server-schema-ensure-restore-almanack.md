### Shared contract P4.D251 ↔ P4.D252 — the chat-settings wire (binding; byte-identical in both orders)

The ONE meeting point between the server lane and the SPA lane. No
pick-order dependency: the SPA types the key optional and defaults it to
`'off'`, so its unit suite is green on its own branch; only the two parked
beats need the union.

   verbs `screens/settings/chat/chat-settings.api.ts` already uses; no new

   position `impersonationVoiceRewrite` held (after `composerUnicode`,
   before `textReplacementsEnabled`). The old key is NEVER emitted. A row
   that predates the column, or holds NULL, reads `'off'` (v4's Zod
   default).

   `impersonationVoiceMode` with exactly those three strings and writes it.
   Any OTHER present value — an explicit `null`, `true`, `false`, `1`,
   `'on'`, `''` — answers the error envelope with the message `Invalid
   impersonationVoiceMode value (must be one of off, ask, always)` (the
   route's existing `includes('Invalid') ? 400 : 500` split → 400; the body
   is the sentence alone, NOT a Zod `details` envelope) and writes NOTHING.
   An ABSENT key leaves the column alone (v4's `typeof !== 'undefined'`
   guard). A bag carrying the RETIRED key `impersonationVoiceRewrite` (any
   value) is IGNORED — 200, the row unchanged, no WARN (§R.4(c)) — and the
   SPA never sends it.

   `Failed to update impersonated-line voice setting` (v4 `useChatSettings.

   `ChatSettingsCard.save` already appends it.
