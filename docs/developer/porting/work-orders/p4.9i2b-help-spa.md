- **Response DTOs mirror v4's route JSON name-for-name** — both lanes derive
  them from the v4 handlers at the anchors; the tier-2 differentials are the
  arbiter. A derivation disagreement between the lanes is a unifier-level
  event, not something either lane patches around. Notable shapes: the
  document LIST row is `{id, slug, title, path, url}`; the single document is
  `{id, title, path, url, content}` (no slug); search rows are `{slug,
  titleHit, snippet}`; eligibility is `{eligible, characters: [{id, name,
  avatarUrl, defaultHelpToolsEnabled, connectionProfileId,
  hasToolCapableProfile}], reasons}`; the help-chat list row is `{id, title,
  updatedAt, participants, messageCount, helpPageUrl}`.
- **Send semantics:** the dispatch reply is the typed result (`{messageId}` —
  the id of the LAST persisted assistant message, or `null` when none was
  produced); the frames ride the global Event channel scope-tagged by
  `chatId`, exactly like `ChatSend`/`BrahmaConsoleSend`: `content`,
  `status`, `toolsDetected`, `toolResult` (batch-relative `index`), `done`,
  `error {error, errorType: 'processing_error' | 'fatal_error', details:
  ''}`, and — multi-character only — `turnStart` / `turnComplete` (from the
  SECOND participant on, `chainDepth = i`) and one `chainComplete {reason:
  'cycle_complete', nextSpeakerId: null, chainDepth: n-1}`. The SPA reads
  `toolResult` frames named `help_navigate` (→ navigation links) and
  `help_search` (→ suggested links) exactly as v4's
  `useHelpChatStreaming.ts:176-231` does; the server does not pre-digest
  them.
- **REST edges** (quilltap-web, v4-path-faithful): `GET /api/v1/help-docs`,
  `?action=chat-count`, `?action=search&q=`; `GET /api/v1/help-docs/{id}`;
  `GET|POST /api/v1/help-chats` (+ `?action=eligibility` on GET);
  `GET|PATCH|DELETE /api/v1/help-chats/{id}` (+ `?action=update-context` on
  PATCH); `GET|POST /api/v1/help-chats/{id}/messages`. `POST /help-chats`
  answers 201; `POST …/messages` returns the send reply body.
- **Constants:** create's title is exactly `` `Help: ${firstChar.name}` ``;
  create writes the SYSTEM row `Help chat initiated for page: ${pageUrl}`;
  update-context writes `[System: User navigated to ${pageUrl}]`; delete
  answers `Help chat deleted successfully`; `verify_help_chat` 404s
  (`Help chat`) unless the row exists AND `chatType === 'help'`; the
  eligibility `reasons` sentences are `No characters have help tools
  enabled` / `No tool-capable connection profiles available`; the search
  short-circuit is `q.trim().length < 2` in UTF-16 units; `SNIPPET_LEAD =
  30`, `SNIPPET_TRAIL = 160`; `maxAgentTurns = 10`. The SPA's storage keys
  (`quilltap:help-chat-selected-characters`, `quilltap:help-chat-last-id`,
  `quilltap:help-tab`) are SPA-only and never reach the wire.
