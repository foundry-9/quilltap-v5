## Scope

1. **Arc blanket impls (the production-shaped ownership answer).** Add to
   `quilltap-core::model`: `impl<T: StreamingCompletionProvider> StreamingCompletionProvider
   for Arc<T>`, and the same for `CompletionProvider` and
   `EmbeddingProvider` (delegate via `self.as_ref()`; RPITIT delegation is
   plain). Add the same for `ToolRunner` + `ToolCallDetector` if the typed
   ask_carina construction needs them. Additive; unit-test one delegation
   each. This is what lets ANY composition point (harness now, the Phase-4
   host later) share one provider between the borrowed spine deps and the
   owned erased seams.
2. **Live `ask_carina`-through-spine corpus case.** In the orchestrator
   harness: wrap the owned providers in `Arc` once; pass `&*arc` (or the Arc
   itself) into `OrchestratorDeps`; construct a `TypedAskCarina` from Arc
   clones (its `tool_runner` must be a SEPARATE `BuiltInToolRunner` without
   the ask_carina seam — the cycle note at `ask_carina.rs:290-292`); attach
   via `with_ask_carina` on the spine's tool runner. Add a corpus case where
   the assistant's canned stream carries a native `ask_carina` tool call
   (anthropic-shaped `content[]` rawResponse — the `RegistryToolCallDetector`
   parses it; the W4.7c `tool_wire` precedent), the tool dispatches through
   the erased seam, the inner carina query consumes its own recorded canned
   stream key, the carina message posts + `carinaAnswer` emits, the tool
   result threads, and the continuation stream completes. v4 side: all real
   (`executeToolCallWithContext` → the real ask_carina handler → the real
   `runCarinaQuery`, consuming the same service-level `streamMessage` mock).
3. **Live-Brahma `@Name:` corpus case.** Reconstruct the harness's
   `RealBrahmaConsole` over the Arc-shared streaming provider + a real
   separate `BuiltInToolRunner` + the real detector. Add a corpus case whose

   `brahma_console_tier3`).
4. **Spine `with_logging` + the orchestrator `llm_logs` dump.** Harness:
