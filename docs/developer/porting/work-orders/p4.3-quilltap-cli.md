## Mandate

Build `quilltap-cli` — the native `quilltap` binary — with the subcommand
surface in oracle-parity order, each shipped verb **output-diffed against
the v4 launcher on the same fixture** (tier-4 #4). This round's scope is the
**direct-mode** verb set (exactly the verbs v4 itself runs without a
server: read-only DB opens, registry/lock/file ops); the HTTP-dispatch mode
lands with the first server-required verb (P4.4 — see Deferrals). Also
close the two P4.1 handoffs this lane owns: the **launcher lock verbs**
over `classify_lock_status` (+ the missing `Suspect` PID-identity probe +
the CLI write-lock) and the **instance-registry write verbs**.

**Exit criterion (milestone M1):** `quilltap db --tables` and
`quilltap docs ls` against a fixture instance, byte-diffed green against
`node <v4>/packages/quilltap/bin/quilltap.js` on the same fixture.

## Locked shape (from the v4 launcher survey)

### Argument routing (`bin/quilltap.js:1101–1203`)

- `SUBCOMMANDS` = `db, themes, docs, memories, instances, memory-diff,
  completion, logs, migrations, maintenance, file-verify`. **All are
  recognized** in v5's router; unshipped ones exit loud ("recognized but not
  yet available" naming the verb — the runner-fallback idiom), unknown bare
  tokens fall through to the launcher path.
- `locateSubcommand` semantics ported exactly: walk argv skipping the value
  tokens of the global value flags (`-p/--port`, `-d/--data-dir`,
  `-i/--instance`, `--passphrase`); the first bare token wins iff it is a
  known subcommand — so `quilltap --instance db db schema` behaves as v4
  does. `subArgs` = everything except the subcommand token; each subcommand
  re-parses flags position-independently.
- Bare `quilltap` (no verb) is v4's server launcher. **This round:** print
  the banner-and-exit with a pointer to `quilltap-web` (wiring
  `quilltap` → embed/exec the web server is a unification/next-round
  decision — do NOT depend on the `quilltap-web` crate from this lane).
  `--help`/`--version` per v4 (`--version` prints the v5 crate version —
  excluded from diffs). The download-manager / native-module-healing /
  `fork(server.js)` machinery does **not** port (D12).

### Resolution chain + pepper unlock (`lib/db-helpers.js`)

`resolve_data_dir_and_passphrase` ported exactly — precedence:
`--data-dir` (appends `/data`) → `--instance` (registry lookup,
case-insensitive; `<path>/data`; passphrase = flag || registry) →
**registered default instance** → `QUILLTAP_DATA_DIR` env (`/data`) →
platform default (`paths::platform_default_base_dir()` + `/data`).
`--data-dir` + `--instance` together = error, exit 1. The
platform-default-with-no-hints case emits the one-time **stderr** hint
listing registered instances, silenced by `QUILLTAP_QUIET_HINTS`.

Pepper unlock = v4 `loadDbKey`: no `.dbkey` → unencrypted open; else try
the internal sentinel `__quilltap_no_passphrase__` first, then
`--passphrase` → `QUILLTAP_DB_PASSPHRASE` env → hidden TTY prompt (raw
mode, no echo, Ctrl-C exits 130); no TTY when needed → v4's exact error.
Compose over the ported `quilltap-core::dbkey` (`load_pepper` etc. — do
not re-implement the crypto). Opens are **read-only** rusqlite connections
following the read-path pragma rules (`key` first and only) unless a verb
is explicitly write-mode.

### Subcommand scope tiers

**Tier R (required, diffed):**

- **`db`** — the legacy flag path complete: `--tables` (one name per line;
  `--json` → `JSON.stringify(names, null, 2)`), `--count <t>` (bare number;
  `--json` → `{table, count}`), raw SQL reader (`--json` → pretty rows;
  empty → `(no results)`; else **`console.table` reproduced byte-exact**,
  including the `(index)` column and box-drawing — it is deterministic V8
  formatting), raw SQL writer under `--write` (`Changes: <n>` /
  `{changes, lastInsertRowid}`), DB selection `--llm-logs` /
  `--mount-points`, plus the **lock commands** `--lock-status` /
  `--lock-clean` / `--lock-override` (v4 `bin/quilltap.js:465–685` output,
  ANSI classification ACTIVE/SUSPECT/STALE, last-10 history). `--write`
  acquires the CLI write lock first and refuses (exit 1, no override) if a
  live holder exists.
- **`docs`** read verbs (direct mount-index reads,
  `lib/docs-commands.js`): `list`, `ls`/`dir` (the fixed-width table with
  the `T links size modified text emb name` columns and the `= T ~ ! -` /
  `Y ~ -` markers), `tree`, `read` (raw byte streaming + the TTY-binary
  guard + `--rendered`), `show`. `assertDocsSchema`'s
  missing-`doc_mount_file_links` refusal + instance hints ported. `qtap://`
  URIs accepted where v4 accepts them (document-store scope only —
  `self`/`project`/`general` rejected), over the ported `qtap_uri` codec.
- **`instances`** — full registry CRUD: `add/remove/list/rename/
  set-default/clear-default/set-passphrase` + `verifyPassphrase`
  (`valid|wrong|no-dbkey|no-encryption`), implemented as the **write verbs
  on `quilltap-host::instances`** (atomic tmp+rename, mode 0600, the
  owner/permission refusal on read — this closes the P4.0/P4.1d registry
  handoff). Case-insensitive name lookup.
- **Lock plumbing in `quilltap-host::lock`** (append-only additions):
  the `Suspect` classification's PID-identity probe (v4 `verifyPidIsNode`
  becomes verify-pid-is-quilltap-or-node — per-OS `ps`/`tasklist`/`/proc`,
  keep v4's classification thresholds), and
  `acquire_write_lock`/`release_write_lock` for CLI write-mode (refuse on
  live holder, no override; reuse `classify_lock_status`).

**Tier B (budget-allowing, in this order):** `db` high-level verbs
(`schema`, `chats`, `messages`, `characters`, `memories`, `find`, then
`logs`/`message`/`log`); `docs` `files`/`status`/`find`/`grep`;
**`memories`** read verbs (`ls`, `show`, `grep`, `tree`, `status`,
`validate` — direct main-DB reads; `find --semantic` is HTTP → deferred);
**`logs`** (`--tail`/`-f`/grep over `<base>/logs/*`); **`completion`**
(bash/zsh/fish emitters). Each shipped Tier-B verb gets the same diff
treatment; unshipped verbs exit loud. Do not start Tier B until Tier R is
green end-to-end.

### Output fidelity rules

- Every shipped verb's stdout/stderr is **byte-diffed** against the v4
  launcher on the same fixture, non-TTY. Check and match v4's ANSI behavior
  per code path (some of the launcher's coloring is hand-rolled and does
  NOT auto-disable off-TTY — reproduce whatever v4 actually emits when
  piped). JSON = `JSON.stringify(x, null, 2)` ↔ `serde_json`
  `to_string_pretty` with insertion-order maps and `js_number_to_json`
  where numbers flow from the DB.
- Documented normalizations only where v4 output embeds environment truth
  that legitimately differs (e.g. absolute lock paths when the fixtures
  can't share a path; version strings). Everything else is exact.

## Deferrals (tracked, with owners)

- **HTTP-dispatch mode** + every server-required verb: `docs`
  `scan/write/delete/mkdir/move/copy/link/rmdir/mvdir/reindex/embed/
  find --semantic`, `memories find --semantic`, `memory-diff` → P4.4 (they
  need dispatch variants that don't exist yet; v5 calls
  `POST /api/dispatch`, not v4's REST tree). The v4 `ECONNREFUSED` →
  "Cannot reach Quilltap server" UX ports with them.
- `themes` (needs the P4.4 themes service), `migrations` (migrations are
  unported P4.4 surface), `maintenance` (`status` is cheap but `run`
  overlaps the host sweeps — take both together later), `file-verify`
  (macOS iCloud recovery — low priority, pure fs).
- Bare `quilltap` launching the web server → unification / next round
  (needs `quilltap-web` on main).
- `db --repl` — interactive; implement if budget allows, verified by
  v5-side transcript tests only (no byte-diff of readline behavior).
