## Shared contract (BINDING — identical in all three orders)

### §1 — the round's new wire surface (P4.9G1 delivers; P4.9G2 consumes; fold-at-unify)

Sixteen new CoreRequest variants (wire `type` tags, exact):
`systemBackupCreate`, `systemRestorePreview`, `systemRestoreExecute`,
`systemExportEntities`, `systemExportPreview`, `systemImportPreview`,
`systemImportExecute`, `systemTasksQueue`, `systemTasksQueueControl`,
`systemJobConcurrencyGet`, `systemJobConcurrencySet`, `systemJobGet`,
`systemJobControl`, `systemJobDelete`, `systemDeleteDataPreview`,
`systemDeleteData`. Payload fields mirror v4's route bodies verbatim (the
G1 survey table is authoritative — e.g. `systemRestoreExecute
{uploadId, mode}`, `systemDeleteData {confirm}`, `systemJobConcurrencySet
{maxConcurrentJobs}`). G1 defines them in `api/types.rs`; G2 mirrors them
in `core-contract.ts` name-for-name; the unifier diffs the two by name at
unification.

Web-edge-only legs (no dispatch verb; G2 reaches them via `apiUrl()` raw):
- `GET /api/v1/system/backup/{id}` — the single-use zip download.
- `POST /api/v1/system/restore?action=upload` — the octet-stream upload
  leg → `{uploadId}`.
- `POST /api/v1/system/tools?action=export` — the NDJSON `.qtap` streaming
  download.
- `POST /api/v1/system/tools?action=import-preview|import-execute`
  multipart legs (the JSON legs ride the dispatch verbs).

Existing surface G2 builds on with NO G1 work: `changePassphrase`
(`types.rs:86`, mirrored at `core-contract.ts:1429`), `lock`
(`types.rs:92`), the unlock-state read with `autoLockMinutes`
(`engine.rs:3641`; DTO `types.rs:2646`), `chatSettingsUpdate` carrying
`autoLockSettings` + `llmLoggingSettings`, and the llm-logs family
(`llmLogsList`/`llmLogGet`/`llmLogDelete`).
