## The gap (why this order exists)

**v4.** A character who dresses, undresses, is given a new garment to wear
now, or archives what it has on gets its avatar re-rolled — awaited inside
the tool handler, before the handler re-reads the wardrobe state and
records the announcement. v4's trigger swallows its own failures (two WARNs),
so a tool never fails because of it. **v5** ported all seven wardrobe tools
with the trigger left as a named seam ("image subsystem seam (out of
scope)") and never came back: a character's own mid-chat wardrobe change
never refreshes its avatar. P4.D238 censused the four v4 sites while porting
the join-path refresh and left this as its own order. The two smalls ride
here because they are the same file family (`avatar_generation.rs`,
`chat_participants.rs`) and no sibling lane touches either.
