### Quirks the port must not miss

1. The WS heartbeat is client-initiated `ping` → `pong`; v4 sends it
   on an interval — keep the cadence (pin it from
   `useTerminalSession.ts` at lane start).
2. On attach, `GET /api/v1/terminals/{id}` returns metadata + the
   scrollback ring buffer — replay it into xterm BEFORE streaming
   (otherwise reattach loses history).
3. Resize is client-computed (fit addon → cols/rows) and must fire on
   pane resize AND divider drag, debounced as v4 does.
4. The collapse state is localStorage-per-session; the pane state
   (`terminalMode` etc.) is chat-persisted — two different stores,
   don't conflate.
5. The embed marker regex must match v4 byte-for-byte
   (`MessageRow.tsx:25`) — an embed rendering as a raw HTML comment
   (or vice versa) is a port failure.
6. xterm needs real DOM geometry — in `ng test` (jsdom-ish) the fit
   addon has no box; unit-test the session service and the marker
   extraction as pure logic, and leave surface rendering to the live
   e2e (the P4.6j Blob.text() precedent for ng-test DOM gaps).
7. Kill vs delete: `?action=kill` signals the PTY; `DELETE` removes
   the session. The embed's kill button uses the action; pin the
   picker's delete affordance from v4.
