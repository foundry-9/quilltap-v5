### The v4 flow — `packages/quilltap/lib/dbkey-restore.js` (new, 347 lines)

`restoreKey(opts)` `:181-345`, in order:

1. **Target** `resolveTarget` `:149-168`: name XOR `--data-dir` (both →
   `Specify either an instance name or --data-dir, not both.`; neither →
   the usage line); `--data-dir` accepts the instance root OR the `data/`
   dir itself (`basename === 'data'`), and scans the registry to recover
   the instance name (else unregistered). Missing dir →
   `Data directory does not exist: <dir>`.
2. Prints (BEFORE the lock): `Instance:    <name or (unregistered)>` /
   `Data dir:    <dataDir>` — note the fixed-width label padding.
3. **Lock** `:195`: the same `<dataDir>/quilltap.lock` write lock as
   `db --write`; contention/corrupt messages are v4's exact three-liners
   (already byte-ported in `quilltap-host/src/lock.rs:662-706`).
   ⚠ Unlike `db --write` (prints bare), restore-key's throw is printed as
   `Error: <message>` + exit 1 by the instances command handler — v5's
   `instances_cmd.rs:56-61` result handler already has that exact shape,
   so a `restore-key` arm returning `Err(String)` inherits it. Release in
   a `finally` (idempotent `release_write_lock`).
4. **Pepper** `:200-211`: env `ENCRYPTION_MASTER_PEPPER` trimmed →
   `Pepper:      from ENCRYPTION_MASTER_PEPPER`; else hidden prompt
   `Encryption master pepper (hidden): ` (non-TTY rejects with v4's
   `This database requires a passphrase. Use --passphrase <pass> or set
   QUILLTAP_DB_PASSPHRASE` — the db-helpers prompt is reused, quirk and
   all); empty → `No pepper provided. Set ENCRYPTION_MASTER_PEPPER or
   paste it at the prompt.`; base64-decode length ≠ 32 → the
   `Warning:     that does not look like a Quilltap pepper (44-char
   base64 of 32 bytes).` line (warning only).
5. **Proof** `provePepper` `:107-132` over exactly three files in this
   order: `quilltap.db`/"main database",
   `quilltap-llm-logs.db`/"LLM logs database",
   `quilltap-mount-index.db`/"mount index database".
   `databaseState` `:83-97`: absent / <16-byte or SQLite-magic header →
   plaintext / else encrypted. Encrypted files open read-only with the
   pepper then `SELECT count(*) AS n FROM sqlite_master`. Output: one
   line per file, `filename.padEnd(28)` then `absent` / `unencrypted
   (nothing to check against)` / `opens with this pepper ✓` /
   `DOES NOT OPEN — <first line of err.message>`, blank lines around the
   block. Any failure → the three-line refusal (`This pepper does not
   open the databases on disk. …`) — **`--force` never waives a
   failure**. No encrypted DB at all → `proved=false`: print
   `No encrypted database exists here, so the pepper cannot be proved.`
   (+ the two-line still-unencrypted note when any file is plaintext),
   then `--force` skips the `Write the .dbkey anyway? [y/N] ` confirm
   (`--yes` auto-answers it). Decline → `Aborted.`
   ⚠ The failure line's `<err.message>` is v4's composed
   `Cannot open <label>: <sqlite msg>` (first line only) — the
   `<sqlite msg>` is engine text (`file is not a database`), the one
   cross-engine byte risk; v5's `dbopen.rs::sqlite_msg` already yields
   better-sqlite3-shaped messages — verify on the wrong-pepper case.
6. **Existing `.dbkey`** `:249-264`: same `pepperHash` → `An existing
   .dbkey already holds this pepper — rewrapping it.`; different → the
   `WARNING: the existing .dbkey holds a DIFFERENT pepper than the one
   given.` (+ `The databases opened with the new one, so the file on
   disk is the stale part.` when proved) and the
   `Replace it? (a timestamped backup is kept)` confirm — gated by
   `--yes`, NOT by `--force`.
7. **New passphrase** `:267-282`, precedence: `--no-passphrase` → none;
   `--passphrase <v>` (non-empty); `--yes` → none; else hidden prompt
   `Passphrase for the rebuilt .dbkey (blank for none): ` +
   `Confirm passphrase: ` (mismatch → `Passphrases did not match.`).
8. **Write** `:290-307`: backup existing to
   `quilltap.dbkey.bak-<ISO timestamp with : and . → ->` (chmod 600
   best-effort); write `preserveExtraFields(existing, encryptDbKey(...))`
   — the unknown-field carry (`minServerVersion`); read back and verify
   the pepper decrypts, else restore the backup and throw `Wrote the
   .dbkey but could not read the pepper back — restored the previous
   file.`
9. **Success output** `:309-318`: `Wrote <dataDir>/quilltap.dbkey (mode
   0600).` / optional `Previous file kept at <basename>.` / exactly one
   of `The instance now unlocks with the passphrase you just set.` |
   `The instance now opens with no passphrase.`
10. **Registry** `:321-328`: registered instances get
    `setInstancePassphrase` + `Updated the stored passphrase for
    "<name>".` | `Cleared the stored passphrase for "<name>".`
11. **Archive note** `:331-341`: when an existing file was replaced AND
    the passphrase effectively changed (`replacingDifferentPepper ||
    hadUserPassphrase !== (new.length>0) || both-set`), the four-line
    `Note: character ARCHIVE bundles in files/ …` paragraph verbatim.

Flags (`instances-commands.js:300-324`): `-d/--data-dir` (value),
`--passphrase` (value), `--no-passphrase`, `--force`, `-y/--yes`;
unknown `-*` → `Unknown flag: <a>`; second positional →
`Specify one instance.`; no target → usage on stderr + exit 1. All
errors: `Error: <msg>` on stderr, exit 1. Verb arms `restore-key` and
`rebuild-key` (`:375-378`).

⚠ `dbkey-restore.js` has its OWN `promptLine` with a `close` handler
