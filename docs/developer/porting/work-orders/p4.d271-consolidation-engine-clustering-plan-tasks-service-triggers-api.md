  table `PARTIAL_DEFAULTS_CLOBBER`** (§R.11). v4's handlers parse with
  `<Schema>.partial()` and "drop undefined keys so a partial write never clobbers
  stored values" (`route.ts:897-914`, `:921-937`). Under Zod 4, `.partial()` over
  `.default()` fields still fills the default for an absent key (survey §0.1,
  MEASURED: `{enabled:true}` → all nine keys; `{}` → all three), so nothing is
  ever `undefined` and EVERY POST rewrites EVERY field. v5 reproduces it: the patch
  is the FULL default-filled parse (re-measure first that v4's `.partial()` parse
  and the full-schema parse agree on data for every corpus input — if they do, the
  setter calls C1 §6's full parse fn; record the measurement), merged
  `{...current, ...patch}` (= patch), validated, written, re-read; the INFO
  `fields` always lists every key in schema order. The table pins BOTH ways:
  v5's bytes equal v4's at the pin AND the stored tuned value is LOST (rows:
  stored `{enabled:true, clusterThreshold:0.5, watermark:300}` + POST
