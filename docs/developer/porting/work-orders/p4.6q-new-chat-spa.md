### Field/behavior pins (the load-bearing details)

1. **Character selection** (required: ≥1 character, ≥1 LLM-controlled,
   every LLM one needs a `connectionProfileId`): roster from
   `characterList`, split client-side by `controlledBy !== 'user'`.
   First selected = "Speaks First" badge. Selecting seeds
   `defaultConnectionProfileId || profiles[0]` + the default system
   prompt (`defaultSystemPromptId` → `isDefault` → first). The
   per-character profile select includes the special
   `__USER_CONTROLLED__` option ("Play As (User)") that flips
   `controlledBy` and clears the profile. Roster sort: favorites >
   user-controlled > chat count desc > lowercased localeCompare name >
   title. No connection profiles at all → warning banner + submit
   disabled.
2. **Play-As is in-place, not a separate slot** — the single source of
   truth is the cast entry with `controlledBy: 'user'`. Revert
   semantics: a default-user persona pulled in by the dropdown is
   REMOVED on revert; a default-LLM character that was flipped is
   handed back to LLM WITH ITS PROFILE CLEARED (so the submit guard
   asks again). All eight behaviors pinned in v4's
   `NewChatForm.test.tsx:230–326` — transcribe them.
3. **Scenario preset dropdown** — mutually exclusive sources with
   prefixed option tokens (`types.ts:170–187`): bare UUID (character
   scenario, only with exactly one LLM character), `project:<path>`,
   `general:<path>`, `group:<groupId>:<path>`. Free-text notes are
   INDEPENDENT — selecting a preset never clears typed text; both are
   sent (the server layers notes under the preset). Payload precedence
   chain: `scenarioId` > project > group > general; every dropdown
   change nulls the other three. Character roster changes reset
   `scenarioId` ONLY (path selections survive). Dropdown renders only
   when a source is non-empty. **The group optgroup is dead UI in v4**
   (the union is fetched but never passed into the form by either entry
   point) — port faithfully: fetch `groupScenariosUnion` like v4 does,
   keep the optgroup unreachable; record the decision.
4. **Seeding precedence** (`useNewChat.ts:380–537`): preset
   pre-selection = project default > general default (a seeded
   character's `defaultScenarioId` rides `scenarioId` but the project
   default wins, with a one-click "switch to character default"
   override note). Image profile = `project.defaultImageProfileId ||
   char.defaultImageProfileId || ''`. `avatarGenerationEnabled` from
   the project default. Exactly one LLM character selected un-seeded →
   its defaults propagate and its default partner auto-joins as the
   user persona (`characterDefaultPartner` wins over the character's
   own field). The project LIST omits the default-* fields — fetch the
   full `projectGet` for defaults (v4's why-comment).
5. **Title is never user-editable** — `generateTitle`: "New Chat" /
   "Chat with X" / "Chat with X and Y" / "Chat with X, Y, and Z" /
   "Group Chat (N characters)" (exact copy).
6. **Submit** (`handleCreateChat` :626–811): pre-flight toasts (≥1
   character; every LLM char has a profile; ≥1 LLM char); generate
   `progressId` (`crypto.randomUUID()`); open the Green Room BEFORE the
   dispatch; POST; **the dispatch resolving is the authoritative ready
   signal, not the SSE `done`** (v4's why-comment); success → toast →
   navigate to `/salon/<id>` → close the dialog; failure → error toast
   + the dialog stays open with the error and a Close button (backdrop/
   Escape disabled — the only dismissal path).
7. **The Green Room** — frames per the Rust source (frozen this round):
   `status {message}`, `log {level, message}`, `wardrobe-start` /
   `wardrobe-result` (render the four-slot outfit preview), `done`,
   `error`. Late-subscriber replay is server-side; consume off the ONE
   global event stream filtered by `progressId` (do NOT open a bespoke
   SSE route — D3/D6). Copy: "Fetching the players from the green
   room…", "The players are ready.", "Something went awry." (Wodehouse
   register carries over verbatim.)
8. **Outfit selector** modes: `default` / `manual` (embedded composer)
   / `llm_choose` (hidden for user-controlled) / `none` ("Start
   undressed") / `previous_chat` (continuation only). Manual mode is
   deferred with the wardrobe-composer family (tier 3) — render the
   mode radio with manual disabled-with-title. Wearing rules for
   manual (fills every slot honoring `replace`) come with that
   deferral.
9. **Timestamp card** ("Reality Injection Mode", compact variant):
   seeded from `character.defaultTimestampConfig`; `timestampConfig`
   is DROPPED from the payload when mode is `NONE`.
10. **Client-side transforms**: booleans sent only-when-true
    (`avatarGenerationEnabled`); optionals truly absent; the autonomous
    hours→ms / minutes→ms conversions live at submit (deferred with
    autonomous mode, but keep the seam shape).

unit tests); no silent stubs — deferred modes render loud
disabled-with-title affordances; `[selected]`-per-option for every
async-options select (the dogfood-#6 class); no control-flow markup
inside `<pre>`; the schema/cipher and server behavior are frozen — if
the form seems to need a server change, STOP and report (the server is
differential-proven; the form adapts to it, not vice versa); if a
unit's fresh v4 survey contradicts this order, STOP and report.
