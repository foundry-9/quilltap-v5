## The drift, classified (surveyed 2026-08-08, from the `f6eac168` diff)

v4 fixed five bugs in one commit; this lane owns the three server-side ones:

- **Bug 50 — fair first-responder rotation.** With 2+ user-driven seats and a
  single LLM, the first responder after a human post was picked from an
  LLM-only shortlist, so that LLM answered every human turn. v4 adds a pure
  helper `selectNextSpeakerAfterUserMessage` (projects the rotation one step
  past the just-typed, unpersisted message) and a spine guard
  `maybePauseForUserSeatTurn` that persists the message and PAUSES for the
  other user-driven seat when the rotation lands there.
- **Bug 47 — Brahma budget-exhaustion salvage.** The forced final turn runs
  no tools, so a model answering it with another tool call left
  `fullResponse` empty → no saved message, no `done` event (a silent hang).
  Both Brahma paths now synthesize an explanatory answer folding in the last
  tool result, and the streaming path always signals completion.
- **Bug 51 (server half) — chat GET projects the impersonation overlay.**
  `impersonatingParticipantIds` (`?? []`) + `activeTypingParticipantId`
  (`?? null`) join the GET projection so a reload restores impersonation
  state.

The chat-GET projection gains exactly two keys, in the chat body returned by
BOTH entrances (dispatch `chatGet` → `{ type: "chat", data: { chat } }` and
REST `GET /api/v1/chats/:id`), positioned with the other turn fields:

- `impersonatingParticipantIds`: `string[]` — ALWAYS present, `[]` when the
  column is NULL/absent.

`nextSpeakerId: <seat>`, `chainDepth: 0`) exactly as already serialized by
`ChainCompletePayload`.
