## Shared contract (BINDING — identical text in P4.D100 and P4.D102)

The `list-models` response envelope, verbatim from v4
(`app/api/v1/image-profiles/route.ts:188-194`):

```
{
  "provider":        <echoed provider string>,
  "models":          string[],          // the list to show
  "supportedModels": string[],          // always the plugin's curated list
  "source":          "provider" | "builtin",
  "fetchError":      string             // present ONLY on keyed live-fetch failure
}
```

Error bodies: missing provider → 400 `Provider is required`; unknown
provider → 400 `Provider ${provider} is not available`; dangling
`apiKeyId` → 404 (API key not-found shape); outer failure → 500
`Failed to fetch models`. `fetchError` is omitted (not null) when absent.
Cache: only `source === "provider"` lists are cached (capability
`image`). Request: dispatch verb `imageProfileListModels`
(`ImageProfileListModels { provider, api_key_id }`,
`api/types.rs:901-908` — already typed on both sides;
`core-contract.ts:4158-4162` client-side).
