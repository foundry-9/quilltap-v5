Per the e3 plan, in order:

1. `compression_tier3` — the writer's through-a-real-call-site proof.
   NOTE: its oracle is currently FULLY DB-mocked, so this step includes the
   `[[jest-real-db-oracle]]` real-DB conversion on BOTH sides (the Rust
   test gains a real `Db` with the llm-logs partition — the three-DB
   `state_sql_tools` fixture shape). The heaviest step; it is first
   because it is the named writer proof.

   path; the moderation-path cases write NONE (bank the absence — the
   moderation-path logging is a tracked seam, see the e3 note: the

3. `answer_confirmation_tier3` — `ANSWER_CONFIRMATION` rows (check +
   re-affirmation both; the dangerous-escalation case's check row carries
   the uncensored profile).
4. `image_generation_tier3` — the four-site matrix incl. the post-hoc
   reroute legs (a failure row THEN a success row) + the
   `IMAGE_PROMPT_CRAFTING` / appearance cheap rows.
5. `avatar_job_tier3` + `story_background_job_tier3` — the job-path rows
   (via the shared `generate_with_reroute`) + `SUMMARIZATION`
   (derive-scene-context) and `IMAGE_PROMPT_CRAFTING`
   (craft-story-background-prompt) cheap rows.
6. `primary_stream_tier3` — `CHAT_MESSAGE` rows with `requestHashes`
   asserted against the ported `compute_request_prefix_hashes` at the
   wire. **DONE — moved to its own order W4.11b** (the mock relocation +
   the failover log-gap fix). Findings there: the lossy `StreamParams`
   message shape is a non-issue for the plain-message corpus (v4's mapped
   `request.messages` equals it); `durationMs` is 0 both sides (the oracle
   freezes `Date.now`); a real port bug surfaced and was fixed — the
   `db::llm_logs` `temperature` seam (integer-valued `1.0` → bare `1`).
7. `memory_processor_tier3` + `context_summary_service_tier3` — their
   cheap-LLM calls now write rows; regenerate with the dump added.
