## The drift, classified (surveyed 2026-08-20, fresh at `b8449b3e`)

`e22f7b36` is a behavior change squarely on ported surfaces — three
coordinated edits breaking the "committee-meeting chorus" failure mode in
group scenes (every turn opening with a roll-call recap, endorsing
everything, parroting coined phrases, restating the plan):

1. **`lib/services/chat-message/context-builder.service.ts`** — a new
   exported `GROUP_SCENE_DISCIPLINE` constant (a six-bullet content-rules
   block) appended to the system message on EVERY multi-character turn,
   on BOTH anchor routes. `applyMultiCharacterTurnAnchor` is
   restructured: it now computes `systemIdx` first, builds a
   `systemAdditions: string[]` (the prose route pushes the existing
   `IMPORTANT — this is a multi-character scene…` instruction FIRST, the
   prefill route does not), always pushes `GROUP_SCENE_DISCIPLINE`, and
   appends `'\n\n' + systemAdditions.join('\n\n')` to the system message
   when `systemIdx >= 0` — and THEN the prefill route still pushes its
   assistant `[Name]` message. Net behavior deltas: the prefill route now
   ALSO edits the system message (it used to return before any system
   read); the prose route's instruction bytes are unchanged but arrive
   via the join.
2. **`lib/chat/context-manager.ts`** — the turn-skip note: the base text
   gains a final paragraph ("If your reply would mostly restate, endorse,
   or re-phrase what has already been said — even in your own voice —
   that is not substantive. Pass.") and the caution sentence is reworded
   ("appears to have been **directly addressed since they last spoke**"
   replacing "addressed or mentioned since you last spoke").
3. **`lib/chat/turn-manager/skip-signal.ts`** — `isRecentlyAddressed`
   requires DIRECT address instead of any name mention: a new
   `buildDirectAddressRegex(character)` (vocative-position name/alias,
   `@`-mention, or targeted whisper) replaces the
   `findMentionedCharacterIds` corpus scan. Two new module constants:
   `VOCATIVE_LEAD_INS` (a small interjection alternation) and
   `VOCATIVE_PRE_BOUNDARY` (a clause-boundary character class). The
   module's client-safe import set changed: `findMentionedCharacterIds`
   out, `escapeRegex` (from `lib/utils/regex`) in. Returns `false` when
   the character has no usable name tokens (`buildDirectAddressRegex`
   returns null).
4. Help docs (`help/chat-multi-character.md`, `help/turn-skipping.md`)
   and an amendment note on
   `docs/developer/features/complete/nothing-to-add.md`.
5. `README.md`/`docs/CHANGELOG.md`/`package.json`/lock — NO-PORT.

v4's own test growth is the oracle model: `__tests__/unit/lib/chat/
turn-manager/skip-signal.test.ts` (+56 lines: vocative by name, alias

**JS-regex fidelity (the trap to plan around):** v4's regex is built
with flags `im` and used via `.test()`. The established v5 convention for
JS `\b` is `(?-u:\b)` — see
`crates/quilltap-core/src/mentioned_characters.rs:80`
(`(?i)(?-u:\b)(?:…)(?-u:\b)`), whose module header documents the
longest-first alternation reasoning. Carry-forwards for this port:

- v4 sorts tokens by `b.length - a.length` — **UTF-16 code units**, not
  bytes or chars. Sort by `s.encode_utf16().count()` (or equivalent) so
  alternation preference matches on non-BMP names.
- The `m` flag affects `^`/`$` — Rust `regex` `(?m)` matches JS here for
  `\n`-separated corpora (the corpus is `join("\n")`), but JS `(?m)$`
  also matches before `\r` — v4 message content can carry `\r\n`; decide
  with a corpus vector, don't assume.
- `VOCATIVE_PRE_BOUNDARY` contains Unicode chars (`…`, curly quotes,
  em/en dashes) — fine in a Rust class, but keep `-` last exactly as v4
  writes it and transcribe the class byte-for-byte.
- JS `i` without `u` vs Rust `(?i)` (full Unicode folding) can diverge on
  exotic names (ß, dotted İ). The corpus must include at least one
  non-ASCII alias vector to pin whichever way it lands; if they diverge,
  match JS (the `js_string` fidelity family precedents apply).
- `escapeRegex`: v4's `lib/utils/regex.ts` vs `regex::escape` — the
  escaped-source bytes differ but only MATCHING must agree; a vector with
  a regex-metachar name (`"Dr. Strange?"`) pins it.
