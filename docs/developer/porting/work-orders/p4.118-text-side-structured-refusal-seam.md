### A. v4 — how a text error reaches `provider-code` (survey §A)

1. **The classifier** (`refusal.ts`): `PROVIDER_MODERATION_CODES` =
   `{moderation_blocked, content_policy_violation, content_filter, safety,
   1301}` compared LOWER-CASED; `codeString(v)` = a non-empty string or a
   finite number as `String(v)`; `collectCodes(error)` reads (1) `record.
   code`, (2) `asRecord(record.error)?.code` — NOTHING else (not `status`,
   `type`, `param`, `error.error.code`, `innererror`); `classify`: typed →
   provider-code (detail `code ${code}[: ${message}]`, the code's ORIGINAL
   case) → finish-reason → message-pattern (eleven patterns; `content_
   filter` and Azure's wording are NOT among them) → inferred. So a
   benign-worded coded 400 is caught by the code ALONE; without it
   `engine.ts`'s `/\b4\d\d\b/` returns `null` → NO failover.
2. **Where the error enters:** `classifyFallbackTrigger(error)` (`engine.
   ts:100`) runs `classifyRefusal({error}).refused` FIRST; `primary-stream.
   service.ts:397` → `attemptHardErrorFailover` with the RAW thrown object
   (skipped when `hasStartedStreaming`); its `moderation-refusal` branch
   (`provider-failover.service.ts:993`) → `classifyRefusal` → `recordRoute
   Failure(…'refused', trigger, refusal.detail ?? failureMessage, refusal.
   evidence)` → the Locked gate → `attemptUncensoredRetry(… refusalWasStated:
   true, substitute: true)` or the chain; the cheap path (`core-execution.
   ts:712`) opens its stand-in chain with the same classification. **The
   tool loops RETHROW** (`native-tool-loop.service.ts:340/421`, `text-tool-
   loop.service.ts:390`) — `attemptHardErrorFailover` is called ONLY from
   the primary stream.
3. **The plugins never re-wrap** (every text `catch` logs and `throw
   error`); the only code-dropping throws are the 200-with-`response.error`
   paths (openai `:498/:526`, grok `:428`) — parity. **Who can carry a
   code (survey §A.3 table):** the openai-SDK providers — OPENAI,
   OPENAI_COMPATIBLE (Azure arrives here; there is no Azure plugin), Z_AI
   (`"1301"`), and structurally DEEPSEEK + NANOGPT — `APIError.code =
   body.error.code` in BOTH slots; NOT: GROK (xAI's `{"error":"<string>"}`
   → message `400 "…"`, no code), ANTHROPIC (`APIError.error` is the WHOLE
   body, NO `code`; `type` never read), GOOGLE (`ApiError {status, message:
   JSON.stringify(body)}`), OPENROUTER (SDK `error.code` = the numeric HTTP
   status; the fetch path a plain Error), OLLAMA (a plain Error).
4. **The openai SDK 7.23.0 shape** (`core/error.d.ts`, `client.ts:864`):
   `makeStatusError` NORMALIZES a JSON body whose `.error == null` into
   `{error: body}` (a flat `{"code":"content_filter","message":"x"}` still
   yields `code` and the message `400 x`); a non-JSON body → `error:
   undefined`, message `${status} ${text}`; an empty body → `${status}
   status code (no body)`; `makeMessage` = `${status} ${error.message}` /
   `JSON.stringify(error.message)` / `JSON.stringify(error)`. Anthropic
   0.115.0: message `${status} ${JSON.stringify(body)}`, no normalization.
   genai 1.52.0: `throwErrorIfNotOK` sets `JSON.stringify(body)`; a non-JSON
   content-type SYNTHESIZES `{error:{message:text, code:status, status:
   statusText}}`. OpenRouter SDK 1.3.28: `error.message` with NO status
   digits.
5. **Streaming throws the SAME coded `APIError` at stream creation**
   (`client.ts:1846`); mid-stream `event: error` frames throw
   `APIError(undefined, data.error ?? data, …)` (status undefined, `code`
   still read); before the first chunk that reaches the failover.
6. **Ready-made v4 test shapes** (all at `acadcc7cd`): `refusal.test.ts:
