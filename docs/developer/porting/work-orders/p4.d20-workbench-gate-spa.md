### v4 — the client-safe pair

Read both files whole; they are short and the comments carry the reasoning.

- **`lib/pascal/metadata-match.ts` (105 lines)** — `Primitive`, `isPrimitive`,
  `MetadataMatchHooks { resolveOperand, onDecline? }`,
  `metadataComparatorHolds(comparator, key, metadata, hooks)`. Fail-soft:
  absent key declines; non-primitive subject declines with the
  `null` / `an array` / `an object` wording; ordering needs numbers both
  sides; `eq`/`neq` compare with `!==`/`===` on the raw value; containment
  needs strings both sides and `ncontains` inverts. **The decline strings are
  load-bearing** — copy them exactly.
- **`lib/pascal/tool-gate.ts` (82 lines)** — `ToolGateVerdict
  { available; withheldBy? }`, `hasToolGate`, `evaluateToolGate`, `gateHolds`.
  `availableWhen` fails → `withheldBy:'availableWhen'`; else `withheldWhen`
  holds → `withheldBy:'withheldWhen'`; else `{available:true}` with
  `withheldBy` **absent, not null**. The gate's operand resolver is the
  identity — literals by construction. **Fail-soft ⇒ fail-CLOSED for
  `availableWhen`:** an empty sheet fails every `availableWhen` and satisfies
  no `withheldWhen`.

### v4 — `lib/pascal/tool-draft.ts` (+161 lines)

- `GateMode = 'none' | 'available' | 'withheld'`.
- `DraftGateCondition { id; key; comparator: ComparatorKey; operand:
  {kind:'number';text} | {kind:'string';text} | {kind:'boolean';value} }` —
  deliberately narrower than `DraftCondition`: the subject is always a
  metadata key, the operand always a literal.
- `ToolDraft` gains `gateMode` and `gateConditions`, **positioned after
  `disabled` and before `revealOdds`**. `newDraft()` seeds `'none'` / `[]`.
  Conditions are **kept while `gateMode` is `'none'`**, like the roll fields.
- `gateConditionsFromGate(gate)` — key order follows the object's own order;
  within one comparator object, key order follows `COMPARATOR_KEYS`. Ids from
  `nextDraftId('gate')`. Number → `{kind:'number', text: numberText(v)}`,
  boolean → `{kind:'boolean', value}`, else `{kind:'string', text: String(v)}`.
- `gateFromConditions(conditions)` — the inverse. Skips blank keys, skips
  unparseable numbers, skips an empty string operand **only for containment
  comparators**; chips on the same key merge into one comparator object;
  returns `undefined` when nothing usable remains.
- `draftFromDefinition` — `const gate = definition.availableWhen ??
  definition.withheldWhen` (at most one, by schema), `gateMode` derived,
  `gateConditions` flattened.
- `KNOWN_KEY_ORDER` gains `availableWhen`, `withheldWhen` after `disabled`.
- `definitionFromDraft` — when `gateMode !== 'none'`, build the gate and emit
  it under the mode's key, **positioned after `disabled` and before
  `revealOdds`**; a gate that reassembles to `undefined` emits nothing.
- `DraftIssue['where']` gains `{ section: 'gate'; conditionId?: string }`.
- `validateGate(draft, issues)` — called from `validateDraft` **after the
  identity checks and before the parameter checks**. Rules, with exact
  wording (v4 `lib/pascal/tool-draft.ts:947-1010`):
  - `gateMode === 'none'` → return immediately.
  - no condition with a non-blank key → `{section:'gate'}`,
    `the gate must test something — add a condition, or set the tool back to “anyone may reach for it”`
    (note the curly quotes).
  - per condition, at `{section:'gate', conditionId}`:
    blank key → `a gate condition needs a metadata key` (and `continue`);
    duplicate `key:comparator` slot → `the gate can test this key with this comparator only once`;
    ordering comparator with a non-number operand → `` `${comparator} can only order numbers` ``;
    containment with a non-string operand → `` `${comparator} needs text to look for` ``;
    containment with an empty string → `the substring to look for must not be empty`;
    otherwise a number operand that does not parse finite →
    `the comparison needs a number`.
  - **Deliberately NOT checked:** whether any character carries the key.
- **v4's `__tests__/unit/lib/pascal/tool-draft.test.ts` gained 140 lines** for
  exactly this. Port them case-for-case, as v5 did for the original 408-line
  suite.
