## Mandate

Build the first Settings slice in `apps/web`: the Settings screen shell
(tabs + collapsible sections + deep links), the **AI Providers** tab (API
keys, connection profiles, cheap-LLM card), the **setup wizard**
(settings mode), and basic **Appearance** (theme select + color mode +
avatar settings) with the theme choice persisted server-side. Exit state
(at unification): a fresh instance walks setup → the wizard → a working
connection profile with a tested key — configured to the point of
chatting.

## Deliverables

1. **The Settings shell**: `/settings` route + nav-rail entry;
   `EntityTabs` + `CollapsibleCard` ports (same `qt-tab-*` /
   `qt-collapsible-card` classes); `?tab=&section=` in the URL; the
   subsystem background per tab; the shared settings fetch fan-out
   (`chatSettings` + `connectionProfileList` + lazily `apiKeyList` /
   `providerList` on the Providers tab) via TanStack Query.
2. **API Keys card**: list (masked `keyPreview` rows as ProfileCards),
   create modal (provider dropdown from `providerList`, filtered to
   `configRequirements.requiresApiKey`; password input; v4's "Your key is
   encrypted and never exposed."), delete with confirm, per-key Test →
   `{valid, error?}` surfaced. Export/import buttons OMITTED (deferral).
3. **Connection Profiles card**: list/create/edit/delete over the pinned
   variants; the modal's four-button flow (Connect → Fetch Models → Test
   Message; Auto-Configure omitted per the sibling deferral — leave the
   slot), the `ModelSelector` combobox fed by `modelFetch`/`modelList`
   with the free-text fallback, the default-profile flag, the rich flags
   (isCheap, isDangerousCompatible, allowToolUse + pseudoToolMode,
   supportsImageUpload, web search, modelClass, maxContext,
   temperature/maxTokens/topP), reorder (drag or up/down per v4),
   duplicate-name inline validation. Courier transport: render the option
   with v4's forced-flag gating (it's a plain create — no provider
   actions).
4. **Cheap LLM card** (`cheapLLMSettings` via `chatSettingsUpdate`) and
   **Avatar Settings card** (mode + style) — both PUT-merge patterns.
5. **The setup wizard (settings mode)**: `ProviderWizard` with steps
   providers → api-keys → models → confirm (the embedding + image steps
   render as v4's skippable steps but immediately skip — their route
   families are deferred); `wizard-api.ts`'s calls map to `providerList` /
   `apiKeyCreate` / `connectionProfileTest` / `modelFetch` /
   `connectionProfileCreate` / `chatSettingsUpdate` /
   `connectionProfileTestMessage`; settings-mode re-entry pre-populates
   from the list variants. Reachable from the Providers tab card AND as
   the fresh-instance path after `/setup` (survey how v4 hands off
   first-run → wizard; wire the equivalent).
6. **Appearance basic**: the theme select over the existing `ThemeService`
   (six bundled packs) + color mode + `showNavThemeSelector`, with the
   choice persisted via `chatSettingsUpdate {themePreference}` (per the
   pinned contract note; if P4.6d's survey lands a dedicated variant,
   reconcile at unification) and re-applied on boot from the server value
   — localStorage becomes the offline fallback. The `.qtap-theme`
   registry/browser/install UI is OUT (deferral with the themes service).
7. **Tests**: Vitest for the tab shell (deep links), each card over a
   mocked CoreClient (incl. the masked-key rendering, the duplicate-name
   validation, the wizard reducer walk), and the theme-persistence
   round-trip; a Playwright spec for the LIVE flow (fresh-instance server:
   setup → wizard → create key + tested profile against the e2e mock LLM
   [extend `e2e/support/mock-llm.ts` with the `/models` +
   validate endpoints the wire expects] → the profile appears in the
   Providers tab), marked skipped-with-reason until unification wires the
   sibling lane's variants. NOTE: "to the point of chatting" ends at the
   configured profile — a fresh instance has zero characters (the
   sample-content seed is a standing P4.4 deferral), so chat creation is
   NOT in this spec's scope; assert the configured state instead.
