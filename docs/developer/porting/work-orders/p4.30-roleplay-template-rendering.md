## Mandate

Close the app-wide `renderingPatterns` / `dialogueDetection` fidelity gap
banked by P4.26: v5 never fetches the chat's roleplay template, so EVERY
message renders with the DEFAULTS, while v4 threads
`template.renderingPatterns` + `template.dialogueDetection` into every
row. After this lane, a chat whose template customizes the patterns
renders v4-identically. SPA-only; the server surface already exists.

**Must NOT touch:** any Rust; `api/types.rs` (FROZEN — if the template
GET truly has no existing verb/REST route, STOP and record rather than
adding one; the templates settings tab already round-trips templates, so
a read path exists); P4.29's census-row files; P4.28's
`screens/settings/system/**`; any existing e2e spec.

## Tiered deliverables

**Tier 1 (must land):**

1. The template fetch + state in `salon-conversation.ts` with v4's exact
   reset semantics, re-firing on `roleplayTemplateId` change.
2. Threading into every rendered message row (both list paths if v5 has
   virtualized + plain, matching v4's two call sites), with v4's
   fallback asymmetry (empty array → defaults; `||` on
   dialogueDetection) preserved byte-exactly in render output.
3. The render-cache story: template-sensitive keying or invalidation,
   with a spec proving a template load re-renders already-rendered rows.
4. **The differential**: regenerate the markdown parity fixtures from
   v4's REAL renderer at the baseline (the P4.d9 recipe —
   `markdown-fixtures.json`, currently 40 vectors) EXTENDED with
   pattern-bearing vectors: at least one custom `renderingPatterns` set,
   one custom `dialogueDetection`, one empty-array patterns (the
   fallback arm), one null template (the reset arm) — byte-parity
   asserted. Existing vectors must come back byte-identical (the
   baseline-neutrality proof).
5. Spec coverage porting v4's fallback logic case-for-case
   (MessageContent's L333–338 arms).

**Tier 2 (should land):**

6. One new e2e spec file: a beat that assigns a template with a visible
   custom pattern to a seeded chat and asserts the rendered DOM shows
   the pattern applied (and reverts to defaults when the template is

7. `roleplayTemplateName` display, if the v5 surface v4 shows it on
   exists (survey first; record if not).

beat. First-run-green fixture arms get mutation proofs (e.g. flip the
empty-array fallback → the parity vectors must go red).
