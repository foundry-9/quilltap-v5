## Mandate

Port `d883a5ee1` whole, so that every memory a character holds ABOUT someone
else is rendered with its subject named in the three self-facing context
blocks (`## Memory Anchors`, `## Relevant Memories`, `Most relevant memories
for this turn:`), on the live turn, in Carina answers, and in character-voiced
announcements — v5 today hands every character other people's lives as
autobiography, on every turn, in every multi-character chat. Five parts: (1)
the pure `format_memory_subject_prefix` + `MemorySubjectContext`; (2) the
prefix spliced into `format_memories_for_context`,
`format_frozen_memory_archive`, `format_dynamic_memory_head` — placed exactly
where v4 places it in each line template and INCLUDED in each line's token
estimate; (3) `characters_read::find_names_by_ids` on the RAW (un-overlaid)
path; (4) the `memory_subject` resolver module (no query when the subject set
is empty; the debug line); (5) the three call sites. Must NOT touch:
`format_inter_character_memories_for_context` (already attributed — v4 leaves
it alone), any other formatter, `cheap_llm*.rs`, `message_context.rs`, the
vault overlay code, `lib.rs`.

## Survey-verified starting points (2026-09-05, from the shipped hunks — ledger §5.3)

1. **v4 post-fix shape** (`lib/chat/context/memory-injector.ts`):
   `MemorySubjectContext { selfCharacterId: string; characterNames:
   ReadonlyMap<string,string> }` (`:130`); `formatMemorySubjectPrefix(
   aboutCharacterId, subject)` (`:148-155`) — `''` when `aboutCharacterId` is
   falsy, `''` when it equals `selfCharacterId`, else `` `About ${name}: ` ``
   on the map's (already trimmed) name, else the literal
   `'About another character: '`. Both fields and the parameter are REQUIRED
   (v4: omission is how the defect arrived). Line templates: memories `:357`
   `` `- [${narrative ? `${age} · ${narrative}` : age}] ${prefix}${body}${meta}` ``
   (prefix AFTER the bracket tag, before the body); frozen `:559`
   `` `- ${prefix}${summary}${meta}` ``; head `:658`
   `` `${idTag} ${whenTag} ${prefix}${summary}${meta}` ``. **The token
   estimate is taken on the prefixed line in all three** — verify each hunk
   and carry that (it is what keeps the prefix inside the block budget).
2. **v5 formatters** (`crates/quilltap-core/src/memory_injector.rs`):
   `format_memories_for_context(memories: &[InjectorResult], max_tokens: i64,
   now_ms: f64)` `:491`; `format_frozen_memory_archive(memories:
   &[InjectorMemory], max_tokens: i64)` `:792`; `format_dynamic_memory_head(
   memories, max_tokens: Option<i64>, max_entries: Option<usize>, now_ms)`
   `:860`. `InjectorMemory.about_character_id: Option<String>` exists
   (`:170`) and is read at only two sites, `:627`/`:643`, both inside
   `format_inter_character_memories_for_context` (`:600`) — the same
   one-of-four attribution v4 just fixed. There is no `About another
   character` string anywhere in `crates/`. **v5's parameter ORDER cannot be
   copied** (v5 takes `now_ms`/`max_tokens` where v4 takes `provider`): add
   `subject: &MemorySubjectContext` as a REQUIRED parameter to all three (a
   `&` reference — no `Option`, no default; the Rust compiler is the "required"
   v4 asks for), and copy byte-for-byte the prefix text, its placement in each
   template, and its inclusion in `estimate_tokens`.
3. **The repository half does NOT port mechanically.** v4's
   `CharactersRepository.findNamesByIds(ids)` (`characters.repository.ts:197-217`):
   dedupe non-empty string ids, `new Map()` on empty, `safeQuery(..., 'Error
   resolving character names', {count}, new Map())`, and inside it calls
   **`super.findByIds`** — the BASE repository, deliberately skipping the vault
   overlay (a per-turn unreadable vault must cost a *name*, not the turn;
   `findById` throws `CharacterVaultUnavailableError` on that shelf); rows
   with a blank/non-string name are absent from the map; names are `.trim()`ed.
   v5's `db/characters_read.rs:344 find_by_ids` calls `overlay_many(...)`
   (`:357`) — it IS the overlaid twin. The new `find_names_by_ids(main:
   &Connection, ids: &[String]) -> HashMap<String,String>` must go through
   `query_raw` (`:226`, the `id IN (…)` placeholder form the file already
   uses) and take NO mount connection at all — the signature is the proof it
   cannot reach the vault. Fail-soft: a DB error → an empty map + v4's warn
   sentence through the tracing seam, never an `Err` up the turn.
4. **The resolver module** — v4 `lib/memory/memory-subject.ts` (59 lines,
