### Quirks the port must not miss

1. Response wrappers are per-handler v4 texture: roleplay list = bare
   array; roleplay delete = `{success, deletedId}`; image list =
   `{profiles, count}`; image delete = `{message}`; mount list =
   `{mountPoints}`; mount delete = `{message}` — the differentials pin
   each.
2. `unsetAllDefaults` mints `updatedAt` on sibling profile rows — the
   differential diffs those rows too (normalize minted ts per the
   established remap; nothing else changes on them).
3. The startup seed mints `updatedAt` on built-in roleplay templates
   every boot (v4 parity, P4.4u3) — keep fixture assertions off
   built-in `updatedAt`, or blank it.
4. The roleplay PUT partial-body seam (`null?.trim()` → `undefined` +
   spread-copies-undefined + full re-validate) is pinned by the oracle,
   not by reading: write the update-with-explicit-null-description case
   FIRST, observe v4, port the observed behavior.
5. Sorts: roleplay = builtin-first + bare `localeCompare` (ICU4X en-US);
   image = default-first + createdAt DESC (+ the sortByCharacter
   default-last tie-break quirk); mounts = createdAt DESC.
6. Mount-point create/PATCH fs side effects (`verifyBasePath`, watcher
   attach/refresh) are injected seams with no-op/deterministic defaults;
   the differential drives both sides with the same verdict (a
   nonexistent path yields the deterministic warning string on both).
7. `createMountPointSchema` uses `.refine` — route-side parsing only;
   never feed it to DDL paths (the P4.1d `.refine` finding).
8. GET-\[id\] vs list compute `embeddedChunkCount` by different code
   paths (hydrating filter vs GROUP BY) — same number, but port both
   shapes; the differential covers a mount with embedded chunks if the
   fixture has any (else add one chunk row with a small embedding).
