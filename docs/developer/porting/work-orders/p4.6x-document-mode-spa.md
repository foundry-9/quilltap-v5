## Mandate

Port v4's **Document Mode client** into the Angular SPA: the document pane
(editor, header actions, frontmatter table, status bar), the open/close/
focus state machine (`useDocumentMode`), the Document Picker modal, the
split-pane integration over the FROZEN P4.6u scaffolding, divider
persistence, autosave with mtime-409 conflict reload, Librarian message
append, and the tool-result reload wiring — with unit specs transcribed from
v4's tests where they exist and fixture-guarded e2e beats activated at
unification.

The **standalone/workspace-tab surface is explicitly out of scope** (tier 3,
loud): v4 renders standalone documents and multi-document chats through its
workspace-tab system, which v5 does not have. This lane delivers the legacy
single-focused-document split-pane surface (v4's `SplitLayout` path); the
open-SET state model still tracks multiple docs (the server contract
supports it) but the UI shows the focused one.

### Quirks the port must not miss

1. **Divider persistence on drag end only**; defaults 45/50; double clamp
   (min-px then 20–80).
2. **The chat pane never unmounts** while Document Mode is open (composer
   state) — visibility/width toggling only.
3. **Markdown → rich editor, everything else → textarea** — byte fidelity
   for non-markdown is the invariant, not a styling choice.
4. **Editable except during LLM edits**; on turn end re-read all open docs
   but SKIP dirty panes.
5. **`documentMode` recompute is server-owned** — trust the responses; the
   client mirrors (normal only when the last doc closes; focus sticks).
6. **The recents list ordering/dedupe is server-owned** (current-chat rows
   win) — render, don't re-sort.
7. **409 handling**: write conflict → reload server content, do not retry
   the write; absorb-first-serialization so a fresh Lexical serialization
   pass doesn't count as dirty.
8. **Announcement asymmetry**: chat-scoped responses carry
   `librarianMessage`; append it via the existing message path (it will
   render as a collapsed Librarian chip — that is correct v5 behavior, the
   P4.6u lesson).

### Error envelope + serialization rules (both server lanes)

- v4's envelope semantics per `lib/api/responses.ts`. `ErrorKind` already
  covers `fileOpStatus`'s 404/409/400/500 after P4.6p — additions only if a
  survey turns up a status v5 lacks.
- File-op failures carry v4's `{ error, code }` body — `code` is the
  `FileOpError` ∪ `DatabaseStoreError` union (`SOURCE_NOT_FOUND | DEST_EXISTS
  | MOUNT_NOT_FOUND | INVALID_PATH | UNSUPPORTED | VERIFY_FAILED | CONFLICT |
  NOT_FOUND | NOT_EMPTY | INVALID`). The SPA error translation keys on `code`
  first, HTTP status second.
- Route reads omit null nullables but create/update echo them AS null (the
  P4.6p standing gotcha).
