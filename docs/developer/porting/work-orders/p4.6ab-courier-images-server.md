### Quirks the port must not miss

1. The courier resolve re-enters the orchestrator — errors after the
   settle must not roll back the settled message (read v4's ordering
   in the route handler, port it faithfully).
2. Upload conflict detection compares against existing chat files —
   the `{duplicate, conflictType, existingFile, newFile}` branch is a
   200, not an error; `resolution`/`conflictingFileId` on the retry
   drive overwrite/rename (pin the exact semantics from
   `useFileAttachments.ts` + the route).
3. `add-tool-result` mints a real transcript message — minted
   id/timestamp normalization via the established remap; the message's
   shape (role, toolName, content layout) is pinned by the oracle.
4. `imageProfileGenerate` expands `{{placeholders}}` server-side
   (`expandedPrompt` echoes the expansion) and persists generated
   images as files — the wire seam is recorder-backed (see
   differential).
5. `pendingExternalAttachments[].downloadUrl` is derived — confirm the
   v5 emission matches v4's URL shape byte-for-byte (it already ships;
   just don't move it).
