# Work order: W4.7b — the five stream decoders

**Size: one Opus session with internal parallelization** (five decoders on
disjoint files after a serial pre-stage of the shared types + the fixture
recorder; the d1 precedent). Independent of W4.7a and of every other open
batch. Decomposition context: [`../provider-manifest.md`](../provider-manifest.md).

## Shape (fixed)

Each decoder is a **sans-IO push state machine** in a new
`model::decoders::<name>` module:

```rust
pub trait StreamDecoder {
    /// Feed received bytes; emit zero or more chunks per push.
    fn push(&mut self, bytes: &[u8]) -> Result<Vec<StreamChunk>, DecodeError>;
    /// The stream ended (transport EOF). Emits any terminal chunk.
    fn finish(&mut self) -> Result<Vec<StreamChunk>, DecodeError>;
}
```

`StreamChunk` is the EXISTING `model::stream` vocabulary — extend it
additively only if a decoder provably needs a field v4's chunks carry that
it lacks (check v4's normalized chunk shape first; the ported
`CannedStreamingProvider` and every loop consumer are downstream — any
extension regenerates their differentials). Byte boundaries are arbitrary:
a decoder must be correct when fed one byte at a time (SSE frames, JSON
objects, and UTF-8 sequences all split mid-token across pushes).

## The five decoders (from the design-doc table — read each v4 plugin for
the full truth)

1. `chat_completions_sse` (openai-compatible, deepseek, z-ai, openrouter):
   `choices[0].delta.content`; the **tool-call accumulator** keyed by
   `tool_calls[].index` concatenating fragmented argument strings; usage in
   the trailing chunk; `[DONE]` terminal; deepseek's `reasoning_content`
   delta routing.
2. `responses_api_sse` (openai, grok): the Responses-API event taxonomy —
   `response.output_text.delta`, `response.reasoning_summary_text.delta`
   (CUMULATIVE — v4 handles the re-send semantics; match it), the terminal
   `response.completed` carrying the full response + usage,
   function-call events.
3. `anthropic_sse`: the `content_block_start/delta/stop` state machine;
   `input_json_delta` partial-JSON buffering per block index;
   `thinking`/`signature` block accumulation; usage split across
   `message_start` + `message_delta`; `error` events mid-stream.
4. `google_parts` (genai `generateContentStream`): `candidates[].content
   .parts` iteration; `thought === true` parts → reasoning vs text;
   `thoughtSignature` capture from the final chunk; functionCall parts.
5. `ollama_ndjson`: newline-delimited JSON (not SSE); `message.content`
   deltas; tool_calls arrive as whole objects normalized to the OpenAI
   shape; the `done: true` terminal with timing/usage fields.

Each decoder also produces the **raw-response value** v4 accumulates for
`detectToolCallsInResponse` (the `rawResponse` the ported loops thread) —
whatever v4's plugin hands back on `done`; reproduce that shape exactly,
it is what W4.7c's `parseToolCalls` reads.

## Fixtures + differential (`stream_decoders_equivalence`)

- **A checked-in fixture recorder** (`harness/oracle/providers/
  record-stream-fixtures.mjs`): given a provider + a raw wire transcript,
  drives v4's REAL plugin stream parser (mock `fetch`/the SDK's transport to
  replay the transcript bytes) and emits the normalized chunk sequence as
  NDJSON. Fixtures are committed **wire transcripts** (`fixtures/streams/
  <provider>/<case>.wire`) + the recorded chunk NDJSON. Author transcripts
  from the providers' documented wire formats + v4's own test fixtures if
  any exist (search the plugin packages); a later live-capture refresh is
  the design doc's open item, not this order's.
- Per-decoder tier-1: replay each transcript through the Rust decoder at
  THREE chunkings (whole-buffer, per-SSE-frame, byte-at-a-time) and diff the
  chunk sequence + the final raw-response value against the recording.
  Byte-at-a-time equivalence is asserted Rust-side (v4 sees one chunking).
- Adversarial cases per decoder: split-mid-UTF-8, split-mid-escape inside
  JSON strings, keep-alive comments/blank frames, fragmented tool-call
  arguments across many deltas, an error event mid-stream, empty stream,
  usage-absent stream, and (anthropic) interleaved thinking/text blocks;
  (responses-api) cumulative-reasoning re-sends; (ollama) a split JSON line.

## Watch-outs

- v4 normalizes usage field names per provider — the recorder output is the
  truth; don't re-map from vendor docs.
- The SSE layer itself (frame splitting, `data:` prefix, multi-line data,
  comment lines) should be ONE shared submodule under `model::decoders`,
  spec-faithful, since three decoders sit on it.
- `google_parts` is not SSE at the same layer — check how v4's SDK delivers
  chunks (JSON array streaming vs newline) and mirror the actual transport
  framing the plugin sees.
- No `tokio`/network in any decoder; `finish()` must be idempotent.
