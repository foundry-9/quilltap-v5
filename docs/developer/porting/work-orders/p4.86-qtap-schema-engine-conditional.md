## Survey-verified starting points (2026-09-07 @ v4 `2f4254b42` — do not re-derive)

### The validator (`lib/validation/qtap-schema-validator.ts`, 120 lines)

- Schema: `public/schemas/qtap-export.schema.json` (89,769 bytes;
  `"$schema": "https://json-schema.org/draft/2020-12/schema"`, `"$id":
  "https://quilltap.app/schemas/qtap-export.schema.json"`), read once from
  `process.cwd()`, cached; a load failure THROWS `Failed to load
  qtap-export schema: …` (caught by `validateQtapExport` → `{valid: false,
  errors: ['Schema validation error: …']}`).
- Engine: `new Ajv2020({ allErrors: true, strict: false, validateFormats:
  true })` + `addFormats(ajv)` (the `ajv-formats` set: `date-time`,
  `uuid`, `uri`, `email`, …); compiled once.
- `validateQtapExport(data)` → `{valid: true, errors: []}` or `{valid:
  false, errors: (validate.errors || []).map(err => \`${err.instancePath
  || '/'}: ${err.message || 'unknown error'}\`)}` — ajv's `instancePath` is
  a JSON Pointer (`/data/memories/0/chatId`), the MESSAGE is ajv's wording
  (`must be string`, `must have required property 'x'`, …). Any throw →
  `{valid: false, errors: [\`Schema validation error: ${msg}\`]}` + an
  `error` log `[QtapSchemaValidator] Validation error`.
- **Engine-parity facts (the comparands):** `valid` MUST agree; the SET of
  `errorSections` derived by `/^\/data\/(\w+)\//` over the error strings
  (v4 `ai-import.service.ts:1147-1152`) MUST agree; the error COUNT and
  the message TEXT may differ between ajv and a Rust engine (per-branch
  reporting under `anyOf`/`oneOf`, message wording) — record as a
  measured divergence per corpus row, and let the count feed the two
  frames v4 renders it into (`step_error` `error: \`${n} validation
  error(s)\``, `errors.validation = \`Validation has ${n} error(s) that
  could not be auto-repaired\``) as a RECORDED divergence where the counts
  differ, a plain equality where they agree. Measure first over the
  corpus; the ruling on the shape goes in the lane record.

### The service's steps 9–10 (`lib/services/ai-import.service.ts:1129-1225`)

- `onProgress({type:'step_start', step:'validation'})`; `validationResult =
  validateQtapExport(exportData)`; valid → `step_complete validation`
  `snippet: 'Validation passed'`; else `warn` `[AIImport] Validation failed,
  attempting repair` `{errorCount, errors: slice(0,5)}` +
  `step_error validation` `error: \`${n} validation error(s)\``.
- Repair (`:1146-1214`): `errorSections` from the paths; `for attempt in
  0..MAX_REPAIR_ATTEMPTS while !repaired`: `step_start repair`; `sectionsTo
  Repair = {section: dataObj[section]}` for sections with a truthy value;
  none → `warn` `[AIImport] No repairable sections identified from error
  paths` `{errors: slice(0,5)}` + `break`; the repair prompt (`:1172-1181`
  — byte-exact template: the errors joined by `\n`, `JSON.stringify(
  sectionsToRepair, null, 2)`, the section-key list joined by `, `);
  `callLLM(provider, apiKey, profile.modelName, '', repairPrompt,
  {temperature: 0.5, maxTokens: 2000, ...llmOpts})`; `parseLLMJson`; only
  the sections present in the reply are replaced (`if (repairedSections[
  section])`); revalidate → `step_complete repair` `snippet: 'Repair
  successful'` + `info` `[AIImport] Repair successful on attempt`
  `{attempt: attempt+1}`, else `step_error repair` `error: \`Repair attempt
  ${attempt+1} still has errors\`` + `warn` `[AIImport] Repair attempt
  failed` `{attempt, remainingErrors}`; a throw → `step_error repair`
  `error: msg || 'Repair failed'` + `warn` `[AIImport] Repair attempt
  error` `{attempt, error}`. `!repaired` → `errors.validation = \`Validation
  has ${n} error(s) that could not be auto-repaired\`` + `warn` `[AIImport]
  Could not fully repair validation errors` `{errorCount}`. Then the
  structural restamp (v5 already has `restamp_structural_fields`).
- Measure `MAX_REPAIR_ATTEMPTS` and `llmOpts` at the pin.
- **The repair prompt embeds the engine's error strings** — where the
