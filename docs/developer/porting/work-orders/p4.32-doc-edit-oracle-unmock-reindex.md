## The defect, restated (from P4.D41 unit 8, verified at planning)

Six oracle cases carry the same mock —
`harness/oracle/cases/doc-{text,fm,ui,enum,blob,fs}.test.ts` (:150, :144,
:140, :115, :160, :226 respectively):

```ts
jest.doMock('@/lib/doc-edit/reindex-file', () => ({
  __esModule: true,
  reindexSingleFile: async () => undefined,
}));
```

`reindexSingleFile` is that module's ONLY export, and it is the
database-store chunk pass itself: for a database-backed store it reads
the bytes back from `doc_mount_documents`, chunks via
`@/lib/mount-index/chunker`, and updates the file record + chunk rows in
the mount index (module doc: "Embedding jobs are NOT enqueued here").
Both v4 consumers AWAIT it: `triggerReindexIfNeeded`
(`lib/tools/handlers/doc-edit/shared.ts:468`, awaited at every
text/markdown/file-management handler site) and `writeDatabaseDocument`
(`lib/mount-index/database-store.ts:148-149`, `:635` — the P4.6BK
chunk-on-write). The mock therefore silences v4's chunk pass wholesale;
v5 chunks (deliberately, P4.6BK/P4.D41), and `doc_text`
(`QT_ORACLE_DT`) + `doc_fm` (`QT_ORACLE_DFM`) diverge on `chunkCount`.
Proven pre-existing at D41: divergence unchanged with the hard-link
group pass probe-disabled, and `reindex_after_database_write` already
present at `ceeec560`.

**What un-mocking does NOT unleash (verified at planning):** embedding
jobs — `reindexSingleFile` never enqueues them, and the separate
`@/lib/mount-index/embedding-scheduler` mock
(`enqueueEmbeddingJobsForMountPoint: () => undefined`) stays in place.
The librarian-writer mocks likewise stay. The ruling's scope is the
reindex module only.
