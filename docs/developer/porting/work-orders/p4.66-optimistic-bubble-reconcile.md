1. **The v5 state flow.**
   `apps/web/src/app/screens/salon/salon-conversation.ts`:
   `optimisticUser` signal at `:1291`; `displayMessages` computed at
   `:1738-1760` appends it unconditionally
   (`return temp ? [...msgs, temp] : msgs` at `:1758-1759`) over
   `this.split()` = the canonical server list off the TanStack query;
   writes: set in `send()` at `:2739`, cleared only at the end-of-turn
   reconcile `:2818` and in `stop()` `:3053`. The mid-turn refetch
   arrives via `realtime/job_topics.rs:81-88` (TITLE_UPDATE /
   CONTEXT_SUMMARY / CHAT_DANGER_CLASSIFICATION / SCENE_STATE_TRACKING /
   WARDROBE_OUTFIT_ANNOUNCEMENT → a `Chats`-scoped hint) →
   `core/realtime-topic-map.ts:76-82` → `chatKeys.detail(id)` — exactly
   the `chatQuery` key (`:993`); ~15 other in-file
   `invalidateQueries(chatKeys.detail(…))` calls reproduce the same
   duplicate if they fire mid-turn.
2. **v4's mechanism (the fidelity reference).** ONE `useState` array:
   `useChatData.ts:14` owns `messages`; `fetchChat()` at `:83` calls
   `setMessages(displayMessages)` — a wholesale replace that overwrites
   the temp bubble out of existence. The push is
   `useSSEStreaming.ts:728-751` (`temp-user-${Date.now()}` id; the
   optimistic author resolved via `findActiveUserParticipant` — the
   bug-45 comment); v4's OTHER optimistic pushes use an id-dedupe
   (`prev.some(m => m.id === msg.id) ? prev : [...prev, msg]` at
   `:797` etc.), and the Courier path skips its push outright
   (`:832-843`, "another optimistic copy here would create a duplicate
   React key").
3. **The fix — two shapes; pick ONE explicitly and record the mechanism
   divergence** (the turnOverride precedent for documented client
   mechanism divergences):
   (a) `displayMessages` drops `temp` when `msgs` already contains a
   server row matching it (v4's id-dedupe idiom — but the temp id never
   matches a server id, so the predicate must match on content: a USER
   row authored by the same seat with the same content arriving after
   the send began); or
   (b) clear `optimisticUser` in an effect when the `chatQuery` data
   changes to contain the persisted row (nearer v4's wholesale-replace;
   needs the same matching predicate).
   (a) is cheaper and timing-independent; either way the predicate is
   the deliverable — write it once, spec it hard (multi-user seats,
   impersonation, attachments-only sends, two identical consecutive
   user messages — the predicate must not eat the SECOND optimistic
   bubble when the user repeats themselves; scope the match to rows
   newer than the send).
4. **Cautions.** The `[messageCount]` binding deliberately reads
   `chat()!.messages.length`, NOT `displayMessages()` — the comment at
   `:355-359` explains the cost-query re-key; do not disturb it. The
   optimistic bubble must still render whisper-filter-proof ("always the
   human's own, so it never filters out" — the computed's doc). `stop()`
   still clears. A turn with NO mid-turn invalidation must render
   exactly as today (the append arm still fires until the server row
   lands).
5. **The beat.** Template:
   `apps/web/e2e/salon-thinking-indicator.spec.ts` — the suite's only
   mid-stream beat; copy its slow-mock idiom
   (`startMockLlm(REPLY, PORT, 350)` — the delayMs rationale at
   `:14-18`: spacing the deltas widens the observation window without a
   sleep), its send gesture (`:62-66`), and its fixture-choice
   constraint (`:19-23` — send on "Group Expedition", never "Solo
   Voyage", whose 15.4K-token baseline `salon-token-cost-flow.spec.ts`
   pins; a message-count-asserting beat must also avoid perturbing
   counts other specs read). The beat must FORCE the mid-turn
   invalidation deterministically — a fresh untitled chat makes
   TITLE_UPDATE fire naturally mid-turn, or drive one of the in-file
   invalidation paths during the stream; while the reply is streaming,
   count the rendered user bubbles for the sent content and assert
   exactly one, then assert the post-turn transcript is intact.
   **Red-first: run the beat against the pre-fix build and record the

   every fallback poll (the standing e2e note) — if the beat watches
