## The drift, classified (surveyed 2026-08-22, fresh at `a6870c5a`)

All three commits are behavior changes on ported surfaces. No DB schema
change anywhere (no `generateDDL`/migration movement — no D23 re-dump);
the `compiledIdentityStacks` envelope is a JSON *content* shape change
inside an existing TEXT column, which v5 follows per D23's spirit (v4
moved it; v5 never moves it unilaterally).

1. **Standing instructions** (`8f868109`): a new pure module
   `lib/chat/context/standing-instructions.ts` resolves project
   instructions via `chat.projectId` and group instructions per the
   RESPONDING character's memberships (never the chat), renders a
   `[STANDING INSTRUCTIONS]` section, and `buildSystemPrompt` injects it
   **between the Taboo section and the tool instructions**,
   template-processed (unlike Taboo). Carina one-off queries mirror the
   insertion; `self_inventory` includes it; help and Brahma chats are
   structurally excluded; the Prospero project-context whisper DROPS its
   `**Project instructions:**` section to avoid duplication. Groups gain
   the missing API acceptance (create/update validators, `max(10000)`).
   `PROMPT_CACHE_STRUCTURE_VERSION` 3 → 4.
2. **Bug 88** (`346e855f`): the tool-reinforcement block (the LAST block
   of the assembled prompt) moves from third person with a pronoun lookup
   (`they CALLS them` for pronoun-less characters) to a fixed
   second-person string with NO pronoun lookup. v5 measurably HAS the bug:
   `system_prompt.rs:546-557` reproduces the `subject` lookup, and
   `system_prompt.rs:774` pins the old string.
3. **Grammatical-person consistency** (`a6870c5a`), server half: the
   identity stack's aliases/pronouns/appearance blocks move to second
   person, manifesto/personality/example-dialogues gain referent-fixing
   wrapper lines, the appearance block loses its markdown bullet;
   `compiledIdentityStacks` becomes a version-stamped envelope
   `{version, stacks}` keyed to `IDENTITY_STACK_BUILDER_VERSION = 2`
   (stale/legacy maps read as absent → lazy read-through rebuild; stale
   maps DISCARDED on merge, CLEARED on the drop path; empty map still
   writes `null`); a CI golden table enforces bump-and-register in both
   directions. **No** `PROMPT_CACHE_STRUCTURE_VERSION` bump for this
   commit (wording inside existing blocks, per the file's own policy).
   The generator person clauses (wizard/optimizer/ai-import/
   field-semantics) land on surfaces v5 does not have — see Tier 3.

## Shared contract (BINDING — identical in P4.D103 and P4.D104)

1. The `groupCreate` dispatch verb's request gains one optional field:
   wire key **`instructions`**, type `string | null`, absent allowed.
   Server validation mirrors v4 `createGroupSchema`:
   `z.string().max(10000).nullable().optional()`; create persists
   `instructions || null` (empty string normalizes to `null`).
2. The `groupUpdate` patch accepts wire key **`instructions`**, validated
   `string ≤ 10000 | null` (v4 `updateGroupSchema`); the update path is a
   validated passthrough — a PUT with `instructions: ""` stores `""`
   (v4's quirk, carried). The CLIENT compensates by sending
   `instructions || null` (v4 GroupDetailView behavior).
3. The `groupGet` response's group object carries
   **`instructions: string | null`** (hydrated by the overlay; the SPA
   mirrors the field onto its group detail type in
   `apps/web/src/app/core/core-contract.ts`).
4. Invalid `instructions` (non-string, or > 10,000 chars) answers v4's
   validation shape: 400 `{"error":"Validation error","details":[…]}` on
   both create and update.
5. e2e activation: P4.D104 authors the group-instructions round-trip beat
   gated on the named constant **`P4D103_SERVER_LANDED = false`** in the
   beat file; the unifier flips it to `true` at unification.
