**C2 — the compact-backup wire.** `CoreRequest::SystemBackupCreate`
gains exactly one field, wire key **`compact`**, boolean, default
false. Edge semantics (v4 `backup/route.ts:23-28`): request body
optional; a malformed body is treated as ABSENT, not rejected; only
JSON literal `true` engages compact. The SPA sends `{ compact }` on
the existing backup-create call. The manifest key `compact: true` is
omitted when false.

**C3 — the import preview additions.** `entities` gains six OPTIONAL
arrays, serialized in v4's order (listed before characters/chats/
tags): `documentStores, files, promptTemplates, providerModels,
pluginConfigs, instanceSettings`. Every entity item may carry
`detail?: string`; the three detail strings, verbatim:
`contents missing — will be skipped` ·
`all settings withheld — re-enter them here` ·
`secrets withheld: <k1, k2>` (comma-space joined). `promptTemplates`
items may carry `matchedExistingId`; `providerModels` and
`instanceSettings` items always have `exists: false`.

**C4 — the entity-listing name shapes** (server produces, SPA
renders as-is): files → `originalFilename` (BACKUP-category and
`/backups` rows excluded); prompt-templates → `name` (built-ins and
foreign-owner rows excluded); provider-models →
`` `${provider} / ${modelId}` ``; plugin-configs → `pluginName`;
instance-settings → `{ id: key, name: key }`.

**C5 — the backup-dialog copy** (SPA renders; server has no part):
checkbox label `Compact backup`, default OFF; sub-label: "A
considerably slimmer archive — the search indexes are left behind and
rebuilt after restoring. Everything you have written travels either
way."

**Change rule:** if either lane must deviate from C1–C5, it updates
BOTH order files in the same commit and says so in its lane record —
