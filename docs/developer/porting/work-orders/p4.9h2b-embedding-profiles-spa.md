## §1 Shared wire contract (BINDING — identical in P4.9H2A and P4.9H2B)

Request variants (`api/types.rs` name — wire `type` tag — fields,
camelCase on the wire):

| Variant | tag | fields |
| --- | --- | --- |
| `EmbeddingProfileList` | `embeddingProfileList` | — |
| `EmbeddingProfileGet` | `embeddingProfileGet` | `profileId` |
| `EmbeddingProfileCreate` | `embeddingProfileCreate` | `name`, `provider`, `apiKeyId?`, `baseUrl?`, `modelName`, `dimensions?`, `isDefault?` |
| `EmbeddingProfileUpdate` | `embeddingProfileUpdate` | `profileId`, then all optional: `name?`, `provider?`, `apiKeyId??`, `baseUrl??`, `modelName?`, `dimensions??`, `truncateToDimensions??`, `normalizeL2?`, `isDefault?` — `??` = tri-state (absent / explicit null / value) riding `double_option`, per the P4.D50 lesson |
| `EmbeddingProfileDelete` | `embeddingProfileDelete` | `profileId` |
| `EmbeddingProfileRefit` | `embeddingProfileRefit` | `profileId` |
| `EmbeddingProfileReindex` | `embeddingProfileReindex` | `profileId`, `scope?` (`'all'` \| `'mismatched-dim'`; absent = v4's legacy no-body call = `'all'`) |
| `EmbeddingProfileReapply` | `embeddingProfileReapply` | `profileId` |
| `EmbeddingProfileListProviders` | `embeddingProfileListProviders` | — |
| `EmbeddingProfileListModels` | `embeddingProfileListModels` | `provider?` |
| `EmbeddingProfileFetchModels` | `embeddingProfileFetchModels` | `provider`, `baseUrl?` — **REFUSAL-ARMED** (tier 3) |
| `MemoryDedupPreview` | `memoryDedupPreview` | `threshold?` (default 0.80) |
| `MemoryDedupRun` | `memoryDedupRun` | `threshold?` |
| `ConversationSummariesRegenerateStatus` | `conversationSummariesRegenerateStatus` | — |
| `ConversationSummariesRegenerate` | `conversationSummariesRegenerate` | — |

Response arms: `Response::EmbeddingProfile(serde_json::Value)` for the
eleven profile verbs; `Response::MemoryMaintenance(serde_json::Value)`
for the four dedup/summaries verbs. Bodies mirror v4's route JSON
name-for-name: list `{profiles, count}`; get = enriched profile
spread; create = created profile spread + `apiKey` (v4 201); update =
updated profile spread + `reembeddingTriggered`; delete `{message}`;
refit/reindex/reapply `{message, jobId, …}` with v4's exact message
strings (reindex adds `scope` + `invalidatedCount`; reapply adds
`targetDimensions`); dedup `{success, result}`; summaries POST
`{success, jobId, message}` / status `{success, inFlight}`.

Error semantics: v4's 400/404/409 sentences byte-for-byte — including
the two INCONSISTENT 409 shapes (hand-rolled
`{error: 'An embedding profile with this name already exists'}` on
create vs the `conflict()` helper on update); carry both faithfully.
The refusal arm answers the family `not_available` shape naming
`embeddingProfileFetchModels`.
