# Work order P4.1b — host drivers: files, images, fs

> P4.1 round, lane (b), per `phase-4.md` "Decomposition and ordering".
> Drift check at round start (2026-07-08): v4 HEAD is still `2494a84b` — the
> oracle baseline; no ported unit stale. Survey facts below are from a fresh
> v4 sweep at that commit (file:line references are v4).

## Mandate

Make the file/image byte layer real: the two `FileBytesStore` seams, the two
`ImageTranscoder` seams, `ProjectImageUpload`, the `deleteFileCompletely`
storage-bytes half, the help-docs disk sync, and a production `ApplyHost` fs
impl. The key survey discovery that shapes this lane: **most of v4's byte
layer is mount-blob-backed** — the bridges return `mount-blob:{mountPointId}:
{blobId}` storage keys whose bytes live in the already-ported
`doc_mount_blobs` table, so large parts of the "byte layer" are DB reads
through ported repos; only the legacy `<base>/files/**` disk layout is real
fs.

## Survey facts (v4 at `2494a84b`)

### The file storage manager (`lib/file-storage/manager.ts`)

- Base path: `getFilesDir()` = `<base>/files` (`lib/paths.ts:310`).
- Storage keys (`buildStorageKey`, `manager.ts:736`): project files
  `{projectId}/{folderPath}/{safeFilename}`; general
  `_general/{folderPath}/{safeFilename}`; thumbnails
  `_thumbnails/{fileId}_{size}.webp`. `safeFilename()` (`:73`): strip
  `/[\/\\:*?"<>|\x00-\x1f\x7f]/g`, collapse `__`, trim leading/trailing
  `_`/`.`, fallback `'unnamed'`. A legacy key form exists
  (`buildLegacyStorageKey :801`) — migration-only, do not port.
- `downloadFile(file)` (`:378`): `mount-blob:` keys → `readMountBlob` (the
  ported `doc_mount_blobs` read); else the local backend `download`
  (= `readFile` under `<base>/files/{key}`).
- `deleteFile(file)` (`:418`): `mount-blob:` → `deleteMountBlob` (GC-aware —
  the ported `delete_with_gc` family); else backend `delete` (idempotent,
  ENOENT-tolerant, also unlinks a legacy `.meta.json` sidecar).
- `uploadRaw`/`deleteRaw`/`fileExists`/`storageKeyExists`/folder ops
  (`:467`/`:492`/`:554`/`:590`/`:618+`). `getFileUrl` (`:517`) →
  `/api/v1/files/proxy/{encodeURIComponent(key)}` (P4.2's route).
- Local backend (`lib/file-storage/backends/local/index.ts`): tilde
  expansion + normalize on basePath; `buildSafePath` (`:121`) strips `..`
  and verifies the resolved path is under basePath (traversal guard);
  `upload` = mkdir-recursive + writeFile; ops wrapped in `withFsRetry`.
- `uploadFile(params)` (`:296`) **requires `projectId`** (throws without —
  `:323`) and routes to `writeProjectFileToMountStore` (the project-store
  bridge → the ported mount-store write path). Returns
  `{storageKey, storedMimeType, sizeBytes, sha256}` — mime/size are
  **post-transcode**.

### The image store + bridges

- `lib/images-v2.ts`: `readImageBuffer(fileId)` (`:362`) → `readFile` →
  `fileStorageManager.downloadFile(entry)`. `ingestImageBuffer` (`:329`) →
  `createFile` (`:87`): auto-`convertToWebP` (skips SVG/webp), sha256,
  hash-dedup **with a storage existence recheck** (`fileExists`; deletes the
  orphaned metadata row if the bytes are gone, `:140`), then
  `writeUserUploadToMountStore({subfolder:'images'})` — always project-less.
  `validateImageFile` (`:218`): `ALLOWED_IMAGE_TYPES` (incl. svg/avif),
  10 MB cap. `getImageDimensions` (`:50`) = a sharp metadata probe.
- Bridges (all return `mount-blob:{mountPointId}:{blobId}`, all transcode
  images to WebP via `storeMountFile({transcodeImages:true})` — the ported
  `link_blob_content` + `transcodeToWebP` path): `user-uploads-bridge.ts`
  (`writeUserUploadToMountStore :94`, subfolders
  `chat|images|diagnostics|restored|uploads|photos`, mount id from
  `instance_settings.userUploadsMountPointId`); `lantern-store-bridge.ts`
  (already ported as `image_job_storage`); `character-vault-bridge.ts`
  (already ported).

### The complete sharp operation inventory (D19: port operations, not bytes)

1. `images-v2.ts:50` — `sharp(buffer).metadata()` → width/height probe.
2. `lib/files/thumbnail-utils.ts:110` — `sharp(buf).resize(size, size,
   {fit:'cover', position:'center'}).webp({quality: 80}).toBuffer()`;
   `DEFAULT_THUMBNAIL_SIZE=150`, `MAX_THUMBNAIL_SIZE=300` (size clamped),
   `COMMON_THUMBNAIL_SIZES=[120,150,300]`; cache key
   `_thumbnails/{fileId}_{size}.webp`, cache write via `uploadRaw`
   fire-and-forget.
3. `lib/files/webp-conversion.ts:108` — `convertToWebP`:
   `sharp(buffer).webp({quality: 90}).toBuffer()` + a metadata probe of the
   OUTPUT bytes; `CONVERTIBLE_MIME_TYPES = jpeg,jpg,png,gif,avif`;
   passthrough svg+xml/webp.
4. `lib/files/image-processing.ts` — the resize-for-provider loop (the
   DECISION half is already ported in `files::image_processing`; the seam
   receives `resize_step(buffer, target_width, format, quality)`):
   `.resize({width, fit:'inside', withoutEnlargement:true})` then
   `.jpeg({quality, mozjpeg:true})` / `.webp({quality})` /
   `.png({compressionLevel:9})` / `.gif()`.
5. `lib/mount-index/blob-transcode.ts:44` — `transcodeToWebP`:
   `sharp(input, {animated:true}).webp({quality: 85, effort:4})`;
   `TRANSCODABLE_MIME_TYPES = png,jpeg,jpg,gif,heic,heif,tiff,avif` (webp
   deliberately stored as-is); extension rewritten to `.webp`.

### deleteFileCompletely + help sync

- `lib/cascade-delete.ts:26`: if `storageKey` present →
  `fileStorageManager.deleteFile(entry)` (mount-blob → GC-aware delete,
  disk → backend delete), then `repos.files.delete(fileId)` (the DB half is
  ported in the W4.8 maintenance sweep, seamed as `FsSeam`).
- `lib/help/help-doc-sync.ts`: `HELP_DIR = cwd/help`;
  `ensureHelpDocsSynced()` (`:220`) lazy — runs `syncHelpDocs()` only when
  `helpDocs.findAll()` is empty, guarded by a module promise.
  `syncHelpDocs()` (`:124`): recurse `*.md`; per file: `parseFrontmatter`
  (extract `url:`), `extractTitle` (first `# H1` else filename-titlecased),
  `generateDocumentId` (strip `help/`+`.md`, non-alnum → `-`, lowercase),
  `hashContent` sha256; skip when `findByPath(relPath).contentHash`
  unchanged; else `upsertByPath({title,path,url,content,contentHash})` (the
  ported upsert) + `clearAllEmbeddingsForDoc` on change. Returns
  `{totalOnDisk, created, updated, unchanged, failed, changedIds[]}`.

## Deliverables

1. **The image codec** (`quilltap-host/src/image_codec.rs`): one codec type
   implementing BOTH `ImageTranscoder` traits
   (`files::image_processing::ImageTranscoder` — metadata probe +
   resize_step; `model::image::ImageTranscoder` — the WebP transcode) plus
   the thumbnail op and `convertToWebP`/`transcodeToWebP` equivalents per
   the inventory above. **Pure-Rust first** (the `image` crate family);
   lossy WebP encoding has no mature pure-Rust encoder — the `webp` crate
   (libwebp bindings) is acceptable given the repo's existing C-compile
   precedent (the sqlite3mc amalgamation); document the choice. Byte parity
   is NOT required (D19) — dimension/format/policy behavior is (assert
   dimensions + format + alpha handling in tests). Animated-GIF→WebP
   (`animated:true`): if the pure stack can't, degrade to first-frame and
   document (a quality divergence, not a policy one).
2. **The storage backend + FSM port**: pure key/path logic in core
   (`services::file_storage` or similar — `build_storage_key`,
   `safe_filename`, key classification `mount-blob:` vs disk) over an
   injected `StorageBackend` trait (upload/download/delete/exists by key);
   the local backend (tilde expansion, `buildSafePath` traversal guard,
   mkdir+write, ENOENT-tolerant delete + legacy `.meta.json` unlink) in
   `quilltap-host/src/files_store.rs`. The `withFsRetry` wrapper: port the
   retry semantics if simple, else document.
3. **The two `FileBytesStore` production impls**: `download_file` /
   `read_image_buffer` dispatch on the key — `mount-blob:` → the ported
   `doc_mount_blobs` read (needs a `Db` handle), else the disk backend.
   `ingest_image_buffer` = the `createFile` flow (convertToWebP → sha →
   hash-dedup with the storage-existence recheck → the user-uploads bridge
   write → `files.create`). The user-uploads bridge needs
   `instance_settings.userUploadsMountPointId` — add the scoped read to
   `db/instance_settings.rs` **append-only at end of file** (lane d also
   appends there; unions resolve).
4. **`ProjectImageUpload`** production impl — v4 `uploadFile`'s project
   route = `writeProjectFileToMountStore` over the ported mount-store
   write path (post-transcode mime/size in the result).
5. **`deleteFileCompletely` bytes half**: implement the maintenance sweep's
   FsSeam (the storage delete before the ported `files.delete`).
6. **The help-docs disk sync** — engine behavior → **differential
   required** (D10): a tsx or jest real-DB oracle driving v4's REAL
   `syncHelpDocs()` over a committed fixture help tree (a few `*.md` with
   frontmatter/H1/edge names), diffing the `help_docs` dump + the returned
   summary; embeddings stay untouched (the sync only clears them — bank
   that). Rust side: a core `services::help_doc_sync` over an injected
   dir-walk or a host fs read (your call; keep the decision documented).
7. **The production `ApplyHost` fs impl** (`quilltap-host`): the four fs
   methods (`finalize_file` = ensure-dir + rename; `undo_finalize`;
   `cleanup_staging_dir` = rm -rf best-effort; `dispatch_invalidations` —
   no-op with a doc comment: v5 has no process-global mount cache and the
   vector store loads per-use). Note: no production consumer yet (U4.4
   moved the enclave to direct writes) — this is inventory completion,
   unit-tested only.

## The ingest differential

`ingest_image_buffer`/`createFile` is engine behavior (DB-visible: `files`
rows + the mount-blob store tables) → differential required: a jest real-DB
oracle driving v4's REAL `ingestImageBuffer` (sharp mocked to a

the W4.9a precedent) over a two-DB fixture with a provisioned user-uploads
mount, banking: fresh ingest (six-table dump per the photo-tools recipe),
hash-dedup hit, the orphaned-metadata recheck path (bytes deleted → row
deleted → re-ingest), and a webp/svg passthrough. Minted ids/timestamps in
the shared-cross-db remap form; `chunkCount` pinned per the standing rule.
