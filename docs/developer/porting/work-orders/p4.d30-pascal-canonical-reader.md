## The drift, classified (surveyed 2026-07-30)

**`83118077 refactor(pascal): custom-tool definitions load through the
canonical mount reader`** — the one commit CLAUDE.md already flagged as owed.
v4's `readToolFile` in `lib/pascal/custom-tools.ts` hand-rolled its own
storage dispatch (`readDatabaseDocument` for database stores, a bare
`fs.readFile(path.join(mount.basePath, relativePath))` for everything else).
It now calls `readMountFileBytes` from `lib/mount-index/read-file.ts`, which
handles every storage shape (filesystem, Obsidian, database documents,
database blobs). **Three effects beyond deduplication:**

1. **Boundary enforcement** — definition reads pass through
   `resolveFsAbsolute`, so a `.tool.json` path can no longer resolve outside
   its own store.
2. **Blob-stored definitions become readable** — on database mounts, a
   definition stored as a BLOB (not a document row) was missed by the old
   direct `readDatabaseDocument` call; the canonical reader finds it.
3. **The race skip widens** — the load loop's "deleted between list and
   read" skip now also recognises `FileOpError` with code `SOURCE_NOT_FOUND`
   (the reader's ENOENT equivalent), alongside the existing
   `DatabaseStoreError NOT_FOUND` and raw `ENOENT` arms.

**The listing side is unchanged on purpose** — `Tools/` is still enumerated
live off disk, because edits inside a mount don't reliably touch the mount
index. Do not "improve" the listing path.

**`0246c6c8` (pascal slice only):** `lib/pascal/llm-consult.ts` had its
private `withTimeout` extracted to the new shared `lib/promise-timeout.ts`
(claimed-neutral), and `app/api/v1/custom-tools/route.ts` had its two bench
handlers' shared opening steps extracted into `parseBenchRequest` +
`benchRefusal` (claimed-neutral; the 422 semantics and response bytes are
unchanged — verified at planning by reading the diff). Your job on these is
neutrality proof + optional structural mirror, not behavior change.

NOT yours: `71dcc7e8`/`80cafed5` (v4-side test coverage, NO-PORT — the three
pascal jest suites' stub move from `readDatabaseDocument` to
`readMountFileBytes` is oracle-side only and comes free with the pinned
worktree).
