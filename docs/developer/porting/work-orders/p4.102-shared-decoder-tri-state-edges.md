## Survey-verified starting points (fresh survey 2026-09-18 on `main` `639de1a1` — do not re-derive)

- **The helper's contract (from `images_generate_request`):** given
  `kind: &str`, `parsed: &Value`, `body_keys: &[&str]` and `path_fields:
  &[(&str, Value)]` (the URL-sourced ids — `characterId`, `id`) → build
  `{"type": kind, <path fields>, <each present body key, null included>}`
  and `serde_json::from_value::<CoreRequest>(...)`. A non-object body folds
  to all-absent (v4's Zod refuses it inside the HANDLER, not the edge).
  Unknown keys dropped (v4's `z.object` strips). The result is `Option<
  CoreRequest>`; `None` is unreachable while every lifted field is a raw
  `Option<Option<Value>>` — and if a variant's field is re-typed later,
  `None` is the refusal answering serde's sentence where v4 answers Zod's:
  the census guard is what keeps that from happening silently.
- **The two `tri` helpers** are hand-mirrors of `double_option`
  (`Some(None)` for `null`, `None` for absent, `Some(Some(v))` for a value)
  — measured equivalent to the decode for JSON inputs; so the retirement
  is behaviour-NEUTRAL and the null arms are pins, not red-first fixes
  (§R.5). If a measurement finds a `tri` that does NOT mirror (e.g. a key
  read with `.cloned()` that collapses `null`), that arm is red-first and a
  FINDING to record.
- **The variants with tri-state fields that have a REST edge and are
  hand-built:** `CharacterSubpromptCreate` (`title`, `content` tri;
  `character_id` from the path), `CharacterSubpromptUpdate` (+ `subprompt_
  id`), `PromptTemplateCreate` (`name`, `content`, `description`,
  `category`, `model_hint`), `PromptTemplateUpdate` (+ `id`). `Prompt
  TemplateGet` — measure (its body is empty; if it carries a tri-state it
  is a query-string one and out of scope).
- **The web-test venue** (`crates/quilltap-web/tests/common`) boots a
  real server over a fixture; `subprompts_web_routes.rs` and `prompt_
  templates_web_routes.rs` already post JSON bodies — the null arms are
  additions there.
