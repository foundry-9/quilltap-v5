## Survey facts (v4 at `2494a84b`)

### The session manager (`lib/terminal/pty-manager.ts`)

- Singleton, `sessions: Map<id, PtySession>`. `spawn(opts)` (`:124`):
  `id = randomUUID()`; shell = `opts.shell || (win32 ? COMSPEC ??
  'powershell.exe' : SHELL ?? '/bin/bash')`; `cwd = opts.cwd ||
  getFilesDir()`; `cols = opts.cols ?? 80`, `rows = opts.rows ?? 24`;
  env = `{...process.env, ...opts.env, QUILLTAP_DATA_DIR: baseDataDir}`
  (the data-dir var set authoritatively LAST), then shell-init overrides
  (`shell-init.ts` — per-session `quilltap` alias/completions/prompt; port
  the mechanism only if cheap, else document as a deferral: the alias
  targets the Node launcher). Terminal name `xterm-256color`.
- **Transcript**: `${logsDir}/terminals/${id}.log`, append stream, raw
  bytes. Deliberately under `logs/` (the v4 file watcher ignores it). The
  DB row stores only `transcriptPath` — transcript text never enters the DB.
- **Ring buffer**: in-memory string, cap `MAX_RING_BUFFER_SIZE = 256*1024`
  (256 KB — keep the LAST 256 KB). `onData`: append+cap, append to the
  Ariel flush buffer, write raw to the transcript, broadcast
  `{type:'output', data}` to subscribers.
- **DB row**: `terminal_sessions.create({...}, {id})` at spawn; on exit
  update `{exitedAt, exitCode}`. (The repo is ported — tier-2.)
- **Lifecycle**: `get`/`list`/`kill(id, 'SIGTERM')`/`write`/`resize`/
  `getRingBuffer`/`kickAllForChat(chatId)`. `subscribe(id, ws)` refuses if
  exited; on attach sends the ring buffer as one `output` message then a
  `meta` message. `unsubscribe` deletes the session from the map once
  exited AND zero subscribers remain. **onExit** (`:292`): stamp
  `exitedAt`/`exitCode`, final Ariel flush (`'session-closed'`), broadcast
  `{type:'exit', code, signal}` + close(1000), end the transcript stream,
  update the DB row, post the close announcement. No idle-timeout
  auto-kill — sessions live until exit/kill/kick.
- **Ariel flush**: buffer raw output; flush on idle
  `ARIEL_FLUSH_IDLE_MS = 30_000` or age `ARIEL_FLUSH_MAX_AGE_MS = 120_000`;
  flush = `cleanTerminalOutput(raw)` (the ALREADY-PORTED
  `crate::terminal_clean::clean_terminal_output`) →
  `postArielTerminalOutputAnnouncement` + broadcast a `chat-update` WS
  message (`reason: 'ariel-terminal-output'`).
- **Reconcile** (`lib/terminal/reconcile.ts:17`): for DB rows with
  `exitedAt == null` and no live session, set `{exitedAt: now,
  exitCode: null}` and post an Ariel close announcement.
- **No write-time cleaning**: the ring buffer/transcript/WS output are raw
  bytes; cleaning happens only on the Ariel path (and the read-time tool,
  already ported).

### The protocol (`lib/schemas/terminal.types.ts` — field names verbatim)

Client→server (discriminated on `type`): `{type:'input', data: string}` /
`{type:'resize', cols: int>0, rows: int>0}` / `{type:'ping'}`.
Server→client: `{type:'output', data: string}` /
`{type:'exit', code: number|null, signal: string|null}` /
`{type:'meta', meta: PtySessionMeta}` / `{type:'pong'}` /
`{type:'chat-update', chatId: string, reason?: 'ariel-terminal-output'}`.
`PtySessionMeta` = the session row minus createdAt/updatedAt:
`{id, chatId, label?, shell, cwd, startedAt, exitedAt?, exitCode?,
transcriptPath?}`.
Dispatch semantics (`lib/terminal/ws.ts`): unknown session →
`{type:'exit', code:-1, signal:'session_not_found'}` + close(1000);
`ping`→`pong`. (Auth does not port — D2.)

## Deliverables

1. **`quilltap-host/src/terminal/`** — the manager over `portable-pty`:
   spawn (defaults verbatim above; env/cwd/dirs passed in as constructor
   params — do NOT touch `paths.rs`, lane d owns it), ring buffer (256 KB
   tail), transcript append stream, `terminal_sessions` row at spawn +
   exit update (through the `Db` writer), subscriber broadcast (a
   `tokio::sync::broadcast` or per-subscriber mpsc of the server-message
   type), kill/write/resize/kick-for-chat, the attach replay (ring buffer
   as one `output` then `meta`), the exit sequence in v4's order.
2. **The protocol types** (`terminal/protocol.rs`): serde types for both
   unions, field names byte-verbatim (serde rename where needed);
   round-trip unit tests against literal v4 JSON strings.
3. **`TerminalScrollbackSource` production impl**: live session →
   `getRingBuffer`; else the transcript-file tail (v4's fallback read —
   check `terminal_read`'s scrollback source in
   `lib/tools/handlers/terminal-read-handler.ts` for the exact fallback
   semantics and cap before implementing; the ported tool feeds
   `full_content` through `clean_terminal_output` already).
4. **The Ariel flush + announcement writer**: the idle/max-age flush
   drivers (tokio timers, host-side) over the ported
   `clean_terminal_output`; the announcement itself is a `chat_messages`
   write = engine behavior → port `postArielTerminalOutputAnnouncement`
   (+ the close announcement `reconcile`/onExit posts) as a core
   `services::ariel_notifications` module following the W4.6b writer idiom
   (`[[post-office-writers-w46b]]`: `json!` MessageEvent → ChatEventInput →
   `add_message`; read the exact `systemSender`/`systemKind`/targeting +
   voice strings from v4 source, byte-exact) **with the standard writer
   differential** (tsx real-DB driving v4's REAL post functions, diffing
   `chat_messages` byte-for-byte — the `post_office_writers_tier3`
   pattern). If the writer drags in unported subsystems, STOP and document
   (seam the call), per the standing rule.
5. **The reconcile pass** (`reconcile_terminal_sessions_for_chat`): core
   service over the ported repo + the Ariel close announcement; unit-tested
   (+ covered by the writer differential if convenient).
