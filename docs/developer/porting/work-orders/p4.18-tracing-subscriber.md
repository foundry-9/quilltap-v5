## Why this order exists

Findings #23 (a total cheap-LLM outage presenting as "jobs COMPLETED,
nothing minted") and #26 (a fold that silently never happens) each cost
hours because v5's failure arms leave no trace anywhere. The dogfood
standing note records the operational reality: "quilltap-host/quilltap-web
emit essentially NOTHING to stdout/stderr after the startup banner … the
job runner logs nothing at all, so 'watch the server console' is never a
usable instruction." **v4 is NOT silent** — a server with no log surface
is itself a divergence from v4, which logs structured JSON to console
and/or rotated files at every one of the corresponding sites. Framing for
the ruling: adding a log surface *restores* v4-parity of operability; the
only genuinely new question is the record format.

## The ruling (arms; recommendation: (a))

- **(a) RECOMMENDED — adopt `tracing` + `tracing-subscriber`.** Console
  (stderr) fmt subscriber initialized in each bin, env-filtered
  (`RUST_LOG`, default `info` — the analog of v4's `LOG_LEVEL` default
  INFO), plus `tracing` events at the surveyed swallow sites. **No v4
  format parity owed**: log records are operator output, not data — no
  differential applies (a first for this port, and worth saying out
  loud; the fidelity obligation stays on the DB/wire/UI surfaces).
  File-transport parity (v4's `combined.log`/`error.log` rotation under
  `<dataDir>/logs`) is tier 3.
- **(b) Minimal:** no subscriber crate; promote the existing `eprintln!`
  convention to the named failure sites only. Cheapest, but unleveled,
  unfilterable, and a second convention to migrate later.
- **(c) Status quo:** stay silent; rely on DB rows (`llm_logs` error
  rows, `background_jobs.lastError`) + `quilltap db`. Rejected by the
  evidence above unless the human says otherwise.

## Survey-verified starting points (2026-07-24)

  `{timestamp, level, message, context, error:{name,message,stack}}`

### v5's confirmed absence + insertion points

- **No subscriber anywhere:** zero hits for
  `tracing`/`tracing_subscriber`/`env_logger`/`log`/`set_global_default`
  across all nine crates' `Cargo.toml` + src. **`tracing` is already a
  transitive dep** (Cargo.lock, via the axum/tokio/hyper/tower stack) —
  only `tracing-subscriber` (and optionally `tower-http`) are net-new.
- **Init points (one per bin, before boot):**
  `quilltap-web/src/main.rs:71` (`fn main`, runtime built `:89`);
  `quilltap-tauri/src/lib.rs:105` (`pub fn run`);
  `quilltap-cli/src/main.rs:178` (lighter/stderr, or none — the CLI's
  stdout is user output; keep events OFF stdout). NOT in `Host::start`
  (`quilltap-host/src/host.rs:209`) — it runs per-assembly and in tests;
  the subscriber is process-global, the *events* belong in host/core.
- **Swallow sites to instrument (tier 1 targets):**
  - `quilltap-core/src/services/job_runner.rs` — the claim loop drops
    errors by design (`:45,:347`); `run_one` best-effort mark/reconcile
    (`:399,:412,:426`); handler failures fold to
    `JobOutcome::Failed(e.to_string())` (`:889`) with no emission. THE
    top-value target: "the job runner logs nothing at all".
  - `quilltap-host/src/spine.rs` — chat-settings lookup swallowed
    (`:441`), LLM invoke folded to `Failed` (`:483`), stream/chain
    errors sent ONLY as client event frames (`:1037,:1120,:1180` — emit

  - `quilltap-host/src/host.rs` — the pump loop (`:505`, def ~`:700`);
    the two seeding `eprintln!` (`:654,:658`) → events.
  - `quilltap-core/src/services/cheap_llm_exec.rs` —
    `log_failed_call` (`:252`, invoked `:355,:431,:461`): the DB error
    row is currently the ONLY visibility; add the event beside it.
  - Existing raw `eprintln!` convertible where ownership allows:

## Units (under arm (a); re-scope if ruled otherwise)

1. **Deps + init.** `tracing` (direct) + `tracing-subscriber`
   (`env-filter` + `fmt`, stderr) in the three bins; `RUST_LOG` default
   `info` when unset; one shared init helper (suggest in `quilltap-web`'s
   lib beside the boot helpers, since all three bins already boot through
   them) so the format is uniform. CLI: events to stderr only, never
   stdout (its stdout is piped user output — `p4.3-quilltap-cli` memory
   note).
2. **Events at the tier-1 swallow sites** (job runner; spine error
   frames; host pump + seeding; `log_failed_call`), each carrying the
   context v4's corresponding site logs (chatId/userId/jobId/task type —
   match v4's context keys where a corresponding site exists, e.g.
   `queue-service.ts:503`, `core-execution.ts:113`). Level per v4's
   convention: `warn` degraded, `error` swallowed-exception.
3. **The `eprintln!` conversions** in files no sibling owns (the list
   above — NOT `orchestrator.rs`/`courier_transport.rs`/
   `chat_settings.rs`/`build_context.rs`/`distill.rs`/
   `recall_replay.rs`; leave those sites for a post-round sweep, noted
   loudly in the record).
4. **Request logging (tier 2):** `tower-http` `TraceLayer` on
   `build_router` at a quiet level (`debug`), so `RUST_LOG` can surface
   it without drowning the default.
5. **Guards.** A unit test on the init helper (idempotent, respects
   `RUST_LOG`); a smoke assertion that a failed job emits an event
   (capture via `tracing-subscriber`'s test writer). No differential —
   record IN the lane record that log output is explicitly outside the
   differential contract (and update the dogfood standing note "reading
   a running dogfood instance" to mention the console now speaks).
6. **Records.** Status-log lane record; the standing-question note in
   `dogfood-findings.md` → RULED (whichever arm); CLAUDE.md standing
   line updated at unification.
