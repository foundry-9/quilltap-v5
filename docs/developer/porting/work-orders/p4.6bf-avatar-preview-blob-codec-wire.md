## Mandate

Two production codec refusals remain, and this lane makes both live:

1. **`wardrobePreviewAvatar`'s render step.** The whole route is ported and
   guard-armed (P4.9f1) but `crates/quilltap-host/src/host.rs:600` passes
   `avatar_preview: None`, so the wardrobe dialog's out-of-chat Preview
   button reaches the typed `NotConfigured` refusal. This lane builds
   `HostAvatarPreviewRenderer` and wires it — **after which the Preview
   button costs real money** (an image-provider call per click). Say so in
   the lane record.
2. **The dispatch-layer mount blob-WebP transcode.** The two
   `store_mount_file` dispatch handlers
   (`crates/quilltap-core/src/api/mount_files.rs:595` and `:725` at
   planning) instantiate `RefusingWebpTranscoder` inline, so blob uploads
   through the dispatch surface store ORIGINAL bytes via v4's
   failure-passthrough arm where v4 stores WebP. (The chat-spine ingest
   paths already run the live codec — `spine.rs:2140-2379`; only the
   dispatch layer refuses.) This lane provides the seam + assembly field;
   the handler-signature half belongs to lane BG per **S1**, and the final
   engine.rs connection is AT-UNIFY.

**Must NOT touch:** `api/mount_files.rs` (lane BG owns it — your half of S1
is the trait impl + the assembly field); the `WebpTranscoder` /

## Survey-verified starting points (surveyed 2026-07-20, v4 @ `7e6d13e5`)

- **The host codec already EXISTS** — this is a composition lane, not a
  codec-building lane. `crates/quilltap-host/src/image_codec.rs` (P4.1b):
  `HostImageCodec` implements `PixelCodec`,
  `files::image_processing::ImageTranscoder`,
  `model::image::ImageTranscoder`, and `thumbnail_webp`, over the `image` +
  `webp` (libwebp, lossy) crates, with the D19 degradations documented in
  its module header (animated GIF → first frame; AVIF/HEIC undecodable →
  v4's failure-passthrough arm). **It does NOT implement
  `services::mount_index::blob_transcode::WebpTranscoder`** (trait at
  `blob_transcode.rs:35`, `encode_webp(&self, bytes, quality) → Result<Vec<u8>, String>`;
  already `Send + Sync`). That impl is new and small: decode + lossy encode
  at the given quality; v4's `effort: 4` (`lib/mount-index/blob-transcode.ts:62`)
  is an encoder-cost knob with no policy surface — drop it with a comment.
- **The renderer contract is FROZEN** (P4.9f1):
  `crates/quilltap-core/src/api/wardrobe.rs:580-670` —
  `AvatarPreviewRenderRequest { prompt, provider, model, quality, api_key, character_name }`,
  `AvatarPreviewImage { buffer, mime_type, filename, revised_prompt }`,
  `AvatarPreviewError { NotConfigured, NoImageData, Failed(String) }`,
  `trait AvatarPreviewRenderer` + `ErasedAvatarPreview`. The core handler
  (`wardrobe.rs:753`, engine arm `engine.rs:3087` /
  `ready_avatar_preview:3290`) already does parse + guards + prompt build +
  persist — the renderer does ONLY provider-call → transcode → filename.
- **The v4 oracle for the renderer half**:
  `app/api/v1/wardrobe/preview-avatar/route.ts` — provider call
  `{ prompt, model, n: 1, size: '1024x1792', quality: profile.parameters?.quality, style: 'natural' }`;
  `rawData = imageData?.data || imageData?.b64Json`; missing →
  `serverError('Image provider returned no image data')` (= `NoImageData`);
  provider mime defaults `'image/png'`;
  `safeName = character.name.replace(/[^a-zA-Z0-9]/g, '_')`; provider
  filename `avatar_preview_<safeName>_<Date.now()>.<ext>`; then
  `convertToWebP` — whose POLICY is already ported byte-faithfully
  (`services/file_storage.rs::convert_to_webp:341`, quality 90,
  SVG/WebP passthrough, jpeg/jpg/png/gif/avif convertible,
  best-effort dimensions, fallback-to-original on encode failure). The
  renderer composes that ported policy over `HostImageCodec` — do not
  re-derive it.
- **The host idiom to follow**: `HostImageGenerationRunner` (P4.6ai — grep
  `image_generation` in `crates/quilltap-host/`) rebuilds the provider per
  request; `HostConsultRunner` (P4.6bd) is the erased-runner precedent. The
  provider-HTTP machinery, request builders, and API-key plumbing all exist —
  reuse them.
- **e2e reality**: `apps/web/e2e/generate-image-flow.spec.ts` deliberately
  stops BEFORE provider spend (the e2e instance has no live image
  provider). The brahma spec starts its own canned LLM server
  (`workspace-brahma-console-flow.spec.ts`, the m4-salon precedent) — that
  is the pattern for a zero-spend canned image endpoint.
- Test-code sites passing `NotConfiguredTranscoder`
  (`orchestrator.rs:3520`, `enclave/step.rs:1803`, the harness tier-3
  suites) are TESTS, not production refusals — leave them alone.

## Shared contract (BINDING — identical in both orders)

- **S1 — the blob-WebP seam.** Lane BF adds
  `pub blob_webp: Option<std::sync::Arc<dyn crate::services::mount_index::blob_transcode::WebpTranscoder>>`
  to `EngineAssembly` (default `None`; production host = the live codec).
  Lane BG changes the two `store_mount_file` dispatch handlers
  (`api/mount_files.rs`, the functions containing `:595`/`:725` at
  planning) to take a trailing
  `webp: Option<std::sync::Arc<dyn WebpTranscoder>>`, using it when `Some`,
  else the existing `RefusingWebpTranscoder` (behavior unchanged on
  `None`). **AT-UNIFY:** the unifier edits the engine.rs call sites of
  those two handlers to pass the assembly's `blob_webp.clone()`.
- **S2 — the doc-edit files-dir thread (lane BG).** The `api/documents.rs`
  + `tools/doc_edit` entry points that reach the host filesystem gain a
  trailing `files_dir: Option<&std::path::Path>` (`None` preserves today's
  FsSeam refusal). v4 semantics: general base = `<files_dir>/_general`,
  legacy project fallback base = `<files_dir>/<projectId>`
  (`lib/paths.ts:310` — files dir = `<base>/files`). Lane BG passes
  `Some(&self.inner.config.base_dir.join("files"))` at its own dispatch
  call sites (verify the exact config accessor against `engine.rs:2971`'s
  `system_data_dir(&self.inner.config.base_dir)` idiom at lane start).
- **S3 — engine.rs REGION SPLIT.** Both lanes edit
  `crates/quilltap-core/src/api/engine.rs` in named disjoint regions ONLY:
  lane BF touches the `EngineAssembly` struct + its defaults/builders +
  assembly-construction plumbing; lane BG touches ONLY the doc-verb
  dispatch call-site lines (the documents/doc-edit match arms). Any merge
  conflict resolves by taking both edits; the unifier verifies the regions
  stayed disjoint.
- **S4 — version-bump ownership.** BF bumps `quilltap-host` +
  `quilltap-core`; BG bumps `quilltap-core` + `quilltap-harness`; either
  lane bumps the SPA only for e2e-spec changes. Identical bumps merge
  silently — the unifier RECOUNTS from the commit history (the P4.6aw
  memory).
- **S5 — the differential/live split.** Committed differentials keep
  canned/refusing seams (the byte-exact fallback arms stay pinned); live
  wires are proven by host tests + Playwright beats. A lane that extends a
  corpus owns regenerating it (BF: wardrobe tier 2; BG: the doc-edit
  families).
