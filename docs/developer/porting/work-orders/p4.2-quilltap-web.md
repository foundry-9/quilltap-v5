# Work order P4.2 — `quilltap-web` (the axum transport) + the production spine

> One of the two parallel lanes of the P4.2 ∥ P4.3 round (`phase-4.md`
> "Decomposition"). Drift check at round start (2026-07-08): v4 HEAD is still
> **`2494a84b`** — the kickoff baseline; no ported unit stale, no re-audit.
> The sibling lane is `p4.3-quilltap-cli.md`; the **Ownership** section below
> is identical in both orders and is binding.

## Mandate

Build `quilltap-web` — the first-class HTTP deployment (D1–D5) — and close
the **production spine composition** gap: a `ChatSend` dispatch that
assembles `OrchestratorDeps` from the P4.1 drivers, plus the model-dependent
job-handler registrations. Deliverables:

1. The axum server: `POST /api/dispatch`, `GET /api/events` (SSE),
   `GET /health`, the binary resource GETs (D4 subset below), the terminal
   REST + WebSocket surface (D5), static SPA serving with fallback,
   readiness gating, bind policy, and the Dockerfile.
2. The spine: the `ChatSend` Request variant end-to-end — dispatch →
   `process_message` over production drivers → frames on the `Event`
   broadcast → a typed result DTO.
3. Job-handler registrations for every handler that is **constructible from
   already-ported code** (thin wrappers only — anything needing NEW ported
   v4 logic is a named P4.4 deferral, not this lane's work).

**Exit criterion (milestone M2):** the headless chat-send e2e smoke — a
scripted send against a fixture instance through the **running axum binary**
(real HTTP dispatch → SSE trace → DB state), running in CI.

## Locked shape

### The route surface (D3/D4/D5)

- `POST /api/dispatch` — body = the `Request` enum (internally tagged JSON);
  reply = the `Response` enum serialized verbatim, with the HTTP status
  mapped from `ErrorKind` (v4 `lib/api/responses.ts` semantics):
  `BadRequest`→400, `NotFound`→404, `Internal`→500, success→200. **`Locked`
  → 503 with v4's readiness body merged in**: the response JSON carries
  `setupUrl: "/setup"` and `pepperState` (v4 `auth.ts:98–105` shape —
  `{"error":"Setup required","setupUrl":"/setup","pepperState":"…"}`; keep
  the `Response::Error` fields alongside so dispatch clients stay typed).
- `GET /api/events` — one global SSE stream per client (D3): subscribe to
  `CoreEngine::subscribe()`, write each `Event` as `data: <JSON>\n\n` (v4's
  frame encoding — no `event:` names), emit the SSE comment keep-alive
  `: keep-alive\n\n` on an interval (check v4's cadence in
  `streaming.service.ts` callers; if none is pinned, 15 s). Assign
  incrementing `id:` fields so clients can resume later; **no replay buffer
  this round** — broadcast lag (drop-oldest) is the resync signal, per D3
  best-effort. Scope filtering is client-side (events are scope-tagged).
- `GET /health` — v4 `app/api/health/route.ts` semantics: 200 healthy;
  **423** `{status:"locked", dbKeyState, timestamp, uptime}` when the vault
  is locked; **409** `{status:"lock-conflict", lockConflict, …}` when boot
  hit the single-instance lock (the P4.1d startup-conflict handoff — carry
  `InstanceLockError.lock_info` through `BootError::Assemble` into a typed
  startup-status the server holds); **503** `{status:"unhealthy", …}` while
  booting/degraded. (v5 has no migrations/plugin phases — collapse the
  phase vocabulary to what exists; document the mapping.)
- Binary GETs (D4 subset this round): `GET /api/v1/files/proxy/{key}`,
  `GET /api/v1/files/{id}` (+`?action=thumbnail&size=`), raw
  `GET /api/v1/mount-points/{id}/files/{path...}` (`?raw=1` /
  `Accept: application/octet-stream` form), and
  `GET /api/v1/mount-points/{id}/blobs/{path...}` — content-type, cache
  headers (`public, max-age=31536000, immutable` for immutable file bytes;
  `private, max-age=3600` for mount paths), `Content-Disposition: inline`
  (RFC 5987), `X-Frame-Options: SAMEORIGIN`, CSP `frame-ancestors 'self'`,
  and the `X-File-Sha256`/`X-Blob-Sha256` headers, per the v4 routes. Bytes
  come from `files::find_by_id`/`find_by_storage_key` +
  `file_storage::download_file` over `LocalStorageBackend` (mount-blob keys
  dispatch to `doc_mount_blobs` internally); blobs from
  `DocMountBlobsRepository::{find_by_mount_point_and_path, read_data}` with
  the doc-fallback mime table (`text/markdown; charset=utf-8`, …).
  Thumbnails: `HostImageCodec::thumbnail_webp` + the
  `build_thumbnail_storage_key` cache read/write path (the P4.1b handoff);
  clamp `size`, non-image → 400. No Range support (v4 has none). **Themes
  assets/fonts and `characters/{id}/photos` are deferred** (they need the
  P4.4 themes service / gallery reads).
- Terminal (D5): `POST /api/v1/terminals` (spawn via `TerminalManager` +
  **post the session-opened Ariel announcement** — the P4.1c call-site
  handoff closes here), `GET /api/v1/terminals?chatId=`, `GET|POST|DELETE
  /api/v1/terminals/{id}` (`?action=kill|write`), and the WebSocket
  `GET /api/v1/terminals/{id}/stream` marshalling `terminal::protocol`'s
  `WsClientMessage`/`WsServerMessage` verbatim (v4 `lib/terminal/ws.ts`
  close-code semantics: bad URL → 1008; unknown session → send
  `{"type":"exit","code":-1,"signal":"session_not_found"}` then close 1000;
  parse errors swallowed). No session auth exists in v5 (D2) — the WS is
  gated only on readiness.
- Static serving: serve a configurable SPA dist directory with fallback to
  `index.html` (the Angular app lands in P4.5; ship a minimal placeholder
  page so `/` isn't a 404); `/setup` must serve *something* readable while
  the vault is locked (a static unlock placeholder is fine this round —
  the real screen is P4.5).
- Bind policy (D2): binary flags `--host` (default `127.0.0.1`) / `--port`
  (default **3000**, v4 parity) / `--data-dir` / `--instance`; the container
  binds `0.0.0.0`. Readiness gating is already in `CoreEngine::dispatch` —
  the transport adds nothing but the 503 body mapping.

### The production spine (`quilltap-host::spine`, new module)

The composition point the whole round exists for. A `ChatSend` Request
variant (fields projected from `SendMessageOptions`: `chat_id`, `content`,
`continue_mode`, `responding_participant_id`, `target_participant_ids`,
`speaking_as_participant_id`, `file_ids`; camelCase on the wire) dispatched
through a **dyn-compatible seam registered at assembly** (the `JobHandler`
boxed-future precedent — RPITIT is not dyn-compatible):
`api` defines the seam trait + a `ChatSendResultDto`; `EngineAssembler::
assemble` grows a richer return (shutdown handle + optional chat driver;
update `NoopAssembler`); the engine's `ChatSend` arm answers
`ErrorKind::Internal` "chat dispatch not assembled" when absent (read-only
embedders stay valid).

The host implementation composes, per call:

- **The reference is the harness construction**
  (`crates/quilltap-harness/tests/orchestrator_tier3_equivalence.rs` ~698):
  mirror which impls are real (`RealBuildContextSeams`,
  `RealAnswerConfirmation`, `RealAsyncCompression`, the cost tracker,
  `RealCarinaQuery`, the Prospero writer, `DangerContentRouter::new(db,
  DbApiKeys(db))`, `ErasedAskCarina`, `RealBrahmaConsole`), swapping ONLY
  the model boundaries for the P4.1a drivers: `ProviderIo::
  streaming_provider(keys)` / `completion_transport()`-backed completion /
  the API-path embedding provider / `pricing_fetcher()` (ONE per host —
  cache state), plus `HostImageCodec` for `image_transcoder`,
  `ProductionFileBytes` for `file_bytes`, `OsRandomBytes` for `rng_bytes`
  (the P4.1d handoff), and a real `OrchestratorSeams` impl (thin
  chat-settings reads over ported repos — mirror the harness's; flag
  anything that would be NEW logic).
- Per-request inputs: `model_context_limit` via the ported
  `get_model_context_limit` chain, `provider_supports_web_search` from the
  manifest `Registry`, `timezone` from host config, a real `ProcessClock`
  (wall now_ms, local offset, real `random01`), `log_context =
  LogContext::none()`.
- The `EventSink` adapter: wrap each `ChatEvent` in
  `Event::chat(chat_id, frame)` → `CoreEngine::event_sender()`. Dispatch
  awaits the turn and returns the result DTO; frames ride `/api/events`.
- The `withTimeout` family (P4.1a handoff): implement the
  answer-confirmation 25 s/60 s as a host wrapper runner (tokio timeout
  around the inner `AnswerConfirmationRunner` future, mapping to the ported
  failure→could-not-verify shape). If the image-description 60 s cannot be
  wrapped without touching core, record it as a deferral — do not modify
  core seams for it.
- The failover-log threading follow-up (route the spine's db +
  `preGeneratedAssistantMessageId` into
  `attempt_empty_response_recovery_with_log`) — close it here if it is the
  one-liner it looks like; otherwise leave the tracked note.

## Verification

1. **The M2 smoke** (always-on, in CI): boot a fixture instance through the
   REAL binary path (spawn the axum server or run the router in-process over
   real HTTP via `tokio` + a bound port), dispatch `chatSend` over
   `POST /api/dispatch`, collect `/api/events` SSE frames until `done`, then
   assert the DB state (assistant row present, `updatedAt` bumped). The
   model boundary is canned (`CannedStreamingProvider` etc. — the spine
   bundle must be constructible with test providers; production uses
   `ProviderIo`). Fixture: follow the host-test lineage — hand-rolled DDL
   where sufficient (the M0 pattern), or a committed test-pepper fixture if
   the chat-send read surface makes hand-rolling unreasonable; an
   env-gated variant over a v4-baked fixture (the `terminal_ariel_e2e`
   pattern) is welcome on top but cannot BE the CI smoke.
2. **Transport contract tests** (tier-4 #2 seed): a committed
   `Request` corpus replayed over real HTTP asserting exact `Response`
   bodies + status codes (incl. the Locked 503 body, BadRequest 400,
   NotFound 404) and an SSE round-trip (publish a synthetic `Event` on the
   broadcast, assert the exact `data:` frame bytes + keep-alive comment).
3. Terminal: a WS integration test over a real PTY (the P4.1c test lineage)
   — spawn via REST (assert the Ariel announcement row lands), attach WS,
   input/output/resize/ping-pong/exit frames verbatim, unknown-session close
   semantics.
4. Binary routes: serve a fixture file + thumbnail + blob; assert bytes,
   content-type, cache headers, sha headers.
5. The standing gate: full workspace `cargo test`, clippy `-D warnings`
   (default AND `native-transport`), fmt. The Dockerfile must build
   (document if the sandbox can't run docker; the build recipe must still
   be correct).
