## The drift, classified (surveyed 2026-07-30)

**Why this is the round's highest-risk lane:** v5's request builders
reproduce v4's provider bodies **byte-for-byte per provider** (P4.11/P4.13),
and the OpenRouter builder specifically reproduces `@openrouter/sdk`'s **zod
re-emission** (key reorder, snake_case, undeclared-key drops, client-side
refusals → `BuildError::ProviderRefused`). Both SDKs just took MAJOR bumps.
If either changed its serialization or its refusal behavior, v4's live wire
bytes moved and v5 is silently divergent — exactly the corpus-blind-spot
class P4.11 (one-mode corpus), dogfood #24 (SDK-synthesized fields), and
P4.21 (corpus-field extension) kept finding. The decisive instrument exists:
regenerate the corpora at the pin and byte-diff.

Per-commit:

1. **`7f6d58a7` + `77ff4e2e` (deps):** root + plugin `package.json`s and
   rebuilt plugin `index.js` bundles (openai 7 across
   openai/grok/deepseek/z-ai/openai-compatible; `@openrouter/sdk` 1.2.2;
   google + mcp bundles rebuilt). The xterm/terminal half of `77ff4e2e` is
   D34's. sharp 0.35 is type-only (`f46b0554`, D32's disposition).

4. **`7b5acdb6`:** deepseek `as unknown as ChatMessage` widening + grok
   `WithGrokStop<T>` type + cast reshuffles — no value-level change on
   inspection; the corpus regen is the proof.
