## The drift, classified (surveyed 2026-08-08, from the `f6eac168` diff)

Three client behaviors, all in `SalonView.tsx` + `useImpersonation.ts`:

- **Bug 48 — impersonating takes the turn.** `handleImpersonateAndTakeTurn`:
  after `handleStartImpersonation(participantId)` resolves, if no LLM is
  mid-generation (`!streamingRef.current`), set the client turn presentation
  to the impersonated seat
  (`setTurnSelectionResult({ nextSpeakerId: participantId, reason: 'queue',
  cycleComplete: false })`). Wired at BOTH impersonate entry points: the
  sidebar's `onImpersonate` and the AllLLMPause modal's take-over handler.
  A client presentation of the rotation — recomputed from history once a
  message is sent; an LLM mid-stream is never interrupted.
- **Bug 49 — the speaking-as follows the current user-driven turn.** A new
  effect: when the turn's `nextSpeakerId` resolves to a seat the human
  drives (`isUserDrivenSeat` over the overlay) and that seat CHANGES (a ref
  latch keyed on the turn seat, `lastFollowedTurnSeatRef`), default the
  speaking-as to it (`setActiveTypingParticipantId(nextId)` client-side
  only — the send path forwards it as `speakingAsParticipantId`; no per-turn
  persistence). A deliberate same-turn SpeakerSelector choice still sticks
  (the latch only reacts when the turn seat itself changes); a non-user seat
  or no next speaker clears the latch.
- **Bug 51 (client half) — seed once, don't clobber.** The chat-sync effect
  now seeds the persisted `activeTypingParticipantId` only when the local
  value is unset (`setActiveTypingParticipantId(prev => prev ?? activeTypingId
  ?? null)`), so a refetch no longer snaps the composer back to the stale
  persisted seat after each turn. The impersonating LIST keeps v4's existing
  semantics: re-applied from the chat record when non-empty (replies own the
  transitions, including to empty).

## Shared contract (BINDING — identical in P4.D60)

The chat-GET projection gains exactly two keys, in the chat body returned by
BOTH entrances (dispatch `chatGet` → `{ type: "chat", data: { chat } }` and
REST `GET /api/v1/chats/:id`), positioned with the other turn fields:

- `impersonatingParticipantIds`: `string[]` — ALWAYS present, `[]` when the
  column is NULL/absent.
- `activeTypingParticipantId`: `string | null` — ALWAYS present, `null` when
  unset.

Identical names and nullability to what the mutation replies
(`chatImpersonate` / `chatStopImpersonate` / `chatSetActiveSpeaker`) already
emit. The SPA contract (`core-contract.ts:2641-2642`) already declares both
as optional on `ChatDetail` — this lane may tighten
`impersonatingParticipantIds` to required but MUST NOT rename. No new event
shapes: the server pause path reuses the existing chain-complete frame
(`reason: "user_turn"`, `nextSpeakerId: <seat>`, `chainDepth: 0`) exactly as
already mirrored in `ChatStreamFrame` (`core-contract.ts:3568-3572`).
