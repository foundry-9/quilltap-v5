# Work order P4.1a — host drivers: provider/model IO

> P4.1 round, lane (a), per `phase-4.md` "Decomposition and ordering".

> oracle baseline; no ported unit stale.

## Mandate

Make the model boundary real: every provider-facing seam gets its production
IO implementation, so a host can stream a completion, embed a text, fetch
pricing, generate an image, moderate content, and web-search against live
providers. Five deliverables:

1. **The streaming composer** — the biggest single gap (it does not exist at
   all): a production `StreamingCompletionProvider` composing the frozen
   sans-IO surfaces. New always-compiled core module
   `model/streaming_provider.rs`, generic over `T: ProviderTransport`
   (mirror `model/completion_provider.rs`, the non-streaming twin):

   - `StreamParams` → `RequestInput` (set `stream: true`; carry
     `tools`/`top_p`/`stop`/`web_search_enabled`/`profile_parameters`/
     `cache_key`/`previous_response_id` — the completion twin's
     `request_input_from_params` is the template but the streaming path sets
     more fields; `max_tokens`/`temperature` are `Option` pass-throughs).
   - `build_request(provider, &input)` → `transport_headers` + auth
     injection. **Hoist `apply_auth`** out of `completion_provider.rs` into a
     shared `pub(crate)` home (e.g. `model/provider_auth.rs` or a
     `pub(crate)` in `transport.rs`) — do not duplicate it.
   - `ProviderTransport::execute_stream` → the byte receiver.
   - **Decoder selection by manifest**: a `decoder_for(provider) ->
     Box<dyn StreamDecoder>` mapping `Registry::get_provider(p).stream_decoder`
     to the concrete decoder, with the `ChatCompletionsFlavor` split the
     manifest does NOT carry (it is an internal selector, W4.7b):
     `DEEPSEEK → Flavor::DeepSeek`, `Z_AI → Flavor::ZAi`,
     `OPENROUTER → Flavor::OpenRouterRaw`, everything else on
     `ChatCompletionsSse → Flavor::OpenAiCompatible`.
   - The pump: feed transport bytes into `decoder.push`, emit each
     `StreamChunk` as `Ok` into a `tokio::sync::mpsc::Receiver
     <StreamChunkResult>`; `decoder.finish()` at transport EOF; a
     `DecodeError` or transport error becomes an `Err(StreamError)` item
     (content already emitted stays emitted — v4 streams can fail after
     yielding). **The core stays scheduler-free**: no `tokio::spawn` in
     always-compiled code — run the pump on a `std::thread` using
     `blocking_recv`/`blocking_send` (the writer-thread precedent), so the
     module compiles and unit-tests without a runtime. (The feature-gated
     reqwest transport may use tokio internally; that is fine.)
   - **OpenRouter no-tools OpenResponses path**: v4 uses the OpenRouter SDK's
     OpenResponses protocol when no tools are present — a distinct,
     undocumented wire that W4.7b explicitly left out of scope. v5 routes
     OPENROUTER through the raw chat-completions wire ALWAYS (the
     differential-verified path). Document this as a deliberate divergence in
     the module doc; do not attempt the OpenResponses wire.

2. **Reqwest `WireTransport` + `SyncWireTransport`** (the W4.7f boundary for
   image dialects / OpenAI moderation / Serper) — in **`quilltap-host`**
   (`src/wire.rs`), D8: the host is the crate that turns seams into IO. The
   sync impl may use `reqwest::blocking` on a dedicated thread (a blocking
   client cannot be created inside a tokio runtime thread — guard for that:
   spawn-and-join or a lazily-created thread-owned client). Do NOT move the
   core's feature-gated `ReqwestTransport` (churn; note it as a candidate
   migration).

3. **The live `PricingFetch`** (`quilltap-host/src/providers.rs`): reqwest
   impls of the three methods — `openrouter_public_models` (GET
   `https://openrouter.ai/api/v1/models`), `openrouter_sdk_models` (survey
   v4's `@openrouter/sdk` `client.models.list()` for the actual endpoint +
   auth header it issues, and reproduce that HTTP call), `ollama_tags`
   (GET `{base_url}/api/tags`). Apply v4's pricing fetch timeout (survey
   `pricing-fetcher.ts` for the `withTimeout` value — the phase-4 inventory
   says 3 s) in the host impl; a timeout/network/non-2xx failure returns
   `None` (the trait's contract — the negative cache is in the ported
   fetcher).

4. **The API-path `EmbeddingProvider`** — port v4 `generateEmbeddingForUser`'s
   real orchestration (survey `lib/embedding/embedding-service.ts` — or
   wherever it lives — FIRST): the per-user embedding-profile resolution,
   the BUILTIN dispatch (→ the ported
   `services::builtin_embedding::generate_builtin_embedding`), the wire
   providers (→ the ported `model::embedding_wire` builders/parsers over the
   `WireTransport` seam), `apply_embedding_profile`, api-key acquisition (the
   ported `api_key_service` / `DbApiKeys` pattern — key material via the
   injected resolver), and the error/priority semantics of the trait.
   This is **engine behavior → differential required** (D10): a jest
   real-DB oracle driving v4's REAL `generateEmbeddingForUser` over a seeded
   fixture (embedding profiles incl. a BUILTIN one + api keys + a fitted
   tfidf vocabulary), with `fetch`/SDK mocked to committed payloads
   (mirrored by a canned `WireTransport` on the Rust side), diffing the
   returned `EmbeddingResult`s (vectors at 1e-12 where the BUILTIN ln seam
   applies, byte-exact elsewhere) and any DB effects. New core module
   `services/embedding_provider.rs` (or similar), generic over the wire
   seam.

5. **Constructor bundle + spine api-keys**:
   - `quilltap-host/src/providers.rs` exposes constructors bundling the
     reqwest transports with `TransportPolicy`, the user agent
     (`quilltap_user_agent(version)`), and `BASE_URL` env — for the streaming
     composer, `execute_completion`, `RealImageProvider`,
     `RealModerationProvider`, `RealWebSearchProvider` (all three W4.7f
     provider impls already exist over the wire seams — no new logic, just
     instantiation).
   - **`build_pricing_context` api keys** (the W4.10a note: "empty
     `api_keys` — the live HTTP fetch is Phase-4 host wiring"): populate the
     connection-profile api keys at the spine composition point
     (`services/orchestrator.rs` — this lane owns that file this round,
     ONLY for this change) so `check_model_supports_tools`' OpenRouter path
     can use a key when the fetch goes live. Re-run
     `orchestrator_tier3_equivalence` against a freshly regenerated oracle
     to prove the change inert under the canned pricing seam.

(union-resolves at unification).

The host crate needs `quilltap-core` with the `native-transport` feature for
`ReqwestTransport` — add the feature to the host's dependency (the workspace
gate already runs clippy on both feature sets).
