**Contract B — the `multiCharacterPrefill` wire (D79 ↔ D81).**
- Read shapes: `multiCharacterPrefill?: boolean | null` on the
  connection-profile DTO (stored value verbatim; `null` = never
  chosen).
- Create bag: field optional; absent → the server stores
  `defaultMultiCharacterPrefill(provider)` (false iff
  `provider.toUpperCase() == "ANTHROPIC"`, true otherwise, true when
  provider is absent); present non-boolean (INCLUDING explicit
  `null`) → 400 with body message exactly
  `multiCharacterPrefill must be a boolean`.
- Update bag: absent → unchanged; boolean → stored; present `null`
  or non-boolean → the same 400. Server-side this REQUIRES the
  double-Option carry (`Option<Option<…>>`, the P4.D57 shape) so an
  explicit null cannot collapse to absent at the web edge (the Taboo
  §3 lesson).
- The SPA's TS twin `defaultMultiCharacterPrefill` has parity-spec
  semantics identical to v4's `lib/llm/multi-character-prefill.ts`.
