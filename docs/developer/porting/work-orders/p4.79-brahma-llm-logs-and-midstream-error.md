**§G The `chainComplete` frame contract (P4.D160 ↔ P4.D161), binding.** The
frame is `{ "chainComplete": true, "reason": <string>, "nextSpeakerId":
<string|null>, "chainDepth": <int>, "paused"?: <bool> }`. The key is spelled
`paused`, a JSON boolean, and is **present on exactly the four
`execute_turn_chain` emits** — the new paused early-return (`reason:
"paused"`, `paused: true`, `chainDepth: 0`, `nextSpeakerId: null`), the
mid-chain decision stop (`paused: decision.reason == "paused"`), the
empty-response stop (`reason: "error"`, `paused: false`), the chain-error
safety stop (`reason: "error"`, `paused: true`) — and **ABSENT** on the
fair-rotation `user_turn` emit (`orchestrator.rs` ≈`:905`, v4
`orchestrator.service.ts:1892`) and on the help-chat orchestrator's
`chainComplete` (v4 `help-chat/orchestrator.service.ts:156`), which v4 did not
touch. The server side therefore carries it as `Option<bool>` with
`skip_serializing_if = "Option::is_none"`; the client reads
`data.paused === true` and treats absent/false alike. Neither lane invents a
second key.
