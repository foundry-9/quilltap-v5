### Shared contract P4.D249 ↔ P4.D250 — the standing-inform wire (binding; byte-identical in both orders)

Wire = `POST /api/dispatch` with the `type`-tagged camelCase body; the SPA
reads `data` through `CoreClient.dispatchData`. All three verbs EXIST
(`api/types.rs:3945-3966`, engine `api/engine.rs:5800-5823`, SPA
`core-contract.ts:8205-8268`); **no new verb, no Event change, the realtime
`chats` publish unchanged.** Measured from v4 `52d6e7ecd` A7/A8 (survey §A).

1. **`chatInform { chatId, contentMarkdown, targetParticipantIds,
   permanent? }`** — `permanent` OPTIONAL boolean (v4 `z.boolean()
   .optional().default(false)`): absent → `false`; `true`/`false` honoured;
   **an explicit `null` or any non-boolean → 400 with v4's Zod `Validation
   error` envelope and NOTHING written** (no batch, no Host record).
   **The SPA ALWAYS sends `permanent` as a boolean** (v4's dialog does).
2. **201 `data`** = `{ success: true, batchId, targetParticipantIds,
   permanent, message }` — EXACTLY this key order; `permanent` is the
   validated boolean (`false` when the request omitted it).
3. **`chatInformsList { chatId }`** → `{ batches: [{ batchId,
   contentMarkdown, createdAt, recordMessageId, permanent,
   pendingParticipantIds }] }` — EXACTLY this per-batch key order;
   `permanent` ALWAYS present (boolean) on the server wire; batches in
   POSTING order (oldest first, `id` tie-break); a standing batch lists
   every target still seated, delivered or not; a delivered one-shot seat
   is absent (unchanged).
4. **`chatInformCancel { chatId, batchId }`** → `{ success, removed,
   recordDeleted }` UNCHANGED in shape. For a standing batch `removed`
   counts EVERY row (delivered or not); `recordDeleted` is true only when no
   row of the batch was ever delivered (`consumedAt` null on all) and a
   record existed.
5. **The SPA types:** `PendingInformBatch.permanent?: boolean` (OPTIONAL —
   v4's client types it so; falsy reads as one-shot, so the SPA renders
   correctly against a pre-P4.D249 server and the two lanes have NO
   pick-order dependency); `ChatInformRequest.permanent: boolean`
   (REQUIRED — always sent); `ChatInformResult.permanent: boolean` between
   `targetParticipantIds` and `message`. The SPA reads nothing new from the
   201 body.
