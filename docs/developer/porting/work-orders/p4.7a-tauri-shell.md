## Mandate

Deliver **`crates/quilltap-tauri`** — the Tauri 2 desktop shell locked by
D1/D3/D4/D5/D8/D9 and the P4.7 decomposition entry: the same `quilltap-host`
engine and the same Angular SPA, with the transport re-mapped from HTTP to
Tauri IPC. Dispatch rides `invoke`; the one global `Event` stream rides Tauri
events; the HTTP-shaped byte/REST surface rides a **custom protocol that
delegates into the reused `quilltap-web` router**; the terminal stream rides
paired IPC (D5). This is a *transport*, thin by decree — **no business logic
above the boundary** (nothing in this crate may touch repos/services directly
except via `Host`/`CoreEngine` and the reused router).

This lane owns `crates/**` and the root `Cargo.toml`/`Cargo.lock`; it must
NOT touch `apps/web/**`. There is no v4 oracle for a desktop shell — the
verification tier is **tier 4 #2** (the transport contract corpus replayed
through the IPC harness, asserting identical `Response` bodies and ordered
`Event` traces against what `quilltap-web`'s `contract.rs` proves over HTTP).

**What this lane must NOT do:** no windowed/GUI walk (the M5 demo is the
unifier's + the human's, after lane B's client exists); no release/signing/
updater work (D21 — dev-grade bundle only); no new `Request`/`Response`
variants (the dispatch surface is frozen for this round); no cadence in the
shell (the `Host` already owns all timers — boot it, don't wrap it).

## Survey-verified starting points (2026-07-15 @ `02865bdb` — do not re-derive)

### What already exists to reuse (all verified today)

- **`quilltap-web` is a lib + bin** and already exports the whole boot +
  router surface: `boot_startup_status`, `build_router`, `web_state`
  (`crates/quilltap-web/src/lib.rs`). `WebState`
  (`src/state.rs`) = `startup: StartupStatus` (Running(Box<Host>) /
  LockConflict / Failed) + `started`/`version`/`spa_dir`/`base_dir`.
  The shell boots the SAME way `main.rs` does: resolve base dir
  (`--data-dir` → `--instance` via `InstanceRegistry` → `QUILLTAP_DATA_DIR` →
  `quilltap_host::paths::resolve_base_dir(None)`, see `main.rs:64–82`), then
  `boot_startup_status` on a tokio runtime. Reuse, don't re-derive: the
  single-instance lock classification (`quilltap_host::lock`), the readiness
  gate (inside `CoreEngine::dispatch`), and the job-pump/enclave cadence
  (inside `Host`) all come free with that call.
- **Dispatch envelope semantics**: `crates/quilltap-web/src/dispatch.rs` —
  the boot-failure arm (lines 44–57: `Response::error(Internal, msg)`), the
  malformed-body arm (`Response::error(BadRequest, …)`), and `status_for`
  (ErrorKind → HTTP status). The IPC command reuses the same arms; only the
  status mapping is HTTP-specific (IPC carries no status — see §1).
- **Events**: `crates/quilltap-web/src/events.rs` — the per-subscriber
  ordering rule is **subscribe to `host.core().subscribe()` BEFORE draining
  `creation_progress_bus().active_snapshot(now_unix_ms())`**, then backlog
  frames before live frames. `RecvError::Lagged` (drop-oldest) is the
  client's resync signal. The SSE `data:` payload is
  `serde_json::to_string(&event)` — the IPC event payload is the SAME
  serialization (§2).
- **The terminal WS surface**: `crates/quilltap-web/src/terminal_routes.rs`
  marshals `quilltap_host::terminal::protocol`; the client/server unions are
  frozen (v4 `lib/schemas/terminal.types.ts`, mirrored in the SPA's
  `apps/web/src/app/terminal/terminal-protocol.ts`: client
  `input`/`resize`/`ping`; server `output`/`exit`/`meta`/`pong`/
  `chat-update`). Re-derive the WS **attach** semantics (what the socket
  emits on open — meta/scrollback behavior) from `terminal_routes.rs` itself
  and mirror them exactly in `terminal_attach` (§4). The terminal REST verbs
  (list/get/spawn/kill, `/api/v1/terminals*`) are plain HTTP routes — they
  ride the custom protocol for free (§3).
- **The transport contract corpus**: `crates/quilltap-web/tests/contract.rs`
  (+ `tests/common/mod.rs` — `materialize_bare_instance`,
  `serve_instance`). This is the tier-4 #2 seed the IPC harness must mirror
  case-for-case: /health vocabulary, dispatch health round trip
  (`{"type":"health"}` → `{"type":"health","data":{ready,…}}`), malformed
  request → the BadRequest envelope, the Locked setup surface, and an `Event`
  publish → exact frame payload.
- **Workspace**: `Cargo.toml` members glob `crates/*` — the new crate joins
  automatically. Toolchain pinned 1.96.0 (Tauri 2.x MSRV is comfortably
  below). Xcode CLT present (wry/tao build fine on this Mac).
- **The SPA build output** feeds `frontendDist`. `apps/web/angular.json` uses

  `apps/web/dist/web/browser`) and point `frontendDist` at it via a relative

### Known risks (flag, don't discover twice)

- **Tauri version**: use the latest **Tauri 2.x** stable at lane start and
  record the exact `tauri`/`tauri-build`/`wry` versions in the closing entry.
  Do not adopt a 3.x even if published — D-series locks name Tauri 2.
- **`tauri::test`**: the mock runtime has no webview and its event-capture
  surface is limited. The pinned requirement is the *corpus + assertions*,
  not the mechanism — if `tauri::test::get_ipc_response` fights, the allowed
  fallback is driving the command fns directly over a real booted
  `StartupStatus` + asserting emitted event payloads via a test listener on
  the `AppHandle` (or by injecting a test emitter seam). Say which you used.
- **Custom-protocol streaming**: Tauri custom-protocol responses are
  buffered, not streamed — that is WHY `/api/events` (SSE) and the terminal
  WS do NOT ride the protocol (§2/§4 replace them). Byte routes buffering a
  whole file/image is acceptable dev-grade.
- **CORS/scheme**: the webview origin (`tauri://localhost` on macOS,
  `http://tauri.localhost` on Windows) fetches `qtap://…` — the protocol
  handler must answer CORS preflight and set `Access-Control-Allow-Origin`
  permissively, or the SPA's raw fetches fail silently.
- **Icons**: `tauri build` requires an icon set; generate a dev-grade set
  with `tauri icon` from any placeholder PNG (D21: no release polish).
- **The Tauri CLI** is a dev-machine tool, not a repo dependency: use
  `cargo install tauri-cli --locked` (record the version); do NOT add npm
  tooling for it (that would cross into lane B's `apps/web/package.json`).

## Shared contract (BINDING — reproduced verbatim in both orders)

The IPC surface, name-level. Lane A implements; lane B consumes. Payload
shapes are the EXISTING wire shapes — no new DTOs.

### §1 — dispatch + health commands

- Command **`dispatch`**, argument key **`request`**: the value is the same
  internally-tagged `CoreRequest` JSON the HTTP body carries, verbatim. The
  command ALWAYS **resolves** (never rejects) with the `Response` enum
  serialized verbatim — `{type, data}` — including typed error envelopes.
  IPC carries no HTTP status; the envelope alone is authoritative (the SPA
  already treats non-2xx bodies as typed envelopes, so nothing is lost).
  Boot-failure arm: resolves `{type:'error', data:{kind:'internal',
  message}}` (the `dispatch.rs` 503 arm's body). Malformed request: resolves
  the BadRequest envelope (the `dispatch.rs` 400 arm's body).
- Command **`health`**, no arguments → `{ status: <number>, body: <the
  GET /health JSON body verbatim> }` where `status` is exactly the HTTP
  status `health.rs` would set (200 healthy / 423 locked / 409 lock-conflict
  / 503 unhealthy), so the SPA's interpreter branches identically.

### §2 — the global event stream

- Tauri event name **`quilltap://event`**; payload = the `Event` JSON exactly
  as the SSE `data:` payload (same serde serialization, no `id:`/framing
  wrapper).
- Command **`events_attach`**, no arguments: (re)starts the forwarder for
  this webview session — subscribe to the core broadcast FIRST, then emit the
  Green-Room `active_snapshot` backlog as `quilltap://event` frames in order,
  then forward live frames (the `events.rs` ordering rule). Idempotent:
  a second attach (webview reload) replaces the previous forwarder.
- On broadcast lag (`RecvError::Lagged`, drop-oldest) the shell emits
  **`quilltap://resync`** (payload ignored); the SPA bumps `resyncCounter` —
  the IPC analogue of the SSE reopen signal.

### §3 — the custom protocol

- Scheme **`qtap`**, registered via `register_uri_scheme_protocol`,
  delegating the full `http::Request` (method + path + query + headers +
  body) into the reused `quilltap-web` router over the same booted state;
  the response is buffered back. CORS preflight answered permissively.
- SPA-side origin rule (per Tauri 2 platform behavior):
  `qtap://localhost` on macOS/Linux, `http://qtap.localhost` on Windows.
  The SPA prepends this origin to the SAME paths it uses today
  (`/api/v1/...`); paths do not change.
- Excluded surfaces (never called via protocol): `GET /api/events` (replaced
  by §2), the terminal WS upgrade (replaced by §4), static serving (the
  webview loads bundled `frontendDist` assets).

### §4 — the terminal stream (tier 2, both lanes)

- Command **`terminal_attach`**, args `sessionId: string`, `onMessage:
  Channel` — the channel carries `WsServerMessage` JSON verbatim
  (`output`/`exit`/`meta`/`pong`/`chat-update`, the frozen union). Attach
  semantics (what is sent on open) mirror the frozen WS route exactly.
- Command **`terminal_send`**, args `sessionId: string`, `message:
  <WsClientMessage>` (`input`/`resize`/`ping`, verbatim).
- Command **`terminal_detach`**, args `sessionId: string`.
- The terminal REST verbs (`/api/v1/terminals*` list/get/spawn/kill) ride §3
  unchanged.
