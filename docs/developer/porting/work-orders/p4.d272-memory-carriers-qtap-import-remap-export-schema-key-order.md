## Rulings made at planning (the planner's calls; the human may overrule before lane start — a STOP item if they do)

- **R-A — the up-front mint is ported with v4's JS `Map` semantics, edges
  included.**
  - **The keys.** v4 keys by `memory.id` raw (`import-entities.ts:449-453`).
    So the port keys by the JSON scalar under JS SameValueZero:
    - an ABSENT id (`undefined`) is its own key, distinct from `null` and
      from `""`;
    - a string and a number never collide;
    - an object/array id is identity-keyed — reachable only by its own item,
      never by a ref.
  - **Duplicate keys: the LAST mint wins** (`Map.set` overwrite). Two bundle
    memories sharing an id therefore both resolve to ONE minted id. The first
    lands, and the second fails the insert (`UNIQUE constraint failed:
    memories.id` — measure v4's exact tail). Two ID-LESS memories collide the
    same way through the `undefined` key.
  - **This is a behaviour change.** Before `d58548051`, and in v5 today, each
    such memory minted its own id and both landed. Port it faithfully; it is
    not a divergence.
  - **Record it as a v4-filing candidate** in the lane record: "a `.qtap`
    bundle with two memories sharing an id, or two id-less memories, now
    loses the second". Filing is the human's call; the number comes after
    P4.D271 R-A's candidate (v4 used 187–197 after the pin).

**B. v4 shapes measured at planning (V8 at Node v24.13.1; re-measure through
v4's real code in the case):**

- **A non-null, non-array `relatedMemoryIds` / `consolidatedFrom`** — a
  string, number, object or boolean — throws inside the payload literal. The
  item's warning tails are, VERBATIM:
  - `(memory.relatedMemoryIds ?? []).map is not a function`
  - `(memory.consolidatedFrom ?? []).map is not a function`
- **Precedence** follows evaluation order: tags (built before the payload) →
  `relatedMemoryIds` → `consolidatedFrom`. `supersededById` cannot throw.
- **A `null` / non-string ELEMENT** maps to itself: `Map.get(null)` is
  `undefined`, so `?? ref` returns the ref. Unlike tags, it is NOT filtered,
  and `MemorySchema` refuses it (`z.array(UUIDSchema)`).
- **A truthy non-string `supersededById`** (`5`, `true`, `{}`) remaps to
  itself and is refused by `UUIDSchema.nullable().optional()`.
- **`Map` keys:** `m.set(undefined, "X"); m.get(undefined) === "X"`
  (measured).
