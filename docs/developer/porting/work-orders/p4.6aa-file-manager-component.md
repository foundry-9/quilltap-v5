### Quirks the port must not miss

1. **The mutation chain serializes** (`createSvarAdapter.ts:77–80`): a
   burst of drags/renames must not interleave; every mutating op is
   followed by a reload-to-reconcile (temp ids reconcile on success,
   revert on error).
2. **The two backend gaps are UI-level refusals, not requests**: the
   event→wire map turns copy-folder and cross-mount folder-move into
   `unsupported` with v4's message — never fire the doomed request.
3. **Cross-storage copy fires the reindex** (`reindex-after-copy.ts`) and
   surfaces the "being re-indexed" notice (`onIndexing`).
4. **Root ops resolve against the pane's mount id** (the `MapContext`
   fallback when a node id can't be resolved).
5. **The dispatch wire replaces v4's per-item REST for JSON verbs** —
   your event→wire map re-targets: same pure shape and refusal arms,
   payloads per the P4.6v variant table (e.g. rename rides
   `mountFileUpdate {mountPointId, path, rename}`; folder delete rides
   `mountFolderDelete`). Upload/open/download stay REST (contract §3).
   Keep the map PURE (no network, no widget runtime) so it stays
   unit-testable like v4's.
6. **v4 voice** for user-facing strings — the error translations and the
   "Summoning the file manager…" loading line port verbatim.
7. **`ng test`, not bare vitest** ([[p4.6e-settings-spa]]); DOM lacks
   `Blob.text()`/`URL.createObjectURL` in ng-test
   ([[p4.6j-characters-remainder-spa]]) — download specs stub
   accordingly.
