## The spine (`services::chat_create` or similar), v4's exact order

1. Input validation — transcribe `createChatSchema` (route.ts:89 onward)
   whole: `participants` (min 1), `title`, `scenario` (free-text notes),
   `scenarioId`, `projectScenarioPath` (requires `projectId`),
   `generalScenarioPath`, `groupScenarioPath` + `groupScenarioGroupId`,
   `timestampConfig`, `projectId`, `imageProfileId`, `outfitSelections`,
   `avatarGenerationEnabled`, `continuationFromChatId`, `progressId`,
   and the autonomous fields (`chatType` salon|autonomous, `scheduleCron`,
   `scheduleFreshnessWindowMs`, `budgetMaxTurns`/`budgetMaxTokens`/
   `budgetMaxWallClockMs`, + the rest past line 149 — survey to the
   schema's end). Validation failures map to `ErrorKind::InvalidRequest`
   with v4's message shape.
2. Progress `status` beats — **byte-exact strings, curly apostrophes
   included** (e.g. "Committing everyone's particulars to memory…" uses
   `’`); extract every beat from the source in order.
3. The continuation ownership pre-check (`continuationFromChatId` must
   resolve to the same user's chat).
4. The autonomous preconditions: no user-controlled participants; ≥2 LLM
   characters; `scheduleCron` validated via the ported `enclave::cron`
   (invalid → reject; whitespace-only → no schedule).
5. `buildAllParticipants` / `buildCharacterParticipant` /
   `pickWeightedByTalkativeness` — **RNG injected** (the standing
   `random01` precedent) so the weighted pick is differential-pinnable.
6. The scenario precedence chain (sub-unit 1): character `scenarioId` >
   `projectScenarioPath` > `groupScenarioPath` > `generalScenarioPath` >
   none — each miss logged-and-falling-through — then
   `combine_scenario_text` layers the free-text `scenario` notes.
7. `build_chat_context` (sub-unit 2).
8. Participant id/timestamp minting.
9. The project defaults chain + the **roster auto-add**
   (`allowAnyCharacter` false → `projects.update` roster RMW).
10. The timestampConfig / imageProfile / roleplayTemplate fallback chains.
11. `chats.create` (incl. the autonomous column block when
    `chatType === 'autonomous'`).
12. Outfits (sub-unit 4) — a failure NEVER fails creation (v4's
    try/catch); the `wardrobe-start`/`wardrobe-result` frames ride the
    emitter.
13. The compiler (sub-unit 3) — errors never propagate.
14. The branch:
    - **continuation**: `writeSystemPromptMessage` →
      `apply_chat_continuation` (sub-unit 6) → scenario/staff seeding
      with `skipFirstMessage`;
    - **autonomous**: system prompt + scenario/staff seeding, no
      greeting;
    - **normal**: `createInitialMessages` → the scenario/staff seed rows
      over the ported writers → `autoGenerateFirstMessage`.
15. `enrichParticipantSummary` (see "New ports" below).
16. The ad-hoc autonomous **auto-start** (`start_autonomous_room_manually`
    — declined/threw swallowed).
17. The final `status` beat + `finish` (NOTE: v4 never emits the terminal
    `error` frame — hard failures leave the channel to the 60 s TTL; port
    that faithfully).

**`autoGenerateFirstMessage`** (route.ts:578–829) — the route-side ladder
around sub-unit 5: responding participant → connection profile → api key
(empty string when `apiKeyId` null — local providers);
`build_first_message_context` + the recent-conversations block (each
failure swallowed); then the attempt ladder — attempt 1 full context →
retry without memories → the **content-filter Concierge reroute** (the
ported W4.2 `resolve_dangerous_content_settings` +
`resolve_provider_for_dangerous_content`) → the final plain retry.
Returns `''` on every no-can-do path (no profile, no key, all attempts
failed) — the chat is still created.
