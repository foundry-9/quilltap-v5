## Survey-verified starting points (fresh, 2026-08-27)

### v4 — the spec (`lib/services/chat-enrichment.service.ts`)

`ChatListPreloaded` `:30-54` — six maps: `characters`, `files`,
`docMountFileLinks` (id → link-with-content), `projects`,
`memoryCounts` (chatId → n), `conversationChunkCounts`
(chatId → {total, embedded}). The doc comment `:29-37` names the
original symptom (287 chats → ~4000+ queries).

Built in `enrichChatsForList` `:620-685`: sort desc by
`lastMessageAt ?? updatedAt` (`:624-629`); ONE pass collecting
`characterIds` (CHARACTER participants), `projectIds`, `fileIds` (story
backgrounds) (`:631-640`); `characters.findByIds` FIRST (its results

`:642-652`); `renderedChatIds` = only chats with `renderedMarkdown`

(`:662-675`); assemble; `Promise.all` over per-chat `enrichChatForList`.

The six batch queries: `characters.findByIds` (`IN` + ONE batched vault
overlay), `files.findByIds` (story bgs only), `docMountFileLinks.
findByIdsWithContent` (dedups ids; `queryJoined WHERE l.id IN`),
`projects.findByIds` (`IN` + store overlay), `memories.countByChatIds`
(`GROUP BY chatId`), `conversationChunks.countByChatIds`
(`COUNT + SUM(CASE embedding IS NOT NULL) GROUP BY chatId`).

Preload-preferring readers (each with a no-preload fallback):
`getCharacterSummary` `:238-294` (avatar: docMountFileLinks map first,

memoryCount `:571-573`, chunkStats `:576-580`).

**NOT batched even in v4** (stays per-chat): `chats.getMessageCount`
(`:533`) and `enrichTags` (`:531`).

Endpoint order (`app/api/v1/chats/route.ts:849-886`): find → chatType

clean. v4 has a transcribable unit suite:
