  cached block and must stop).
- Id rule `PROGRESSION_ID_PATTERN = /^[a-z][a-z0-9_-]{0,63}$/` (ASCII —
  no JS-regex fidelity question). Cadence grammar `REPORT_FREQUENCY_PATTERN
  = /^(turn|increment|[1-9]\d{0,4}[smhdw])$/`. `TimeIncrement` enum
  `second|minute|hour|day|week|month|year`; `OnComplete` enum `keep|once`.
- Limits: `MAX_PROGRESSIONS_PER_CHARACTER = 32`, `MAX_REPORT_TEMPLATE_LENGTH =
  500`, `MAX_PROGRESSION_NAME_LENGTH = 80`, `MAX_PROGRESSION_DESCRIPTION_LENGTH
  = 500`, `MAX_QUANTITY_UNIT_LENGTH = 16`; every `min`/`max` is Zod 4.5's
  CODE-POINT length (`jsstr::zod_len_*`).
- The record (a `z.strictObject` — unknown keys REFUSE the entry), in v4's
  declaration order: `name` (string 1–80), `description?` (≤ 500),
  `startTime` (ISO instant), `endTime` (ISO instant, strictly after
  `startTime` — a `superRefine` at path `['endTime']`, message `must be
  strictly after startTime`), `timeIncrement`, `percentageReport` (bool,
  default `true`), `reportFrequency` (string matching the grammar, default
  `'turn'`), `quantity?` (`strictObject { total: finite positive number,
  unit: string 1–16, precision: int 0–6 default 1 }`), `reportTemplate?`
  (1–500), `onComplete` (default `'keep'`), `updatedAt?` (ISO instant).
- `IsoDateTimeSchema`: a string whose `parseIsoInstant` is finite; message
  `must be an ISO-8601 date-time with an offset or Z (e.g.
  2026-08-01T00:00:00Z)`. `parseIsoInstant(value)`: non-string → NaN;
  `trim()`; must match `ISO_INSTANT_PATTERN = /^\d{4}-\d{2}-\d{2}[Tt ]\d{2}:
  \d{2}(:\d{2}(\.\d{1,9})?)?([Zz]|[+-]\d{2}:?\d{2})$/` (a SPACE separator is
  admitted, a zone is REQUIRED); then `Date.parse(trimmed)`. v5: the
  `episodic::js_date_parse_ms` twin (`pub(crate)`, the full V8 ISO subset)
  behind the same regex — the space form needs the `format_time.rs`
  space→`T` treatment before it.
- `ProgressionsSchema` = record keyed by the id pattern, refined to ≤ 32
  entries (message `a character may carry at most 32 progressions`).
  `parseProgressions` is the FAIL-SOFT reader (C.2) and never uses the
  record-level refine — it trims the 33rd and keeps 32.
- `parseProgressKey(key)` → `{ok:true,id,field}` | `{ok:false,reason}`; the
  three reasons, byte-exact: `"<key>" names no field — write "<progression
  id>.<field>", e.g. "cannon.complete"` (no dot); `"<id>" is not a
  progression id — lowercase, starting with a letter, then letters, digits,
  _ or - (at most 64)`; `"<field>" is not a progression field name` (field
  must match `/^[a-zA-Z]+$/`). Split at the FIRST dot.
- `WRITABLE_PROGRESSION_FIELDS`, in order: `name, description, startTime,
  endTime, timeIncrement, percentageReport, reportFrequency, onComplete,
  reportTemplate, quantity.total, quantity.unit, quantity.precision,
  remove`. `updatedAt` is NOT writable (the applier stamps it).

### C.2 The engine — `quilltap_core::progressions` (P4.D167 delivers; frozen at its tip)

Module layout: `crates/quilltap-core/src/progressions/mod.rs` (re-exports),
`schema.rs` (C.1 + the typed parse), `engine.rs` (below). Client-safe in
v4 terms = no DB, no tracing, no I/O in this module; the ONE logging reader

Public names (snake_case twins of v4's exports; the SPA twin keeps v4's

- `parse_iso_instant(&Value) -> Option<i64>` (v4 `NaN` ⇔ `None`).
- `parse_progression(&Value) -> Result<Progression, Vec<ZodIssue>>` where
  `ZodIssue { path: Vec<String>, message: String }` and the issue sentence
  joined for `on_issue` is `` `${path.join('.') || '(root)'}: ${message}` ``
  joined by `'; '` — the sentences are Zod 4.5.4's, MEASURED through the
  corpus (unknown key, wrong type, too small/big, invalid enum, invalid
  format, the custom refine). `Progression` is a typed READ struct; the

  as v4 mutates the parsed object, so key order falls out identically —
  no struct round-trip on a write.

  FnMut(&str, &str)) -> Vec<(String, Progression)>` in `Object.entries`
  order, fail-soft: non-object metadata → empty; a non-object
  `progressions` value → `on_issue("*", "the progressions key does not hold
  an object")` (only when the key is PRESENT) → empty; a bad id →
  `on_issue(id, "the id is not a lowercase identifier (a-z, 0-9, _ and -,
  starting with a letter)")`; the 33rd+ → `on_issue(id, "over the ceiling

- `UNIT_MS` (second 1000, minute 60_000, hour 3_600_000, day 86_400_000,
  week 604_800_000, month 2_629_746_000, year 31_556_952_000); the FINER
  unit table (year→month, month→day, week→day, day→hour, hour→minute,
  minute→second, second→none); the period suffixes `s m h d w`.

  `Math.abs`; `"0 <units>"` only when no finer unit or both zero; plural by
  `count === 1`), `format_span_whole(ms, unit)`.
- `derive_progression(id: &str, p: &Progression, now_ms: i64) ->
  DerivedProgression { id, name, start_ms, end_ms, now_ms, elapsed_ms,
  remaining_ms, percent: f64 (UNCAPPED; `spanMs > 0 ? … : 100`),
  percent_clamped, state: Pending|Active|Complete, started, complete,
  quantity_current: Option<f64>, elapsed, elapsed_whole, remaining,
  remaining_whole }` — the display spans differ by state (pending counts
  DOWN to the start; complete counts UP from the end).
- `parse_report_period_ms(&str) -> Option<i64>`.
- `should_report_progression(p, d, last_turn_ms: Option<i64>) ->
  ShouldReportResult { report: bool, reason: ReportReason }` with
  `ReportReason` ∈ `first|updated|transition|silenced|turn|increment|
  period|skip` (`as_str()` gives v4's literal) and v4's SEVEN rules in
  order (`null`/non-finite → first; `updatedAt > lastTurn` → updated;
  state-at-last-turn ≠ state → transition; complete+once → silenced (no
  report); `turn` → turn; `increment` → floor(elapsedAt(now)/unit) ≠
  floor(elapsedAt(last)/unit) ? increment : skip; period → epoch-anchored
  bucket change ? period : skip; an unparseable period → turn).
- `render_progression_report(p, d, &RenderProgressionOptions { timezone:
  Option<&str> }) -> String`: pending → `` `${name}: begins in
  ${remaining}.` ``; complete → `` `${name}: complete; ${elapsed} since it
  finished.` ``; active → `substitute(reportTemplate ??
  default_in_progress_template(p), placeholders)`. `default_in_progress_
  template`: `{{name}}: {{elapsed}} elapsed, {{remaining}} remaining` +
  `, {{percent}}% complete` (if `percentageReport`) + ` ({{quantity}})`
  (if `quantity`) + `.`, prefixed by `description + ' '` when present.
  `progression_placeholders(p, d, opts)` → the eleven keys `name,
  description ('' when absent), elapsed, elapsedWhole, remaining,
  remainingWhole, percent (String(Math.round(percentClamped))), quantity
  (`${current.toFixed(precision)}/${total.toFixed(precision)} ${unit}` or
  ''), start, end, increment`. `substitute` = the plain
  `/\{\{([^}]+)\}\}/g` scan, `trim()` the key, unknown stays VERBATIM.
  ⚠ `start`/`end` = `Intl.DateTimeFormat('en-US', { dateStyle: 'medium',
  timeStyle: 'short' (omitted when the increment is day or coarser),
  timeZone })` → e.g. `Sep 8, 2026, 2:02 PM` / `Sep 8, 2026` — **Node ≥ 20
  renders a U+202F NARROW NO-BREAK SPACE between the minutes and `AM`/`PM`,
  not U+0020; measure the exact bytes on Node 24 and pin them in the
  corpus.** An unresolvable zone falls back to the host's (v5: `jiff::tz::
  TimeZone::get` failure → the host zone). Byte-exact over the corpus.
- `ProgressPrimitive` = Number(f64) | String | Bool (a `serde_json::Value`
  subset). `flatten_progressions(metadata, now_ms, on_issue) ->
  serde_json::Map<String, Value>` (preserve_order): per progression in

- `infer_increment(span_ms) -> TimeIncrement` (thresholds 2 min / 2 h /

- `parse_progress_key(&str) -> Result<(String, String), String>` and
