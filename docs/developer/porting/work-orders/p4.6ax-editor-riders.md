### Item 1 — `__bold__` on-type

v4 has no custom rule: it mounts stock `@lexical/markdown` transformers —
the exact list is `components/chat/lexical/plugins/MarkdownBridgePlugin.tsx:67-87`,
with `BOLD_UNDERSCORE` at `:71` (and `ITALIC_STAR`/`BOLD_ITALIC_STAR`
deliberately excluded, design note `:8-13,60-66`). v5's parser side is
already done (pasted/loaded `__bold__` parses to strong); ONLY the live
input rule is missing. Add one `markInputRule` in `editing-commands.ts`
following the underscore-italic flank pattern at `:90` (non-word left
flank; intra-word `a__b__` must NOT fire), targeting `strong`.
Serialization note: strong serializes as `**`, so `__bold__` normalizes to
`**bold**` on round-trip — that matches v4 (Lexical bold exports `**`) and
the existing gate's parser behavior; pin it in a spec, don't "fix" it.

### Item 2 — the form-field source-mode toggle

**v4 mechanics** (`components/markdown-editor/MarkdownLexicalEditor.tsx`):
`showSourceToggle` prop **default `true`** (`:59-61,:150`) — every form
caller gets the toggle; `showSource` state `:153`; `toggleSourceMode`
`:188-193`; conditional render `:216-238` (`<textarea>` `:217-226`,
controlled off `value`/`onChange` `:219-220`). **The re-parse quirk:**
leaving source mode bumps `sourceLeaveCount` (`:190`) folded into
`composerKey` (`:195`) → `key=` on the composer (`:207`) — v4 force-
remounts the whole Lexical editor because its bridge reads
`initialMarkdown` once. The chat composer's parallel path syncs
explicitly instead (`app/salon/[id]/components/ChatComposer.tsx:302-320`:
leave → `setMarkdown(input)`, enter → seed from `getMarkdown()`). **v5
uses the explicit-sync shape** (the handle already exists); reproduce the
same end state as v4's remount: enter source = textarea seeded from
`getMarkdown()`, leave source = `setMarkdown(textarea)`, textarea edits
emit `contentChange` continuously.

**The toggle button** lives in the toolbar:
`components/chat/FormattingToolbar.tsx:427-451` — rendered only when the
callback is provided; `code` icon in rich mode / `pencil` in source;
`aria-pressed={showSource}`; titles "Edit markdown source" / "Switch to
rich text editor" (carry the strings verbatim).

**Source-mode formatting:** in source mode the toolbar's buttons operate
on the textarea via pure transforms in `lib/chat/text-transforms.ts`:
`sourceApply` `:123-134`, `sourceToggleWrap` `:137-147`,
`sourcePrefixLines` `:150-165`; dispatch branches

`handleDelimiterClick` `:317-331` (the delimiter branch is chat-only —
out of scope here; port the markdown + code-block branches the form
toolbar actually offers).

### Item 3 — the GFM table transformer

**v4:** `components/chat/lexical/transformers/table-transformer.ts`
(259 lines, `MultilineElementTransformer` at `:119`). **Live on every
surface** — in `COMPOSER_TRANSFORMERS` (`MarkdownBridgePlugin.tsx:86`),
used by the bridge, the composer wrapper, the document pane, and
`MarkdownLexicalEditor` (nodes registered `:164-174`). Semantics to carry:

- Import `:137-197`: contiguous pipe rows; requires ≥2 lines with the
  separator row SECOND (`isSeparatorRow` `:75-79`); GFM alignment parsed
  on import (`parseAlignment` `:35-42`); escaped-pipe-aware cell split
  (`splitRow` `:48-70`); `regExpStart` `:124` requires a leading pipe.
- Export `:202-252`: per-column width computed, cells PADDED, separator
  emitted — and **alignment is always written left**
  (`alignments = Array(colCount).fill('left')`, `:232`). The round trip is
  deliberately LOSSY: aligned input → left-align output; unpadded input →
  padded output. Reproduce the lossiness byte-for-byte.
- **There is NO table-insert toolbar button anywhere in v4** (grep for
  `INSERT_TABLE`/commands returns nothing) — tables come only from
  typed/pasted markdown. Do not invent one.

**v5 landing zone:** table nodes into `dialectSchema`
(`markdown-dialect.ts:63-81`), the parse rule into
`buildDialectMarkdownIt` (`:307-320` — markdown-it's built-in `table`
rule is the starting point, constrained to v4's import semantics), and
serializer node handlers (`:372-406`) reproducing v4's export exactly.
Extend the byte-round-trip gate with the recorded table vectors.

### Tier-3 evidence (why `roleplayTemplateId` is not a rider)

v4's template-aware toolbar is chat-only in practice: the toolbar itself
fetches `/api/v1/roleplay-templates/${id}` (`FormattingToolbar.tsx:88-118`,
fetch `:99`) and appends a delimiter button group (`:404-424`, gated
`:373`, narration synth+dedup `:342-372`, apply via
`APPLY_DELIMITER_COMMAND` → `FormattingCommandPlugin.tsx:132-180`); the id
flows from the chat (`SalonView.tsx:729-758,1475,1525,1742`), and **none
of the 20 form-field callers pass it**. v5 has the types
(`core-contract.ts:1667,2719-2812`) and the rendering engine, but the
salon never fetches the chat's template (`chat/message-content.ts:36`
renders with `DEFAULT_RENDERING_PATTERNS`) and the composer has no toolbar
at all. That is a Salon slice (composer toolbar + template fetch + the
delimiter group), not an editor rider.
