## Mandate

Port the **chat administration + tools** half of v4's remaining chat action
surface: eleven dispatch verbs (`regenerate-title`, `add-tag`, `remove-tag`,
`bulk-reattribute`, `merge-conversation`, `update-tool-settings`, `run-tool`,
`rng`, `toggle-agent-mode`, `reclassify-danger`, `render-conversation`). These are dispatch verbs on `quilltap-core`'s boundary; v5 has **no** `?action=`
REST edge for chats (verified: no `chats_routes.rs`; `quilltap-web/src/lib.rs`
registers no `/api/v1/chats` route), so no REST edge is owed and none may be
added.

This lane lands the **server** surface. Most of its UI arrives in a later round
(`p4.9e3`'s dialog family — Merge / Reattribute / BulkReplace / RunTool /
SearchReplace / AllLLMPause / SelectLLMProfile / LibraryFilePicker / ChatRename /
ChatProject), deliberately out of scope here; only `ChatRng` and
`ChatUpdateToolSettings` get a consumer this round, from E1B. **Landing a verb
with no UI is normal for this port** (precedent: P4.6k ∥ P4.6l, P4.9G1) — what
is not acceptable is landing it unverified.

**Must NOT touch:** `apps/web/**` (E1B's), `services/chat_participants.rs` and
`services/chat_avatars.rs` and the eight cast/avatar verbs (E1A's), anything
under `services/backup/`, `services/quilltap_import/` or `services/restore*`
(the coming v4 drift round's).

### Two quirks worth pinning

**`run-tool` has a deny-list.** `run-tool.ts:19-23` refuses
`submit_final_response` and `request_full_context` as non-user-invocable. Port
the set and its error exactly. The request also carries
`private: z.boolean().default(false)` — a whispered run, hidden from the salon
unless "show all whispers" is on and excluded from every character's LLM
context. v5's whisper machinery is ported (`apps/web/src/app/chat/whisper-visibility.ts`,
`services/announcer/`); reuse it.

**`update-tool-settings` sets a third column the client never sends**
(`tools.ts:80-85`): alongside `disabledTools` and `disabledToolGroups` it writes
`forceToolsOnNextMessage: true`, so the next message announces the tool change.
Its response echoes only the two client-sent arrays. Both halves are load-bearing.

### ⚠ Deliberately NOT in this lane: the `TimestampConfigSchema` normalization

P4.d18 recorded a real divergence — v4 re-parses `chats.timestampConfig` through
`TimestampConfigSchema` at the repository write **and** on the chat-UPDATE path,
materializing defaults and refusing bad values, where v5 stores the request JSON
verbatim. It is small and it has a probe-verified spec in P4.d18's unit-2 lane
record.

It is **out of this round** because it straddles the two server lanes' seam: the
repository half lives in `db/chats.rs` (this lane's) and the UPDATE half in
`api/salon.rs`'s `chat_update` (P4.9E1A's, which uses a raw single-column write
that bypasses `db/chats.rs` precisely to stay off this lane's files). Splitting
one normalization across two lanes would guarantee two implementations that
drift. **Do not port it here** — it wants a round that owns both files.

## Shared contract (BINDING)

### §1 — the wire surface (written verbatim and identically in P4.9E1A, P4.9E1B and P4.9E3A)

Added to `Request` in `crates/quilltap-core/src/api/types.rs`
(`#[serde(tag = "type", rename_all = "camelCase")]`), inside a labelled
`// === P4.9E3A: the chat-admin + tools verbs ===` region appended **after**
P4.9E1A's region. E1A owns its own eight variants; this lane owns these eleven.

```rust
/// Regenerate a chat's title from its transcript (v4 `POST …?action=regenerate-title`).
#[serde(rename_all = "camelCase")]
ChatRegenerateTitle { chat_id: String },
/// Attach a tag (v4 `POST …?action=add-tag`).
#[serde(rename_all = "camelCase")]
ChatAddTag { chat_id: String, tag_id: String },
/// Detach a tag (v4 `POST …?action=remove-tag`).
#[serde(rename_all = "camelCase")]
ChatRemoveTag { chat_id: String, tag_id: String },
/// Re-attribute many messages at once (v4 `POST …?action=bulk-reattribute`).
/// `source_participant_id` is v4-`nullable` (explicit null = unattributed);
/// `role_filter` defaults to `"both"`.
#[serde(rename_all = "camelCase")]
ChatBulkReattribute {
    chat_id: String,
    source_participant_id: Option<String>,
    target_participant_id: String,
    #[serde(default)] role_filter: Option<String>,
},
/// Fold another conversation's cast + summary into this chat (v4
/// `POST …?action=merge-conversation`). `chat_id` is the merge TARGET.
#[serde(rename_all = "camelCase")]
ChatMergeConversation {
    chat_id: String,
    source_chat_id: String,
    #[serde(default)] character_ids: Option<Vec<String>>,
    #[serde(default)] outfit_selections: Option<Vec<serde_json::Value>>,
},
/// Replace the chat's disabled-tool sets (v4 `POST …?action=update-tool-settings`).
/// The service ALSO sets `forceToolsOnNextMessage = true`; the response echoes
/// only the two arrays.
#[serde(rename_all = "camelCase")]
ChatUpdateToolSettings {
    chat_id: String,
    disabled_tools: Vec<String>,
    disabled_tool_groups: Vec<String>,
},
/// Operator-initiated tool execution (v4 `POST …?action=run-tool`).
#[serde(rename_all = "camelCase")]
ChatRunTool {
    chat_id: String,
    tool_name: String,
    #[serde(default)] arguments: Option<serde_json::Value>,
    #[serde(default)] character_id: Option<String>,
    #[serde(default)] private: Option<bool>,
},
/// Manual RNG from the composer gutter (v4 `POST …?action=rng`). `kind` is
/// either a die size (integer 2..=1000) or `"flip_coin"` / `"spin_the_bottle"`;
/// `rolls` defaults to 1 (1..=100); `preview` returns without writing a message.
#[serde(rename_all = "camelCase")]
ChatRng {
    chat_id: String,
    kind: serde_json::Value,
    #[serde(default)] rolls: Option<u32>,
    #[serde(default)] preview: Option<bool>,
},
/// Toggle agent mode for this chat (v4 `POST …?action=toggle-agent-mode`).
#[serde(rename_all = "camelCase")]
ChatToggleAgentMode { chat_id: String },
/// Reset and re-queue danger classification (v4 `POST …?action=reclassify-danger`).
#[serde(rename_all = "camelCase")]
ChatReclassifyDanger { chat_id: String },
/// Queue a Scriptorium render with full re-embed (v4 `POST …?action=render-conversation`).
#[serde(rename_all = "camelCase")]
ChatRenderConversation { chat_id: String },
```

**Binding notes.**
- `ChatRng.kind` is `serde_json::Value` because v4's `type` is a
  `z.union([z.number().int().min(2).max(1000), z.enum([...])])`. The field is
  renamed `kind` on the v5 wire because `type` is the enum's own serde tag;
  **this rename is the contract** — E1B sends `kind`.
- `role_filter` stays `String` and is validated in the service against v4's
  enum (`ASSISTANT|USER|both`), reproducing v4's rejection exactly.
- **Response bodies are NOT pinned here.** Each lane defines its own response
  types in its own module; the unifier folds them.
- **E1B's only two dependencies on this lane are `ChatRng` and
  `ChatUpdateToolSettings`.** If either shape must change, it is a cross-lane
  escalation — record it, do not change it unilaterally.
