## Mandate

The llm consult is **DARK in production**. Nothing at the dispatch layer
holds a `CompletionProvider`, so all three entrances — the `run_custom`
executor, the composer's `chatCustomToolRun`, and the workbench bench's
`{live:true}` arm — pass `None` and fall through to
`"no LLM invoker was available in this context"`
(`crates/quilltap-core/src/pascal/custom_tools.rs:1142`). The 60 s timeout
decorator named in the P4.d8 deferral was never built. This lane makes the
consult live: an erased consult seam on `EngineAssembly` following the
`image_generation` idiom, host construction that rebuilds the provider per
request the way `HostImageGenerationRunner` does, a `TimeoutConsult`
decorator shaped exactly like `TimeoutConfirmation`, all three entrances
wired, and a readiness gate that mirrors `ready_memory_embedding`'s loud
not-assembled error so a canned or read-only assembly answers loudly
instead of silently failing soft.

**Say it plainly: after this lane, consults cost real money on all three
entrances.** That is the point — the workbench `{live:true}` bench and a
composer-run `llm` tool become real spend against the user's configured
cheap-LLM provider. §4 forbids any sibling lane in this round from adding a
second provider path, wiring another provider seam, or un-refusing an
LLM-backed verb; P4.9f1's `analyze-image` stays refusal-armed for exactly
this reason.

### The timeout — no decorator exists

The DEFERRAL at `llm_consult.rs:53-61` names the required shape: a host-side
decorator wrapping `CustomToolLlmInvoker` with
`tokio::time::timeout(CONSULT_TIMEOUT_MS, …)`, mapping elapsed →
`LlmInvokeResult::Failed { reason: consult_timeout_reason(CONSULT_TIMEOUT_MS) }`.

**The live precedent to copy is `crates/quilltap-host/src/spine.rs:404-439` —
`TimeoutConfirmation<R>`** (v4's answer-confirmation `withTimeout` family): a
struct holding `inner` + `ceiling: Duration`, a
`tokio::time::timeout(self.ceiling, self.inner.run(...))`, and `Err(_)` →
the ported soft outcome. A `TimeoutConsult<I: LlmInvoker>` follows this
exactly, and lands in the same crate (`quilltap-core` has no tokio timer
driver in its default build — that is why the deferral pointed at the host).

v4 applies its timeout **OUTSIDE** `consult`, at the invoker boundary:
`lib/pascal/llm-consult.ts:159` —
`withTimeout(consult(context, prompt, options), CONSULT_TIMEOUT_MS)` wrapped
in try/catch → `{ok:false, reason:getErrorMessage(error)}` at `:160-162`. So
a v5 decorator wrapping the whole `LlmInvoker` (not the inner consult) is the
faithful shape. v4's `withTimeout` is `:67-84`; it rejects with
`` `the consult timed out after ${Math.round(ms / 1000)}s` `` — the same
string `consult_timeout_reason` already produces.

## The differential requirement, restated

The standing discipline holds without exception: **every ported unit ships an
equivalence test driving v4's REAL `lib/` code** — never a reimplementation,
never inspection. This lane's units are model-dependent, so the tier is
**tier 3 (mocked-LLM): inject the same canned response on both sides, then
tier-2 the writes** (the persisted rows the consult produces — the Pascal
message, the `CUSTOM_TOOL_CONSULT` llm-log row).

Use the recipes already in tree rather than inventing one:
`pascal_run_custom_handler_equivalence.rs:318-339` (entrance (a), the real
invoker over `CannedCompletionProvider`),
`pascal_custom_tools_route_equivalence.rs:287-305` (entrance (b)),
`pascal_custom_tools_execution_equivalence.rs:84-110` (`CannedInvoker`, the
scripted corpus), `pascal_workbench_route_equivalence.rs` (the live bench
case). Pin the completions by **oracle-RECORDED canned keys** — the
`tier3-completion-oracle` memory idea; do not invent a keying scheme.

Two traps this lane must not fall into. First, the existing extension-point
cases pass today *because* the consult never resolves — a green run proves
nothing about the wire until a profile-bearing case exists. Second, corpora
declared separately from the oracle's silently partial-pass: assert the case
COUNT against the oracle's, and run the lane's differentials **by name with
`--nocapture`, grepping for `SKIP`** (`cargo test` hides `eprintln`, so an
unnamed run's SKIP is invisible — the `p4d8` memory).

The timeout message has no v4 export to diff against; it stays pinned by the
in-crate test at `llm_consult.rs:269-304`, and the decorator gets its own
unit test proving the elapsed branch maps to that exact string.
