## The drift, classified (surveyed 2026-08-23, fresh at `a14a1811`)

### Bug 94 — the attachment failure ledger had no reader

Plugins reported dropped attachments in `attachmentResults`; the object
rode the SSE done event to a client that never read it — **"this is why
bug 91 lasted as long as it did."** v4's fix
(`app/salon/[id]/hooks/useSSEStreaming.ts`, +26):

1. The `SSEEvent` type gains
   `attachmentResults?: {sent?: string[], failed?: Array<{id: string,
   error: string}>} | null`.
2. Inside `if (data.done)`, immediately after `setResponseStatus(null)`
   and BEFORE the `inChain` branch:
   ```ts
   const failedAttachments = data.attachmentResults?.failed
   if (Array.isArray(failedAttachments) && failedAttachments.length > 0) {
     const first = failedAttachments[0]?.error ?? 'unknown reason'
     const more = failedAttachments.length > 1
       ? ` (and ${failedAttachments.length - 1} more)` : ''
     showWarningToast(
       `${failedAttachments.length === 1 ? 'An attachment was'
         : `${failedAttachments.length} attachments were`} not sent to the model${more}: ${first}`
     )
   }
   ```
   Surface: a **warning toast**; only the FIRST error text shown, the
   rest counted. Note the `more` suffix sits before the colon. No server
   change in v4 for this bug — the emit predates it.
