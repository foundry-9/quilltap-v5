### v4 — what the commit actually does, server side

- **`lib/chat/scenario-selection.ts` (NEW, 164 lines).** The four-tier
  precedence chain (`scenarioId` > `projectScenarioPath` > `groupScenarioPath`
  > `generalScenarioPath`), free text layered beneath whatever resolves via
  `combineScenarioText`, `undefined` when nothing chosen and nothing typed.
  Every tier fails soft with a `logger.warn` carrying the caller's `logTag`
  (default `'[Scenario]'`; the create route passes `'[Chats v1]'` — so do
  both v5 call sites). The bodies resolve through `findByIdRaw` +
  `resolveProjectScenarioBody`/group/general twins — v5 already has all of
  these on the create path (`crates/quilltap-core/src/services/chat_create.rs`
  holds the inline chain this module replaces).
- **`app/api/v1/chats/route.ts` (−116 lines).** The create route's inline
  chain deleted, replaced by one `resolveScenarioSelection` call. This is the
  refactor half: v5's `chat_create.rs` gets the same extraction into a NEW
  `crates/quilltap-core/src/services/scenario_selection.rs`, and the
  chat-create capstone family must prove the refactor NEUTRAL.
- **`app/api/v1/chats/[id]/actions/scenario.ts` (NEW, 150 lines)** — the
  verb. Key shapes (read the file; highlights):
  - `findCharacterOwningScenario`: searches the WHOLE active cast
    (`type === 'CHARACTER'`, `characterId` present, `status !== 'removed'`)
    for a character whose `scenarios` array holds the id; a character whose
    vault read throws is SKIPPED with a `logger.debug`, never fails the
    change.
  - Body → `setScenarioSchema.parse` (uncaught → the flat `Validation error`
    envelope, per the standing memory note
    `v4-refusal-envelope-parse-vs-safeparse.md`); missing chat → `notFound('Chat')`.
  - `nextScenarioText = resolved ?? null`; **no-op guard**: when
    `nextScenarioText === previousScenarioText` answer
    `{scenarioText, changed: false, message: 'Scenario unchanged'}` — no
    write, no recompile, no announcement (plus a `logger.debug`).
  - Real change: `repos.chats.update(chatId, {scenarioText})` (failure →
    `serverError('Failed to update chat')`), then
    `compileAllIdentityStacks(updatedChat)` in a try/catch whose failure only
    `logger.warn`s (non-fatal — the compiler has a read-through fallback;
    carry the why-comment), then `postHostScenarioRevisionAnnouncement`
    (NOT wrapped — a throw here propagates), then a `logger.info` with
    `{chatId, hadScenario, hasScenario, scenarioLength, source}` where
    `source` is the first-match cascade
    character/project/group/general/custom.
  - Success: `{scenarioText, changed: true, message: 'Scenario updated'}` or
    `'Scenario cleared'` when null.
- **`app/api/v1/chats/[id]/schemas.ts`** — `setScenarioSchema`: six fields,

## Shared contract (BINDING — identical text in `p4.d116-scenario-change-spa.md`)

1. **Verb:** wire name `chatSetScenario`, Rust variant `ChatSetScenario`.
   Request fields, exactly v4's `setScenarioSchema` (all optional AND
   nullable — the absent/null/value tri-state is preserved end-to-end):
   `chatId` (path/id), `scenario: string?`, `scenarioId: uuid?`,
   `projectScenarioPath: string(≤500)?`, `groupScenarioPath: string(≤500)?`,
   `groupScenarioGroupId: uuid?`, `generalScenarioPath: string(≤500)?`.
2. **Success body** (v4 success envelope):
   `{ scenarioText: string|null, changed: boolean, message: 'Scenario
   updated' | 'Scenario cleared' | 'Scenario unchanged' }`.
3. **Error arms:** invalid body → v4's flat `Validation error` 400 envelope;
   unknown chat → v4's `notFound('Chat')` 404; failed write →
   `serverError('Failed to update chat')` 500.
4. **Chat GET** gains `scenarioText: string|null` in its projection.
5. **The SPA reuses the EXISTING scenario list verbs** (general / project /
   group-union / character tiers — already in `api/types.rs` ~:545-838). No
   new list endpoints.
6. **Announcement kind `scenario-change`** rides the existing host-message
   machinery; the client renders it through the existing announcement render
   sites (P4.D116 verifies both sites accept the new kind).
