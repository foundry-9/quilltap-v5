### v4 — `lib/background-jobs/activity-registry.ts` (206 lines, NEW)

- `globalThis`-backed singleton state: `local` counts, `child` counts
  (parent-side mirror), `started` monotonic totals.
  `BLIP_THRESHOLD_MS = 250` — `started[kind]` increments **when a span
  ENDS**, and only if it lasted ≥ 250 ms (a cache hit never blips).
- `beginActivity(kind) -> end` — end is **idempotent** (double-call safe);
  decrement floors at 0 (`Math.max(0, …)`).
- `trackActivity(kind, fn)` — **re-entrant by kind** via
  `AsyncLocalStorage<ReadonlySet<ActivityKind>>`: if an enclosing span (or
  the job handler's own attribution) already accounts for `kind`, the call
  is transparent; otherwise begin + run under attribution + end in
  `finally` (failures still end the span).
- `runAttributedToJob(kind | null, fn)` — attribution WITHOUT a count (the
  job's PENDING/PROCESSING row is already the count); `null` kind passes
  through untouched.
- `getActivityCounts()` = local + child per kind;
  `getActivityStartTotals()` = copy of `started`.
- `applyChildActivityDelta` / `resetChildActivity` / `mirrorToParent` /
  `isJobChild` — the **child-IPC mirror legs. NO-PORT**: v5's job runner
  is in-process (`job_runner.rs:1-54` documents the retired fork/IPC).
  There is one process; `local` is the whole truth and there is no crash
  mirror to zero. Record the non-port with this evidence in the module
  header. The *accounting semantics* (re-entrancy, idempotent end, blip
  threshold, floor-at-zero) are all in scope.
- v4's own suite:
  `__tests__/unit/background-jobs/activity-registry.test.ts` (203 lines)
  — mirror its semantics in the Rust unit tests (nesting same-kind
  collapses, different-kind nests and counts, blip threshold both sides,
  idempotent end, failure still ends).

### v5 — design notes the lane must settle (constraints, not choices)

- **Registry home.** v4 chose a process-global deliberately (single-user,
  single-process). The faithful v5 twin is a `static` (e.g.
  `OnceLock`/atomics) readable from `jobs_list` and writable from any
  service without threading a handle through every signature. An
  engine-owned field would force signature churn across ten call sites —
  don't, unless something already in scope carries it everywhere.
- **Attribution.** v4 uses `AsyncLocalStorage`; the Rust twin is
  `tokio::task_local!` with a `.scope()` around the wrapped future. ⚠
  Trap: task-locals do NOT cross `tokio::spawn`. v5 handlers that spawn
  (e.g. `join_all` resolves) lose attribution inside the spawned tasks —
  survey whether any in-scope wrapped path spawns same-kind work; if one
  does, record the divergence loudly rather than silently double-counting.
- **Job types.** v5 gates 23 type strings at `system_data.rs:609-633`. If
  a real enum exists, make the kind map an exhaustive `match` (v4's
  totality property); if strings, a const table PLUS a unit test asserting
  the table's key set equals the gate list (the mechanical totality twin).

## Shared contract (BINDING — identical text in `p4.d124-realtime-server.md` and `p4.d125-activity-realtime-spa.md`)

**§A The jobs snapshot** (P4.D123 serves it; P4.D125 reads it):

1. `GET /api/v1/system/jobs` (and the dispatch verb behind it) answers,
   ALWAYS: `stats` (unchanged), `activeByKind`, `startedByKind`,
   `processor` (unchanged).
2. `activeByKind` and `startedByKind` are objects with EXACTLY the five
   keys, in this order: `memory`, `embedding`, `summary`, `danger`,
   `image`; integer values ≥ 0. `activeByKind` = PENDING+PROCESSING job
   rows mapped through the kind table PLUS in-flight registry counts.
   `startedByKind` = monotonic per-kind totals of ended spans ≥ 250 ms,
   since process boot (a fresh server answers zeros; the client treats it
   as a delta base, never absolute).
3. `activeByType` is present iff `includeByType=true` OR
   `includeJobs=true` (v4's `includeByType = param === 'true' ||
   includeJobs`); same shape as before this round.
4. The five kind ids above are the server↔client join; chip labels,
   titles, and CSS classes are client-side (P4.D125 transcribes v4's
   `ACTIVITY_CHIPS`, including the `image`→`qt-queue-badge-story`
   badgeClass quirk).

**§B The realtime hint** (P4.D124 emits it; P4.D125 consumes it):

1. A NEW `EventPayload` variant (working name
   `EventPayload::Realtime(RealtimeHint)`) rides v5's EXISTING event
   channel — the engine broadcast → SSE `GET /api/events`
   (`quilltap-web/src/events.rs`) in HTTP mode, → `quilltap://event`
   (`quilltap-tauri/src/events_pump.rs`) in the shell. **No new
   WebSocket endpoint** — this is a documented mechanism divergence from
   v4's `/api/v1/system/realtime/stream` socket, mandated by the locked
   transport-agnostic boundary ("streaming only ever on the Event
   channel"); record it in the round's divergence notes with this
   rationale.
2. Wire bytes (the `Event` flatten): `{"v":1,"topic":"<topic>"}` plus
   `"id":"<id>"` ONLY when scoped (omitted, never null — v4's spread)
   and `"at":<server-ms>`; no `chat_id`/`room_id`/`progress_id` keys.
   `at` is debugging-only — clients must not order, dedupe, or expire on
   it.
3. Topics, verbatim and closed for this round: `jobs`,
   `autonomousRooms`, `chats`, `projects`, `characters`, `mountPoints`.
   The client IGNORES unknown topics (an older tab must survive a newer
   server).
4. The server coalesces per `topic` / `topic:id` with a 250 ms
   trailing-edge debounce. Clients must tolerate BOTH missed hints (any
   (re)connect, SSE `id` gap, or Tauri `quilltap://resync` ⇒ invalidate
   every mapped prefix) and duplicate hints (invalidation is
   idempotent).
5. Client discrimination on the shared stream: a frame is a hint iff it
   carries both `topic` and `v` (chat/creation frames carry `type` /
   their own keys; the server lane verifies the untagged serde round
   trip stays unambiguous).
6. Fallback polling survives everywhere, gated on channel health: every
   migrated site keeps its original cadence wired but returns
   `false`/long while the channel is healthy (v4 decision 5). In the
   Tauri shell the pump is in-process — "connected" is true whenever
   the listener is attached.
