## Mandate

Fix a **real v5 defect**: the `.qtap` import preflight's
exists-checks swallow repository READ errors to "id free"
(`.ok().flatten()`) at TEN sites, where v4 PROPAGATES the error and
refuses the whole import. A preflight that mistakes "the table is
unreadable" for "the id is free" defeats its own purpose — the
preserveIds machinery would then attempt id-carrying INSERTs into a
database it could not even read, and the refuse-on-collision /
skip-if-present semantics silently degrade. The archive service is a
LIVE consumer (rehydrate runs the same preflight). Propagate at all
ten sites, byte-match v4's refusal surface, and pin it with a
planted-unreadable-table differential arm. The lane must NOT touch
anything outside `services/qtap_import/**` + its harness arms — in
particular not `db/connection_profiles.rs` or `qtap_export/**`
(P4.D79), not `character_archive/**` or `chat_enrichment.rs`
(P4.D80).

## The defect, surveyed (escalation record 2026-08-14; sites re-verified at lane start)

The ten swallow sites (line numbers from the escalation — re-verify
before editing, the tree has moved):

- `crates/quilltap-core/src/services/qtap_import/mod.rs:805,826,835,845`
- `crates/quilltap-core/src/services/qtap_import/entities.rs:445,532`
- `crates/quilltap-core/src/services/qtap_import/preview.rs:124,130,148,172`

Each is an exists-check of the shape `repo.find…(id).ok().flatten()`
— a `DbError` collapses to `None` = "id free". v4's counterparts
`await` the repo find and let a throw propagate: the import (or
preview) fails whole, with the error surfaced through the ordinary
import-error envelope. **Survey v4's exact error surface FRESH at
lane start** (which sentence/envelope a thrown find produces on the
import route and on the preview route — do not assume they match each
other), and match it byte-wise per path. Two adjacent traps from the
escalation era:

- The duplicate+preserveIds+name-match oracle arm: the UUID
  normalizer labels minted and claimed ids alike — **compare
  literally** (`uuid-normalizer-blinds-fixture-baked-ids`).
- A planted condition must actually produce the error you think it
  does (`planted-fs-conditions-in-differentials` — the fs-level
  analog; for an unreadable TABLE prefer an in-database plant, see
  Deliverables).
