## Mandate

After a `replace` restore, every restored character points at the vault
the archive restored, every restored project and group at the store the
archive restored, and every project-less file lands in the ARCHIVE's
Quilltap Uploads store — on a target whose built-in pointers match the
archive's AND on a freshly provisioned (or re-minted) target. The
acceptance measure is the standing note's: mount-point count equals the
archive's, no duplicate store names beyond the archive's own, every entity
pointer equal to the archive's with the archive's link count behind it,
ZERO `Quilltap Uploads mount has not been provisioned` warnings. The
fallback arms (an archive with no stores at all; a pointed store MISSING
from the archive) stay v4-convergent: a fresh store is minted exactly as
today. **Must NOT:** change ANY writer byte (`services/backup/collect.rs`,
`marshal.rs`, `manifest.rs`, `restore/archive.rs` — `system_backup_
equivalence` stays green untouched); edit `services/backup/uuid_remap.rs`
/ `uuid_remapper.rs` (byte-proven by `backup_uuid_remap_equivalence`; a
new-account pointer translation, if ever ruled in, lives in the
orchestrator); edit `db/character_vault.rs`, `db/chat_informs.rs`
(the `=== 1` integer decode stays RECORDED), `services/file_storage.rs`,
`services/builtin_mounts.rs`, `services/delete_all.rs`, `db/projects.rs`,
`db/groups.rs`, `db/document_store_overlay.rs`, `services/quilltap_import/
**` (P4.148), `db/fallback.rs` (P4.149 — CALL `error_text`, never edit),
`crates/quilltap-host/**`; re-provision a built-in mount the archive does
NOT carry (a named follow-up — survey §2.5); extend either fix to
`new-account` mode (a named follow-up — the ruling questions in §Rulings);
