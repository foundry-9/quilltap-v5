## Mandate

Port v4's `proactiveRecallTask` end-to-end into the v5 chat spine: every
character turn runs the per-character proactive distill + semantic pre-search
*before* buildContext, the results ride `BuildContextInput`, and a non-empty
pre-search suppresses build_context's fallback distill exactly as v4's
`context-manager.ts:1141-1145` does. The compression half of v4's pre-compute
service is ALREADY PORTED (inline at `orchestrator.rs:1673-1712`, W4.4a4) —
do not move it; this lane adds the sibling task.

This lane must NOT touch: `crates/quilltap-web/**`, `apps/web/**`, the
dispatch surface (`api/types.rs`, `api/engine.rs`), or anything §Ownership
assigns to the sibling lanes. No new wire verbs — this is a spine-internal
port.

- `proactiveRecallTask` (:172-340) — THE PORT TARGET. `ProactiveRecallOutcome

**The windowing algorithm (`messagesSinceLastSpoke`), exact:**

1. Guard (:182): no `cheapLLMSelection` or no `character.id` → `undefined`.
2. `messageEvents` (:185-186): filter `existingMessages` to
   `type === 'message' && 'role' in m && 'content' in m`.
3. `characterMessages` (:189-191): `messageEvents.filter(m => m.role ===
   'ASSISTANT' && m.participantId === characterParticipant.id)` — **keys on
   the participant id, not character.id**.
4. Never spoke (`length === 0`) → `undefined` (:193-195).
5. `lastCharacterMessage = characterMessages[last]`;
   `lastCharacterMessageIndex = messageEvents.lastIndexOf(lastCharacterMessage)`
   (:197-198).
6. `messagesSinceLastSpoke = messageEvents.slice(lastCharacterMessageIndex +
   1).filter(role USER || ASSISTANT)` (:199-201).
7. If `!isContinueMode && content`: push `{role:'USER', content}` — the
   just-saved user message, absent from the snapshot (:205-210).
8. Empty → `undefined` (:212-214).

**The distill leg (:238-260):** emits the `recalling_keywords` status; if
`isChatActiveDangerous(chat)` → `recallSelection =
resolveUncensoredCheapLLMSelection(cheapLLMSelection, true, dangerSettings,
allProfiles)`; message array is a `reduce` that lowercases role and, for
assistants, `stripToolArtifacts(content)` dropping empties; then
`extractMemorySearchKeywords(messages, character.name, recallSelection,
userId, chatId, character.id, {nowIso: new Date().toISOString(),
timelineMode: chat.timelineMode ?? 'realtime'})`. `!success ||
keywords.length === 0` → `undefined` (the whole outcome, signals included).

**The pre-search leg (:267-326):** emits `recalling_memories`; `searchQuery =
signals.paraphrase || signals.keywords.join(' ')`;
`getMemoryRecallSettings()` (:283) → `scopePolicy`, `expandRelated`;
`RecallContext` (:285-294) carries `currentProjectId: chat.projectId ?? null`,
`turnContext: signals.context`, `turnTemporal: signals.temporal`,
`turnRetrospective`, `presentAboutCharacterIds`, `expandRelated`,
`recentlyWhisperedIds: recentlyWhisperedIdSet(chat.commonplaceRecallHistory)`.
Retrospective extra probes (:299-308): the entity join, and
`"{paraphrase} (around {from} to {to})"`. Then
`searchMemoriesSemantic(character.id, searchQuery, {userId, limit: 20,
minImportance: 0.3, recallContext, entityAnchors: signals.entities,
occurredWithin: retrospective ? (signals.timeRange ?? null) : null,
extraProbes})`. On results: `{memories: results.slice(0, 10), signals}`. On
empty **or throw**: `{memories: undefined, signals}` — **signals still flow**
so the retrospective cadence fires.

**Call site + threading:** `orchestrator.service.ts:1017` destructures the
bag; `preSearchedMemories`/`recallSignals` pass into `buildMessageContext` at
`orchestrator.service.ts:1075-1076`; `stopKeepAlive()` at ~:1096. Threading:
`context-builder.service.ts` :71/:73 (input decl), :493-494/:642-643
(pass-through). **Consumption + fallback suppression:**
`lib/chat/context-manager.ts` — options fields :387/:394;
`turnRecallSignals = options.recallSignals ?? null` (:1139); the skip at
**:1141-1145**: non-empty `preSearchedMemories` → `memoryPath =
'pre-searched'`, `dynamicHeadResults = preSearchedMemories.filter(r =>
!archiveIds.has(r.memory.id))`; else the `memorySearchQuery` branch runs the
fallback `slice(-12)` distill (:1146+). `recallSignals` drives the enlarged
retrospective head and mini-recap **on both paths**. Transcribe
`context-manager.ts:1139-1200` carefully at port time — the interplay of
`turnRecallSignals` with the fallback's own distill result is load-bearing.
