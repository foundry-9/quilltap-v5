## The drift, classified (surveyed FRESH 2026-08-14 at `24633026`)

One commit, 32 files, +1,335/−56. The mechanics, from the diff:

- **New table** `help_doc_chunks` (main DB): `id` PK, `docId` →
  `help_docs(id)` ON DELETE CASCADE, `chunkIndex`, `heading` (nullable),
  `content`, `embedding` BLOB (nullable), `createdAt`/`updatedAt`,
  `UNIQUE(docId, chunkIndex)`, index `idx_help_doc_chunks_docId`. DDL is
  in `migrations/scripts/create-help-doc-chunks-table.ts:51-66` and
  `docs/developer/DDL.md` (both byte-agree). v4 registers the repo in
  `repositories/index.ts`, the child writer proxy
  (`child-repositories-proxy.ts` +5), and
  `manager.ts` `registerBlobColumns('help_doc_chunks', ['embedding'])`.
- **Chunking** (`lib/help/help-doc-chunking.ts`, new, 75 l): reuses the
  Scriptorium chunker (`lib/mount-index/chunker.ts` `chunkDocument`)
  with `HELP_CHUNK_OPTIONS = {targetMinTokens: 400, targetMaxTokens:
  700, overlapTokens: 100}` (deliberately smaller than the Scriptorium's
  800–1200). `buildHelpDocChunks(content)` maps to `{chunkIndex,
  heading: headingContext, content}`. `helpChunkEmbeddingText(docTitle,
  heading, content)` = `` `${heading ? `${docTitle} › ${heading}` :
  docTitle}\n\n${content}` `` — the title/heading prefix is added at
  EMBED time only; stored chunk text stays a faithful excerpt.
- **Sync** (`help-doc-sync.ts` +116): on a changed content hash the doc
  is re-sliced wholesale — `repos.helpDocChunks.replaceForDoc(doc.id,
  chunks)` (old rows discarded, never diffed; embeddings refilled by the
  HELP_DOC job the caller already enqueues); result gains
  `chunksWritten`. On prune, `deleteByDocId`. **The backfill**
  (`backfillHelpDocChunks(existing)`): an upgraded instance matches
  every hash so nothing would ever slice — one `count()` query, `> 0` →
  return; else slice EVERY existing doc (`chunks.length === 0` docs
  skipped), then `enqueueHelpDocEmbeddings(ids)` even though the docs'
  own embeddings are present (the job is what fills chunk vectors).
  Whole backfill is try/caught — a failure warns, never blocks help.
- **Embed job** (`embedding-generate.ts` +82): after storing the doc
  embedding, `embedHelpDocChunks` — `findByDocId`, skip chunks whose
  `embedding.length > 0` (cheap retry), skip empty text, per-chunk
  failure LOGGED AND SKIPPED (doc stays findable; next sync/reindex
  retries), outer try/catch too; returns `chunksEmbedded` (logged).
  Deliberately the SAME job — no chunk entity type — so reindex enqueue,
  `embedding_status` bookkeeping, and dimension reconcile all keep
  counting `help_docs` rows, and a chunk can never carry a dimension its
  parent doesn't.
- **Riders:** reindex (`embedding-reindex.ts` +4) calls
  `helpDocChunks.clearAllEmbeddings()` beside the doc clears (comment:
  they clear together or the re-embed pass would skip stale-profile
  chunks). Reapply (`reapply-profile.ts`): `MAIN_DB_TABLES` grows
  `'help_doc_chunks'` (4 → 5). The startup embedding repair
  (`repair-text-embeddings.ts` +3): the table list gains `{table:
  'help_doc_chunks', unit: 'help doc sections'}` + result key
  `helpDocChunksRepaired`. `prettify.ts` +1 is a migration-label string
  (v5 has no migration runner — NO-PORT, record it).
- **Search** (`help-search.ts` +67, `help-search.types.ts` +19):
  `scoreSections(queryEmbedding)` scores every embedded chunk, keeps the
  best per doc (dimension mismatches skipped exactly as for docs; ANY
  failure swallowed — section scoring is an improvement, not a
  precondition). Per doc: `rawScore = best ? Math.max(docScore,
  best.score) : docScore`, and `matchedSection: {heading, content,
  chunkIndex}` is attached **only when `best.score >= docScore`**.
- **Tool handler** (`help-search-handler.ts` +58, `help-search-tool.ts`
  +9): budgets `MATCHED_SECTION_CHARS = 1500`, `DOC_CONTEXT_CHARS =
  600`, `DOC_EXCERPT_CHARS = 1000`; `truncate` appends `...` on cut.
  When a section matched, the context block LEADS with it (get the exact
  block layout — labels, the section heading line, the doc excerpt
  below at 600 chars — from the v4 file at the pin; byte-contractual)
  and the result JSON gains `matchedSection: {heading, content}`. No
  section → the old first-1000-chars shape, byte-identical to today.
- **NOT ported this round** (unported vertical, → the `p4.9i2` bank):
  `app/api/v1/help-docs/route.ts` `?action=search&q=` (min length 2,
  case-insensitive substring over title+content, `buildSnippet` with
  the deliberately lopsided `SNIPPET_LEAD 30`/`SNIPPET_TRAIL 160`,
  markdown-furniture strip, title-hits-first sort) and the Guide client
  (`components/help-chat/HelpGuideTab.tsx`: 200 ms debounce, instant
  title filter on first keystroke, stale-response query tagging;
  `HelpCategorySection.tsx`). Also `help/chat-settings.md` +
  `help/help-chat.md` content deltas → the bank (the P4.D73 precedent).
