## The drift (classified: BEHAVIOR change, one already-ported unit)

v4 `02865bdb` — "fix: strip a trailing 'nothing to add' line from an
otherwise real turn". The whole diff is `lib/chat/turn-manager/
skip-signal.ts` + its unit test (+ README/CHANGELOG/help/package
files). Verified file-by-file: it touches NOTHING in the
files-family/image-gen/SPA surface — the other three lanes are
unaffected, and their P4.6ae survey stays byte-valid at `02865bdb`.

**The behavior change to `detectSkipSentinel`:** previously, if the
FIRST non-empty line was not the sentinel, the function returned `{skip:
false}` (no cleaning). Now it ALSO inspects the LAST non-empty line:
when the first line is real prose AND the message ends with a lone
sentinel line, it returns `{skip: false, cleaned}` with that trailing
sentinel line removed. Weak models narrate a genuine turn and then tack
`[NOTHING TO ADD]` on the end — the narration is kept, but the dangling
sentinel must never reach display / persistence / memory. Bare
sentinels (real passes) and mid-sentence mentions of the phrase are
UNAFFECTED. The sentinel-FIRST arm (already ported) is unchanged, just
restructured.

**The exact new v4 logic** (`skip-signal.ts`, after the change):

- First non-empty line IS the sentinel: trailing all-whitespace →
  `{skip: true}`; else drop the sentinel line → `{skip: false,
  cleaned}` (the EXISTING arm, restructured).
- First non-empty line is NOT the sentinel: walk from the end to find
  the LAST non-empty line; if that line (index `> firstIdx`) is a
  sentinel line, drop it → `{skip: false, cleaned}` (`[...slice(0,
  lastIdx), ...slice(lastIdx+1)].join('\n').trim()`); else `{skip:
  false}`.

**The new v4 unit cases (the authoritative expectations):**

- `'*I stay where I am, my hand on his arm.*\n\n*There is nothing I need
  to add.*\n\n[NOTHING TO ADD]'` → `{skip: false}`, cleaned =
  `'*I stay where I am, my hand on his arm.*\n\n*There is nothing I need
  to add.*'`.
- `'*She nods once and says nothing more.*\n\n**[nothing to add]**'` →
  `{skip: false}`, cleaned = `'*She nods once and says nothing more.*'`
  (the trailing sentinel is stripped even when markdown-wrapped —
  `isSentinelLine` already sheds wrappers).
- `'There is nothing to add here, but I will speak anyway.'` → `{skip:
  false}` (NO cleaning — the phrase is mid-line, not a lone final line).

## The v5 port point (RE-CONFIRMED on main 2026-07-14)

`crates/quilltap-core/src/skip_signal.rs` — `detect_skip_sentinel`
:152-198. The current early-return at :180-182:

```rust
if !is_sentinel_line(lines[first_idx]) {
    return DetectSkipResult::NoSkip { cleaned: None };
}
```

is where the new arm slots in. Restructure to mirror v4: keep the
sentinel-first branch (:184-197) inside an `if is_sentinel_line(...)`;
in the `else` (first line is prose), locate the LAST non-empty line by
walking `lines` from the end down to `first_idx + 1`, and if it is a
sentinel line, return `NoSkip { cleaned: Some(js_trim(&[...before,
...after].join("\n")).to_string()) }`; otherwise `NoSkip { cleaned:
None }`. Reuse the existing `is_sentinel_line` :203 (its wrapper/bracket/
punctuation shedding already handles the markdown-wrapped case) and
`js_trim` — **do not touch `is_sentinel_line`, `js_trim`, or `utf16_len`**
(they are byte-exact leaves; the change is purely the line-selection
logic in `detect_skip_sentinel`). Update the doc-comment (:139-151) to
describe the trailing-sentinel arm, carrying v4's *why* (weak models
narrate then dangle the sentinel).

**Match v4's slice arithmetic exactly:** v4 joins with `'\n'` then
`.trim()` (JS trim — the ported `js_trim`), and selects `lastIdx` as the
last index `> firstIdx` with a non-empty trimmed line. A single lone
sentinel with prose only on the first line, and a sentinel that is the
ONLY non-empty line (already caught by the sentinel-first arm), must
both behave as v4 does — add a Rust unit test for each new v4 case above
plus a regression for the sentinel-first arm and the mid-line
non-match.
