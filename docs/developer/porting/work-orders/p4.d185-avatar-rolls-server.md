### C.1 `chats.transcriptVersion` (P4.D182 ensures; P4.D183 bumps, reads and projects; P4.D187 reads)

  boot ensure ONLY (`db/chats_transcript_version_repair.rs::
  ensure_chats_transcript_version_column`, wired in `host.rs` after the
  P4.D171 blocks). It is NOT in `fresh_schema.json` (v4's `generateDDL`
  never emits it — §R.5(a)), NOT a field of `ChatUpdate`, NOT read by
  `chats_read::marshal_row` (the 100-column census does not move), NOT in
  any `.qtap` chat record, backup or restore reader, NOT remapped, NOT
  exported. Existing rows read `0`.
- **Writer:** exactly ONE — `ChatMessagesRepository::announce_transcript_
  change(chat_id)` (pub): an atomic `UPDATE chats SET transcriptVersion =
  transcriptVersion + 1 WHERE id = ?` (v4's `$inc`; a failure is
  swallowed with v4's `Failed to bump transcript version` warn and the
  publish still fires), then `tracing::debug!("Transcript change
  announced", chatId)`, then `publish_realtime(RealtimeTopic::Chats,
  Some(chat_id))`. A private `commit_transcript_change(chat_id, chat,
  update)` wraps "the bookkeeping `ChatsRepository::update` when `chat`
  exists AND the patch is non-empty, then ALWAYS announce".
- **Reader:** `ChatsRepository::get_transcript_version(chat_id) -> i64` —
  a raw single-column read, `0` when the row is missing, the cell is
  NULL, or the read fails.
- **Chat GET (`chatGet` → `ChatDetail`):** `transcriptVersion: number`

  in the key order the `salon_reads` family compares). SPA type:
  `ChatDetail.transcriptVersion?: number` (optional — a server without

### C.2 The transcript verb + the messages edge (P4.D183 ↔ P4.D187)

- **Verb `chatTranscript`** — `Request::ChatTranscript { chat_id: String,
  known_version: Option<serde_json::Value> }` (wire `{ type:
  'chatTranscript', chatId, knownVersion? }`). The handler applies v4's
  gate: `knownVersion` counts only when it is a JSON number that is an
  integer (JS `Number.isInteger`); anything else (absent, null, a float,
  a string) reads as "no known version" — a full read, never an error.
- **Response `CoreResponse::ChatTranscript(Value)`** — the BARE body:
  `{ unchanged: true, version: number }` when `knownVersion === version`
  (nothing else is read or projected — the version is read BEFORE the
  projection, never after); otherwise `{ unchanged: false, version:
  number, messages: [...], offSceneCharacters: [...], count: number }`
  where `messages`/`offSceneCharacters` are byte-identical to the chat
  GET's (ONE projection function feeds both — C.1's neutrality proof).
  Key order as listed.
- **Refusals:** a missing chat → 404 `Chat not found`; a projection
  failure → 500 `Failed to read transcript` (+ v4's `[Messages API v1]
  Error reading transcript` error line, `{chatId}` + the error).
- **REST (NEW `crates/quilltap-web/src/messages_routes.rs`, registered
  at `/api/v1/messages`):** `GET /api/v1/messages?chatId=<id>&action=
  transcript[&knownVersion=N]` → the body above; `chatId` missing → 400

  Action { character_id: String, file_id: String, action: String }`
  with `action ∈ { "save-to-album", "set-avatar" }` → `CoreResponse::
  CharacterAvatarRollAction(Value)`: `{ linkId: string, alreadyInAlbum:

  boolean }` for `set-avatar`. Set-avatar ALWAYS goes through
  save-to-album first (idempotent) and points `defaultImageId` at the
  album LINK id, never a `files` id.
- **Verb `characterAvatarRollDelete`** — `Request::CharacterAvatarRoll

  false` (not a roll of this character) answers 404 `Avatar roll not
  found` at the edge. Order: scrub `chats.characterAvatars` → the
  character's `defaultImageId` (legacy files-id shape only) +
  `avatarOverrides` → the roll's OWN link via `delete_with_gc` (never
  the album's; never `delete_mount_blob`) → `files.delete`.
- **Error ladder (both action verbs + delete, measured from v4's
  `respondToError`):** message starts with `Character not found` → 404
  `Character not found`; starts with `Avatar roll not found` → 404
  `Avatar roll not found`; contains `no linked database-backed vault` /
  `not an image` / `empty bytes` / `already in` → 400 with the message;
  else 500 with the message + v4's `[Characters/AvatarRolls v1] Avatar
  roll action failed` error line.
- **REST (`characters_routes.rs`):** `GET /api/v1/characters/{id}/avatar-
  rolls?limit=&offset=` (Zod: `limit` int 1..=200, `offset` int ≥ 0;

  `{ error: 'Action parameter required', availableActions: [...] }`;
  unknown → 400 `{ error: 'Unknown action: <x>', availableActions:
  [...] }`); `DELETE /api/v1/characters/{id}/avatar-rolls/{fileId}`
  (`!id`/`!fileId` → 400 `Missing character id` / `Missing avatar roll
  id`). Guard order: auth → id presence → action → service → the ladder.
- **Log lines (info, byte-exact):** `[AvatarRolls] Roll copied into the
  photo album` `{characterId, fileId, linkId}`; `[AvatarRolls] Roll
  promoted to the character portrait` `{characterId, fileId, linkId,
