## The drift, classified (surveyed FRESH 2026-08-12 at `03154b72`)

`db195fba` extends all three completion templates
(`packages/quilltap/lib/completion/{bash,fish,zsh}.template`) with the
`db characters` sub-subverb family that P4.D66 shipped (`status archives
archive rehydrate export`) and its flags (`--instance --data-dir
--passphrase --json --limit --diverged --blocked --id --write -p/--port
--out --help`):

- **bash**: a new `elif [[ "$subverb" == "characters" ]]` branch inside
  `_quilltap_complete`'s db handling (verbs vs `char_flags` on `-*`).
- **fish**: a `db characters sub-subverbs` block of six `complete -c
  quilltap -n '__quilltap_using_subverb db characters' …` lines (five
  verbs + the `-l port -s p` flag).
- **zsh**: `_quilltap_db` gains an early `return` after the
  `(( CURRENT == 2 ))` `_describe`, then a full
  `[[ "$words[2]" == "characters" ]]` branch (`char_verbs` described at
  `CURRENT == 3`, `char_opts` via `_arguments` — including
  `_quilltap_instance_names` and `_files` actions).

v5's templates (`crates/quilltap-cli/src/help/completion/*.template`,
re-ported at P4.D33) list `characters` as a db verb but carry **none** of
the sub-subverb machinery — verified at planning (zsh has only the
one-line verb entry; bash's `db_verbs` string names it with no branch;
fish has the verb line and the top-level `--diverged`/`--blocked` flags
only). The P4.D66 CLI family landed the subcommands themselves; the
completions never followed because v4 hadn't written them yet — this
commit is v4 catching up to its own 4.8.0 feature, and v5 mirrors it.
