### New Request variants (wire `type` names; Rust mirrors in PascalCase)

Courier + chat images (lane A builds, lane B consumes):
- `messageResolveExternalTurn {chatId, messageId, replyContent}` →
  v4's resolve envelope (pinned by lane A's oracle; the settled turn
  re-enters the chain server-side)
- `messageCancelExternalTurn {chatId, messageId}` → v4's cancel
  envelope (pinned)
- `messageSaveImage {chatId, messageId, fileId, mountPointId,
  caption?}` → `{data: {mountPoint, relativePath}}`
- `chatPhotoAlbums {chatId}` → `{albums: AlbumOption[]}` (option shape
  pinned by lane A's oracle)
- `chatAddToolResult {chatId, tool: 'generate_image', initiatedBy,
  prompt, images}` → the created tool-result message echo (pinned)
- `chatFilesList {chatId}` → v4's chat-file list shape (pinned)
- `chatFileDelete {fileId}` → v4's `/chat-files/[id]` DELETE shape
  (pinned)
- `imageProfileGenerate {imageProfileId, prompt, chatId?, count?}` →
  `{success, data: [{id, filename, filepath, mimeType}],
  expandedPrompt}` — the EXISTING refusal-armed variant goes LIVE
  (lane A tier 2); `imageProfileValidateKey` / `imageProfileListModels`
  stay refusal-armed.

REST leg (web edge, lane A): `POST /api/v1/chats/{id}/files` multipart
(fields `file`, `resolution?`, `conflictingFileId?`) → `{file}` |
`{duplicate, conflictType, existingFile, newFile}` | `{error}` — the
P4.6m multipart precedent (base64 CoreRequest `chatFileUpload` at the
edge; the JSON verbs all ride `POST /api/dispatch`).

Autonomous rooms (lane C builds and consumes; listed here so names
never collide):
- `systemAutonomousRooms {}` → `{rooms: Room[]}` (v4 sort:
  running→idle→paused→budgetExhausted→stopped→error, then updatedAt
  desc)
- `chatAutonomousRoomStatus {chatId}` → the status snapshot
- `chatAutonomousRoomStart {chatId}` → `{runId, jobId}`
- `chatAutonomousRoomPause {chatId}` → `{paused: true}`
- `chatAutonomousRoomStop {chatId}` → `{stopped: true}`
- `chatAutonomousRoomResume {chatId}` → `{runId, jobId}`
- `chatAutonomousRoomUpdateSettings {chatId, settings}` (v4
  `updateSettingsSchema`: every cap nullish so the modal can CLEAR
  values; ms units) → `{updated: true, clampedDestructive}`

Envelope rule: variant and param NAMES are binding at name level;
exact response envelopes/nullability are pinned by the owning lane's
oracle (expect the P4.6p pattern — route reads may omit null nullables
while mutations echo them AS null) and reconciled name-for-name at
unification.
