## Shared contract (binding — identical in P4.6bi)

The character `canChooseOutfit` field is the meeting point between this
server lane and the SPA lane. Name-level, binding both ways:

1. **Character read shape.** The character GET (`/api/v1/characters/:id`)
   and list (`/api/v1/characters`) responses include
   **`canChooseOutfit: boolean`** (never null — default `false` when the
   vault omits it). The SPA reads this field name verbatim.
2. **Character PUT accepts** (all optional; omitted keys unchanged):
   - **`canChooseOutfit: boolean`** — vault-routed (`properties.json`).
   - **`canDressThemselves: boolean | null`** — DB column tri-state;
     explicit `null` is preserved (inherit-global), never stripped.
   - **`canCreateOutfits: boolean | null`** — DB column tri-state; same
     null semantics.
3. **Defaults / hydration.** A character whose vault `properties.json`
   lacks `canChooseOutfit` hydrates as `false` (no migration, no
   backfill). Freshly scaffolded vaults write `canChooseOutfit: false`.

The SPA lane (P4.6bi) may proceed against this contract before this lane
lands — it depends only on these names/types, not on this lane's internal
wiring.
