## Survey-verified starting points (2026-07-27 — from the `e8a49597` diff itself)

### What v4 changed (all in `app/api/v1/chats/[id]/custom-tools/route.ts`)

1. **`operatorCharacterIds(participants, activeTypingParticipantId)`** (new,
   :179–207): the operator's characters in preference order — filter to
   `type === 'CHARACTER' && controlledBy === 'user' &&
   isParticipantPresent(status ?? 'active')` (a **removed participant is not a
   candidate**), then the participant named by `activeTypingParticipantId`
   first, then the rest in stored order; returns `characterId`s.
   (`isParticipantPresent` / `ParticipantStatus` imported from
   `@/lib/schemas/types` — v5's analog already exists from the P4.9E1A cast
   work.)
2. **`preferOperator(candidates, characterIdOf, operatorIds)`** (new,
   :209–232): first candidate matching an operator id, in operator-preference
   order, `isOperator: true`; else `candidates[0]` with `isOperator: false`.
3. **`handleList`'s single-variant arm** (was `sightings[0]`; v5 analog
   `custom_tools.rs:293`): now `preferOperator` over the sightings, and the
   row's label becomes
   `isOperator || perspectives.length === 1 ? undefined : chosen.perspective.characterName`
   — i.e. **unlabelled when it runs as the operator or the room has one
   character; otherwise the row names who it will run as** ("as Friday").
4. **`characterLabel`'s doc contract widened** (:83–88): no longer "set only
   on per-character variants" — now also set on a shared tool that fell back
   off the operator's characters. Absent means "runs as you", or a
   one-character room.
5. **`handleRun`'s `asCharacterId`-less fallback** (was `perspectives[0]`; v5
   analog `custom_tools.rs:411`): now the same
   `preferOperator(perspectives, …, operatorCharacterIds(…)).chosen` — so
   "arbitrary" means the same thing in both places.
6. **Unchanged on purpose — do not touch:** `run_custom`'s mid-turn path
   (reads `context.characterId`) and per-variant rows (still run as the
   character on their label).

v4 also added `__tests__/unit/app/api/v1/chats/custom-tools-perspective.test.ts`
(366 lines) — a mock-based unit test. **Port its CASES into the differential,
not its mocks**: the preference (own character, active-typing first), the
fallback label, the two paths that must NOT start preferring the operator.
