## Survey-verified starting points (2026-07-31)

**v4 (at `ff12f491`):**

- **The repo delete** —
  `lib/database/repositories/llm-logs.repository.ts` `cleanupOldLogs`
  (~:368): `retentionDays < 0` → `logger.warn('Invalid retention days')` +
  return **0** (note `< 0`, not `<= 0` — the zero guard lives in the
  handler); cutoff via **local calendar-day arithmetic**
  (`cutoffDate.setDate(cutoffDate.getDate() - retentionDays)`, NOT
  `now − N×86400000` — they differ across a DST boundary); delete where
  `userId` AND `createdAt: { $lt: cutoffDate.toISOString() }`; returns the
  count; `logger.info` on completion. Runs on the **llm-logs partition**.
- **The handler** — `lib/background-jobs/handlers/llm-log-cleanup.ts`
  (73 LOC), semantics in order:
  1. payload `{ userId, retentionDays? }`;
  2. `retentionDays` undefined → `chatSettings.findByUserId(job.userId)`;
     settings row MISSING → `logger.warn` + return (job completes);
     else `llmLoggingSettings?.retentionDays ?? 30`;
  3. `retentionDays <= 0` → return (keep forever);
  4. **a SECOND settings fetch runs unconditionally** (even when the
     payload carried `retentionDays`): `chatSettings && !enabled` → return.
     ⚠ Note the asymmetry: on this second fetch a MISSING settings row does
     NOT bail — cleanup still runs. Carry it faithfully.
  5. `cleanupOldLogs(job.userId, retentionDays)`; success →
     `logger.info`; error → `logger.error` + **rethrow** (the job runner
     records the failure).
- **Registration** — `lib/background-jobs/handlers/index.ts:45`
  (`LLM_LOG_CLEANUP: handleLLMLogCleanup`).
- **The enqueue path** — `lib/background-jobs/queue-service.ts:832`
  (`enqueueJob(userId, 'LLM_LOG_CLEANUP', payload, options)`), driven by
  the scheduled cleanup (`lib/background-jobs/scheduled-cleanup.ts`).

**Clock/TZ hazard (the P4.d26 lesson):** the calendar-day cutoff is
LOCAL-time arithmetic. A TZ=UTC-only differential is structurally blind to
the DST/zone behavior — the family needs a UTC leg AND an America/Chicago
leg whose cutoff crosses a DST boundary, with the clock pinned on both
sides (jest fake timers in the oracle; the harness's fixed-clock convention
in Rust — see `chain-depth-frozen-clock-artifact` for the tick discipline).

   (the `jest-real-db-oracle` recipe, Node 24, fake clock pinned); the Rust
   side runs the ported handler through the job runner; diff the post-state
   llm-logs partition AND the `background_jobs` rows (the
   `memory_pipeline_jobs` shape). ⚠ Cleanup MUTATES the fixture — both
   sides run against /tmp COPIES of the committed DBs (the standing rule,

   the minted `background_jobs` rows INCLUDING payload bytes — this pins
   finding #41's `7`-not-`7.0` fix at the differential level and closes the
   coverage hole that let it ship.
