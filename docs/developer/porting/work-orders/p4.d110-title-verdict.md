## The drift, classified (surveyed 2026-08-23, fresh at `0ba942b1`)

v4 `3c041e46` "fix(titles): a misspelled key stops silencing the auto-titler
(bug 96)". A cheap model answered `needsNewTitle: true` with the title under
`suggestTitle` (two letters short of `suggestedTitle`); reading the canonical
key alone + `|| null` coerced it away, the handler folded
decline / unreadable / agreed-but-unfindable into one silent branch, the
checkpoint cursor advanced, and no story background ever generated (it is
queued only from the rename-succeeded branch). **A behavior change on a ported
surface** (P4.6ao's consideration tasks + the title-update job handler).

**⚠ A commit-prose trap, settled by measurement at planning:** the commit
message says "only the first justifies advancing the checkpoint cursor, and
all three did" — but the SHIPPED v4 fix does **not** restructure cursor
advancement. All three no-rename outcomes still advance
`lastRenameCheckInterchange` (title-update.ts:204–210, with the in-code
comment at :190–194 saying so); the fix (a) shrinks the third set via the
tolerant parser and (b) makes the residue loud via warns. Port the shipped
behavior, not the prose.

### What v4 shipped (post-commit line numbers, `git show 3c041e46:<path>`)

1. **NEW `lib/memory/cheap-llm-tasks/title-verdict.ts`** (164 lines):
   - Exports: `interface TitleVerdict { needsNewTitle: boolean; reason:
     string; suggestedTitle: string | null }` (:22),
     `MAX_TITLE_LENGTH = 60` (:29),
     `parseTitleVerdict(content, taskLabel, chatId?)` (:103–164).
   - `TITLE_KEYS` (:40–46), canonical first:
     `'suggestedTitle'`, `'suggestTitle'`, `'newTitle'`, `'proposedTitle'`,
     `'title'`.
   - `foldKey` (:49–51): `key.toLowerCase().replace(/[^a-z0-9]/g, '')`.
   - `readTitleKey` (:59–80): **pass 1** walks `TITLE_KEYS` in order over the
     literal keys, accepting the first value that is neither `undefined` nor
     `null` (an explicit-`null` canonical key falls through); **pass 2**
     builds a `Map<foldedKey, firstActualKey>` over `Object.keys(parsed)`
     (**first occurrence wins on fold collisions**, :67–71), then walks
     `TITLE_KEYS` in order again via `folded.get(foldKey(key))`, same
     non-undefined/non-null check. Both passes iterate canonical-first —
     that ordering IS the precedence rule when several keys are present.
     Returns `{ value, key: actualKey }` or null.
   - `normalizeTitle` (:83–91):
     `raw.trim().replace(/^["']/, '').replace(/["']$/, '').trim()` — note the
     **second trim**, which the old inline parsers (and v5 today) lack; empty
     → null; over 60 → `substring(0, 57) + '...'`.
   - Outcomes: JSON.parse throws → warn + `{needsNewTitle: false, reason:
     'Failed to parse response', suggestedTitle: null}` (:108–119); parsed
     but not a non-null non-array object → warn + same verdict (:121–128);
     object → `needsNewTitle = record.needsNewTitle === true` (strict, :131);
     `reason` accepted only when `typeof === 'string' && record.reason.trim()`
     truthy — returns the **untrimmed** original — else `'No reason provided'`
     (:132–134; stricter than the old `||` chain, which accepted any truthy
     value); `suggestedTitle` from `readTitleKey` only when
     `typeof found.value === 'string'` (:139), through `normalizeTitle`.
     A genuine decline still extracts a present title, with no warn.
     Agreed-but-unreadable warns but still returns
     `{needsNewTitle: true, …, suggestedTitle: null}` — the handler decides.
   - **The four warn arms, byte-exact** (all `logger.warn`, all
     `context: 'cheap-llm-tasks.title-verdict'` — P4.49 makes these land in
     `combined.log`, so the strings are operator-visible surface):
     - :112 `'[Title Verdict] Response was not JSON — keeping the current
       title'` (meta `taskLabel`, `chatId`, `contentPreview:
       content.slice(0, 200)`)
     - :122 `'[Title Verdict] Response JSON was not an object — keeping the
       current title'` (meta `taskLabel`, `chatId`)
     - :142 `'[Title Verdict] Title arrived under a non-canonical key'`
       (meta `taskLabel`, `chatId`, `actualKey`, `expectedKey:
       'suggestedTitle'`) — fires only when the normalized title is non-null
       AND `found.key !== 'suggestedTitle'` (:141)
     - :155 `'[Title Verdict] Model asked for a rename but supplied no usable
       title'` (meta `taskLabel`, `chatId`, `responseKeys:
       Object.keys(record)`)
