## The drift, classified (surveyed 2026-08-20, fresh at `c8a3cf77`)

A behavior-change feature landing squarely on ported surfaces: the
memory-search spine (`searchMemoriesSemantic`), the vault
conversation-summary search, the proactive pre-compute path
(`runPreContextPreCompute` → `buildMessageContext` → `buildContext`),
the consolidated Commonplace Book whisper, the retrospective mini-recap,
the fold-triggered `relevant-conversations` refresh, instance settings,
and the memories API. **No schema change** — the new setting rides the
existing `instance_settings` bag (`memoryRecall`), so no D23 re-dump.

The feature: a new instance-wide setting
`memoryRecall.perTurnConversationSummaries` (off by default, **no
chat/project/character override by design**) re-runs the
relevant-past-conversations search over the responding character's vault
`Conversation Summaries/` folder EVERY turn and folds the result into
the consolidated whisper's `relevantConversations` part. It costs **no
extra embedding call**: `searchMemoriesSemantic` reports the vector it
embedded through a new `captureQueryEmbedding` hook, and
`searchVaultConversationSummaries` accepts it as `precomputedEmbedding`.
With no vector available (memories skipped, failed embedding,
text-search fallback) the cadence **sits the turn out** rather than
embedding on its own. Dedup: the per-turn list filters against the
standing fold-posted `relevant-conversations` whisper, the retrospective
mini-recap now filters against BOTH, and the cadence stands down
entirely on recap turns. The list-length ramp constants (3→10 over
4K→32K) move into `lib/memory/conversation-summary-search.ts` so both
cadences read the same numbers.
