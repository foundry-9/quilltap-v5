## Preamble

- **Not a v4 port.** `DbError` is a v5-invented taxonomy; v4 has no
  analog and no oracle drives it. The differential obligation here is
  **inverted**: prove that no v4-comparable byte moved (wire bodies,
  fixed sentences, corpus rows), not that new bytes match v4.
- **Origin:** dogfood finding #96 (2026-08-19, the owed pass on the
  Friday copy; `dogfood-findings.md` row 96): a provider failure was
  logged as `key derivation failed: primary stream failed: HTTP 500 …`.
  Nothing about the failure involves key derivation. Reproduced twice (a
  500 and a 400). It matters because P4.49 just made `combined.log` the
  place an operator looks after a failed turn — and the first sentence
  they find there lies about the cause.
- **Drift-check at lane start** (standard: both v4 branches, verify the
  checkout). v4 movement does not block THIS lane (no oracle regen
  needed), but report it.
- **Worktree:** per the `carryout` skill.

  key from the pepper failed" but is constructed at **246 sites**
  workspace-wide (`ggrep -rn "DbError::Key(" crates/ | wc -l`), the
  overwhelming majority as a generic string catch-all: serialize/parse

  (`enclave/step.rs:1789`), and more.
- `db/mod.rs:161` — the `Display` prepends `"key derivation failed: "`,
  so every one of those sites lies in any surface that renders the error.
- Where the string goes: `api/types.rs:3676-3687` `db_error_response`
  maps every non-`StoreUnavailable` `DbError` to

## Mandate

Split the catch-all out of `Key` so error text stops lying, with **zero
observable change on any v4-pinned surface**. One new variant, KISS:

- Add `DbError::Internal(String)` (name final unless the lane finds a
  concrete reason to differ — record it) whose `Display` is the bare
  message (`write!(f, "{msg}")` — the same shape `StoreUnavailable`
  already uses). No prefix: these sites composed their own sentences
  assuming they'd be read as-is.
- Migrate every non-key `DbError::Key(...)` construction site to
  `Internal`. Mechanical where possible, but **classify per site** —
  produce the census (site → kept-Key | Internal, with the dozen-ish
  kept-Key sites justified one line each) in the lane record. Do NOT
  invent additional variants or per-domain taxonomies (YAGNI — the
  finding demands the sentence stop lying, nothing more); note candidate
  future splits if the census suggests them, don't do them.
- `db_error_response` and every `impl From<DbError>` shim (the survey
  found ~10: `tools/terminal.rs:92`, `tools/wardrobe_create.rs:224`,
  `db/scenarios.rs:170`, `db/chats_participants.rs:65`,
  `db/database_store.rs:92`, `db/document_store_overlay.rs`,
  `db/text_replacement_rules.rs`, `db/vault_wardrobe_public.rs`,
  `documents/mod.rs`, `photos/*_gallery_service.rs` — enumerate fresh)
  gain the `Internal` arm; map it wherever the `Key` catch-all mapped
  (behavior-preserving modulo the dropped prefix).
- Must NOT touch: the on-wire fixed sentences (v4's exact 400/404/500/503
  bodies pinned across many families), the `StoreUnavailable` machinery,
  `ErrorKind` (the boundary enum stays as-is — `Internal` maps to
  `ErrorKind::Internal` exactly as `Key` did).
