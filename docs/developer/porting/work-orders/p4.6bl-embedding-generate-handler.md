## Mandate

Port v4's **EMBEDDING_GENERATE background-job handler** — the 490-LOC
`lib/background-jobs/handlers/embedding-generate.ts` over all four entity types
(`MEMORY`, `CONVERSATION_CHUNK`, `HELP_DOC`, `MOUNT_CHUNK`) — register it live
in the production spine, and **heal the backlog** the missing handler has been
accumulating.

This is dogfood **finding #35** and the round's headline: both enqueue families
are live in v5, no handler is registered, every job retries three times and
dies. On the Friday copy that is **2,088 DEAD rows**, a console warning every
few seconds, and — the real damage — **every chunk and memory written since v5
took over the instance is unembedded**, so semantic search over new content
silently finds nothing. The embedding *provider* seam already exists and is
wired live (`EngineAssembly.memory_embedding`, since P4.6s), so this is a
handler port over an available capability, in exactly the shape P4.6bj
established for `MEMORY_EXTRACTION` / `CONTEXT_SUMMARY`.

**Port `isPermanentEmbeddingError` and the oversize/empty pre-flight guards
with it, deliberately.** v4's own doc comment (lines 19–27) records the
motivating incident: tens of thousands of DEAD rows from deterministic
failures being retried forever. A port that omits the classifier inherits that
bug on day one — and v5 has already demonstrated it can mint 2,088 dead rows
from a related gap in a single day.

**Must NOT touch:** `apps/web/**` (P4.9E3C's); `services/chat_*.rs`,
`db/chats*.rs`, `api/salon.rs`, and any new tools-inventory / chat-export
module (P4.9E3B's). The existing refusal arms this lane un-arms
(`engine.rs:2661–2668`) are this lane's to edit; nothing else in another
lane's labelled regions.

**⚠ The missing-entity handling is asymmetric — reproduce it verbatim.**
MEMORY (:131), HELP_DOC (:332) and MOUNT_CHUNK (:419) call
`markAsFailed(…, '<X> not found')`; **CONVERSATION_CHUNK just logs and returns
(:242–249) with no `markAsFailed`.** This is exactly the kind of quirk a port
"cleans up" and thereby breaks equivalence.

**`isPermanentEmbeddingError` (:28–38)** — lowercases the message; permanent on
any substring hit: `'nan'` · `'non-finite'` · `'exceeds the context length'` ·
`'maximum context length'` · `'cannot embed empty input'` ·
`'dimension mismatch'`. In every catch block the handler *first* calls
`markAsFailed(entityType, entityId, profileId, errorMessage)`, then:
**permanent** → `logger.warn` + `return` (the job COMPLETES — never retried,
never DEAD; :209–217, :292–301, :381–389, :471–479); **transient** →
`logger.error` + `throw` → queue retries to `maxAttempts: 3` → DEAD.
`"fetch failed"` / timeouts / connection resets deliberately do **not** match.

**`skipIfOversize` (:49–96)** — two deterministic-unembeddable pre-flight
guards, both → `markAsFailed` + bail without throwing:
1. Empty/whitespace (:59–75): reason `'Empty input — nothing to embed'`.
2. Oversize (:77–95): `text.length > EMBEDDING_MAX_CHARS` → reason
   `` `Oversize: ${text.length} chars exceeds ${EMBEDDING_MAX_CHARS}-char cap` ``.

`EMBEDDING_MAX_CHARS = 128 * 1024` — `lib/embedding/embedding-service.ts:74`.
**⚠ This constant is not ported anywhere in v5** (zero hits) — introduce it;
it is the single most load-bearing constant for avoiding the DEAD-row
incident.

**Payload** — `lib/background-jobs/queue-service.ts:126–137`:
`{ entityType, entityId, characterId? (memories only), profileId, chatId?
(conversation chunks only) }`. No batching in the handler — one entity per
job (batching lives in reindex's fan-out, `embedding-reindex.ts:25`
`BATCH_SIZE = 200`).

**Registration** — `lib/background-jobs/handlers/index.ts:46`; `getHandler` at
:69–75. `maxAttempts` default **3** (`queue-service.ts:447`). Enqueue helper
