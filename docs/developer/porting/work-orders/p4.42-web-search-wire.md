## Mandate

Wire the existing `RealWebSearchProvider` into production so that with
`SERPER_API_KEY` set (or an active SERPER api-key row), `search_web`
actually executes on **every** tool-running surface: the in-chat turn
(native + text tool loops), Carina/ask_carina, the Brahma Console, and
the operator Run Tool modal. Close the latent
advertised-vs-refusing inconsistency: today
`web_search_configured = true` (from the bare env read at
`host.rs:761`) advertises `search_web` as available in the tools
inventory while the runner is built with `NotConfiguredWebSearch` and
every call refuses — after this lane, the bool and the provider must
derive from the SAME check so they can never disagree again.

The Serper-PLUGIN half of v4's OR
(`searchProviderRegistry.isSearchConfigured() || SERPER_API_KEY`)
stays the standing no-plugin-runtime deferral — this lane wires ONLY
the env-key/api-key-row path, which is built and just unconnected.

Do NOT touch: the wire-building functions' BYTES
(`build_serper_request` body/URL defaults, `map_serper_results`,
`format_web_search_results`, the two error sets — all pinned by the
existing differentials, which must stay green unmodified except where
this order names an additive seam); `api/types.rs` (no new verbs
exist in this lane); the `host.rs:468-513` seam-free job registry
block (P4.9H2A's); anything in P4.9H2A/B's Ownership lists.
