### Quirks the port must not miss

1. **`useDocumentStores` patches, not refetches**: after scan / convert /
   deconvert it re-GETs the ONE store and splices it into the list state;
   after create it appends; after update it replaces. Keep that shape (a
   full list refetch is a behavior change).
2. **Convert/deconvert are live-guarded refusals** (P4.6y): the
   `capabilities.canConvert` gate is real and live (also refuses during a
   scan), and confirming the dialog fires the variant — the server answers
   with the typed refusal. Surface it through the normal error path
   (v4-voice alert), loudly. Do not pre-hide the affordances beyond what
   `canConvert` hides in v4.
3. **The detail scan button re-labels**: `Re-chunk` for database mounts,
   `Scan Now` otherwise; disabled while `scanning || store.scanStatus ===
   'scanning'`; database-mount title tooltip ("Rechunk all documents…").
4. **FileTable upload is database-mounts-only** and posts multipart to the
   blobs route (201 at the edge); the table mirrors uploads on refresh.
5. **Blob-backed = `blob`/`pdf`/`docx`** (`isBlobBacked`,
   FileTable.tsx:80) — expansion + description editing + blob download URLs
   key on it; the lazy blob-detail fetch de-dupes via a fetched-ids set.
6. **Reads omit null nullables; create/update echo them AS null** (the
   P4.6p standing gotcha) — extractors read defensively (the P4.6t
   precedent).
7. **Dialog/e2e mechanics from the standing notes**: never assert
   visibility on a zero-box modal HOST — `getByRole('dialog')`
   ([[p4.6pqr-round-plan]]); `[selected]`-per-option for any select with
   async options (dogfood #6); container `(blur)` never fires — use
   `(focusout)` ([[p4.6x-document-mode-spa]]); CollapsibleCard-style
   async gating on a `ready` signal where applicable.
8. **v4 voice**: user-facing strings keep the steampunk register and port
   verbatim wherever v4 has them ("Summoning the file manager…" belongs to
   the sibling; your empty states / confirms / errors come from the v4
   files above).
