## Shared contract B (binding; identical text in P4.D83 and P4.D84)

**The optionsSchema wire.** The providers listing (v5: the
`providers`-listing verb/route served from `api/settings.rs`; v4:
`app/api/v1/providers/route.ts:25–55`) carries, per provider,
`optionsSchema: ProviderOptionsSchema | null` — `null` exactly when the
plugin declares no schema (google only, at the pin). The shape is v4's
`packages/plugin-types/src/plugins/provider-options.ts`, verbatim:

```
ProviderOptionsSchema = { groups: ProviderOptionGroup[] }
ProviderOptionGroup   = { title?, helpText?, fields: ProviderOptionField[] }
ProviderOptionField   = { key, label, helpText?, type, default?,
                          enumValues?, multiEnumSource?, max?, showIf?,
                          affects?, appliesToModels? }
type ∈ 'boolean'|'enum'|'multi-enum'|'string'|'number'
ProviderOptionEnumValue = { value, label, description? }
ProviderOptionShowIf    = { field, equals }
multiEnumSource ∈ 'fetchedModels';  affects ∈ 'modelInput'
```

Field keys are storage keys inside the profile's `parameters` blob and
must round-trip untouched (the renderer reads/writes the flat bag; the
provider reads the same keys at call time). P4.D83 serves it (manifests
via the generator; the listing differential proves all eight schemas
byte-for-byte); P4.D84 renders it and must not invent, rename, or
reorder fields. The SPA contract type is
`core-contract.ts:3008–3034` (`optionsSchema?: unknown | null`) —
P4.D84 narrows its own client-side type from this contract text, not
from the server code.
