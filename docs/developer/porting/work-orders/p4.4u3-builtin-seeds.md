## Mandate

Close two of the three P4.4 named seed deferrals so a fresh v5 instance
matches a fresh v4 instance: (1) the built-in roleplay templates
("Standard" / "Quilltap RP") including the `delimiters`
discriminated-union marshaling the Phase-2 port deferred, and (2) the

subfolder scaffolds. The third family (the `lorian-and-riya.qtap`
sample-content import) stays DEFERRED — see the deferral section.

## The v4 facts (survey 2026-07-10 — verify per unit, don't re-derive)

### Family 1 — built-in roleplay templates

- Seeding runs on **EVERY startup** (not first-boot-gated):
  `lib/startup/seed-initial-data.ts:57` →
  `repos.roleplayTemplates.seedBuiltInTemplates()`. The old lazy
  read-path seed was deliberately removed (readonly-connection hazard in
  forked children) — the parent-process startup call is the only site.
- Seed literals: `lib/database/repositories/roleplay-templates.repository.ts`
  `BUILT_IN_TEMPLATES` **lines 21-105** — "Standard" (:22-67, `delimiters`
  :46-49, `renderingPatterns` :51-58, `dialogueDetection` :60-64,
  `narrationDelimiters: '*'`) and "Quilltap RP" (:68-104, `delimiters`
  :92-96 incl. a `linePrefix` kind `marker: '// '`, `dialogueDetection:
  null`, `narrationDelimiters: ['[',']']`). Both `userId: null`,
  `isBuiltIn: true`, `tags: []`. Transcribe VERBATIM (the
  `[[byte-exact-static-data-transcription]]` pattern — a generated data
  module + a checked-in generator script is acceptable; hand transcription
  with a differential proving the bytes is equally fine here since the
  payload is small).
- Idempotency (`_doSeedBuiltInTemplates`, :141-196): per template,
  `findOne({name, isBuiltIn: true})` → absent = insert (new UUID) /
  present = **update-in-place** of systemPrompt / description /
  delimiters / renderingPatterns / dialogueDetection /
  narrationDelimiters / updatedAt (so code changes propagate on upgrade).
- The `delimiters` Zod union (`lib/schemas/template.types.ts`):
  discriminated on `kind` — `wrap` (:84-91, `delimiters: string |
  [string,string]`), `linePrefix` (:97-102, `marker`), `tagPrefix`
  (:109-137, `open`/`close`/`tokenPattern`); common fields :59-78 (`name`,
  `buttonName`, `style`, `hideDelimiter?`, `addOns?` = bold/italic/
  reverse/underline/border/font). `TemplateDelimiterSchema` (:153-160)
  wraps the union in a **`z.preprocess` that backfills `kind:'wrap'` on
  legacy rows lacking the discriminant** — port that read-side backfill.
  On the template row: `delimiters: z.array(...).default([])`,
  `narrationDelimiters: string | [string,string]` default `'*'`.

### Family 2 — the three mount stores

- Each is a v4 **migration** (run by MigrationRunner at startup), NOT
  part of seed-initial-data:

| Store | v4 migration | `instance_settings` key | Scaffolded subfolders |
|---|---|---|---|
| Quilltap General | `migrations/scripts/provision-general-mount.ts` | `generalMountPointId` | `Scenarios` |
| Quilltap Uploads | `provision-user-uploads-mount.ts` | `userUploadsMountPointId` | `chat`, `images`, `shell`, `diagnostics`, `restored`, `uploads` |
| Lantern Backgrounds | `provision-lantern-backgrounds-mount.ts` | `lanternBackgroundsMountPointId` | `generated`, `tool` |

- Identical `doc_mount_points` row shape (e.g. general :210-234):
  `mountType='database'`, `storeType='documents'`, `basePath=''`,
  `enabled=1`, `includePatterns='[]'`, `excludePatterns=
  ['.git','node_modules','.obsidian','.trash']`, counts 0,
  `scanStatus='idle'`, `conversionStatus='idle'`; global (no project
  link).
- Idempotency is **by settings pointer, not by name** (`shouldRun`,
  general :150-178): provision only if the settings key is empty OR the
  pointed-at mount row no longer exists; if the id resolves, ADOPT the
  existing mount (and still ensure subfolders). Settings write is
  `INSERT ... ON CONFLICT(key) DO UPDATE`. Subfolders via
  `ensureFolderPath` (separately idempotent).
- Runtime re-ensure: `ensureGeneralScenariosFolder()`
  (`lib/mount-index/general-scenarios.ts:44-61`) re-creates General's
  `Scenarios/` folder at startup — idempotent, folder-only.
- Ordering: instance_settings table exists first (v5's fresh schema
  already has it); registration order Lantern → Uploads → General is not
  load-bearing for a fresh instance but keep it for determinism.

## Deliverables

### 1. The `delimiters` union marshaling (`db::roleplay_templates`)

Extend the ported repo's marshaling with the full discriminated union as
**typed serde structs in schema field order** (`[[json-column-key-order]]`):
the three kinds + common fields + `addOns`, optional keys
`skip_serializing_if`, the read-side `kind:'wrap'` preprocess backfill,
and `narrationDelimiters`' string-or-pair union. Extend the existing
`roleplay_templates_tier2_equivalence` corpus with rows exercising every
kind (wrap string + wrap pair, linePrefix, tagPrefix with tokenPattern,
addOns present/absent, hideDelimiter, a legacy kind-less delimiter
round-tripped through v4's update) and regenerate green.

### 2. `seed_built_in_templates` (new `services::builtin_templates` or on the repo)

The verbatim seed data + the find-by-(name,isBuiltIn) insert-or-update
loop, minting via `clock::now_iso` + `uuid` on insert, updating the six
fields + `updatedAt` on drift. The built-in read-only guard on
update/delete already exists in the ported repo — the seeder writes
through internal paths, not the guarded public ops (mirror v4's
collection-level access; a repo-internal `seed` method is fine).

### 3. Mount-store provisioning (new `services::builtin_mounts`)

`ensure_builtin_mounts(main, mount_index)` implementing the three
provision-or-adopt units with v4's exact semantics: the settings-pointer
`should_run` check, the verbatim row INSERT (list exactly v4's column
subset so DDL defaults fill the rest — the `link_document_content`
precedent), the ON-CONFLICT settings upsert, and the subfolder ensures
(the ported `ensure_folder_path`). Plus
`ensure_general_scenarios_folder` (the runtime re-ensure).
`instance_settings` already has the three key getters
(`get_general_mount_point_id` etc.) — add the setters.

### 4. Wiring — provisioning + every assembly

- `services::provisioning::provision_fresh_instance` runs both families
  after the schema replay + existing seed rows (a fresh v5 instance =
  fresh v4 instance).
- The host assembly path (`quilltap-host/src/host.rs` — this lane OWNS
  it this round) runs both families on every assemble/unlock (matching
  v4's every-startup semantics: template drift-update + mount
  adopt/heal). Idempotent by construction; a real pre-existing instance
  (migration-vintage) must ADOPT its existing stores, never duplicate —
  bank that in tests (the W4.0 adopt-branch precedent).

### 5. Differentials

- **`builtin_templates_equivalence`** (tsx or jest real-DB): drive v4's
  REAL `seedBuiltInTemplates()` on a fresh fixture AND on a fixture with
  a stale-content built-in row (proving update-in-place) and a
  user-created same-name row (proving `isBuiltIn` keying); diff the
  `roleplay_templates` dump in the minted-values remap form (ids +
  timestamps minted). The delimiters bytes are the point — diff exact.
- **`builtin_mounts_equivalence`** (jest real-DB): drive v4's REAL
  migration `run()` functions (import the migration modules directly)
  over three fixture states — empty settings (fresh provision), a
  dangling pointer (re-provision), a live pointer (adopt + subfolder
  re-ensure) — diffing `doc_mount_points` + `doc_mount_folders` +
  `instance_settings` in the shared-id-map remap form.
- The **provisioning differential** (`provisioning_equivalence`) extended:
  a fresh v5 instance's `roleplay_templates` / `doc_mount_points` /
  `doc_mount_folders` / `instance_settings` now also diff against a
  fresh-v4-with-migrations+seed instance. NOTE the v4 side of this
  fixture must run the migration runner + seedInitialData, not just
  repo-driven table creation — extend
  `harness/oracle/provision/dump-fresh-schema.ts`'s sibling scripts, do
  not change the schema-capture itself.
- Re-verify inert: `roleplay_templates_tier2`, `image_ingest_tier2`
  (uploads-mount pointer consumers), the web setup e2e (fresh instance
  now carries the seeds — assert the two templates + three mounts exist
  post-setup in `crates/quilltap-web` tests).
