## Rulings made at planning

No §R.7 ruling names this lane. The drafter's decisions, each binding (the
human may overrule before lane start — an overruled one is a STOP item):

- **D-1 — the option is `plainDocument?: boolean`, default `false`.** Not
  named `documentMode`: "Document Mode" is already a Salon feature name. When
  `true`, `renderMarkdownToHtml` renders with v4 `FilePreviewText`'s plugin
  list and nothing else (item 1). When absent or `false`, the function's
  behaviour is byte-identical to main.
- **D-2 — the viewer's Markdown arm follows `isMarkdownFile(file)`, not the
  preview kind.** v4 decides inside `FilePreviewText` (`:53-59`): MIME type
  contains `markdown`, OR the name ends `.md` / `.markdown`. A `markdown`-kind
  row named `notes` with no MIME type is shown as plain text by v4; a
  `text`-kind row named `a.md` is rendered. v5 ports that predicate.
- **D-3 — frontmatter: STRIP and SHOW**, as v4 (`:349-362`, `:551-566`): the
  body is rendered without the block; the "Document Info" table shows when
  the parsed data has at least one key. Copy copies the WHOLE raw file (v4
  `:548` `<CopyButton content={content} />`).
- **D-4 — links follow v4's store viewer exactly.** v4's `DocumentViewer`
  passes no `files` and no `onNavigate` to `FilePreviewText`
  (`DocumentViewer.tsx:107-112`), so every wikilink and every relative link
  is rendered as the BROKEN button (`qt-wikilink qt-wikilink-broken`,
  `title="File not found"`) and a click does nothing. v5 renders the same
  inert button. No navigation is ported (there is none to port).
- **D-5 — sanitisation model: generated markup + v4's URL transform, then
  trusted** (the chat's and the `.docx` arm's model:
  `bypassSecurityTrustHtml`). Angular's own HTML sanitizer is NOT used: it
  strips `style` attributes and MathML, which breaks KaTeX. Safety comes from
  (a) raw HTML in the source being emitted as ESCAPED TEXT (item 1: `remark-
  rehype` with `allowDangerousHtml: true` and `rehype-stringify` WITHOUT it —
  `hast-util-to-html`'s `raw` handler prints text; this is also exactly what
  v4's `react-markdown` shows) and (b) a verbatim port of `react-markdown`
  10.1.0's `defaultUrlTransform` applied to every `a[href]` and `img[src]`
  (item 2), which blanks `javascript:`, `data:` and — as in v4 — `qtap:`.
- **D-6 — the oracle is v4's real `FilePreviewText` rendered to static
  markup with `react-dom/server` under `tsx` at the pin** (jest cannot import
  ESM-only `react-markdown`; v4's own tests mock it). Compared after a DOM
  canonicalisation (attribute order, void-tag and entity spelling differ
  between React and `rehype-stringify`). Rows that still differ live in ONE
  named both-ways table `STORE_VIEWER_MARKDOWN_RESIDUE` (item 3).
- **D-7 — the Inventory signal crosses through the actions object.** The
  picker gains a `filed` output; its host (the control dialog) forwards it to
  `actions.notifyFiled()`; the browser watches `actions.filed()` and calls
  `state.setSelectMode(false)`. The picker's success order is v4's: toast →
  `filed` → `closed` (`ItemFolderPickerDialog.tsx:108-112`).
- **D-8 — new files.** The pure Markdown-for-stores logic lives in a NEW
  `document-browser/store-markdown.ts` (not inline in the component), so it
  can be compared with the v4 capture without a component fixture.
