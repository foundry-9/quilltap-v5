**The TZ rider (v5 side, verified on main today):**

- v5's host resolves its zone via `jiff::tz::TimeZone::system()`
  (`crates/quilltap-host/src/paths.rs:89`), which honors the `TZ` env
  var, then platform sources. In a container neither is set → UTC,
  which is the exact v4 bug `a7f691e7`/`298563eb` fixed. The
  zone-sensitive surfaces are already ported and live: same-day recall
  (`server_tz`, P4.d26 — threaded at `crates/quilltap-host/src/spine.rs:1069/1261/1334`),
  autonomous-room cron/local-midnight budget rollover.
- v5's `Dockerfile` has NO entrypoint script — `ENTRYPOINT
  ["quilltap-web", "--host", "0.0.0.0", "--port", "3000"]`
  (`Dockerfile:124`), so the v4 entrypoint-script approach doesn't
  transplant; the equivalent seam is the top of
  `crates/quilltap-web/src/main.rs` (`fn main`, line ~71): map
  `QUILLTAP_TIMEZONE` → `TZ` **before anything reads the clock or
  constructs the host** (jiff reads `TZ` lazily but treat it as
  boot-time-only; set it first thing). v4's precedence (from
  `a7f691e7`): whichever of the two is set fills the other;
  `QUILLTAP_TIMEZONE` WINS when both are set and disagree; neither set
  → unchanged (UTC in a container). v4 also validates the value is an
  IANA name (UTC, or containing `/`) and REJECTS abbreviations like
  `CDT` rather than forwarding them (`298563eb` — ICU would silently
  fall back to UTC; jiff would error differently, but the same
  reject-don't-forward rule is the faithful shape).
- Extract the precedence+validation as a pure function
  (`Option<String>, Option<String> → Option<String>` or similar) so it
  is unit-testable without process-global env mutation; `main` applies
  it via `std::env::set_var` before the runtime starts.
- Docs: `docs/developer/running.md` (P4.10's doc) gains the
  `QUILLTAP_TIMEZONE`/`TZ` row + a `-e QUILLTAP_TIMEZONE=` example;
  the Dockerfile gets a comment pointing at the resolver.
