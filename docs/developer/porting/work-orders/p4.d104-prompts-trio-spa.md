v4 expectation tables in `ng test`), not the jest oracle — the same
mechanism as the D57 turn-banner and D85 number-field lanes. The wire

## Shared contract (BINDING — identical in P4.D103 and P4.D104)

1. The `groupCreate` dispatch verb's request gains one optional field:
   wire key **`instructions`**, type `string | null`, absent allowed.
   Server validation mirrors v4 `createGroupSchema`:
   `z.string().max(10000).nullable().optional()`; create persists
   `instructions || null` (empty string normalizes to `null`).
2. The `groupUpdate` patch accepts wire key **`instructions`**, validated
   `string ≤ 10000 | null` (v4 `updateGroupSchema`); the update path is a
   validated passthrough — a PUT with `instructions: ""` stores `""`
   (v4's quirk, carried). The CLIENT compensates by sending
   `instructions || null` (v4 GroupDetailView behavior).
3. The `groupGet` response's group object carries
   **`instructions: string | null`** (hydrated by the overlay; the SPA
   mirrors the field onto its group detail type in
   `apps/web/src/app/core/core-contract.ts`).
4. Invalid `instructions` (non-string, or > 10,000 chars) answers v4's
   validation shape: 400 `{"error":"Validation error","details":[…]}` on
   both create and update.
5. e2e activation: P4.D104 authors the group-instructions round-trip beat
   gated on the named constant **`P4D103_SERVER_LANDED = false`** in the
   beat file; the unifier flips it to `true` at unification.
