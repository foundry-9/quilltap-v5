## §C — the subprompts wire contract (BINDING — verbatim-identical in P4.D163, P4.D164 and P4.D165)

### C.1 The record

`SubpromptRecord` — v4 `Subprompt` (`lib/subprompts/subprompts.ts:52-63`),
keys in THIS order on the wire:

```
{ id: string, path: string, title: string, content: string, updatedAt: string }
```

`id` = the vault file name sans `.md` (one path segment; stable across title
edits); `path` = `Subprompts/<id>.md`; `title` = frontmatter `title`, falling
back to the id; `content` = the body with frontmatter stripped, leading
newlines removed, `trimEnd`; `updatedAt` = the file's `lastModified` as an ISO
8601 string (`new Date(mtime).toISOString()`).

### C.2 The verbs (dispatch `type` literals; the v5 idiom of the

|---|---|---|---|
| `characterSubpromptList` | `{ characterId }` | `{ subprompts: SubpromptRecord[] }` (title-sorted; `[]` for no vault / no folder) | `GET /api/v1/characters/[id]/subprompts` |

### C.4 Error envelopes (v4's `lib/api/responses.ts` sentences, byte-exact)

| condition | status | body `error` |
|---|---|---|
| character missing (`findByIdRaw`, overlay-free — an ARCHIVED character still resolves for reads) | 404 | `Character not found` |
| subprompt missing (get / update / delete-returned-false) | 404 | `Subprompt not found` |
| `subpromptId` fails `isValidSubpromptId` (get / delete; update after the body parse) | 400 | `Invalid subprompt id` |
| create/update body fails the Zod schema (`title` min 1 max 100 [code points]; `content` min 1; update: both optional) | 400 | v4's `validationError` envelope (`error: 'Validation error'` + `details`), as the P4.62 web edges emit it |
| the service's own validation (`validateTitle` / `validateContent` — UTF-16 `.length` rules, AFTER Zod) | 400 | `A subprompt needs a title` / `A subprompt title is at most 100 characters` / `A subprompt needs some instruction text` |
| character archived, on a WRITE | 409 | `Character is archived; subprompts cannot be added` / `… cannot be edited` / `… cannot be deleted` |
| any other failure | 500 | `Failed to list subprompts` / `Failed to read subprompt` / `Failed to create subprompt` / `Failed to update subprompt` / `Failed to delete subprompt` |

Guard order, as v4 wrote it and to be MEASURED before pinning (the
`a6870c5a` guard-order class): POST and PUT parse the body FIRST (a bad body
on a missing character is 400, not 404); GET and DELETE validate the id first,
then the character, then the subprompt.
