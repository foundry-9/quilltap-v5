## Survey facts (v4 at `2494a84b`)

### The instance lock (`lib/database/backends/sqlite/instance-lock.ts`)

- Path: `<base>/data/quilltap.lock` (`paths.ts:402`), acquired at backend
  init; an `InstanceLockError` becomes a startup-state conflict (surfaced
  to the UI — in v5, a typed boot error the P4.2 startup-status route will
  carry).
- Lock JSON `LockFileContent` (`:52`): `{pid, hostname, startedAt,
  lastHeartbeat, environment, processTitle, processArgv0, history[]}`;
  `history` capped at 50 entries; events
  `acquired|released|stale-detected|stale-claimed|override|override-rejected`.
- Acquisition (`:485`): no file → atomic create (`O_CREAT|O_EXCL`, EEXIST
  re-reads); same host + same PID → re-entrant refresh; same host + dead
  PID (`kill(pid, 0)`, EPERM = alive) → claim stale; **different hostname**
  (VM/container) with heartbeat fresher than 5 min → REFUSE, else claim
  stale; live different PID same host → refuse.
- Heartbeat: every 60 s, verify ownership, rewrite `lastHeartbeat`;
  **losing the lock (file vanished / foreign content) self-terminates the
  process** — in v5, trigger the host shutdown + surface a fatal error
  (document the exact mapping; a silent `process::exit(1)` is acceptable
  as the faithful port, but prefer shutdown-then-exit).
- Release on close: write a `released` event then unlink; never throws.
- `detectEnvironmentType()` (`:208`): electron → lima
  (`LIMA_CONTAINER==='true'`, checked BEFORE docker) → wsl2
  (`WSL_DISTRO_NAME`) → docker (`DOCKER_CONTAINER==='true'` or
  `/.dockerenv`) → `local`. (v5: no electron; keep the vocabulary, emit
  what applies.)
- The launcher has a JS mirror (`packages/quilltap/lib/lock-helpers.js`)
  with a read-only `getLockStatus` → `absent|corrupt|active|stale|suspect`
  and a no-override `acquireWriteLock` — that is **P4.3 CLI** surface; port
  only the server-side lock here, but shape the module so P4.3 can reuse
  the status classification.

### The scheduler sweeps (`lib/background-jobs/`, started in
### `instrumentation.ts:760` in order: cleanup → housekeeping → maintenance
### → danger scan → autonomous)

| Sweep | Interval | Startup | Last-run state |
|---|---|---|---|
| LLM-log cleanup (`scheduled-cleanup.ts`) | 24 h | immediate | none |
| Memory housekeeping (`scheduled-housekeeping.ts`) | 24 h | 5 min grace, skip if a COMPLETED scheduled job within 20 h | peeks recent `MEMORY_HOUSEKEEPING` job rows (`findRecentByType`) |
| Maintenance (`scheduled-maintenance.ts`) | 24 h | 5 min grace, skip if last sweep within 20 h | `instance_settings` get/set `lastMaintenanceSweepAt` |
| Danger-scan enqueuer (`scheduled-danger-scan.ts`) | 10 min | immediate; skip starting entirely if ALL users' danger mode is OFF | none |

- The cleanup + housekeeping sweep BODIES are ported
  (`queue_service::run_scheduled_cleanup` / `run_scheduled_housekeeping`);
  the cadence constants exist (`services::job_scheduler`). The host loops
  are this lane's work (in `host.rs`, the P4.0 loop idiom: `watch` stop +
  `tokio::select!`).
- **The maintenance sweep body** (`runScheduledMaintenance`, `:142`) — four
  independently try/caught sweeps in order: (1) `cleanupFinishedJobs()`
  (ported); (2) `collapseStaleChatAssets()` (ported, W4.8 — its
  storage-bytes half is lane b's seam; call through the seam); (3)
  `docMountFileLinks.sweepOrphanedFiles()` — **check port status**; if
  unported, port it (a mount-index repo op → tier-2 differential); (4)
  `terminalSessions.cleanupClosedSessions(cutoff)` with
  `CLOSED_TERMINAL_RETENTION_DAYS = 30` — **check port status**; if
  unported, port (tier-2; the transcript-FILE deletion half goes through a
  small fs seam or reads `transcriptPath` and unlinks host-side — do NOT
  touch lane c's terminal module). Record `setLastMaintenanceSweepAt` at
  the end regardless of per-sweep failures. `instance_settings` needs the
  WRITE helper (get exists as a read pattern; add get+set append-only —
  lane b also appends a read to that file; unions resolve).
- **The danger-scan enqueuer body** (`runScheduledDangerScan`, `:102`) —
  the W4.8 tracked deferral, now fully specced; **port as a core service
  (`services::danger_scan`) with a differential** (D10). Per user with
  `resolveDangerousContentSettings(settings).mode !== 'OFF'` (ported
  resolver), iterate `repos.chats.findByUserId` (ported). Gates per chat:
  skip `isModerationExemptChatType(chatType)` (ported); skip
  `conciergeOverride === 'OFF'`; include if `isDangerousChat == null`
  (never classified) OR (`isDangerousChat === false` AND
  `dangerClassifiedAtMessageCount != null` AND `messageCount >
  dangerClassifiedAtMessageCount`) — dangerous chats are sticky, never
  re-checked. Resolve a `connectionProfileId`: first non-user participant
  with a still-valid `connectionProfileId`, else the first available
  profile; skip the chat if none. Enqueue branch: `contextSummary` present
  → `enqueueChatDangerClassification({chatId, connectionProfileId},
  {priority: -2})`; no summary and `messageCount > 50` →
  `enqueueContextSummary({chatId, connectionProfileId,
  forceRegenerate:false}, {priority: -2})` (the summary handler chains
  classification); no summary and `messageCount <= 50` → the
  classification enqueue (the handler falls back to raw messages).
  `queue_service` likely lacks `enqueue_context_summary` — add it (the
  ported enqueue pattern, dedupe/priority per v4). Also port the sweep's
  all-users-OFF pre-check (the "skip starting" gate — expose it as a pure
  decision the host loop consults).
  **Differential**: tsx real-DB (no model call — reads + enqueues only)
  driving v4's REAL `runScheduledDangerScan` over a seeded fixture (users
  with mode OFF/on, exempt chat types, an operator-waved-off chat, a
  never-classified chat, a safe-but-grown chat, a sticky-dangerous chat, a
  chat with no resolvable profile, the summary/no-summary×>50/≤50 matrix),
  diffing `background_jobs` in the minted-values form.

### `SelfInventoryEnv` production values
### (`lib/tools/handlers/self-inventory/builders.ts`)

- `version` = the package version (v5: the host's version string — the
  P4.0 `HostConfig.version` precedent).
- `release_notes`: `findReleaseNotesFile(version)` (`:716`) scans
  `docs/releases/*.md`, parses `major.minor.patch` stems, picks the
  **newest release ≤ the current version**, reads it; returns the body +
  that release's version. `changelog`: read `docs/CHANGELOG.md`. In v5 both
  live in the repo/app bundle — take the docs dir as a config path; absent
  files → `None` (v4's "not found").
- `runtime_mode` = `resolveRuntimeMode()` (`:689`): combinations of
  electron/docker/lima/dev →
  `electron-vm|electron-docker|electron|vm|docker|local-dev|local-production`.
  v5 web host: `docker`/`vm`/`local-production` per the same env probes
  (reuse the lock's `detectEnvironmentType` probes); the tauri shell maps
  later.
- `client_shell` = browser for the web host (the core `ClientShell` type).
- `mount_index_degraded`: v4 reads a global set when the mount-index DB
  fails to open. v5: derive from the assembled `Db` (the mount-index
  partition unavailable ⇒ degraded).
- `model_info` / `fallback_pricing` / `registry_default_context`: source
  from `provider_manifest::Registry::built_in()` + the generated
  `LEGACY_FALLBACK_PRICING` rows (the W4.7e static) — a
  `SelfInventoryEnv::production(...)` constructor in the host (`env.rs`).
