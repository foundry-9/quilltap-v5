and prioritized by the human on the spot: *"it's been killing me that we're

**operability** lane, not a fidelity lane — but see the P4.18 carve-out in
"The one ruling this lane needs", because parts of it ARE mechanically

## Why (the finding, in one paragraph)

v5 logs to **stderr only**. `quilltap-web::init_tracing`
(`crates/quilltap-web/src/lib.rs:107-116`) installs a `tracing_subscriber::fmt`
writing to `std::io::stderr`, `RUST_LOG`-filtered; the instance's `logs/` dir is
used by exactly one thing, `logs/terminals` for PTY transcripts
(`quilltap-host/src/host.rs:469,688`). There is **no file appender anywhere in
the workspace**. So a warning written for a human to act on — the bug-70
`No room left for conversation history` / `[ContextManager] Message budget
exhausted before any history` pair is the case that surfaced this — is readable
only by whoever is watching the terminal at the moment it fires. On v4 the same
event is in `logs/combined.log` and greppable a day later, which is where an
operator (and this port's own dogfooder) actually looks. Every v5 diagnosis
currently starts with less instrumentation than v4 had.

## Survey-verified starting points

**v4** (all paths in `~/source/quilltap-server`):

- `lib/logger.ts:41-66` — `initializeTransports()`: `ConsoleTransport` when
  `LOG_OUTPUT` is `console` or `both`; `FileTransport(logPath, maxFileSize,
  maxFiles)` when it is `file` or `both`.
- ⚠ **The code default and the lived default disagree, and the lived one is
  what "parity" means here.** `lib/env.ts:31` defaults `LOG_OUTPUT` to
  `console`, and `.env.example:69` ships `console` — but the v4 checkout's own
  **`.env.local:28` sets `LOG_OUTPUT="file"`**, i.e. files ONLY, no console.
  That is why the human reports never setting a `LOG_*` variable and always
  having logs: on their machine the files are not a fallback, they are the
  only destination. Confirmed on the real instance
  (`~/iCloud/Quilltap/Friday/logs/`): `combined.log` + `combined.0..9.log`,
  `error.log` + `error.0..9.log`, and `error.log` carries **only**
  `level:"error"` records — the FileTransport fan-out, not a stderr redirect
  (the separate `quilltap-stdout.log` / `quilltap-stderr.log` /
  `startup.log` / `embedded-server.log` ARE launcher redirects, and are
  exactly the files unit 3's sweep must never touch).
- `lib/logger.ts:55-57` — the `LOG_FILE_PATH` quirk: the env value is used
  **only if set AND not the literal default `'./logs'`**; otherwise
  `getLogsDir()` (the instance's own logs dir). Port the quirk, not a
  simplification of it.
- `lib/logger.ts:10-28` — five levels (`error`/`warn`/`info`/`debug`/`trace`,
  numeric 0–4) and `CURRENT_LEVEL` from `LOG_LEVEL`, default `info`.
- `lib/logging/transports/base.ts` — the record: `{ timestamp, level, message,
  context: {…}, error?: { name, message, stack? } }`.
- `lib/logging/transports/file.ts` (**194 lines — the whole port**):
  - `STEMS = ['combined','error']`; `activeLogName` = `<stem>.log`;
    `rotatedLogName` = `<stem>.<N>.log`.
  - `write()`: `JSON.stringify(logData) + '\n'` → **combined always**, → error
    **only when `level === ERROR`**.
  - `writeToFile()`: size measured with `Buffer.byteLength(content,'utf-8')`;
    rotate **before** appending when `currentSize + contentSize > maxFileSize`;
    running size held in a `Map<Stem, number>`; every failure is a
    `console.error` and a swallow.
  - `rotateFile()`: unlink `<stem>.<maxFiles-1>.log`, then shift `i` from
    `maxFiles-2` down to `0` (`.i` → `.i+1`), then rename active → `.0.log`,
    then reset the size counter to 0. **Every step is individually
    best-effort** ("not present is fine").
  - `initializeDirectory()`: `mkdir -p`, then `purgeStrayLogs()`, then `stat`
    each stem to seed its size (missing → 0).
  - `purgeStrayLogs()` + `belongsToStemFamily()`: allowlist = the two active
    names + `<stem>.<0..maxFiles-1>.log`. A directory entry is deleted only if
    it is NOT allowlisted AND belongs to a stem family, where "belongs" means
    it starts with the stem AND (is exactly the stem OR the next character is
    **non-alphanumeric**). ⚠ This predicate is the subtle part — see unit 3.
- `lib/logging/README.md:55-105` — the four `LOG_*` knobs and the documented
  contract, incl. the iCloud/Finder rationale.
- **`__tests__/unit/logging-transports.test.ts` — 36 `it(` cases, and this
  lane's parity corpus.** Mirror the file-transport cases 1:1 the way SPA
  lanes mirror v4's component tests (`impersonation-overlay-spa-gaps`: v4's own
  tests are the oracle when the surface has no NDJSON oracle).

## The one ruling this lane needs

**P4.18 declared log records non-differential** ("Log records are operator
output, not data — no differential applies", `lib.rs:104-107`). That ruling
stands for the *content* of an event — v5's messages, fields and targets are
its own and must not grow a fidelity obligation.

**It does not extend to this lane's file behavior.** File names, the rotation
sequence, the sweep's allowlist predicate, the JSON envelope's key set, and
the "errors go to both files" rule are a **contract with the operator and with
their existing greps**, and v4 has 36 executable cases pinning them. Port them
as mechanically-checked parity, mirroring v4's tests. The carve is:

- **Checked:** file names, rotation order and naming, the sweep predicate
  (both directions — deletes conflicts, spares neighbours), size accounting +
  the rotate-before-append threshold, the envelope keys, error-level fan-out,
  the `LOG_FILE_PATH` quirk, the knob defaults.
- **Not checked, and deliberately so:** which events v5 emits, their wording,
  and their field names. v5's `context` will not match v4's `context`
  event-for-event and is not required to.

## Units

**Unit 1 — the record shape and the writer.** A `LogFileWriter` (suggested
`crates/quilltap-web/src/log_file.rs`) owning the two stems, the size map, and
the append path. Serialize `{timestamp, level, message, context, error?}` with
`timestamp` as v4's ISO-8601 (`new Date().toISOString()` — millisecond
precision, `Z` suffix; v5 already has ISO helpers, do not hand-roll a format),
`level` as v4's lowercase strings, and `context` as the flattened tracing
fields plus `module` from the event target. Tests: envelope keys exactly v4's;
error level writes BOTH files; non-error writes only `combined`.

**Unit 2 — rotation.** Port `rotateFile`/`writeToFile` including the
before-append threshold, the `Buffer.byteLength` (UTF-8 byte length, NOT chars
— pin with a multi-byte message), the downward shift, and the per-step
best-effort swallow. Tests mirrored from v4's rotation cases, plus: a rotation
with gaps in the backup sequence, and `maxFiles = 1` (the loop's degenerate
case — `maxFiles-2` is negative; make sure the Rust port does not underflow a
`usize`, which is the obvious way to reproduce this in Rust and panic where v4
merely skips the loop).

**Unit 3 — the stray-file sweep.** Port `purgeStrayLogs` +
`belongsToStemFamily` exactly. Tests must cover **both directions**, because
this predicate deletes files: DELETED — `combined 2.log`, `combined.log.9 2`,
`combined(2).log`, `combined.log.3` (the old rotation shape), `error 2.log`;
SPARED — `errors.log` (next char is alphanumeric), `embedded-server.log`,
`startup.log`, `quilltap-stdout.log`, `terminals/` (a directory), and any
allowlisted active/rotated name. Add a v5-specific spared case the sweep must
never eat: anything under the instance `logs/` that `host.rs` owns.

**Unit 4 — composition and the knobs.** `LOG_OUTPUT` (`console`/`file`/`both`,
default `console`), `LOG_FILE_PATH` (with the `'./logs'` quirk),
`LOG_FILE_MAX_SIZE` (10485760), `LOG_FILE_MAX_FILES` (10). Wire as a
`tracing_subscriber::Layer` beside the existing fmt layer so `RUST_LOG`
filtering applies to both, and `init_tracing` stays idempotent via `try_init`.
⚠ The file layer needs the instance dir, which `init_tracing` does not
currently receive (it is called before `resolve_instance_base_dir` in
`main.rs:180`) — resolve that ordering explicitly rather than reaching for a
global.

**Unit 5 — the CLI's twin, ruled not guessed.** `quilltap-cli/src/main.rs:185`
inlines its own init. v4's CLI shares the one logger, so the faithful default
is that the CLI writes files too when `LOG_OUTPUT` says so — but a short-lived
client process appending to (and rotating!) the server's active log while a
server holds it is a real hazard worth thinking about. **Measure what v4's
`npx quilltap` actually does before choosing**; record the decision in the lane
record either way.

**Unit 6 — the default: RULED `both` (human, 2026-08-18).** v5 writes to
console AND files by default, a **recorded divergence** from v4's code default
of `console`.

The reasoning, so it is not re-litigated as an accident: v4's `.env.local` runs
`file`, so no deployment in actual use relies on the code default; P4.18
already ruled log records non-differential, so a default cannot break an
oracle; and a lane whose entire purpose is that v5 output evaporates should not
depend on someone remembering an env var. `both` rather than v4's `file`
because v5's stderr is genuinely useful when running the binary in a terminal,
which is how the dogfood server runs.

**Scoped to the port.** The human's ruling names its own expiry: once primary
development moves to Rust/Angular in this repo, the default is expected to
become **environment-dependent** (production vs development) rather than a flat
`both`. Do not build that conditional now — there is no environment concept in
`init_tracing` to hang it on, and inventing one is out of scope. Leave the four
knobs honoured so the change is a one-liner when the time comes, and record
this paragraph's existence in the lane record so the future change reads as a
planned step rather than a drift.
