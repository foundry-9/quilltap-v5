### v4 — `components/ui/ProgressBar.tsx` (NEW, 173 lines) — the behavior spec

- `ProgressSegment {key, label, estimatedDurationMs}`;
  `ProgressBarProps {segments, currentKey: string|null, startedAt:
  number|null, indeterminate?, hideLabels?, className?}`.
- 500 ms tick recomputes fills. Segments before `currentKey` = 100%
  (`qt-progress-fill-success`); the active one animates
  `min(elapsed/estimate, 0.9)*100` — **never reaches 100%** ("a slow
  phase reads as still working, not finished-and-stuck"); later ones
  0% (`qt-progress-fill-idle`). Per-segment first-active timestamps in
  a ref. `currentKey === null && startedAt !== null` = finished → all
  success. Indeterminate renders `qt-progress-indeterminate` on
  segment 0 only. Labels row: active `text-primary font-medium`, done
  `qt-text-success`, else `qt-text-secondary`, `text-[10px]`; plus a
  right-aligned elapsed `Xm Ys` timer. `hideLabels` for dense rows.
- Markup per segment: `<div class="qt-progress flex-1"
  title={label}><div class="qt-progress-fill …" style={{width}}/></div>`,
  row `flex gap-1`. NO raw color utilities — qt-progress family only.

## §1 Shared contract — the Almanack wire (BINDING; identical in P4.37 and P4.38)

Dispatch verbs (`api/types.rs` CoreRequest ↔ the SPA
`core-contract.ts` mirror, diffed name-for-name at unification).
Web-edge action strings keep v4's `capabilities-report-*` names
verbatim (v4 froze them deliberately: "renaming them would break
bookmarks to buy nothing").

1. `SystemAlmanackGenerate { progressId?: string (uuid) }`
   → `{ success: true, reportId, filename, storageKey, size, content }`
   (`reportId` = the files-row id — v4's 404-fix shape).
   Web edge: `POST /api/v1/system/tools?action=capabilities-report-generate`.
2. `SystemAlmanackList {}` → `{ reports: [{ id, filename, storageKey,
   createdAt, size }] }`, newest first.
   Web edge: `GET ?action=capabilities-report-list`.
3. `SystemAlmanackGet { reportId }` → `{ reportId, filename, content,
   size }`.
   Web edge: `GET ?action=capabilities-report-get&reportId=…`; the
   `&download=true` leg is WEB-EDGE-ONLY (Content-Disposition
   attachment, text/markdown) — same action, no separate verb.
4. `SystemAlmanackDelete { reportId }` → `{ success: true }`.
   Web edge: `POST ?action=capabilities-report-delete` body
   `{reportId}`.

Progress: NO dispatch verb and NO per-id SSE route (the standing
D3-family divergence — the creation-progress precedent). The server
emits a NEW frame kind on the ONE global event stream, scope-tagged by
`progressId`:

    { kind: 'phase', key, index (1-based), total, label }

alongside the existing `status`/`log`/`done`/`error` kinds (whose wire
bytes must not move). The SPA subscribes `core.events$` filtered by
progressId (the Green-Room pattern, `green-room.state.ts:36-48`); the
POST's own resolution is authoritative. v4's
`GET ?action=capabilities-report-progress` SSE action is NOT ported —
both lanes record it as the D3-family divergence.

The phase manifest (server Rust constant ↔ SPA TS mirror, byte-equal
labels): seven phases, in order, keys `premises`, `machinery`,
`ledgers`, `scriptorium`, `personae`, `wire-records`, `binding`, with
v4's labels and `estimatedShare` values from
`lib/tools/almanack/phases.ts` (shares sum to 1). `ALMANACK_NAME` =
"The Almanack"; `ALMANACK_TITLE` = "The Almanack (System Report)". The
settings-card `sectionId` stays `"capabilities-report"`.
