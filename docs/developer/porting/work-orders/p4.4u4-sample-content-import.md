## Survey-verified starting points (2026-07-11 @ `a7b1398d`, do not re-derive)

### The format (the finding that reshapes assumptions)

**`.qtap` is NOT an archive.** Two serializations: legacy monolithic
JSON (`manifest.format === 'quilltap-export'`, `version === '1.0'`,
hard-pinned in `lib/import/quilltap-import/validation.ts:48,55`) and
streaming NDJSON (`format: 'qtap-ndjson'`, `version: 1` — reader in
`lib/import/ndjson-reader.ts`, reassembler in
`lib/import/quilltap-import-stream.ts`). **The seed file is the legacy
monolithic JSON** — the NDJSON path is dead for both seed consumers and
stays unported (loud refusal on a `qtap-ndjson` sniff). Blobs ride
inline as base64; the seed payload carries NO blobs — avatars are
seeded separately from `first-startup/avatars/*` files.

`seedInitialData` internals over fresh (empty) DB pairs, tier-2
DB-state diff. Recipes: `[[jest-real-db-oracle]]` (resetModules+doMock

minting needs pinning.

- **`qtap_import_equivalence`** — drive v4's `executeImport` with the
  REAL committed `.qtap` on an empty DB; dump characters + wardrobe +
  memories tables; diff against the Rust port's writes. Pin whether
  create() preserves source ids or mints (the oracle decides — if
  minted, use the established UUID remap). Cases: the happy first-boot
  import; a second run against the populated DB with `skip` (drive
  `executeImport` directly, bypassing the gate, to exercise the skip
  branch — reset-builtins reaches it); a malformed-version reject; the
  scenario-string migration asserted on the written character rows.
- **`seed_avatars_equivalence`** — v4's `seedAvatars` over the imported
  characters + the real `Lorian.webp`; six-table blob dump + the
  `defaultImageId` update; idempotency case (second run no-ops).
- **`reset_builtins_equivalence`** (tier 2) — v4's
  `handleResetBuiltins` (jest real-DB, auth mocked, un-mock the
  character-vault-bridge per `[[p4.6i-characters-remainder-server]]`)
  vs the Rust service: ids preserved, cascade side effects, post-reset
  table state.
- The startup gate itself (zero-characters short-circuit, per-file
  swallow) is unit-tested Rust-side (host wiring is a v5 seam; v4's
