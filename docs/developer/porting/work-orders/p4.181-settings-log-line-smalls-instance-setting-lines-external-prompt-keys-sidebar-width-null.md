## Rulings made at planning

These are decided. Do not reopen them.

- **D-1 — the comparand for a log line** is
  `{ "level": "<lowercase>", "message": "<text>", "context": [["key","value"], …] }`.
  `context` is an ARRAY OF PAIRS in v4's key order, every value rendered as a
  string. It is an array because `external_prompt_tier3_equivalence.rs`'s
  `normalize` (`:494-505`) SORTS object keys and `serde_json::Map` equality
  ignores order (memory note `serde-json-map-eq-ignores-order`) — an object
  would hide a key-order defect.
- **D-2 — value rendering, both sides:** a string as itself; a number or
  boolean through JS `String(v)`; `null` as the text `null`; a v4 field whose
  value is `undefined` is OMITTED; an array or object as key + `Json` suffix
  with `JSON.stringify(v)` (§R.5); `durationMs` MASKED to the text `<ms>` on
  both sides.
- **D-3 — v4's third `logger.error` argument** (`logger.error(msg, {}, err)`)
  is NOT a context key. The comparand carries it as
  `"hasError": true|false` (v4: `err instanceof Error`; v5: the line has an
  `error=` field). The error TEXT is not compared (V8 / better-sqlite3 wording
  is not rusqlite's). Precedent: `instance_settings_json_warns_equivalence`.
  This applies to items 3 and 5 only. In item 1 `error` is a real v4 context
  key (`{ characterId, error: errorMessage }`) and its value IS compared.
- **D-4 — tracing targets.** `generators/external_prompt.rs` keeps its
  explicit `target: "quilltap::external_prompt_generator"`.
  `api/settings.rs` uses NO explicit target (the file's existing convention,
  `:381-385`), so the captured target is `quilltap_core::api::settings`.
- **D-5 — a v4 `null` in a log context** renders in v5 as the text `null`
  (the file's precedent: `settings.rs:1214`
  `imageProfileId = ….unwrap_or("null")`).
- **D-6 — F-a's write-back is NOT ported.** After a PUT on a row whose
  `sidebarWidth` cell is NULL, v4's full `$set` writes `256` into the cell;
  v5's partial `SET` leaves it NULL. That is the existing ruled divergence
  R-1 `PARTIAL_SET_ON_UNREFUSED_COLUMNS` (`db/chat_settings.rs:2387-2389`).
  Both sides READ `256` afterwards. Do not add a `dumpCells` row for it; write
  one sentence in the lane record.
- **D-7 — red-first without a red commit.** For each item: edit the tests and
  the oracle case in the working tree (uncommitted), regenerate, run → RED,
  record; then edit the source → GREEN; then ONE commit with tests + source.
