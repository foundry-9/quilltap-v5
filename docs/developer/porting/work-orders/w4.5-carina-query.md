## What to port (new `services::carina_query`)

1. **Answerer resolution**: `findCharactersByName(userId, name)` all matches
   oldest-first; prefer `canBeCarina === true`; else the asker-opens gate
   (`operatorInitiated` always; user-controlled persona always; a character
   asker needs `canBeCarina`); the Brahma fallback (below); `not-found`
   error kind.
2. **Profile resolution chain** (NOT participant-scoped — carry the
   why-comment): answerer's `defaultConnectionProfileId` → instance default
   (`connections.findDefault` — add the scoped read if missing) → first
   profile supporting webSearch (capability from injected registry data) →
   `no-profile`. API key via the established `ApiKeyResolver` seam.
3. **System-prompt construction**: `build_identity_stack` (no per-turn
   roleplay/tool reinforcement — the carina variant), the `## Scenario`
   append, `loadAskerIdentity` → `build_public_identity_card` (graceful
   null), the EXACT `## Reference Query` framing strings (with-asker and
   without-asker variants — generated `prompt_text` submodule), and the
   memory recall: `search_memories_semantic(answerer, question, {limit: 12,
   minImportance: 0.3})` → `format_memories_for_context(…,
   CARINA_MEMORY_TOKEN_BUDGET = 1200, provider)` →
   `buildCommonplaceLLMContext` ("You remember…", persona-free).
4. **Prior-exchange history**: `loadPriorCarinaExchanges` — scan
   `getMessages` for `systemSender: 'carina'` + `systemKind:
   'carina-response'` + matching `carinaMeta.answererId`, replayed as
   alternating user(question)/assistant(answer) pairs.
5. **The tool loop**: `build_tools` with the carina flag set
   (`helpToolsEnabled = answerer.defaultHelpToolsEnabled`,
   `canDress/canCreate = false`, `agentMode = false`), the `ask_carina`
   recursion filter, then the stream → `detectToolCallsInResponse`
   (the injected `ToolCallDetector` seam, as in the native loop) →
   `process_tool_calls` → thread → re-stream, `MAX_TOOL_ITERATIONS = 5`,
   and the **forced-text final turn** (empty answer + pending tool calls →
   one re-stream with `tools: []`). Empty final answer → `llm-failed`.
6. **Persistence + follow-ups**: `postCarinaResponse` (ported — compose,
   don't re-port), the `onPosted` surface callback (never throws), and
   `enqueue_carina_memory_extraction` (add to `queue_service`: payload
   `{chatId, carinaMessageId, answererId, connectionProfileId}`, dedupe by
   `carinaMessageId`).
7. **Error shape**: `CarinaResult` ok/err with kinds
   `not-found`/`no-profile`/`llm-failed` (+detail) — never throws;
   Prospero routing stays the CALLER's job (already ported).
8. **Brahma**: port `is_brahma_name` + `BRAHMA_CARINA_ANSWERER_ID`
   (`b4a4c0de-0000-4000-8000-000000000001`) + the `brahmaIsReachable` gate
   (`find_by_id_raw` overlay-free — carry the why-comment: a broken asker
   vault must not block) — but the Brahma one-shot console
   (`runBrahmaQuery`, 358 lines) is an **injected seam** (`AnswerAsBrahma`,
   default = the `llm-failed` shape v4 produces on a console failure) —
   its port is a tracked follow-up sub-unit (W4.5b) since it drags in the
   Brahma system-prompt builder + operator surface. The gate + sentinel-id
   post path ARE in scope (drive with the seam canned).
9. **Seam closures**: construct the real `RunCarinaQuery` at the
   orchestrator/finalizer composition point (the trait is frozen — implement
   it); wire the `ask_carina` dispatch row in `BuiltInToolRunner` (deferred
   from W4.1d5 part 2) — its `emitCarinaAnswer`/`onPosted` tool-context slot
   closes here.
10. **The carina memory-extraction job handler** (v4
    `carina-memory-extraction.ts`, 199): the synthetic one-slice transcript
    (question/answer, no user-controlled char → SELF-only) over the PORTED
    `processTurnForMemory`. Port as a service function
    (`services::carina_memory_extraction`); the job RUNNER dispatch row is
    W4.8's.

## Differential plan (`carina_query_tier3_equivalence`)

Jest real-DB oracle driving v4's REAL `runCarinaQuery` over a two-DB baked
fixture (three characters — one `canBeCarina`, one name-collision pair;
vaults + memories + gate-band vectors; prior carina exchanges baked via v4's
real writer; connection profiles incl. a webSearch-capable fallback), with
the model boundaries canned (recorded stream keys prove the system-prompt +
history bytes), tool calls canned per the native-loop three-boundary split,
API key canned, Brahma console mocked to the same canned seam. Cases:
plain answer (no tools), name-collision (canBeCarina preferred), asker-gate
refusal (`not-found`), profile chain fallback (default → webSearch), memory
recall present (canned embedding), prior-exchange replay, one tool
iteration + threading, forced-text final turn, empty → `llm-failed`,
whisper vs public targeting, Brahma gate (reachable + unreachable), and the
extraction enqueue. Diff: result objects + `chat_messages` + `chats` +
`background_jobs` (minted values per the established forms). Then extend
`message_finalizer_tier3` / `orchestrator_tier3` with a live `@Name:` markup
case (the runner's seam now real) and a live `ask_carina` tool call; the
extraction handler gets its own differential over the ported processor
(`carina_memory_extraction_tier3_equivalence` — SELF-only outcome banked).

  recorded stream key.

  (`[[chain-depth-frozen-clock-artifact]]`).

  per-case fresh fixture copies.

  reuse the native loop module; port the 5-iteration shape faithfully
  (different accept/force-final semantics).
