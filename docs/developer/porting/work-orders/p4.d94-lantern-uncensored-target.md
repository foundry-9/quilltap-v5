## The drift, classified (surveyed 2026-08-19, fresh at `9125f492`)

A behavior change on two ported surfaces (the STORY_BACKGROUND_GENERATION
handler and the cheap-LLM story-background prompt crafter). v4's crafter
carried a "depicting intimate or unclothed states" section that translates
narrative nudity into cinematic concealment (drapery, silhouette,
foreground occlusion) — moderation armor baked unconditionally into the
system prompt constant. A dangerous-marked chat with an uncensored image
profile got accurate appearance text (the appearance sanitizer already
steps aside for exactly that case) fed into a crafter that then draped a
sheet over it. v4 now selects the intimacy guidance per call:

1. `StoryBackgroundPromptContext` gains optional `uncensoredImageTarget`;
   the prompt constant becomes a shared head/tail plus one of two
   intimacy blocks and one of two worked examples, assembled by a builder
   — **the concealed/default path stays byte-identical to the old
   constant**.
2. The handler computes `uncensoredImageTarget = isDangerousChat &&
   hasUncensoredImageProvider` — the SAME two booleans the appearance
   sanitizer uses — and threads it into the initial craft AND the
   empty-response retry (carried UNCHANGED on the retry: swapping in the
   uncensored *text* profile does not change the *image* target).
3. The post-hoc moderation-rejection reroute re-crafts the prompt
   candidly for the reroute target (skipped when the prompt was already
   candid), re-runs the step-9b character-enumeration pass over the
   replacement, and is best-effort in BOTH failure shapes (a soft empty
   result and a thrown error each keep the existing concealed prompt so
   the reroute still produces an image).

Unchanged in v4 and therefore out of scope: the `generate_image` tool's
crafter (never had concealment language), the avatar builder, and
concealment as the default for moderated providers.
