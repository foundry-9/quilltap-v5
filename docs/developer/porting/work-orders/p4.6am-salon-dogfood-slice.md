### Finding #7 — the chained-response rendering gap

**v5 today:** the reducer already does the accumulation work —
`core/chat-stream.reducer.ts` `ChatStreamState.messages:
StreamMessage[]` (`:117-118`; the union kind assistant/carina/host at
`:63-83`, assistant carries `intermediate: boolean`). `reduceDone()`
(`:280-354`) folds each finished bubble in via `dedupePush` keyed on
the server messageId; intermediate dones skip empty bubbles
(`emitBubble = prev.inChain ? content.trim().length > 0 : true`,
`:326-345`). `turnComplete` (`:247-249`) resets ONLY the live buffer;
`chainComplete` (`:252-263`) is terminal. **The gap is render-side:**
`chat/streaming-message.ts` renders ONLY the live buffer
(status/content/reasoning/toolBatches/error — no `.messages`
reference anywhere), and `screens/salon/salon-conversation.ts`
`displayMessages` (`:544-555`) merges only the canonical
`['chat', chatId]` query messages (with swipe overrides) + the
optimistic user bubble. On turn completion `runTurn()` (`:745-811`)
invalidates the chat query and sets `stream` to null (`:799-803`) —
so the accumulated `state.messages` are never shown, then dropped.

**v4 semantics to match** (`app/salon/[id]/hooks/useSSEStreaming.ts`):
each intermediate `done` appends a finished ASSISTANT bubble with the
**server-assigned id** to the visible list (`onIntermediateDone`,
`:759-788`) — dedupe against the canonical refetch is by id; Carina
answers and Host announcements append live with an explicit
some-by-id dedupe (`:684-691`); skipped turns append NOTHING
(`data.skipped` → buffer reset only, `:763-767` — the Host note
arrives separately); `turnComplete` triggers a refetch in v4, but v5's
single reconcile-at-end is the established P4.2-era arrangement —
keep it, render the accumulated bubbles instead.

**The fix shape:** render `state.messages` (assistant + carina +
host) in the streaming region above the live bubble — either in
`message-list.ts` (it already receives `[stream]`, `:97-98`) or a
sibling of `qt-streaming-message` — deduped by id against
`displayMessages` so the post-reconcile canonical rows never double
up. Reuse the ported message rendering (markdown pipeline, memoized
per the P4.6h arrangement) so a chained bubble looks identical before
and after the refetch handoff.

## Shared contract (BINDING — identical in all three orders)

### §1 New dispatch variants (lane A implements in Rust; TS mirrors per §2)

Names and shapes are pinned; no lane renames:

- `textReplacementsList` `{}` →
  `{ rules: TextReplacementRule[], count: number }`
- `textReplacementCreate`
  `{ fromText, toText, caseSensitive?, enabled?, sortOrder? }` → the
  created rule (v4 201-created envelope; duplicate
  fromText+caseSensitive → the v4 conflict arm)
- `textReplacementUpdate` `{ id, ...partial rule input }` → the
  updated rule
- `textReplacementDelete` `{ id }` → v4's delete envelope
- `textReplacementsBulkReplace` `{ rules: input[] }` →
  `{ rules, count }` (transactional full-list replace)
- `chatGetBackground` `{ chatId }` →
  `{ backgroundUrl, fileId, filename, sha256, linkSummary }` (all-null
  when the chat has no `storyBackgroundImageId` or the file row is
  missing — v4 `get.ts:182-193`)

`TextReplacementRule` (camelCase serde, exactly these keys):
`{ id, fromText, toText, caseSensitive, enabled, sortOrder, createdAt,
updatedAt }`.

REST edges (lane A): `GET/POST /api/v1/settings/text-replacements`,
`POST /api/v1/settings/text-replacements?action=bulk-replace`,
`PATCH/DELETE /api/v1/settings/text-replacements/:id`,
`GET /api/v1/chats/:id?action=get-background` — each edge UNWRAPS the
dispatch envelope to v4's raw route body (the P4.6ah lesson).
