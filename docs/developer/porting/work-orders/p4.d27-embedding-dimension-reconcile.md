## The drifted commit, classified (2026-07-30)

`7391404e` fixes v4's dimension-mismatch outage: switching the default
embedding profile to OpenAI `text-embedding-3-large` never re-embedded the
legacy TF-IDF corpus (258-d raw Float32 blobs), so ~19.7k of ~27.6k memories,
888 conversation chunks, and 27 mount chunks were invisible to vector search
and the jobs child warned continuously. Four behavior surfaces:

1. **NEW startup self-heal** `lib/startup/reconcile-embedding-dimensions.ts`

   meta, NULLs stale-chat chunks to the cold-tier state, counts recoverable
   mismatches per entity type, and enqueues ONE deduped `mismatched-dim`
   EMBEDDING_REINDEX_ALL. COUNT-only when the corpus conforms. **PORT TARGET
   (new module).**

   embedding-reindex.ts`): new Phase 4 re-embeds doc mount chunks (enabled
   mounts only); the memory fan-out switches from `characters.findByUserId`

   silently dropped); stale chats skip in the chunk phase; FAILED entities
   skip in `mismatched-dim` scope. **Lands on the PORTED P4.6BM handler.**
3. **Housekeeping merge pass** skips dimension-mismatched entries quietly
   (one summary log instead of a warn per entry). **Lands on the PORTED

4. **PUT `/api/v1/embedding-profiles/[id]` trigger matrix** (becoming

### 1. The new reconcile module — `lib/startup/reconcile-embedding-dimensions.ts`

Suggested v5 home: `crates/quilltap-core/src/services/
embedding_dimension_reconcile.rs` (sibling of
`conversation_render_reconcile.rs`, whose shape it copies).

Shapes and exports (v4 lines):
- `EmbeddingDimensionReconcileResult` (:52–72): `{ targetDimensions:
  number|null, skippedReason: 'no-profile'|'builtin-profile'|'no-fixed-dim'
  |'db-unavailable'|null, vectorEntriesDeleted, vectorIndexMetaFixed,
  staleChunkEmbeddingsCleared, mismatched: { memories, conversationChunks,
  helpDocs, mountChunks }, reindexEnqueued: boolean }` + `EMPTY_RESULT`
  (:74–80).
- `reconcileEmbeddingDimensions()` (:128–137) wraps `runReconcile()` in
  try/catch — **never throws into the startup path**; on error logs and
  returns `{targetDimensions: null, skippedReason: null, ...EMPTY_RESULT}`.

Phase structure of `runReconcile()` (:139–282), arm by arm:
1. DB unavailable → skip `'db-unavailable'` (:140–144).
2. Default profile resolved **straight off the row** (`SELECT id, userId,
   provider, dimensions, truncateToDimensions FROM embedding_profiles WHERE
   isDefault = 1 LIMIT 1`, :148–161). No profile → `'no-profile'`;
   `provider === 'BUILTIN'` → `'builtin-profile'` (:163–168) — BUILTIN dims
   are the fitted vocabulary size, owned by the refit pipeline.
3. `targetDim = truncateToDimensions ?? dimensions`; missing/≤0 → warn +
   `'no-fixed-dim'` (:170–177).
4. `DELETE FROM "vector_entries" WHERE <NONCONFORMING>` (:189–194) —
   deleted outright (derived data), **no NOT_FAILED, no user scoping**.
5. `UPDATE "vector_indices" SET dimensions = ? WHERE dimensions != ?`
   (:198–203).
6. Either changed → `getVectorStoreManager().unloadAll()` (:205–209) —
   **documented no-op in v5** (no in-memory store cache; carry the note, the
   `embedding_reindex_job.rs:47–55` precedent).
7. `clearStaleChatNonconformingChunks` (:313–353): candidates = `SELECT
   DISTINCT "chatId" FROM "conversation_chunks" WHERE "chatId" IS NOT NULL
   AND <NONCONFORMING>`; per candidate fetch `{id, updatedAt}` from `chats`,
   staleness via the **shared** gate (`isStale({id, updatedAt: updatedAt ??
   ''}, cutoffMs, repos)`, `cutoffMs = retentionCutoff(await
   resolveStaleChatDays()).getTime()`); stale ⇒ `UPDATE "conversation_chunks"
   SET embedding = NULL WHERE "chatId" = ? AND <NONCONFORMING>` — converge to
   the exact state the stale sweep produces; Salon reopen re-embeds.
8. Recoverable-mismatch COUNTs (all guarded by `tableExists`, :117–122):
   - memories (:221–234): `(embedding IS NULL OR <NONCONFORMING>) AND
     "characterId" IS NOT NULL AND <NOT_FAILED('memories')>` binding
     `(targetDim, 'MEMORY', profile.id)` — the `characterId IS NOT NULL`
     guard mirrors the reindex fan-out so unreachable rows don't re-trigger
     every boot; NULL included ("nothing else re-embeds a NULL there").
   - conversation chunks → `countNonconformingLiveChunks` (:291–305):
     `<NONCONFORMING> AND "chatId" IN (SELECT "id" FROM "chats") AND
     <NOT_FAILED>` — **orphan exclusion**; NULL NOT counted (cold tier);
     stale chats already NULLed above so they no longer match.
   - help_docs (:241–245): includeNull variant.
   - mount chunks → `countNonconformingMountChunks` (:360–408): whole thing
     try/catch → 0 on error; `SELECT id FROM doc_mount_points WHERE enabled
     = 1` on the MAIN DB; chunks live in the **separate mount-index DB — no
     cross-DB JOIN, ids carried over as placeholders**; FAILED exclusion
     pulled from main (`entityType = 'MOUNT_CHUNK'`) and applied **in memory
     as a Set filter**.
9. `totalMismatched > 0` → `enqueueMismatchedReindex` (:415–431). **Dedupe:**
   `backgroundJobs.findRecentByType('EMBEDDING_REINDEX_ALL', 10)`; any
   PENDING/PROCESSING among those 10 → log "already queued" and return false;
   else enqueue `EMBEDDING_REINDEX_ALL` with `{ profileId, scope:
   'mismatched-dim' }`.
10. Log shape (:258–279): `touchedAnything` → `logger.info('Embedding
    dimension reconcile found non-conforming vectors', {...full result...})`;
    else `logger.debug('...corpus conforms', {profileId, targetDimensions})`.
    **Port the two-arm shape** — don't repeat the §4c gating gap.

Key SQL to port **verbatim** (byte-identical row selection is the point):
- `NONCONFORMING` (:83): `embedding IS NOT NULL AND ${EMBEDDING_DIM_SQL} != ?`
- `NOT_FAILED(table)` (:90–96): `NOT EXISTS (SELECT 1 FROM "embedding_status"
  es WHERE es."entityType" = ? AND es."entityId" = "<table>"."id" AND
  es."profileId" = ? AND es."status" = 'FAILED')` — binds entityType then
  profileId.
- `EMBEDDING_DIM_SQL` (moved to `float32-conversion.ts` ~:282–295, exported):

  ```sql
  CASE
    WHEN substr(embedding, 1, 3) = X'EB0101' THEN length(embedding) - 11
    WHEN substr(embedding, 1, 3) = X'EB0102' THEN (length(embedding) - 7) / 2
    ELSE length(embedding) / 4
  END
  ```

  (int8: 11-byte header + 1 byte/dim; f16: 7-byte header + 2 bytes/dim; else
  legacy raw Float32.) **v5 has NO `EMBEDDING_DIM_SQL` anywhere** — v5's
  convention decodes dims in Rust (`blob_to_float32(...).len()`). For the
  reconcile, port the SQL const (home it beside the codec in
  `crates/quilltap-core/src/embedding_blob.rs`, v4's "beside the blob layout"
  rationale) so DELETE/COUNT row selection is byte-identical to v4 AND keeps
  the COUNT-only boot path cheap. Note the semantics split the survey found:
  v4 measures in SQL here but in JS (`embedding.length`) in the reindex's
  dim-match — they agree on well-formed blobs; do not "unify" them.

### 2. Boot wiring — `quilltap-host/src/host.rs` (`seed_built_ins`, :763–848)

v5's analog of v4's 3.x boot chain is ONE `write_blocking` closure on a
spawned-and-joined OS thread: template seeds → fictional-clock repair → the
P4.6BM render reconcile (v4 Phase 3.6) at :800–817 → the mount-index block
(`ws.mount_index()`, :819+). **The dimension reconcile inserts immediately
after the render-reconcile block (~:818), inside the same closure** — v4's
3.6-then-3.7 order preserved. Constraints, all inherited from P4.D25:

- **`&Connection` twins throughout.** Inside `write_blocking` the read pool
  is out of reach; a nested `&Db` read deadlocks. Use `is_stale_conn`
  (`services/maintenance.rs:235`) + `resolve_stale_chat_days_conn`
  (`services/queue_service.rs:838`) — NOT the `&Db` flavors. Mixing them up
  compiles and deadlocks at runtime (the exact P4.D25 trap).
- **The enqueue cannot call the async `enqueue_embedding_reindex_all`**
  (`queue_service.rs:782–793` — which already exists, priority −1.0,
  maxAttempts 3, and whose doc :776–781 names this exact future
  `Some("mismatched-dim")` caller). Follow the render reconcile's precedent:
  write the job row directly on the held connection.
  `background_jobs.rs:791–804` already has `find_recent_by_type` for the
  dedupe — it may need a `_conn` twin.
- **Mount-index access:** the mount-chunk count needs `ws.mount_index()`
  (available on the same `ws`); on a main-only instance skip that count to 0,
  mirroring v4's try/catch-to-0.
- **Fire-and-forget divergence note:** v4 runs Phase 3.7 async
  fire-and-forget (`instrumentation.ts:862–888`); v5's boot seeds are
  synchronous-on-a-joined-thread. v5's existing reconcile already accepts
  this — the COUNT-only fast path bounds the boot cost and the repair is
  enqueued, never inline. Carry the divergence note in the module doc.

**The dogfood rider (free, log-only, outside the differential contract per
P4.18):** `host.rs:805` gates the render-reconcile boot log on
`reconcile.enqueued > 0 || reconcile.failed > 0`, so the healthy outcome
(`enqueued ≈ 0`, `skipped_stale` large) prints nothing —
`dogfood-findings.md:117–125`. Fix per the finding: log unconditionally when
`incomplete_chats > 0` (nearer v4, which logs a "found incomplete
conversations" line before its loop and its completion line unconditionally),
or at minimum `|| reconcile.skipped_stale > 0`.
