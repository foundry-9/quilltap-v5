## The drift, classified (surveyed 2026-07-30)

One commit past `5cc76688`:
`dcd9440a fix(stores): a failed properties.json read no longer wipes project settings`.

v4's `readProperties` in the document-store overlay engine caught EVERY error
and returned `null`; its callers read `null` as "no file yet, seed from the raw
row", and post-4.7-cutover the slim row carries no property values — so one
transient store failure reset an entire project/group settings bag to schema
defaults, invisibly (the no-default optionals serialize to nothing) and
compoundingly (every later read-modify-write re-seeds from the wiped file).
Observed on a real v4 instance: a project silently lost
`defaultDisabledTools`, `defaultAgentModeEnabled`, `storyBackgroundImageId`,
`backgroundDisplayMode`, and four more keys; the visible symptom was the
Lantern generating backgrounds and never announcing them.

**The drifted surfaces:**

1. `lib/database/document-store-overlay.ts` — `readProperties` now returns
   `null` ONLY for a genuinely absent `properties.json` (a
   `DatabaseStoreError` with code `NOT_FOUND`); it THROWS the entity's
   unavailability error when the file exists but is unreadable, malformed
   JSON, or fails schema validation. It gains an optional `entityId` param
   (default `'(unknown)'`) used in the error message, and logs at `error` on
   both refusal paths (`debug` on the genuine-absence path).
   `applyWriteOverlay` passes the entity `id` through and now propagates the
   throw instead of writing a defaults-seeded bag. **PORTED surface** — v5's
   `read_properties` (`crates/quilltap-core/src/db/document_store_overlay.rs:381-395`)
   reproduces the OLD fail-soft behavior line-for-line (`from_str` error →
   `Ok(None)`; `parse_properties(...).ok()` → `None`), and
   `apply_write_overlay` (:501-511) then seeds from `parse(entity)` = the
   defaults. **This is the lane's port target.**
2. `lib/startup/backfill-project-stores.ts` + `backfill-group-stores.ts` —
   the throw now routes to their existing per-entity catch, so a store that
   merely failed to read is counted as an error and skipped rather than
   "healed" by overwriting all four overlay files. **UNPORTED surface** — the
   startup-backfill slice is a standing v5 deferral (see
   `db/ensure_official_store.rs`'s scope note: the adopt heuristic "lands
   with the startup-backfill slice"). **No v5 action**; record in the lane
   record that the backfill slice, when it runs, must port the POST-`dcd9440a`
   behavior.
3. `__tests__/unit/lib/projects/project-store-write-overlay.test.ts` — NEW
   174-line jest suite; its six cases are the differential-case blueprint
   (enumerated under "Tiered deliverables").
4. `README.md` / `docs/CHANGELOG.md` / version chores — no action.

  entityId = '(unknown)')`: NOT_FOUND → `logger.debug` ("… absent — caller may
  seed defaults") + `null`; any other read error → `logger.error` ("…
