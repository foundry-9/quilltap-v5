## The drift, classified (2026-07-28)

Four commits past `e8a49597`, all authored 2026-07-28, fixing v4's
`found-bugs.md` Bug 6 (both halves) and Bug 7. Every one of the first three
carries an explicit "Oracle note for the v5 port" naming its `lib/` changes.
**All drifted surfaces are PORTED in v5** (P4.6BL/P4.6BM landed the embedding
worker + startup reconcile; the sweeps and repos are older), so this is a pure
catch-up: no new subsystem, no SPA surface, no schema change.

1. **`a0243abd` — "the boot reconcile leaves cold-tiered chats cold" (Bug 6).**
   The startup render/embed reconcile read the cache collapse's deliberate
   cold-tiering (NULL `renderedMarkdown`, NULL chunk embeddings) as damage and
   re-rendered + re-embedded the entire cold tier on every boot (~$2/restart on
   the measured Friday instance). Fix: the reconcile filters its scan through
   the shared `isStale` gate + `resolveStaleChatDays()` window; stale chats
   skip (the chat-open `cold-chunk-reembed` path remains their recovery);
   unknown staleness skips rather than heals; the result/log gain
   `skippedStale`. `lib/` files: `lib/startup/reconcile-conversation-rendering.ts`
   (behavior), `lib/background-jobs/maintenance/collapse-stale-chat-assets.ts`
   (**type-only**: `isStale` param narrowed to `Pick<ChatMetadata,'id'|'updatedAt'>`).
2. **`f7cc887b` — "reopen re-embeds survive the stale-chat sweep" (Bug 6
   follow-up).** Reading a cold chat re-embedded it on open, but reading never
   counts as played activity, so the next sweep discarded the fresh vectors —
   one paid re-embed per read/sweep cycle. Fix: `clearEmbeddingsForChat` gains
   an optional `olderThan` ISO cutoff (`AND updatedAt < ?`) and the caches
   sweep binds its staleness cutoff to it — embeddings younger than the
   retention window are deliberate warmth and survive. No schema change; the
   embedding row's own `updatedAt` is the signal. `lib/` files:
   `lib/database/repositories/conversation-chunks.repository.ts`,
   `lib/background-jobs/maintenance/collapse-stale-chat-caches.ts`. Also
   `help/data-retention.md` (+2 content lines — **no v5 action**: v5 syncs help
   docs from disk at runtime via `load_help_source_files`, vendoring nothing).
3. **`a5d6cee5` — "mark* outcomes actually land, and FAILED chunks stop
   re-rendering every boot" (Bug 7).** `markAsEmbedded`/`markAsFailed` were
   find-then-update and silently returned null when no row existed — which,
   since the enqueue-time upserts left v4, was *every* newly-minted entity — so
   `embedding_status` never recorded an outcome. Fix: both mark* now **upsert**
   and take a **required `userId`** (needed to mint a row); the
   embedding-generate handler passes `job.userId` at all 13 v4 call sites; and
   the reconcile's condition (B) excludes chunks with a FAILED status for the
   profile a re-embed would actually use (default, else first; no profile → a
   sentinel that matches no rows). `lib/` files:
   `lib/database/repositories/embedding-status.repository.ts`,
   `lib/background-jobs/handlers/embedding-generate.ts`,
   `lib/startup/reconcile-conversation-rendering.ts`.
4. **`083fdf68` — version chore.** No `lib/` source; the large `plugins/dist/*`
   diffs are dist rebuilds (no plugin source changed in the drift). Baseline
   commit only.

## Survey-verified starting points (2026-07-28 — from the `e8a49597..083fdf68` diff and v5 main at `9d9042b8`)

### 1. `db/embedding_status.rs` — mark* become upserts with required userId

v5 today: `crates/quilltap-core/src/db/embedding_status.rs:227`
(`mark_as_embedded`) and `:251` (`mark_as_failed`) — both find-then-update,
`Ok(false)` when the (entityType, entityId, profileId) triple has no row, with
a doc comment explicitly recording the OLD v4 semantics ("a marker never
invents it") — that comment is now wrong and must be replaced with v4's new
*why* (the enqueue-time upsert paths left v4; outcomes were silently lost).

v4's new shape (both functions):
- **exists** → `update` with the same patch as before (`markAsEmbedded`:
  status EMBEDDED, embeddedAt = now, error = null; `markAsFailed`: status
  FAILED, error — embeddedAt untouched).
- **missing** → `logger.debug(...)` then `create({ userId, entityType,
  entityId, profileId, status, embeddedAt, error })` — `markAsEmbedded` sets
  `embeddedAt: now`, `error: null`; `markAsFailed` sets `embeddedAt: null` and
  the error string. `userId` is a new REQUIRED parameter on both.
- Preserve v5's two-clock-read order note where it still applies on the update
  arm; the create arm mints its own timestamps via the repo's create path —
  match v4's field-for-field create payload and let the harness's frozen clock
  prove the stamps.
- Return type: v4 returns the row/null; v5 returns `Ok(bool)` today. Keep
  whatever v5 signature is faithful (callers only need success), but the
  differential diffs the resulting DB rows either way.

### 5. `services/conversation_render_reconcile.rs` — the big one

v5 today: `crates/quilltap-core/src/services/conversation_render_reconcile.rs`
— `SELECT_INCOMPLETE_CHATS` at `:59` (binds only `?1` = EMBEDDING_MAX_CHARS),
`ReconcileResult` at `:82` (no `skipped_stale`), `IncompleteChat` at `:95` (no
`updated_at`), `pub fn reconcile_conversation_rendering(main: &Connection)` at
`:111`. Host caller: `crates/quilltap-host/src/host.rs:798`.

v4's new `SELECT_INCOMPLETE_CHATS`, verbatim (port byte-faithfully; `?1` =
EMBEDDING_MAX_CHARS, `?2` = the resolved default profile id):

```sql
  SELECT c."id" AS chatId, c."userId" AS userId, c."updatedAt" AS updatedAt
  FROM "chats" c
  WHERE (
    -- (A) Real messages but never rendered to Markdown.
    c."renderedMarkdown" IS NULL
    AND EXISTS (
      SELECT 1 FROM "chat_messages" m
      WHERE m."chatId" = c."id"
        AND m."type" = 'message'
        AND m."role" IN ('USER', 'ASSISTANT')
    )
  ) OR EXISTS (
    -- (B) At least one recoverable un-embedded interchange chunk
    --     (non-empty, within the embedder's size cap, and not already
    --     permanently FAILED for the current default profile).
    SELECT 1 FROM "conversation_chunks" cc
    WHERE cc."chatId" = c."id"
      AND cc."embedding" IS NULL
      AND LENGTH(cc."content") BETWEEN 1 AND ?
      AND NOT EXISTS (
        SELECT 1 FROM "embedding_status" es
        WHERE es."entityType" = 'CONVERSATION_CHUNK'
          AND es."entityId" = cc."id"
          AND es."profileId" = ?
          AND es."status" = 'FAILED'
      )
  )
```

The new behavior around it, arm by arm (all from the diff):

- **Profile resolution** (before the scan): `embeddingProfiles.findAll()`,
  pick `isDefault` else first, `?.id ?? ''`. On error → `logger.warn("Failed
  to resolve default embedding profile; FAILED-status exclusion disabled")`
  and keep `''` — the sentinel matches no rows, so the exclusion no-ops.
  (v5: `db::embedding_profiles` has the reads; same selection the render
  handler makes.)
- **Staleness gate** (per row, after the scan): resolve
  `cutoffMs = retentionCutoff(await resolveStaleChatDays()).getTime()` once,
  then for each row `isStale({ id, updatedAt: row.updatedAt ?? '' }, cutoffMs,
  repos)` → stale ⇒ `skippedStale++`, continue. **A thrown staleness check
  also skips** (`skippedStale++`, warn "Staleness check failed during
  reconciliation; skipping chat") — unknown staleness skips, never heals; the
  Salon open path is the recovery. Two distinct fail-soft arms — port both.
- **`skippedStale`** joins the result struct and the summary log line.
- Carry v4's new header paragraph (why stale chats are excluded — the two
  subsystems fought) and the SQL comment block about FAILED exclusion.

**Integration point the lane must solve:** v5's reconcile takes
`&Connection`, but `is_stale` is `pub(crate) fn is_stale(db: &Db, chat:
&Value, cutoff_ms: i64)` (`services/maintenance.rs:219`) and
`resolve_stale_chat_days(db: &Db)` (`services/queue_service.rs:830`) both need
`&Db` (is_stale does a `read_main` for the last played message). Re-signature
the reconcile to take `&Db` (adjusting `host.rs:798`) — the boot site runs on
the writer thread either way. Synthesize the `chat` Value as
`json!({"id": …, "updatedAt": …})` — which matches v4's narrowing of `isStale`
to `Pick<ChatMetadata,'id'|'updatedAt'>` exactly.
