**v5:** the guard (`workspace/workspace-redirect.guard.ts:31-43`) builds
`queryParams` as ONLY `{ open }` + the per-route `ParamMapper`'s output;
`app.routes.ts:130-133` binds `settings/wizard` with NO mapper, so the

**The prescribed fix:** the `settings-wizard` guard binding
**passes through** (does not redirect) when `mode=setup` is present — the

`SettingsWizardTabPayload`, so the query cannot ride a tab payload; v4
has no equivalent handoff (its setup pages are a documented divergence,
`m6-screen-parity.md` §1.7), so there is no oracle to violate. Record it
as a documented divergence in the guard's comment. If you find v4
evidence contradicting this (an actual v4 workspace arm for setup),
STOP and flag instead.
