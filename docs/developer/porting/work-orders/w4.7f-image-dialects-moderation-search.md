## 1. The image wire dialects (extend `model::image` sans-IO)

Per provider: `build_image_request -> BuiltRequest` +
`parse_image_response -> ImageGenResponse` (`{images: [{data|url,
mimeType, revisedPrompt?}]}`), with the rejection shapes normalized to the
exact error STRINGS v4 surfaces (that's what the already-ported
`isImageModerationError` matches):

- **OPENAI** (SDK `images.generate`): `model, prompt, n`;
  `response_format:'b64_json'` ONLY for non-gpt-image models; size
  validated/normalized; `quality` (default standard) + `style` (default
  vivid) only for non-gpt-image. Parse `b64_json || url || ''`,
  mimeType HARDCODED `image/png`, `revised_prompt`. Moderation string
  comes from the UPSTREAM SDK throw ("…safety system…") — fixtures must
  be RECORDED SDK errors, never synthesized 200s. Explicit throw only:
  `Invalid response from OpenAI Images API`.
- **GOOGLE, two dialects** (raw fetch, `x-goog-api-key` header):
  - Imagen `:predict` (`imagen-4`→`imagen-4.0-generate-001`,
    `imagen-4-fast`→`…fast-generate-001`): body `{instances:[{prompt}],
    parameters:{sampleCount, aspectRatio?, seed?}}`; parse
    `predictions[].bytesBase64Encoded` + per-prediction mimeType. The
    ONLY manufactured moderation error in v4: the empty-200 branch
    collects `raiFilteredReason` (prediction-level ?? data-level ??
    `filteredReason`) and throws
    `` Google Imagen rejected prompt by content policy${reason ? `: ${reason}` : ''} `` —
    byte-exact, keyword-matching. HTTP errors throw
    `error.error?.message || 'Google Imagen API error: {status}'`.
  - Gemini `:generateContent`: body `{contents:[{parts:[{text}]}],
    generationConfig:{responseModalities:['TEXT','IMAGE'],
    imageConfig?}}`; parse `candidates[0].content.parts[].inlineData`;
    text parts captured. Empty-images throws `textResponse || 'No images
    returned from Gemini API'` — the documented keyword GAP.
- **GROK** (OpenAI SDK, `baseURL https://api.x.ai/v1`): `model, prompt,
  n, response_format:'b64_json'`, `aspect_ratio`, `resolution:'2k'` for
  `-pro` imagine models. mimeType HARDCODED `image/jpeg`. Moderation via
  upstream throw ("…rejected by content moderation.") — recorded fixture.
- **OPENROUTER** (raw fetch to the CHAT endpoint
  `/api/v1/chat/completions`): `{model, messages:[{role:'user',
  content:prompt}], modalities:['image','text'], image_config?}`;
  ⚠️ `negativePrompt` and `style` are APPENDED TO THE PROMPT STRING;
  `quality==='hd'` → `image_config.image_size:'4K'`. Parse
  `message.images[].image_url.url` via the
  `data:(image/[^;]+);base64,(.+)` regex, content-array fallbacks.
  Refusal: `Model declined to generate an image: {text sliced to 200}` —
  the documented keyword GAP (never reroutes).
- **Z-AI** (OpenAI SDK, `/paas/v4/images/generations`): `model, prompt,
  n, size` (default `1280x1280` for glm-image else `1024x1024`),
  `quality`. Parse keeps BOTH `b64_json` AND `url` (30-day URLs — the
  only provider populating `url` on the happy path). No moderation
  handling — the gap.

Wire the dialects into the real `ImageProvider` impl over the transport
seam (W4.7d's trait — see the round note below); the sans-IO build/parse
is verified independently of transport.

## 3. The real `ModerationProvider` (closes W4.2's seam)

Only `qtap-plugin-openai` registers moderation. Port: `POST
{base}/v1/moderations` (trailing slash stripped), `Authorization: Bearer`,
body `{input: content}`; HTTP error throws
`OpenAI moderation API error ({status}): {errorText}`; parse
`results[0]` → `ModerationResult {flagged, categories: [{category,
flagged, score}]}` from `Object.entries(categories)` with
`category_scores[cat] ?? 0`; empty results → `{flagged:false,
categories:[]}`. The ported `mapModerationResult` input shape is CONFIRMED
compatible — compose, don't touch. `autoDetectModerationApiKey` is the
connection-PROFILE provider match → `apiKeyId` →
`findApiKeyByIdAndUserId` (W4.7d's `db::api_keys` — see the round note).

## 4. The real `WebSearchProvider` (closes the W4.1d5 seam)

- Serper plugin: `POST https://google.serper.dev/search`, headers
  `X-API-KEY` + User-Agent, body `{q, num}`. ⚠️ Errors are RETURNED (not
  thrown) with exact strings: 401/403 → `Invalid Serper API key. Please
  check your API key in Settings > API Keys.`; 429 → `Serper API rate
  limit exceeded. Please try again later or upgrade your plan at
  serper.dev.`; else `Serper API error: {status} {statusText} -
  {errorText}`; catch → `error.message || 'Unknown error during Serper
  web search'`. Result map: `organic[]` → `{title, url:link, snippet,
  publishedDate:date}`; the knowledgeGraph row UNSHIFTED when
  `kg.description && results.length < maxResults` (title
  `kg.title ?? 'Knowledge Graph'`, url `kg.source?.link ?? ''`).
- The handler's key lookup (`getAllApiKeys()` scan for `provider===X &&
  isActive`) and the deprecated env-var Serper fallback
  (`SERPER_API_KEY`, only when NO provider plugin is registered; slightly
  DIFFERENT error strings — port both string sets faithfully). The env
  var is host config — inject it.
- **`formatResults`** (the tracked v5 deferral — close it): the verbatim
  `[Result {i+1}]{dateStr}\nTitle: …\nURL: …\nSummary: …` blocks joined
  `\n\n` under `Found {n} search results:\n\n`; empty → `No search
  results found.` ⚠️ `dateStr` is
  `` ` (Published: ${new Date(publishedDate).toLocaleDateString()})` `` —
  and Serper's `date` is a FREE-FORM string ("2 days ago"), so the COMMON
  rendering is literally `(Published: Invalid Date)`. Reproduce: JS
  date-parse for the corpus value space (ISO strings → en-US `M/D/YYYY`,
  UTC-pinned per the `format_time` precedent; unparseable → the literal
  `Invalid Date`), documented as a bounded seam (exotic parseable formats
  kept out of the corpus). The handler's built-in fallback formatter is
  byte-identical — port ONCE, use twice.
