## The drift, classified (surveyed 2026-08-03)

+485/−7) — the Salon's custom-tool run dialog can save its parameter
values as named presets, list and load them from a dropdown, and reset to
defaults. A preset is an ORDINARY JSON document in the running character's
vault — `Tools/{tool}.{preset}.settings.json`, a flat object of parameter

`help/custom-tools.md` gains a Presets section (→ the `p4.9i2` bank; v5

- `lib/pascal/tool-presets.ts` (NEW, 52 lines, pure/client-safe — port
  verbatim): `PRESET_NAME_PATTERN = /^[a-z0-9][a-z0-9_-]{0,63}$/`
  (lowercase alnum lead, then `[a-z0-9_-]`, 1–64 chars, NO dots — tool
  names (`IDENTIFIER_PATTERN`) never contain a dot, so
  `{tool}.{preset}.settings.json` parses unambiguously);
  `PRESET_FILE_SUFFIX = '.settings.json'`;
  `sanitizePresetNameInput(raw)` =
  `raw.toLowerCase().replace(/[^a-z0-9_-]/g,'').slice(0,64)` — a
  keystroke filter, NOT a validator (it can yield `''` or `-x`, which the
  pattern refuses — two gates, deliberately);
  `presetSettingsPath(tool, preset)`;
  `parsePresetFromPath(tool, relPath)` — prefix `Tools/{tool}.` + suffix
  match, middle must pass the pattern, else `null` (rejects another
  tool's preset, prefix-sharing names like `coin` vs `coin_toss`,
  `.tool.json`, nested paths, `x..settings.json`, `x.a.b.settings.json`,
  mixed case).
- `__tests__/unit/lib/pascal/tool-presets.test.ts` (92 lines) — the
  port's test spec, three describes: pattern accepts `a`, `hard-mode`,
  `take_2`, `2nd-attempt`, `'a'×64`; rejects `''`, `has space`,
  `dotted.name`, `path/name`, `back\slash`, `Uppercase`, `-leading-dash`,
  `_leading-underscore`, `..`, `'a'×65`. Sanitizer:
  `'Hard Mode! v2.0'→'hardmodev20'`, `'../../etc/passwd'→'etcpasswd'`,
  200 chars → 64, `'hard-mode_2'` unchanged, and the explicit
  filter-is-not-the-validator cases (`'-x'→'-x'`; `'!!!'→''`).
  Round-trip: `presetSettingsPath('coin_toss','hard-mode') ===
  'Tools/coin_toss.hard-mode.settings.json'`.
