## Mandate

Port the STORAGE and API half of v4's character-subprompts feature so that a
v5 instance reads, writes, lists and resolves the `Subprompts/*.md` files v4
keeps in a character's vault, carries a seat's `selectedSubpromptIds`
through every participant write without losing it, answers the five
subprompt verbs and their REST edges with v4's bodies and guard order, fans a
subprompt edit or deletion out to every chat carrying it, and publishes the
realtime hints — and re-vendor the four `help/` files `2f4254b42` touched so
`help_tree_equivalence` is green at the new baseline. This order does NOT
render subprompts into any prompt (P4.D164's), does NOT touch `apps/web/**`
(P4.D165's), and does NOT open `characters_routes.rs` or any generator file
(the K lanes').

Measured at planning: `crates/quilltap-core/src/db/chats.rs:62`'s
`ChatParticipant` has NO `#[serde(flatten)]` carry, and every participant

### v4 — the module (`lib/subprompts/subprompts.ts`, 395 lines, NEW)

- Constants: `SUBPROMPTS_FOLDER = 'Subprompts'`, `SUBPROMPT_TITLE_MAX_LENGTH

  and `SubpromptForPrompt { title, content }`. Two error classes:
  `SubpromptNotFoundError(characterId, subpromptId)` — message `Subprompt

  answer `notFound('Subprompt')`) — and `SubpromptValidationError(message)`.
- **Pure helpers (tier-1, `:83-140`):**
  - `isValidSubpromptId(id)`: `typeof === 'string'`; `id.length` (UTF-16
    units) in `1..=120`; not `.`/`..`; no `[\\\/<>:"|?*]`; every
    `charCodeAt(i) < 32` refused (per UTF-16 unit); `id.trim() === id` (JS
    whitespace set — `jsstr` trim).
  - `subpromptPathForId(id)` = `` `Subprompts/${id}.md` ``.
  - `slugifySubpromptTitle(title)`: `.normalize('NFKD')` →
    `.replace(/[̀-ͯ]/g, '')` → `.toLowerCase()` (JS full-Unicode
    lowercase; v5's `str::to_lowercase` is byte-identical — Phase 1) →
    `.replace(/[^a-z0-9]+/g, '-')` → `.replace(/^-+|-+$/g, '')` →
    `.slice(0, 60)` → `.replace(/-+$/, '')`; empty ⇒ `'subprompt'`. After the
    class replace only ASCII survives, so `slice(0,60)` is 60 bytes.
  - `composeSubpromptContent(title, content)` = `serializeFrontmatter({title})
    + '\n' + content.trim() + '\n'` (v5 twin: `doc_edit::markdown_parser::
    serialize_frontmatter`, `markdown_parser.rs:53`).
  - `parseSubpromptContent(id, raw, updatedAt)`: `parseFrontmatter(raw)`
    (v5 twin `markdown::parse_frontmatter`, `markdown.rs:65`, with
    `body_start_offset` in UTF-16 units — `markdown_parser.rs:118` shows the
    `utf16_slice` idiom); body = `raw.slice(bodyStartOffset).replace(/^\n+/,
    '').trimEnd()`; title = `data.title` if a string with non-blank trim
    (trimmed), else the id.
  - Private: `isRootSubpromptFile(rel)` — case-INSENSITIVE `Subprompts/`
    prefix, no further `/`, case-insensitive `.md` suffix;
    `idFromRelativePath` strips the last segment's `.md` case-insensitively;
    `validateTitle` (trim; empty → `A subprompt needs a title`; `> 100`
    UTF-16 units → `A subprompt title is at most 100 characters`);
    `validateContent` (trim; empty → `A subprompt needs some instruction
    text`).
- **Vault resolution (`:146-178`):** reads use `repos.characters.findByIdRaw`
  (overlay-free; **archived characters still resolve**) and return
  `characterDocumentMountPointId ?? null`; writes use `findByIdRaw` too,
  then throw `SubpromptNotFoundError(cid, '(character)')` when missing,
  `CharacterArchivedError` when `archivedAt` is truthy, and for a live
  character WITHOUT a vault call `ensureCharacterVault(character)` and warn

  `{characterId, mountPointId}`. v5 twins: `characters_read::find_by_id_raw`
  (`db/characters_read.rs:289`), `is_archived` (`api/characters.rs:116` —
  JS-truthy), `character_vault::ensure_character_vault` (`db/
  character_vault.rs:246`, six args incl. the `CharacterVaultWriteInput` —
  measure what v4's `ensureCharacterVault(character)` projects and build
  the same input).
- **Reads (`:182-283`):** `listSubpromptsInVault(vaultId)` →
  `listDatabaseFiles(vaultId, {folder: 'Subprompts'})` filtered to
  `kind !== 'folder' && isRootSubpromptFile`; per file `readDatabaseDocument`
  → `updatedAt = new Date(mtime).toISOString()` → `parseSubpromptContent`;
  a per-file read error is SKIPPED with `logger.warn('Skipping unreadable
  subprompt file', {vaultId, relativePath, error})`; sort
  `a.title.localeCompare(b.title) || a.id.localeCompare(b.id)` (ICU en-US —
  v5's ICU4X collator); `logger.debug('Listed subprompts', {vaultId,
  count})`. `listCharacterSubprompts(cid)` → `[]` + debug when no vault.
  `readCharacterSubprompt(cid, id)` → `null` on invalid id, no vault, or
  `DatabaseStoreError` code `NOT_FOUND`; any OTHER error rethrows.
  **`resolveSelectedSubprompts(cid, ids)`** (`:254-283`, P4.D164's entry
  point): `[]` for null/empty; lists ALL, matches `id.toLowerCase()` against

## §C — the subprompts wire contract (BINDING — verbatim-identical in P4.D163, P4.D164 and P4.D165)

Every name below is the wire. Server lanes implement it; the SPA lane codes
against it (mocked until unification); the unifier runs the name-for-name
diff across the three orders' implementations.

### C.1 The record

`SubpromptRecord` — v4 `Subprompt` (`lib/subprompts/subprompts.ts:52-63`),
keys in THIS order on the wire:

```
{ id: string, path: string, title: string, content: string, updatedAt: string }
```

`id` = the vault file name sans `.md` (one path segment; stable across title
edits); `path` = `Subprompts/<id>.md`; `title` = frontmatter `title`, falling
back to the id; `content` = the body with frontmatter stripped, leading
newlines removed, `trimEnd`; `updatedAt` = the file's `lastModified` as an ISO
8601 string (`new Date(mtime).toISOString()`).

### C.2 The verbs (dispatch `type` literals; the v5 idiom of the
`characterPrompt*` family — every field camelCase on the wire, snake_case in
`api/types.rs`)

| verb | request | success body | v4 route |
|---|---|---|---|
| `characterSubpromptList` | `{ characterId }` | `{ subprompts: SubpromptRecord[] }` (title-sorted; `[]` for no vault / no folder) | `GET /api/v1/characters/[id]/subprompts` |
| `characterSubpromptGet` | `{ characterId, subpromptId }` | `{ subprompt: SubpromptRecord }` | `GET …/subprompts/[subpromptId]` |
| `characterSubpromptCreate` | `{ characterId, title, content }` | `{ subprompt }` (REST status **201**) | `POST …/subprompts` |
| `characterSubpromptUpdate` | `{ characterId, subpromptId, title?, content? }` | `{ subprompt }` | `PUT …/subprompts/[subpromptId]` |
| `characterSubpromptDelete` | `{ characterId, subpromptId }` | `{ success: true }` | `DELETE …/subprompts/[subpromptId]` |

Update and delete each run the fan-out (C.5) AFTER the write and BEFORE
answering; the fan-out's `{chatsTouched, seatsRecompiled}` is folded into the
info log line only, never into the body.

### C.3 The participant field

`selectedSubpromptIds?: string[]` on the participant record — v4
`ChatParticipantBaseSchema` / `ChatParticipantSchema` (`lib/schemas/
chat.types.ts:606,649`): `z.array(z.string().min(1).max(120)).optional()`,
placed in schema order **directly after `selectedSystemPromptId`, before
`displayOrder`**. Absent or empty → none.

- `chatCreate.participants[].selectedSubpromptIds?: string[]` — v4
  `createParticipantSchema` (`app/api/v1/chats/route.ts:97`):
  `z.array(z.string().min(1).max(120)).max(100).optional()`; the stored value
  is `isUserControlled ? [] : (data.selectedSubpromptIds ?? [])` — a
  CREATED participant ALWAYS carries the key (an array, possibly empty).
  The client OMITS the key when nothing is ticked or the seat is
  user-controlled, so a plain create stays byte-identical.
- `chatUpdateParticipant.selectedSubpromptIds?: string[]` — v4
  `updateParticipantSchema` (`app/api/v1/chats/[id]/schemas.ts:57`), same
  bounds; PRESENT replaces the whole set; ABSENT leaves it untouched (a
  plain `Option<Vec<String>>` — this field is NOT nullish; an explicit
  `null` is a Zod `invalid_type` 400, measured on v4 before pinning).
  The seat recompiles when the set changes by an ORDER-INSENSITIVE compare
  (`sameIdSet`), independently of the `selectedSystemPromptId` trigger.
- The chat-GET enrichment (`EnrichedParticipantDetail`) projects
  `selectedSubpromptIds: string[]` — ALWAYS present, `participant.
  selectedSubpromptIds ?? []`, placed directly after `selectedSystemPromptId`.
- `.qtap` export/import carries the key inside the participants blob (no
  writer change; `public/schemas/qtap-export.schema.json` documents it).

### C.4 Error envelopes (v4's `lib/api/responses.ts` sentences, byte-exact)

| condition | status | body `error` |
|---|---|---|
| character missing (`findByIdRaw`, overlay-free — an ARCHIVED character still resolves for reads) | 404 | `Character not found` |
| subprompt missing (get / update / delete-returned-false) | 404 | `Subprompt not found` |
| `subpromptId` fails `isValidSubpromptId` (get / delete; update after the body parse) | 400 | `Invalid subprompt id` |
| create/update body fails the Zod schema (`title` min 1 max 100 [code points]; `content` min 1; update: both optional) | 400 | v4's `validationError` envelope (`error: 'Validation error'` + `details`), as the P4.62 web edges emit it |
| the service's own validation (`validateTitle` / `validateContent` — UTF-16 `.length` rules, AFTER Zod) | 400 | `A subprompt needs a title` / `A subprompt title is at most 100 characters` / `A subprompt needs some instruction text` |
| character archived, on a WRITE | 409 | `Character is archived; subprompts cannot be added` / `… cannot be edited` / `… cannot be deleted` |
| any other failure | 500 | `Failed to list subprompts` / `Failed to read subprompt` / `Failed to create subprompt` / `Failed to update subprompt` / `Failed to delete subprompt` |

Guard order, as v4 wrote it and to be MEASURED before pinning (the
`a6870c5a` guard-order class): POST and PUT parse the body FIRST (a bad body
on a missing character is 400, not 404); GET and DELETE validate the id first,
then the character, then the subprompt.

### C.5 Fan-out and realtime

- Every successful write publishes `characters/<characterId>` on the
  realtime bus. The SPA topic map's `characters` arm gains
  `characterKeys.subprompts(id)` beside `detail`/`prompts`/`photos`.
- `fanOutSubpromptChange(characterId, subpromptId, {removeSelection})` over
  `chats.findByCharacterId`: for every seat of that character that is
  `controlledBy !== 'user'`, `status !== 'removed'`, and whose selection
  contains the id CASE-INSENSITIVELY — with `removeSelection`, strip the id
  from the persisted selection first (case-insensitive), then
  `compileIdentityStackForParticipant`; per-seat failures warn and fall
  through; `chats/<chatId>` published once per touched chat.

\n## Additional Instructions\nThe following also apply to you in this conversation.\n<### {title}\n{processTemplate(content)}> joined by \n\n
