## Mandate

Teach v5's restore file replay to recognise that the archive **already carries
the document-store rows** for a file, and skip re-ingesting the bytes rather
than creating a second, colliding set. Deliver it with a differential that
exercises both of the hazards it removes — which means **building the two
archives the family currently lacks**, because neither hazard is reachable today.

**This is a deliberate divergence from v4, and it must be recorded as one.** v4
re-ingests unconditionally; v5 will not. v4 named this repair itself and put it
out of scope (`docs/developer/found-bugs.md:400-402`):

> *"Fixing this properly means teaching the replay to recognise that the archive
> already carries the store rows for a file and skip re-ingesting it, rather than
> reshuffling phase order. Out of scope here."*

So the expected outcome is that `system_restore_state`'s divergence list **grows
by one well-named entry**, not shrinks. That is correct here and should not be
read as a regression of P4.d22's convergence work.

**Must NOT touch:** the files-phase ORDER in
`services/backup/restore/orchestrator.rs` (the ruling pins it), `apps/web/**`,
or anything in the chat-action surface.

## Survey-verified starting points (2026-07-26 — do not re-derive)

### The two hazards, and why neither is currently reachable

| Slot | Hazard | v4 reference |
| --- | --- | --- |
| v5's (after the doc-store family) | The replay's content lookup matches an archived content row **by sha** and hard-links to it; 22f's `INSERT INTO doc_mount_blobs` then violates `UNIQUE(fileId)` and the **ARCHIVED blob row is refused** | `found-bugs.md:361-370` |
| v4's `22a-bis` | The replay wins the race into `restored/<name>`, so a **second-generation** archive's own folder + link rows collide with it and **the archived link ids are lost** | `found-bugs.md:385-397` |

**Neither fires against the committed `restore-archives/` family**, for two
separate reasons P4.d22 recorded:

1. No committed archive has a restored user file that shares a sha with an
   archived doc-store file, so the `UNIQUE(fileId)` path is never taken.
2. **In `replace` mode neither engine restores a user file at all** over these
   archives — they carry no Quilltap Uploads mount and no
   `userUploadsMountPointId`, so the pointer dangles on both sides and both warn
   identically. The disaster-recovery case v4's own fix targets is unexercised.

That is why fixture work is tier 1 here, not a nicety.

### The v5 anchors

- **`services/backup/restore/orchestrator.rs`** — `restore_one_file` (the

- `crates/quilltap-harness/tests/system_restore_state.rs` — the differential,

### ⚠ One thing to establish before designing the check

P4.d22 reasoned the id-keyed lookup from `restore_one_file` and v4's
`UNIQUE(fileId)` note, but **did not run it**. Confirm first that the archived
`doc_mount_files` / `doc_mount_file_links` / `doc_mount_blobs` rows for a given
file id are actually queryable at the moment the files phase runs, and decide
deliberately what "already carries the store rows" means — id alone, or id plus
a content check. Record the predicate and why. A wrong predicate here silently
drops a file the user expected back, which is the worst failure this surface has.

## The differential requirement, restated

Every ported unit ships with an equivalence test driving v4's **real** `lib/`
code. This lane is **tier 2** (structural DB diff) and its predecessor is
`system_restore_state` — read P4.d22's lane records ("Lane record — P4.d22 unit
1" and "… units 2–3") before starting: the normalizers, the per-table minted
labels, the `preState` dump, and the `restore_preview_writes_nothing` arm are
all load-bearing context.

**The trap that matters most here:** a differential that passes because its
oracle is stale proves nothing (`oracle-regen-silent-stale-pass`). Grep each
regenerated NDJSON for the behaviour you expect before trusting a pass. And
**anchor jest patterns** — `npx jest -- system-restore` is an unanchored
substring, and at the last unification `-- system-import` silently ran
`system-import-execute.test.ts` too and clobbered the output
(`chat-action-remainder-round`).
