## The v4 behavioral contract (implementation-independent)

From `4f088e7c` (new `components/chat/lexical/transformers/
list-indentation.ts`, 322 lines, + plugins/toolbar/CSS; three test files):

- **(a) Import depth from STRUCTURE, not an indent divisor.** v4's stack
  algorithm (`mapListLines` :120-198, core ~:169-180): pop while `width <
  top.width`; push on `width > top.width`; same level replaces the slot
  and records the marker; depth = stack length − 1. List-item recognition
  `LIST_ITEM_RE = /^([ \t]*)([-*+]|\d{1,9}[.)])([ \t]+\S.*|[ \t]*)$/`
  (whitespace required before content so `---`/`*emphasis*` aren't
  markers); tab = 4 columns; a non-blank column-0 non-list line closes the
  stack; blank/indented lines don't. **v5 HAS this natively** (CommonMark)
  with ONE edge divergence — see the ruling item below.
- **(b) Export re-indents at the unit the document was LOADED with.**
  `detectListIndentUnit` (:300-322 — min bullet-parented step;
  ordered-parented 3 reads as the conventional 2; default 2; clamp 1–8);
  per-editor unit memory (WeakMap analog); `applyListIndentUnit`
  (:213-227) re-indents export output. A two-space file stays two-space;
  ONE EDIT MUST NOT REFLOW every nested line. **v5 LACKS all of this** —
  the core port item.
- **(c) A child never narrower than its parent's marker:** `width =
  parentWidth + Math.max(step, markerWidth(parentMarker))` — `1. ` keeps
  children ≥3 cols, `10. ` ≥4, even at unit 2. **v5 has this natively**
  (prosemirror-markdown's marker-width delims) — KEEP it when (b)
  parameterizes the unit; v4's max() is the rule.
- **(d) Fenced code + leading YAML frontmatter pass through the
  indentation passes untouched** (fence tracking via `FENCE_RE`, close
  matched by char + length; a leading `---` block copied verbatim — YAML
  sequences look exactly like bullet lists). v5's fences already pass; the
  guard obligation TRANSFERS to the new detect/re-indent scans. (v5's
  pre-existing frontmatter mangling at parse is whole-dialect and OUT of
  this order's scope — do not "fix" it here; record it.)
- **(e) Tab/Shift+Tab confined to list items** — Tab outside a list moves
  focus (return false / fall through); the selection-in-list-item check
  must handle the element-point caret (v4's `$selectionIsInListItem`
  checks anchor/focus nodes AND getNodes() — the empty-getNodes caret
  lesson). Rationale: Markdown cannot represent an indented paragraph.
- **(f) Toolbar indent/outdent buttons that also work in raw-source
  mode** — `⇤`/`⇥`, titles "Outdent list item (Shift+Tab)" / "Indent list
  item (Tab)"; source mode uses pure line transforms
  (`indentSourceLines`/`outdentSourceLines` over `shiftSourceListLines`
  :250-281: expand selection to whole lines, shift ONLY list lines by the
  detected unit; outdent drops one tab or up to `step` spaces, stops at
  column 0).
- **(g) The doubled-bullet CSS fix — NO-PORT:** Lexical's wrapper-`<li>`
  DOM has no ProseMirror/remark analog (verified: standard nested
  `<li><p><ul>` markup; `qt-lexical-li-nested` appears nowhere in v5).
  Only the `.qt-formatting-button-indent/-outdent { font-size: 1.05rem;
  line-height: 1 }` sizing rule rides with (f) — your named `_chat.css`
  section.

v4's three test files (list-indentation 160, markdown-list-roundtrip 142,
