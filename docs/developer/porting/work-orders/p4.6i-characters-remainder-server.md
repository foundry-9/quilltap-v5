### Per-character chats — `[id]/handlers/get.ts` `chats` action (105–229)

Composes already-ported repos: `chats.findByCharacterId` → filter to
`userId === user.id` → per chat `getMessages`, compute `lastMessageAt`
from `type==='message'` timestamps (fallback `chat.updatedAt`) → sort desc
→ optional case-insensitive `search` over title + message content →
`slice(offset, offset+limit)` (defaults limit 10 / offset 0) → enrich:
projects map (`projects.findById`), tags (`tags.findById` → `{tag:{id,name}}`),
`messageCount` (`type==='message' && role !== 'SYSTEM' && role !== 'TOOL'`),
`memoryCount` (`memories.countByChatId`), scriptorium status
(`renderedMarkdown` + `conversationChunks.findByChatId` embedded/total →
`'embedded'|'rendered'|'none'`), 3 most-recent messages, `storyBackground`
(`files.findById(storyBackgroundImageId)` → `{id, filepath}`),
`isDangerousChat`. Returns `{chats: [...], total: filteredChats.length}`.
Full DTO shape is in the **Shared contract** below.

## Shared contract (BINDING — identical in `p4.6j`)

The eight `Request` variants are ALREADY in `api/types.rs` (do not change
their names/fields):

- `characterDelete {characterId, cascadeChats?, cascadeImages?}`
- `characterCascadePreview {characterId}`
- `characterChats {characterId, search?, limit?, offset?}`
- `characterExport {characterId, format?}` — `format` `"json"` only until
  PNG lands (tier 3); the SPA downloads the returned JSON client-side.
- `characterImport {payload}` — JSON body leg; the PNG leg is the multipart
  web route (deferred).
- `characterPhotoList {characterId, limit?, offset?}`
- `characterPhotoSaveById {characterId, fileId?, linkId?}` — exactly one of
  `fileId`/`linkId`.
- `characterPhotoRemove {characterId, linkId}`

Responses reuse the loose-`serde_json::Value` style of the characters/
settings lanes (`Response::Character(...)` / `Response::Characters(...)` /
generic data payloads) — the DTO **bytes** are pinned by the differentials,
not the Rust types. The response payload field lists the SPA codes against
(mock until unification):

- **CharacterDelete** → `{success: bool, deletedChats: number,
  deletedImages: number, deletedMemories: number}`.
- **CharacterCascadePreview** → `{characterId, characterName,
  exclusiveChats: [{id, title, messageCount, lastMessageAt}],
  exclusiveCharacterImageCount, exclusiveChatImageCount,
  totalExclusiveImageCount, memoryCount}`.
- **CharacterChats** → `{chats: [{id, title, createdAt, updatedAt,
  lastMessageAt, character: {id, name}, project: {id, name} | null,
  storyBackground: {id, filepath} | null, messages: [{id, role, content,
  createdAt}] (≤3, recent-first), tags: [{tag: {id, name}}],
  isDangerousChat: bool, _count: {messages, memories},
  scriptoriumStatus: 'embedded'|'rendered'|'none'}], total}`.
- **CharacterPhotoList** → `{entries: CharacterGalleryEntry[], total,
  hasMore}` — `CharacterGalleryEntry` = the v4 iface (survey
  `character-gallery-service.ts:63`; at minimum `{linkId, filepath, caption,
  tags, …}`). Lane A pins the exact entry fields in the first commit and
  reports them here.
- **CharacterPhotoSaveById** → the saved entry `{linkId, …}`.
- **CharacterPhotoRemove** → `{deleted: bool, fileGC: bool}`.
- **CharacterExport (json)** → the ST character-card object (verbatim
  `exportSTCharacter` output).
- **CharacterImport** → `{character: <created character>}` (the
  create-echo shape).

If any name or field must change, BOTH orders change and the change is
reported at unification.
