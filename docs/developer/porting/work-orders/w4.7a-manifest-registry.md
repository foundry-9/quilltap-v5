# Work order: W4.7a — the provider manifest + registry core

**Size: one Opus session.** The first W4.7 unit (decomposition:
[`../provider-manifest.md`](../provider-manifest.md), "The porting
decomposition"). Independent of every other open batch — safe to run in
parallel with anything that doesn't edit the same consumer modules
(coordinate the seam-input replacements below; they touch `model_pricing` /
`tool_build` / `cheap_llm` / attachment consumers).

## What to build

1. **The manifest schema** (`provider_manifest` module): serde structs for
   the sketch in the design doc (`schemaVersion`, `id`, `displayName`,
   `auth`, `baseUrl`, `endpoints`, `streamDecoder` + `requestTransform` as
   CLOSED enums, `capabilities`, `attachmentMimeTypes`, `charsPerToken`,
   `defaultContextWindow`, `fallbackModels`, `pricing`, plus the fields the
   registry survey adds: `abbreviation`, `colors`, `configRequirements`
   [requiresApiKey/requiresBaseUrl/labels/placeholder/default],
   `messageFormat` [supportsNameField/supportedRoles/maxNameLength],
   `cheapModels` [defaultModel/recommendedModels], `legacyNames`,
   `toolFormat`, attachment `maxFileSize`/`maxBase64Size`/`maxFiles`,
   `description`/`notes`). JSON-Schema validation at load, fail-loud with a
   typed error naming the field (a malformed manifest never half-loads).
2. **The built-in manifests**: one JSON per v4 provider (anthropic, openai,
   google, grok, deepseek, z-ai, openrouter, ollama, openai-compatible),
   **generated** from v4's registry by a checked-in
   `harness/oracle/providers/gen-provider-manifests.mjs` that imports the
   real plugin metadata objects and emits the manifest JSON (the
   `gen-tool-catalog.mjs` precedent — transcription, not re-derivation;
   regen recipe in the header). Embedded via `include_str!` + parsed once
   (`LazyLock`).
3. **The registry**: `get_provider(name)` with v4's exact semantics
   (case-sensitive canonical ids; `legacyNames` resolution — read the v4
   source for whether legacy lookup is exact or normalized), `all_providers`
   ordering, the capability accessors (`supports_capability`,
   `get_attachment_support`, `get_message_format`, `get_chars_per_token`
   default 3.5, `get_default_context_window` default 8192, `get_tool_format`,
   `get_cheap_model_config`, `get_model_pricing`).
4. **`rewrite_localhost_url`** (pure): v4's `rewriteLocalhostUrl` — tier-1
   rows incl. non-localhost passthrough and the container/VM mappings.
5. **Seam-input replacement, consumer by consumer** (each with its
   differential regenerated, none skipped): the `getModelContextLimit`
   override/default tables' registry-default input; `cheap_llm`'s
   recommended-list/default injection; `tool_build`'s
   `provider_supports_web_search`; the W4.4b attachment
   `supportedMimeTypes` injection (if W4.4b landed); `message_formatter`'s
   provider name-field data if it was injected. Where a consumer's injected
   input was itself differential-pinned, the pin moves to "the registry
   value equals the pinned value" — assert that in the registry-parity
   oracle so drift is caught there, not silently.

## Differential plan (`provider_registry_equivalence`)

A tsx oracle in `harness/oracle/cases/` drives v4's REAL
`lib/plugins/provider-registry` convenience getters over EVERY registered
provider (initialize the registry the way v4's runtime does — find the
bootstrap; plugins are static imports in `plugins/dist/*`) and emits one
NDJSON row per (provider × getter). The Rust side answers from the
manifests. Tier-1 exact, including the defaults for absent fields and the
legacy-name lookups. Plus a determinism row (dump twice) and the malformed-
manifest fail-loud unit tests (missing field, bad enum, wrong
schemaVersion).

## Watch-outs

- `streamDecoder`/`requestTransform` enum values must match the design-doc
  table exactly — W4.7b/c implement against them; adding a variant later is
  fine, renaming is not.
- v4's registry is HMR-stateful (globalThis) — none of that ports; the
  registry is static data + accessors.
- Third-party manifest loading (filesystem, signing) is a design open item —
  build the load/validate path but wire only the built-ins; no fs in core.
- Pricing in the manifest is the STATIC fallback tier — the live pricing
  fetcher is W4.7e; don't conflate.
