### New Request variants (wire `type` names; Rust mirrors in PascalCase; lane A builds, lane B consumes)

The general files family (all JSON verbs ride `POST /api/dispatch`):

- `filesList {projectId?, folderPath?, filter?}` → `{files:
  FileEntry[]}`. `FileEntry` is v4 `serializeFileEntry`: BOTH
  `originalFilename` AND `filename` (= originalFilename), `filepath`
  = `/api/v1/files/{id}`, `folderPath` RESOLVED via
  `resolveEffectiveFolderPath`, `fileStatus` defaulted `'ok'`. Sort:
  `createdAt` DESC.
- `fileMove {fileId, folderPath?, filename?, projectId?}` → `{data:
  ManagedFile}` — the managed shape (`filename` only, RAW
  `folderPath`, no `originalFilename`/`width`/`height`/`fileStatus`).
  At least one field required; `projectId` absent keeps, null clears
  (the tri-state — do not collapse).
- `filePromote {fileId, targetProjectId?, folderPath?}` → `{data:
  ManagedFile}`.
- `fileDelete {fileId, force?, dissociate?}` → `{success: true}` |
  the 400 associations envelope (`'File is linked to other items'`,
  code `FILE_HAS_ASSOCIATIONS`, `associations {characters,
  messages}`).
- `filesGenerateThumbnails {fileIds, size?}` → `{total, generated,
  cached, errors}`.
- `filesCleanupStale {dryRun?}` → v4's stale-cleanup shape.
- `filesCleanupOrphans {mode, dryRun?}` → v4's dry/wet shapes.
- `filesFoldersList {projectId?}` → `{folders: Folder[], count}`
  (sort: `path` localeCompare ASC).
- `filesFolderCreate {path, projectId?}` → `{folder, alreadyExists,
  message}` (idempotent; auto-creates the parent chain).
- `filesFolderRename {path, newName, projectId?}` → `{oldPath,
  newPath, foldersUpdated, filesUpdated}`.
- `filesFolderDelete {path, projectId?}` → `{message, path}`; refuses
  non-empty (two DISTINCT 400 messages: files vs subfolders).
- `filesSync {}` → STAYS refusal-armed (loud, names the unported
  `lib/file-storage/reconciliation` subsystem).
- `fileUpload {filename, contentType, data (base64), tags?,
  projectId?, folderPath?}` — the core variant behind the REST leg
  below.
