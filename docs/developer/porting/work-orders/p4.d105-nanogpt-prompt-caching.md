## The drift, classified (surveyed 2026-08-22, fresh at `f8973813`)

One commit, one surface: the NanoGPT plugin (1.0.2 → 1.0.3), a **behavior
change on a ported surface** (NanoGPT landed whole in P4.D101, the
`4cb1035e` round). Three moving parts, all in
`plugins/dist/qtap-plugin-nanogpt/`:

1. **Two new per-profile options** (`index.ts` `optionsSchema`, a new
   "Prompt Caching" group appended after the existing groups):
   - `enablePromptCaching` — `boolean`, default `false`, with a helpText
     naming the Anthropic-routed scope;
   - `cacheTTL` — `enum`, default `'5m'`, values
     `{'5m', "5 minutes (1.25x write cost)"}` /
     `{'1h', "1 hour (2x write cost)"}`, with
     `showIf: { field: 'enablePromptCaching', equals: true }`.
   The group's `helpText` is a long Wodehouse-register paragraph —
   byte-copy it, do not paraphrase.
2. **The request-body helper** (`provider.ts` `buildRequestBody`): when
   `params.profileParameters?.enablePromptCaching === true`, set
   `body.promptCaching = { enabled: true, ttl }` where
   `ttl = cacheTTL === '1h' ? '1h' : '5m'` (any other value, including
   absent, collapses to `'5m'`). **Placement in v4's key order: after
   `user`, BEFORE `applyProfileParams`.** The two option keys are
   **consumed, never forwarded** — v4 keeps them off
   `NANOGPT_PROFILE_PARAM_ALLOWLIST`; v5's allow-list builder excludes
   them by construction, but assert it (see Tier 1 item 3).
3. **Cache-usage normalization** (`provider.ts`): a new
   `extractCacheUsage(usage)` reading BOTH dialects the gateway emits —
   Anthropic-style `cache_read_input_tokens` /
   `cache_creation_input_tokens` AND OpenAI-style
   `prompt_tokens_details.cached_tokens` (implicit caching). Semantics,
   exactly:
   - `read = cache_read_input_tokens ?? prompt_tokens_details?.cached_tokens ?? 0`;
     `written = cache_creation_input_tokens ?? 0`.
   - `read <= 0 && written <= 0` → `undefined` (no `cacheUsage` key at
     all).
   - Otherwise: `cacheReadInputTokens` + `cachedTokens` (both = read,
     only when read > 0) and `cacheCreationInputTokens` (only when
     written > 0).
   - **The house rule:** cache reads are EXCLUDED from prompt/total —
     `promptTokens = max(0, prompt_tokens − read)`,
     `totalTokens = max(0, total_tokens − read)`; `completionTokens`
     untouched. Applied on BOTH the non-streaming `sendMessage` return
     and the streaming final chunk.
   - The streaming final chunk additionally carries
     `rawProviderUsage: usage ?? null` (diagnostics).
4. Doc/help edits: the plugin README + `index.ts` doc comment,
   `help/connection-profiles.md` NanoGPT section (two lines), a v4
   CHANGELOG entry, and the additive provider-options schema snapshot.
   v4's audit note ("extended thinking and the streaming protocol already
   match the documented contract") is a claim about ALREADY-PORTED
   surfaces — spot-check it against v5's decoder, don't re-port.

No DB schema change (no D23 re-dump). No new routes. No v4 `lib/` change
outside the plugin.
