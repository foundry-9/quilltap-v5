## Mandate

Port v4 `b90cd1f5` ("nothing to add" turn-skipping for group chats) across
the already-ported spine, and regenerate every affected differential green
against v4 HEAD. The feature: in qualifying group scenes, an LLM character
may pass its turn by replying with the single line `[NOTHING TO ADD]`; the
Host posts a `turn-pass` note (never containing the sentinel), the rotation
advances, and a stall guard forces speech when everyone else has passed.
`git show b90cd1f5` in the v4 checkout is the spec; the notes below pin the
load-bearing facts found in the drift-check survey.

## Sub-units (leaf-first)

### 1. The pure module `crate::skip_signal` (new, core root)

Port `lib/chat/turn-manager/skip-signal.ts` (358 lines) whole. It composes
three ALREADY-PORTED leaves — `normalize_content_block_format`,
`strip_character_name_prefix` (message_formatter), and
`find_mentioned_character_ids` — plus `is_participant_present`
(chat_predicates). Reuse them; port nothing twice. Match `turn_state.rs`'s
existing event representation for the history-walking functions. Key facts:

- `NOTHING_TO_ADD_SENTINEL = "[NOTHING TO ADD]"`,
  `TURN_PASS_SYSTEM_KIND = "turn-pass"`.
- `is_turn_pass_message`: `type === 'message'` AND `systemSender === 'host'`
  AND `systemKind === 'turn-pass'` AND `hostEvent.participantId` is a string.
- `detect_skip_sentinel(response, characterName?, aliases?)`: normalize →
  strip own-name prefix **only when a name or non-empty aliases were given**
  (the fallback generic bracketed-name pattern would eat the sentinel's own
  brackets — v4 has an explicit guard; carry the why-comment) → find the
  FIRST non-empty line → `isSentinelLine` on it. Bare sentinel (only
  whitespace after) → `{skip: true}`; sentinel + trailing prose →
  `{skip: false, cleaned}` where `cleaned` = all lines minus the sentinel
  line, joined `'\n'`, `.trim()`ed; no sentinel → `{skip: false}`.
- `isSentinelLine` (private): trim; repeatedly shed matched wrapper chars
  from the set `* _ ~ " ' \`` — one char from EACH end per iteration, taken
  when the first char is a wrapper AND (`first === last` OR the last is any
  wrapper), re-trimming each pass, while `s.length > 1`; then drop ONE
  optional leading `[` and ONE trailing `]` (`replace(/^\[/,'')` /
  `replace(/\]$/,'')`), trim; drop trailing `[.!?,;:]+`; trim; compare
  `toLowerCase() === 'nothing to add'` (plain ASCII lowering suffices for the
  literal, but use the JS-faithful lowering you already have).
- `find_skipped_since_last_substantive`: backward walk; collect
  `hostEvent.participantId` from turn-pass records; STOP at the first
  non-whisper USER/ASSISTANT message with a `participantId` (whisper =
  non-empty `targetParticipantIds` array). Turn-pass rows carry a null
  `participantId` so they never terminate the walk.
- `qualifies_for_turn_skipping(participants)`: active chars =
  `type === 'CHARACTER'` AND present AND has `characterId`; `> 2` → true;
  else `≥ 2` with `controlledBy !== 'user'` → true.
- `is_first_character_turn(events)`: no `message` event with
  `role === 'ASSISTANT'` AND a non-null `participantId` (Staff rows have
  null participantId → don't count; greetings count).
- `is_recently_addressed(events, respondingParticipantId,
  respondingCharacter)`: find the responder's last non-whisper non-Staff
  ASSISTANT message; collect subsequent "visible conversational turns"
  (non-Staff, not silent, non-empty string content, and any whisper must
  include the responder); window = last 10; a whisper targeted at the
  responder → true; else join the window's contents with `'\n'` and run
  `find_mentioned_character_ids(corpus, [respondingCharacter])` — non-empty
  → true.
- `compute_skip_eligibility(options) -> {offer_skip, must_speak_reason,
  recently_addressed}`: `recentlyAddressed` computed UNCONDITIONALLY first;
  withhold precedence: `not-multi-character` → `feature-disabled` →
  `first-character-turn` → `summoned` → `already-skipped` →
  `all-others-skipped`. The stall rule: every OTHER active CHARACTER
  participant (LLM **or user-controlled**) has a pass since the last
  substantive message; with no other participants the `.every()` is
  vacuously true (skipping into an empty room forbidden — carry the
  why-comment).

### 2. Turn state + chain gates

- `turn_state.rs` `calculate_turn_state_from_history`: in the
  `lastSpeakerId` backward walk, a turn-pass record (checked BEFORE the
  role/participantId/whisper tests) sets `lastSpeakerId =
  hostEvent.participantId` and breaks. Carry v4's why-comment (a pass
  occupies the passer's floor position so the last substantive speaker
  doesn't become permanently unpickable).
- `services/turn_orchestrator.rs` `should_chain_next`: (a) in the all-LLM
  auto-pause counter, `continue` past any message with a `systemSender`
  (Staff rows are ASSISTANT-role but not character turns — carry the
  comment); (b) `ChainDecision` gains
  `selection_reason: Option<Queue|Algorithm>`, set on the chain-true return
  (`queue` when the speaker came off the turn queue, else `algorithm`).
- `execute_turn_chain` (wherever v5 hosts it): the initial-result gate
  becomes `!isMultiCharacter || (!hasContent && !skipped) || isPaused`; each
  chained `process_message` receives `chain_selection_reason:
  decision.selection_reason`; the chained-turn `turnComplete` frame now
  ALWAYS carries `skipped: chainResult.skipped === true` (present on every
  chained turn — a byte-shape change for existing multi-turn cases); the
  empty-response chain-stop becomes `!hasContent && !skipped` (a skipped
  turn falls through to the next `decideNextTurn` iteration).

  assistant tails — carry it).
- `message_context.rs`: pass `turn_skip` through to `build_context`
  unchanged.

### 4. Orchestrator spine

`services/orchestrator.rs` (v4 `orchestrator.service.ts` at `b90cd1f5`):

- `ProcessMessageInput` gains `nudge: Option<bool>` and
  `chain_selection_reason: Option<Queue|Algorithm>`;
  `ProcessMessageResult` gains `skipped: bool` (or Option per house style)
  and `skipped_participant_id: Option<String>`.
- **Eligibility** (right after the existing-messages read): when
  `qualifies_for_turn_skipping(chat.participants)` AND the responding
  participant is not user-controlled, run `compute_skip_eligibility` with
  `summoned = nudge == true || chain_selection_reason == Queue` and
  `turn_skipping_enabled = chat.turnSkippingEnabled !== false`; keep the
  resulting `turnSkip` triple for BOTH the context build and the sentinel
  handling. NOTE: eligibility is computed (and sentinel handling later
  runs) even when `offer_skip` is false — the branches differ.
- **Sentinel handling** (after `flush_pending_wardrobe_announcements`,
  before the has-content finalizer branch): when `turnSkip` is set, run
  `detect_skip_sentinel(full_response, name, aliases)`. On `skip: true`:
  tools ran this turn → warn + clear `full_response` to `''` (the tool-save
  branch must win); else `offer_skip` → `handle_turn_skip`; else (sentinel
  without the offer) → clear to `''` (routes to the existing empty-response
  branch). On `cleaned` present → replace `full_response` with the cleaned
  prose and fall through as a real reply.
- **`handle_turn_skip`**: post the Host turn-pass announcement (writer
  errors swallowed); re-read the chat fresh (`find_by_id`); compute
  `compute_spoken_this_cycle_after_skip` (ALREADY PORTED in
  `turn_state.rs`) over the fresh participants + stored cycle JSON; update
  the chat with a minted `updatedAt` ALWAYS plus `spokenThisCycleParticipantIds`
  only when the helper returned non-null (v4 mints `updatedAt`
  unconditionally here — unusual for this repo, faithful); whole re-read/
  update wrapped in a swallow-and-warn. Emit the `hostAnnouncement` frame
  (only when the post succeeded) then the `done` frame with `messageId:
  null`, usage/cacheUsage/attachmentResults from streaming state,
  `toolsExecuted: false`, `skipped: true`, `skippedParticipantId`,
  provider/model from the effective profile. Return
  `{isMultiCharacter, hasContent: false, skipped: true,
  skippedParticipantId, messageId: null, userParticipantId, isPaused}`
  (isPaused from the fresh read).
- The enclave (`enclave::step`) needs NO logic change (v4's autonomous
  handler is untouched — a pass consumes a turn because the turn completed
  normally); only the `ProcessMessageResult` shape ripples. Verify the step
  compiles + its differential regenerates green.

### 5. Events + Host writers + marshaling

- `services/chat_events.rs`: `DonePayload` gains

- `services/host_notifications.rs`: the three byte-exact builders
  (`build_turn_pass_content` / `build_user_turn_pass_content` /
  `build_turn_pass_opaque_content` — steampunk register, transcribe

  participant_id, source: llm|user})` posting `systemKind: 'turn-pass'`
