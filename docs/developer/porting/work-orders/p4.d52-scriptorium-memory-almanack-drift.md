### Bug 17 — oversize chunks can never embed (v4 `62ab1bc8`) — FAITHFUL, the big port

v4's `lib/scriptorium/markdown-renderer.ts` grew 224 → 404 LOC.
Post-fix map: `CHUNK_CHAR_BUDGET = 24_000` (**exported**, `:33`);
`CHUNK_HEADER_RESERVE = 80` (`:36`); `lastBoundaryCut` (`:43` —
`lastIndexOf`, returns `null` when `idx <= 0`, else `idx + sep.length`
so the separator stays with the preceding text); `splitOversizeText`
(`:56`); `RawInterchange` (`:76`); `PackedRun` (`:87`);
`splitInterchange` (`:99`); `enforceChunkBudget` (`:149`);
`renderConversationMarkdown` calls it at `:397`.

The algorithm, exactly:
- `splitOversizeText(text, budget)`: while `remaining.length > budget`,
  `window = remaining.slice(0, budget)`, cut at the LAST occurrence of,
  in strict `??` fallback order: `'\n\n'` → `'. '` (trailing space —
  a sentence at EOL does not match) → `'\n'` → `' '` → hard cut at
  `budget`. Pieces concatenate back byte-exactly; never mid-word
  except the hard cut.
- `splitInterchange(ic, budget, extraReserve)`:
  `effective = max(1, budget - 80 - extraReserve)` where
  `extraReserve = metadataPrefix.length` for interchange 0 only.
  Greedy pack over per-message entries with
  `blockLen = entry.block.length + 1` (the join char counted even for
  a run's FIRST block — conservative by one, reproduce exactly). An
  over-`effective` block flushes the run and pushes one run per
  `splitOversizeText` piece, each repeating the message's id.
  `flush()` joins with `'\n'`; names are an insertion-ordered dedup
  (v5's `push_unique` at `conversation_markdown.rs:173` is the
  semantics).
- `enforceChunkBudget`: the over-budget test is on
  `metadataPrefix + content` (a small interchange 0 with a big header
  can split). Under-budget interchanges pass through **byte-identical
  to pre-fix**. Split headers: `## Interchange ${ordinal}` for piece
  0, `## Interchange ${ordinal} (continued ${i})` after (interchange
  ordinal, `continued` from 1); the metadata prefix rides ONLY on
  piece 0 of interchange 0; `content = prefix + header + "\n\n" + run.text`;
  `messageIds: run.ids`; `participantNames: run.names` with the
  **empty-run fallback to `ic.participantNames`**; `index` is a chunk
  ordinal counting across ALL interchanges. Interchanges never merge.
  `- Interchange Count:` stays the count of RAW interchanges (v4
  `:375`), NOT chunks — v5 currently writes `interchanges.len()` at
  `conversation_markdown.rs:346`, which becomes wrong the moment the
  list holds chunks; compute it from the pre-split list. Full markdown
  joins the CHUNK list with `'\n'`, so `chats.renderedMarkdown` gains
  the `(continued k)` lines for sub-chunked chats.

**⚠ UTF-16, the likeliest byte break:** v4's `.length` / `slice` /
`lastIndexOf` are UTF-16 code-unit measures. The Rust port must
measure and slice in UTF-16 units, not bytes (`String::len`) and not
scalar values (`chars().count()`). The repo has prior art for UTF-16
walking (the P4.D35 tokenizer); follow it.
