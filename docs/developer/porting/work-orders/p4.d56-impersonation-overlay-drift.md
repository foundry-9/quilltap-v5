## The drift, classified (surveyed 2026-08-07)

**`62c63dc3`** (23 files, +253/−113) is v4 implementing **Bug 44** — the
upstream correction the #39 ruling queued v4-FIRST (ruling record:
`status-log.md` → "Ruling — the #39 impersonation mechanism", 2026-08-06;
the ruling explicitly named this commit's arrival as "a real drift round").
Impersonation stops being a mutate-and-restore and becomes a **pure
overlay**:

- `handleImpersonate` no longer writes `controlledBy: 'user'` and no longer
  recompiles identity stacks; `addImpersonation` (the
  `impersonatingParticipantIds` append + `activeTypingParticipantId` set)
  is the whole state change.
- `handleStopImpersonate` no longer writes `controlledBy: 'llm'` in either
  arm; the `newConnectionProfileId` arm becomes a plain profile
  reassignment (`connectionProfileId` only), and the no-profile arm becomes
  a no-op beyond `removeImpersonation`. No recompile.
- A new shared helper **`isUserDrivenSeat(participant,
  impersonatingParticipantIds)`** (`lib/chat/turn-manager/utils.ts`) —
  `controlledBy === 'user'` OR overlay membership — is consulted at the
  two turn-resolution gates: **attribution** (`findActiveUserParticipant`,
  `findUserParticipantName`'s selected-speaker branch, `resolveUserIdentity`
  via the former) and **who-responds** (`selectNextSpeaker`'s
  `buildResult` user-turn reason, the LLM-candidate filter in
  `resolveRespondingParticipant`, `shouldChainNext`'s pause gate,
  `turn.ts`'s `skipUserTurn` gate + its `selectNextSpeaker` call), plus
  answer-confirmation's `isUserDrivenTurn` (restructured onto the helper —
  **truth-table-neutral**, verify not just port).
- **Owner-seat readers deliberately KEEP reading the column** — this is
  half the fix and must be ported as faithfully as the changes:
  `findUserParticipant` / `userParticipantId`, `isAllLLMChat`,
  `getActiveLLMParticipants`, the participant-update `controlledBy` sync,
  and set-active-speaker's lazy-add are all UNCHANGED in v4. That
  stability is what returns the card's Stop-Impersonate button with **zero
  client changes** (v4 shipped none).
- Transition: seats flipped by the old mechanism while an impersonation was
  active at upgrade time are **left alone** (no migration, no repair pass).
  v5 does the same by doing nothing.
- Docs riders: `API.md`, `help/chat-participants.md`, `found-bugs.md`
  (Bug 27 correction banner + Bug 44 fixed). v5 has no help surface —
  `help/chat-participants.md` joins the `p4.9i2` bank.

v5 currently mirrors the OLD flip mechanism byte-faithfully (P4.D53
server-side, P4.D54 SPA-side, both landed 2026-08-06 under the port
discipline with the ruling conflict flagged). This lane absorbs the
correction as an ordinary drift re-port — and the impersonation e2e beat
**re-gestures BACK** (the Stop button returns to the card), exactly as the
ruling predicted.
