## Survey-verified starting points (2026-07-20: v4 @ `7e6d13e5`, v5 @ main `716d048f` — do not re-derive)

### v4 — the new behavior (`lib/markdown/math.ts`, now 196 lines; file:line at `7e6d13e5`)

- **`REMARK_MATH_OPTIONS`** (:31) — UNCHANGED
  (`{ singleDollarTextMath: false }`); the doc-comment now explains the
  promotion-in-preprocessing design.
- **`MATH_SKIP_PATTERN`** (:40) — UNCHANGED (fenced/inline code +
  existing `$$` regions).
- **`LATEX_MARKER`** (:48) = `/\\[a-zA-Z]|[_^{}]/` — a
  backslash-command, a sub/superscript, or braces makes a span
  unmistakably LaTeX; currency carries none of these.
- **`BARE_TOKEN`** (:57) = `/^[A-Za-z][A-Za-z0-9]{0,2}$/` — a letter
  plus up to two alphanumerics (`$K$`, `$x$`, `$v0$`).
  **Letter-anchored so a lone currency figure `$5$` never qualifies.**
- **`mapPlainRegions(markdown, transform)`** (:65) — the extracted
  skip-region walker: `split(MATH_SKIP_PATTERN)`, transform even
  indices, pass odd/undefined through, join.
- **`promoteSingleDollarMath`** (:84) — per plain region, per LINE
  (split/rejoin on `\n` — inline math never spans a newline, and the
  bare-token rule is line-scoped).
- **`lineHasMarkerPair`** (:97) — whether some `$...$` pair on the
  line carries a marker, using the SAME left-to-right pairing as
  `promoteLine` (a non-marker pair releases its closing `$` to open
  the next candidate) so the answer matches actual pairing.
- **`promoteLine`** (:120) — each `$` pairs with the nearest following
  `$`; accept iff `inner.length > 0 && (LATEX_MARKER.test(inner) ||
  (hasMarker && BARE_TOKEN.test(inner)))`; accepted → emit
  `$$inner$$`, resume after the closing `$`; rejected → **emit through
  the opening `$` and resume at `open + 1`** so the rejected pair's
  closing `$` can re-open (this is how "The $50 fee scales as
  $\pi r^2$" doesn't let the currency consume the formula's opening
  delimiter — carry the why-comment).
- **`rewriteBackslashDelimiters`** (:162) — the old `\(...\)` /
  `\[...\]` rewrite, now extracted and expressed via
  `mapPlainRegions` (behavior unchanged: `\[...\]` → newline-wrapped
  flow `$$`, `\(...\)` → inline `$$`, both `.trim()`ed).
- **`normalizeMathDelimiters`** (:187) — two independent passes, each
  behind a cheap substring guard: (1) `promoteSingleDollarMath` if the
  string contains `$`; (2) `rewriteBackslashDelimiters` if it contains
  `\(` or `\[`. **Promotion runs FIRST so the `$$` it mints becomes a
  protected region for pass 2** (pass 2 re-splits on
  `MATH_SKIP_PATTERN`) — carry the ordering why-comment.
- **v4's new test family** (`__tests__/unit/lib/markdown/math.test.ts`,
  `describe('normalizeMathDelimiters — single-dollar promotion')`,
  15 cases — mirror case-for-case): backslash-command promotion;
  script promotion; plain currency untouched; paired prose amounts not
  swallowed; lone bare `$K$` stays literal; bare token promoted with a
  marker sibling on the SAME line; NOT promoted when the sibling is on
  another line; `$5$` never a bare token; currency untouched on a line
  with real math; mixed sentence promotes only the mathy spans; single-`$`
  inside inline code untouched; inside fenced code untouched; existing
  `$$` untouched; several spans across one message; composes with the
  backslash rewrite.
- **The workbench backdrops** (`8f24ccc9`): in
  `components/custom-tools/DestinationPicker.tsx` and
  `WorkbenchEditor.tsx`, the dialog wrapper div's
  `className="fixed inset-0 z-50 flex items-center justify-center
  bg-black/40"` became `className="qt-dialog-overlay"`;
  `role="dialog" aria-modal="true"` kept.
