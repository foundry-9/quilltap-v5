### Quirks the port must not miss

1. **`STANDALONE_CHAT_ID` is the exact all-zeros UUID** — a schema-valid
   sentinel no real chat holds; standalone opens join the cross-chat recents
   through it. The `(chatId, filePath, scope, mountPoint)` uniqueness still
   dedupes reopens.
2. **Close ≠ delete** — `chat_documents` rows deactivate, never delete
   (quick-reopen history).
3. **Recents dedupe: current-chat rows win** so a file touched in this chat
   keeps "this chat first".
4. **`resolvedPathExists` re-raises non-ENOENT/non-NOT_FOUND errors** —
   never treat a permission failure as absent.
5. **`effectiveScope` fallback** — a new blank with `project` scope but no
   project coerces to `general`.
6. **The move-sync seam is best-effort everywhere** — the rename already
   succeeded on disk; a sweep failure must not fail the request.
7. **`writeDocumentFile` schedules the store refresh only for
   `document_store` scope** — through the seam, loud-skip when unwired.
8. **Standalone responses have no `librarianMessage`** — the announcement
   asymmetry between the two routes is contract surface for lane C.
9. **`openDocumentSchema` defaults** (`scope:'project'`, `mode:'split'`) are
   Zod-parse-materialized — the P4.6c nested-bag rule class.

### The refresh seam (lane B → lane A, wired at unification)

Lane B ports v4 `scheduleDocumentStoreRefresh` as a seam trait in its own

```rust
pub trait MountRefreshScheduler: Send + Sync {
    /// Fire-and-forget: reindex + embeddings + stats for the scoped path.
    fn schedule_refresh(&self, mount_point_id: &str, path: Option<&str>);
}
```

`EngineAssembly` gains an `Option<Arc<dyn MountRefreshScheduler>>` field
defaulting to `None`. When `None`, log the skip loudly at the call site — a

Neither lane wires it live in-lane.

### Error envelope + serialization rules (both server lanes)

- v4's envelope semantics per `lib/api/responses.ts`. `ErrorKind` already
  covers `fileOpStatus`'s 404/409/400/500 after P4.6p — additions only if a
  survey turns up a status v5 lacks.

  first, HTTP status second.
- Route reads omit null nullables but create/update echo them AS null (the
  P4.6p standing gotcha).
