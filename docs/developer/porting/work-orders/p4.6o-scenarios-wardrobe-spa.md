## Shared contract A↔B (BINDING — identical in `p4.6n`)

**Frozen variant names (already in `api/types.rs` / the SPA
`core-contract.ts`):** `groupScenarioList {groupId}`,
`groupScenarioCreate {groupId, scenario}`, `groupScenarioGet {groupId,
scenarioPath}`, `groupScenarioUpdate {groupId, scenarioPath, scenario}`,
`groupScenarioRename {groupId, scenarioPath, newFilename}`,
`groupScenarioDelete {groupId, scenarioPath}`, `groupScenariosUnion
{characterIds}`, `projectScenario*` (mirror, `projectId`),
`projectFileList {projectId}`, `projectFileAdd {projectId, fileId}`,
`projectFileRemove {projectId, fileId}`.

**NEW variants (the general family):** `scenarioList {}`,
`scenarioCreate {scenario}`, `scenarioGet {scenarioPath}`,
`scenarioUpdate {scenarioPath, scenario}`, `scenarioRename
{scenarioPath, newFilename}`, `scenarioDelete {scenarioPath}`.

**The scenario bag — re-pinned 2026-07-11 from v4's Zod schemas
(supersedes the P4.6k `{name, content, isDefault}` sketch; identical
across all three families):**

- create: `{filename: string (1–100, required), name?: string (1–200),
  description?: string (≤500), isDefault?: boolean, body: string
  (min 1, required)}` — optionals truly absent, no Zod defaults.
- update: `{name?: string (1–200), description?: string (≤500),
  isDefault?: boolean, body: string (min 1, required)}` — **no
  filename** (the path rides the variant field).
- rename: `newFilename: string (1–100, required)` — the only field.
- There is NO set-default verb: the SPA sets a default by re-sending
  update with `isDefault: true` (v4's `setDefaultScenario` idiom).

**Response payloads (mock these lane-B-side until unification; bytes
pinned by lane A's differentials):**

- list → `{mountPointId, scenarios, warnings}` (general:
  `mountPointId: string | null`, empty arrays when unprovisioned)
- create → `{mountPointId, path, scenarios, warnings}`
- get → `{scenario}`
- update / delete → `{scenarios, warnings}`
- rename → `{path, scenarios, warnings}`
- union → `{groupScenarios: [{groupId, groupName, mountPointId,
  scenarios, warnings}]}` (groupName order, ICU4X en-US)
- Scenario DTO: `{path, filename, name, description?, isDefault,
  rawIsDefault, body, lastModified, createdAt, updatedAt}`
- `projectFileList` → `{files, count}` (the two-branch legacy-file-
  shaped DTO; store-backed rows add `mountPointId`/`relativePath`)

**Error arms the SPA must surface:** create collision → `A scenario
named "X" already exists`; rename target exists → 400; empty body →
`Scenario body cannot be empty`; unprovisioned general mutation →
`Quilltap General mount has not been provisioned yet — restart the
server`; nested/invalid paths → 400.

If any name or field must change, BOTH orders change and the change is
reported at unification.
