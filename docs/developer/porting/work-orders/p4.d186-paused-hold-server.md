### C.6 Avatar rolls (P4.D185 server ↔ P4.D188 client)

- **`AvatarRollEntry`** (wire, key order as listed): `{ fileId: string,
  rollLinkId: string | null, albumLinkId: string | null, fileName: string,
  url: string, mimeType: string | null, fileSizeBytes: number, width:
  number | null, height: number | null, createdAt: string,
  generationPrompt: string | null, generationModel: string | null,
  sha256: string, isPortrait: boolean, usedInChatCount: number }`.
- **Verb `characterAvatarRollList`** — `Request::CharacterAvatarRollList
  { character_id: String, limit: Option<i64>, offset: Option<i64> }` →
  `CoreResponse::CharacterAvatarRolls(Value)`, the BARE `{ entries:
  AvatarRollEntry[], total: number, hasMore: boolean }` (limit clamped
  to 1..=200, default 60; offset ≥ 0; newest first; paginated in
  memory). Refusals: 404 `Character not found`.
- **Verb `characterAvatarRollAction`** — `Request::CharacterAvatarRoll
  Action { character_id: String, file_id: String, action: String }`
  with `action ∈ { "save-to-album", "set-avatar" }` → `CoreResponse::
  CharacterAvatarRollAction(Value)`: `{ linkId: string, alreadyInAlbum:
  boolean }` for `save-to-album`, `{ linkId: string, addedToAlbum:
  boolean }` for `set-avatar`. Set-avatar ALWAYS goes through
  save-to-album first (idempotent) and points `defaultImageId` at the
  album LINK id, never a `files` id.
- **Verb `characterAvatarRollDelete`** — `Request::CharacterAvatarRoll
  Delete { character_id: String, file_id: String }` → `CoreResponse::
  CharacterAvatarRollDelete(Value)`: `{ deleted: boolean, blobRemoved:
  boolean, chatsScrubbed: number, keptInAlbum: boolean }`; `deleted:
  false` (not a roll of this character) answers 404 `Avatar roll not
  found` at the edge. Order: scrub `chats.characterAvatars` → the
  character's `defaultImageId` (legacy files-id shape only) +
  `avatarOverrides` → the roll's OWN link via `delete_with_gc` (never
  the album's; never `delete_mount_blob`) → `files.delete`.
- **Error ladder (both action verbs + delete, measured from v4's
  `respondToError`):** message starts with `Character not found` → 404
  `Character not found`; starts with `Avatar roll not found` → 404
  `Avatar roll not found`; contains `no linked database-backed vault` /
  `not an image` / `empty bytes` / `already in` → 400 with the message;
  else 500 with the message + v4's `[Characters/AvatarRolls v1] Avatar
  roll action failed` error line.
- **REST (`characters_routes.rs`):** `GET /api/v1/characters/{id}/avatar-
  rolls?limit=&offset=` (Zod: `limit` int 1..=200, `offset` int ≥ 0;
  an issue list joined `; ` → 400; `!id` → 400 `Missing character id`);
  `POST /api/v1/characters/{id}/avatar-rolls/{fileId}?action=save-to-album
  |set-avatar` (v4's `withActionDispatch` envelope: no action → 400
  `{ error: 'Action parameter required', availableActions: [...] }`;
  unknown → 400 `{ error: 'Unknown action: <x>', availableActions:
  [...] }`); `DELETE /api/v1/characters/{id}/avatar-rolls/{fileId}`
  (`!id`/`!fileId` → 400 `Missing character id` / `Missing avatar roll
  id`). Guard order: auth → id presence → action → service → the ladder.
- **Log lines (info, byte-exact):** `[AvatarRolls] Roll copied into the
  photo album` `{characterId, fileId, linkId}`; `[AvatarRolls] Roll
  promoted to the character portrait` `{characterId, fileId, linkId,
  addedToAlbum}`; `[AvatarRolls] Roll deleted` `{characterId, fileId,
  rollLinkId, keptInAlbum, blobRemoved, chatsScrubbed}`.
- **Album membership (P4.D185, both reads):** `is_character_album_
  relative_path(p)` = `is_photos_relative_path(p) || lower(p) ==
  "images/avatar.webp"` — `images/history/` is NOT album material any

  (v4 `handlers/get.ts:318-356`).
- **SPA (`characters.api.ts`):** `characterKeys.avatarRolls(id) =
  ['characters', id, 'avatar-rolls']`; `fetchAvatarRolls(core, id)`
  (limit 200), `avatarRollAction(core, id, fileId, action)`,
  `deleteAvatarRoll(core, id, fileId)`; every mutation invalidates
  `avatarRolls(id)`, `photos(id)` AND `detail(id)`.
