## Shared contract (BINDING)

### §1 — the wire surface

**Written verbatim and identically in P4.9E1A, P4.9E1B and P4.9E3A.** This lane
consumes it; it does not define it. The authoritative text is the §1 block in
**P4.9E1A** (the eight cast + avatar verbs) and in **P4.9E3A** (the eleven
chat-admin + tools verbs, of which this lane uses `ChatRng` and
`ChatUpdateToolSettings`). Read both before writing a single request.

Binding notes that bear on the client specifically:

- `Option<Option<T>>` fields (`imageProfileId`, `selectedSystemPromptId`,
  `joinScenario`, `talkativeness`) are **three-valued**: omit the key to leave
  the value alone, send `null` to clear it, send a value to set it. Model them
  as `field?: T | null` in `core-contract.ts` and be deliberate at every call
  site.
- `ChatRng.kind` — **`kind`, not `type`** (see above).
- `ChatAddParticipant` carries no `type` field; v4's `z.literal('CHARACTER')`
  is expressed by the verb name.
- **Response bodies are not pinned in §1.** Each server lane defines its own; if
  a response shape you need is unspecified, ask via a cross-lane escalation in
  your lane record rather than guessing and shipping a mismatch.
