### v4 service behavior (the quirks the port must carry)

- **Backup create** (`backup-service.ts:548`): `collectUserData` (:135) pulls
  the full user graph (characters, chats, messages, memories, profiles,
  tags, projects, groups, plugins, files); stages under
  `os.tmpdir()/quilltap-backup-*` (mkdtemp :577); streams JSON arrays
  (`writeJsonArrayFile` :505); copies blobs into `data/`+`blobs/`
  (:644-670); zips. `storeTemporaryBackup` holds `backupId→zipPath` in an
  **in-memory Map, 30-min TTL** (`temporary-storage.ts:92`).
- **Backup download**: `retrieveTemporaryBackup` is **single-use** (removes
  the entry on read), streams with `Content-Length`, and on stream close
  **unlinks the zip + rm's its temp dir** (`backup/[id]/route.ts:63-77`).
- **Restore upload** (`restore/route.ts:86`): streams the octet-stream body
  to `os.tmpdir()/quilltap-restore-<uuid>.zip` with back-pressure; tracks
  `pendingUploads` in an **in-memory Map, 1-hour TTL**, lazy
  `cleanupExpiredUploads` each request (:43). Quirk: `getPendingUpload`
  accepts `userId` but never checks it (:56-61) — carry faithfully, note it.
- **Restore execute** (`restore/restore.ts`): v4 shells out to `unzip`; v5
  uses a zip crate (a deliberate mechanism divergence — the DB-state
  differential is the equivalence proof, not the unzip mechanics).
  `mode:'replace'` wipes user data then restores; `'new-account'` **remaps
  all UUIDs**. Returns `{characters,chats,messages,tags,files,memories,
  warnings[]}`. Temp file removed in `finally` (:238).
- **Export** (`ndjson-writer.ts:731`): a long-lived NDJSON stream
  (`application/x-ndjson`, filename `quilltap-<type>-<date>.qtap`,
  `Cache-Control: no-store`); async per-entity generators resolve tag
  names / api-key labels / blobs inline. No disk writes.
- **Import** (`quilltap-import/execute.ts`): accepts multipart file
  (`loadQtapFromUpload`) or legacy JSON body; validates
  `quilltap-export v1.0`; conflict strategies `skip|replace|overwrite|
  duplicate` with the **`replace`→`overwrite` remap at route :780**; writes
  characters/chats/memories/profiles/tags/projects/document-stores/blobs,
  then reconciles relationships. Preview is count-only, no writes.
- **Tasks queue** (`handleTasksQueue` :205): per-job fields `typeName,
  status, priority, attempts/maxAttempts, scheduledAt/startedAt, lastError,
  estimatedTokens, chatId, characterName` (:267-281); stats `pending,
  processing, failed, completed, dead, paused, activeTotal` +
  `totalEstimatedTokens` (:287-297). Retry is implicit (failed with
  `attempts < maxAttempts` re-list as active); explicit actions are
  pause/resume/delete + processor start/stop + concurrency (Zod 1–32).
- **Delete-all** (`lib/backup/restore/delete-service.ts`):
  `deleteAllUserData` :215 (counts → core `deleteUserData` :90 → API keys
  :254-263; returns `DeleteSummary`); `previewDeleteAllUserData` :299
  (counts only). `deleteUserData` deletes per-userId: characters, chats,
  tags, connection/image/embedding profiles, prompt & roleplay templates,
  projects, groups, llmLogs, chatSettings, folders, wardrobe items
  (:125-143); memories per-character first (:117-122); files from storage
  via `fileStorageManager.deleteFile` + row delete (:145-158); then
  `clearFormat3Entities()` (:164) bulk-DELETEs chunks/vectors + group
  membership/`doc_mount_links` + `doc_mount_points`. The `/backups` folder
  rides the file sweep (:244-248, :265-269).
- **Dead**: `GET .../tools?action=capabilities-report` (:817) returns a
  hard-coded static object wired to nothing — do NOT port it.

oracles` (drive services directly where the route adds nothing). Run every
