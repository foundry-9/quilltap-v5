Port v4 `8bc43333`'s VAULT half: every character vault gains an optional

and the qtap-import threading.

**Explicitly NOT this lane:** the Pascal side of the same commit
(`when.metadata`, `{{metadata.key}}`, `metadataTested` — lane AY), the
mount-namespace changes (lane D7), the SPA (lane BA), and every region of
`db/character_vault.rs` outside your §3 pin.

### The load-bearing rules (from the v4 survey — carry every why-comment)

1. **metadata has NO DB column.** The vault file is the sole source of
   truth; `null`/absent and `{}` are equivalent. This is why the round's
   `fresh_schema.json` re-dump (lane D7's §1) shows NO characters change
   — if you think you need a column, the survey is wrong: STOP.
2. **Not a keystone.** A fat-fingered `metadata.json` costs metadata for
   that read and nothing else — it never hollows the character (only
   `properties.json` may declare a vault broken). Parser returns
   null → hydration substitutes `{}`.
3. **The guarded write.** `writeCharacterVaultManagedFields` writes
   `metadata.json` ONLY when `character.metadata != null`. Absence means
   "no opinion", not "empty" — writing `{}` on absence would let a
   raw-row caller (the repopulate path) silently erase a real fact
   sheet.
4. **Patch = whole-object REPLACE, not key-merge.** One field owns one
   file; a merge would make deleting a key impossible. Key-level edits
   are the caller's read-modify-write.
5. **The existence-check seed.** `ensureCharacterMetadataFile` checks the
   file EXISTS (`findByMountPointAndPath`) — it never parses, so an
   invalid sheet is never "healed" into an empty one.
