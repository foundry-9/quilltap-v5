## 7. Premise corrections / surprises

1. **Two of the four commits' SPA halves have NO v5 host.** b3f's avatar-picker `orientation: 'portrait'` + Shape line lives in `components/images/image-generation-dialog.tsx`, reached only through `ImageUploadDialog` from `avatar-selector.tsx` — v5's two avatar pickers (`screens/profile/avatar-picker.ts:16-33`, `screens/characters/edit/avatar-picker-modal.ts:10-17`) both record that leg as a named deferral; `images/generate-image-dialog.ts` is a DIFFERENT v4 component (chat). Likewise #82's "Import-from-image keeping the photograph" — v5 never shipped the import-from-image modal (`wardrobe-control-dialog.ts:105-107`, tier-3 `analyze-image`). Order these as explicit deferrals, not lane items.
2. **#81's "new-chat composer sending `wornBundleIds`" is unreachable in v5:** `manual`/Compose is disabled (`outfit-selector.ts:224-230`) and `ChatCreateOutfitSelectionInput` carries `slots?` only. Only the dialog's two `set_all` paths can send ids today.
3. **The "shared" semantics shift:** v5's `· shared` text (`wardrobe-item-row.ts:80-82`) = "not manageable". v4's chip = "not manageable AND has a non-character `origin`" — a borrowed row with no origin (an old server) shows NOTHING, and a project view with `canManage=()=>true` shows no chip for its own project-origin rows. The Show-shared filter still keys off `canManageItem` (`:975`), unchanged.
4. **`formatSlotLabels` reorders:** canonical slot order, not item order — `outfit-quick-pick.ts:137` currently prints item order.
5. **v5 has no TanStack cache for wardrobe lists** (signals via `loadCharacterWardrobeItems`), so v4's `queryKeys.wardrobe.all` / `.images()` / `.wearHistory()` invalidations map to `reloadItems`/`invalidateWardrobe`/a per-section refetch, and `mountPoints` realtime resolves to nothing (`realtime-topic-map.ts:121-130`) — a tool-drawn picture won't repaint an open dialog without a `characters`-event hook.
6. **The wire types are all absent:** `WardrobeItemDto` lacks `origin`/`wear`/`imageFileId`; `ChatEquipRequest` lacks `wornBundleIds`; `ChatSettingsDto` lacks `wardrobeImageSettings`; no images-route verbs. The four per-container item GET verbs DO exist (`characterWardrobeGet :1368`, `projectWardrobeGet :2086`, `groupWardrobeGet`, `wardrobeItemGet :7574`) but none has an SPA consumer and `wardrobe.api.ts` has no `containerGetRequest` router (its sibling header promises one) — `?action=wear-history` is the first consumer.
7. **Help text ≠ code:** `help/wardrobe.md` says `*Worn 4× · last Tue*`; `formatRelativeDays` never prints a weekday (`today`/`yesterday`/`N days ago`…). Port the code; don't "fix" toward the help.
8. **The section is labelled `Picture` in the UI** (`aria-label="Picture"`, `qt-label` text `Picture`), while help and the commit message say "Image section".
9. **`qt-badge-wardrobe-shared` is NOT new** — it is already in v5's `_content.css:229` badge family (v4 reused an existing class), so #80 ships no CSS.
10. **Dialog-only state:** Sort + Never worn are not persisted and Never worn is NOT scope-gated (unlike Show shared); `Never worn` composes with any sort; never-worn items sort LAST alphabetically under the two wear sorts.
