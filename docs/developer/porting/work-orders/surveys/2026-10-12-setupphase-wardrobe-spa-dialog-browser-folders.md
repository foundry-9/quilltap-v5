## 3. Bug 229 — the exact mechanism, and the v5 analogue

**v4:** `BaseModal` closes on a document `mousedown` outside `modalRef` via `useClickOutside(modalRef, onClose, { enabled: isOpen && closeOnClickOutside, onEscape })` (`BaseModal.tsx:97-99`) and renders through `createPortal` (`:106`). The picker is ITS OWN `BaseModal` (a sibling portal), so a mousedown inside it was "outside" the wardrobe dialog. The dialog suspends click-outside only while `overlayOpen = actions.overlayOpen || importFromImageOpen` (`:390, 397-398`), and before `97f` the picker's state lived in `WardrobeBrowser` (`useState` `:133`), invisible to `actions.overlayOpen` — so the picker's first mousedown closed the dialog (and the picker with it); "Bulk and single moves to a folder could not be done with a mouse from a chat's wardrobe." Fix (`97f`): `folderPicker` state + `openFolderPicker`/`closeFolderPicker` in `useWardrobeItemActions`, `overlayOpen` counts `folderPicker !== null`; the browser reads `actions.folderPicker`. Test: `wardrobe-browser.folders.test.tsx:280-300` renders the browser inside a `BaseModal` wired `closeOnClickOutside={!actions.overlayOpen}` with the picker state held as the hook holds it, opens the picker from the row kebab ("More actions" → menuitem "Move to folder…"), fires `mouseDown` + `click` on the "Wardrobe (top level)" option, and asserts the dialog's `onClose` was NOT called, the listbox is still there, and "Move" is enabled.

**v5's close plumbing** (`wardrobe-control-dialog.ts:1774-1797`): backdrop close is a `(click)` on `.qt-dialog-overlay` with `(click)="$event.stopPropagation()"` on `.qt-dialog` (`:160-167`) — a click inside ANY child rendered within `.qt-dialog` (where `qt-wardrobe-browser` will sit) never reaches `onBackdrop`; Escape is a `(document:keydown.escape)` host listener → `onEscape` → `if (this.editorOpen()) return;` (`:1779-1792`) — **`editorOpen` (`:1122-1130`) is v5's `overlayOpen` twin and MUST count the folder picker from the start**, or Escape inside the picker closes the whole dialog (the v5 form of bug 229). A picker built on `qt-modal` (`ui/modal.ts`, `closeOnBackdrop`, `overlayClass`) renders in place as a sibling overlay; its own backdrop click closes only it. Port: the actions store owns `folderPicker` and `overlayOpen` (counted in the dialog's `editorOpen`); the browser spec transcribes the bug-229 case as "with the picker open, a mousedown+click on an option leaves the dialog mounted and Move enabled, and ONE Escape closes the picker only" (the §J.3 idiom at `wardrobe-control-dialog.spec.ts:1512`).
