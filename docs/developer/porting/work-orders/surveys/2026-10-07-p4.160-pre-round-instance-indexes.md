## The six UNIQUE names and their duplicate pre-check

The pre-check is generic. Its key terms come from the artifact statement's own
column list, split at top-level commas, with any trailing `ASC`/`DESC`
dropped. Every term gets `IS NOT NULL`, because SQLite treats NULLs as DISTINCT
inside a UNIQUE index while `GROUP BY` would call them equal. Any partial
`WHERE` is ANDed in. The count is `SUM(n - 1)` over colliding groups: the rows
a dedupe would have to touch.

| index | partition | handled how | pre-check SQL (as the pass builds it) |
|---|---|---|---|
| `idx_chat_documents_unique` | main | pre-check → SKIP + WARN on duplicates (R-A) | `SELECT COALESCE(SUM(n - 1), 0) FROM (SELECT COUNT(*) AS n FROM "chat_documents" WHERE "chatId" IS NOT NULL AND "filePath" IS NOT NULL AND "scope" IS NOT NULL AND "mountPoint" IS NOT NULL GROUP BY "chatId", "filePath", "scope", "mountPoint" HAVING COUNT(*) > 1)` |
| `idx_connection_profiles_userId_name` | main | v4's REAL rename-dedupe (ported), then the pre-check as a safety net, then CREATE (one transaction) | `… FROM "connection_profiles" WHERE "userId" IS NOT NULL AND lower(trim("name")) IS NOT NULL GROUP BY "userId", lower(trim("name")) …` |
| `idx_folders_userId_projectId_path` | main | present by then (the folder collapse runs earlier in the boot) → skipped | `… FROM "folders" WHERE "userId" IS NOT NULL AND COALESCE("projectId", '') IS NOT NULL AND "path" IS NOT NULL GROUP BY "userId", COALESCE("projectId", ''), "path" …` |
| `idx_doc_mount_folders_mp_path` | mount-index | present PLAIN → pre-check → DROP + CREATE UNIQUE in ONE transaction, or left PLAIN + WARN | `… FROM "doc_mount_folders" WHERE "mountPointId" IS NOT NULL AND "path" IS NOT NULL GROUP BY "mountPointId", "path" …` |
| `idx_group_character_members_group_char` | mount-index | pre-check → SKIP + WARN | `… FROM "group_character_members" WHERE "groupId" IS NOT NULL AND "characterId" IS NOT NULL GROUP BY "groupId", "characterId" …` |
| `idx_group_doc_mount_links_group_mount` | mount-index | pre-check → SKIP + WARN | `… FROM "group_doc_mount_links" WHERE "groupId" IS NOT NULL AND "mountPointId" IS NOT NULL GROUP BY "groupId", "mountPointId" …` |

`db/migration_index_family_repair.rs`'s
`nulls_never_collide_and_the_partial_clause_applies` checks the count against
SQLite's own verdict on the same rows. The NULL case is also pinned end to
end: in `null_mount_points_are_not_duplicates`, two `chat_documents` rows that
differ only in a NULL `mountPoint` are no duplicate, and the index is made.

## The JS-vs-SQLite normalization asymmetry (item 2), measured

The rename uses v4's JS `normalizeProfileName` (`trim().toLowerCase()`). The
index, and so the pre-check, uses SQLite's `lower(trim("name"))`: ASCII-only
`lower`, space-only `trim`. Measured by the `clash` shape of v4's REAL
migration (`migration-index-backfill.ts`):

- `Éclair` (oldest) and `éclair`: JS folds them, so v4 renames the second to
  `éclair (2)`. SQLite's `lower` leaves `É` alone, so the bare index would
  have ACCEPTED the pair.
- `\tAlpha`: JS `trim` strips the tab, so it collides with `Alpha` and becomes
  `Alpha (4)`. SQLite's `trim` keeps the tab, so the bare index would have
  accepted it.

JS's fold is the coarser of the two. After the rename every stored name is
JS-trimmed, so SQLite's space-trim is a no-op on all of them. Where two names
agree under ASCII `lower`, they agree under `toLowerCase`, so a JS-deduped set
always satisfies the index. The pass's post-dedupe pre-check is therefore
unreachable. It is kept so that a surprise rolls the renames back and WARNs
instead of failing the `CREATE`.

**A v5 defect found here, and fixed red-first:** `services::profile_names` used
Rust's `str::trim`, which keeps U+FEFF and strips U+0085, the reverse of JS's
`trim`. The `unicode-trim` shape measured it: v4 renamed `Gamma﻿` →
`Gamma` and left `Delta\u0085` alone; v5 did the opposite. Both helpers now
trim through `jsstr::js_trim`. That also moves the settings duplicate-name 409,
the `.qtap` importer's rename and the restore merge's rename onto v4. All three
call the same two helpers, and all three port the same v4 function.
