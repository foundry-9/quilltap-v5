### 1a. `lib/memory/day-references.ts` (NEW, 221 lines) → NEW `crates/quilltap-core/src/day_references.rs`

Pure + I/O-free (v4's header: "no logging, no DB, no LLM… same contract as
`lib/memory/recall-tags.ts`"). Crate-root leaf, the `recall_tags.rs` /
`episodic.rs` convention. The self-hosted rule: **the server's local
timezone IS the user's timezone** — plain local-calendar accessors, "Never
use the `getUTC*` family for these boundaries."

Exports:
- `DayReferenceResolution` (:24): `{ timeRange: {from, to} /* full
  toISOString() strings */, pastPointing: boolean, matched: string }`. The
  window is only *meaningful* when `pastPointing` — for a future reference
  it is computed for debug logging only; callers must NOT apply it.
- `resolveDayReference(text: string, now: Date) -> … | null` (:205).

Internals: `NUMBER_WORDS` one…fourteen (:42); `MAX_DAYS_AGO = 14` (:60);
`DAY_REFERENCE_PATTERN` (:68) — ONE ordered alternation, flags `gi`,
`\b`-bounded, **order matters twice** (longest-first so "day before
yesterday" is consumed whole; the scan resumes after each match so an inner
phrase never wins the latest-match tie-break). Alternation order:
`day before yesterday` · `last night` · `earlier today` · `this morning` ·
`this afternoon` · `this evening` · `tonight` · `yesterday` · `today` ·
`(?:\d{1,2}|one|…|fourteen) days? ago` · `this week` · `last week` ·
`next week` · `tomorrow`.

Helpers: `startOfLocalDay(d, offsetDays=0)` (:91) = `new Date(y, m,
date+offset, 0,0,0,0)`; `localTimeOnDay` (:96); `startOfLocalWeek` (:101) —
**Monday-anchored**, `daysSinceMonday = (d.getDay() + 6) % 7`; `window`
(:107) = both ends via `.toISOString()`.

`resolvePhrase` (:112) mapping:

| phrase | window (local) | pastPointing |
|---|---|---|
| `today`, `earlier today`, `this morning`, `this afternoon`, `this evening`, `tonight` | [local midnight today, `now`] | true |
| `last night` | [yesterday 18:00, today 06:00] | true |
| `yesterday` | [midnight −1d, midnight today] | true |
| `day before yesterday` | [midnight −2d, midnight −1d] | true |
| `this week` | [Monday midnight this week, `now`] | true |
| `last week` | [Monday −1w, Monday this week] | true |
| `N days ago` (digits or word, 1 ≤ N ≤ 14) | [midnight −N, midnight −(N−1)] | true |
| `tomorrow` | [midnight +1, midnight +2] | **false** |
| `next week` | [Monday +1w, Monday +2w] | **false** |

Why-comment to carry: the sub-day phrases deliberately do NOT narrow the
window ("memories carry coarse event times, and a too-tight window starves
recall").

Edge cases (port exactly): `N days ago` outside 1–14 → `resolvePhrase`
returns **null** and "the previous winner stands rather than being clobbered
by a null" (so does "0 days ago" — `Number("0")` is falsy); empty text or
non-finite `now` → null; `lastIndex` reset; **later matches in the text
win**; the zero-length-match loop guard (impossible with this pattern, but
present — carry it).

Rust notes: `jiff = "0.2.31"` already a quilltap-core dep (bundled tzdb);
`regex = "1"` available. ISO output via `crate::clock::iso_from_unix_ms`.
⚠ JS `\b`/`\d` are ASCII — use `(?-u:\b)` / explicit ASCII classes (the
`starts_with_date_prefix` precedent in `distill.rs:380`). See §4a for the
timezone-parameter design.

### 1f. The timezone seam (design decision, pinned here)

The day-references resolver and the distill TODAY line need real
local-calendar math. **The Rust side must take the timezone as an explicit
parameter, never read process TZ** (parallel test threads; jiff's
`TimeZone::system()` reads env at lookup). A single `local_offset_minutes`
is NOT sufficient: v4's `new Date(y, m, d)` resolves the offset **per
constructed day** (DST-correct), so "last week" across a DST boundary needs
real zone math — pass an IANA zone and convert civil dates via jiff
(`jiff::tz::TimeZone::get`, the existing `chat_timestamp.rs:193` /
`spine.rs:890` pattern). The host already carries the zone:
`quilltap-host/src/spine.rs:837` (`pub tz: String`) — thread it to the three
distill call sites (pre_compute :259–280, build_context :2104–2112,
recall_replay :265) and the resolver as a new input field. Document the JS
DST-gap edge (a zone where local midnight doesn't exist — jiff
`Disambiguation::Compatible` is the closest analog to V8's choice).
