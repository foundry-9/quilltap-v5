## Shared contract B↔C (BINDING — identical in `p4.6m`)

Three v4-shaped quilltap-web routes (NOT dispatch variants):

1. `POST /api/v1/characters/{id}/photos` — EITHER multipart/form-data
   (`file` required, `caption?` string, repeated `tags` entries) OR JSON
   `{fileId?|linkId?, caption?, tags?}` (exactly one of fileId/linkId).
   → `201 {linkId, mountPointId, relativePath, keptAt, sha256}`.
   Errors: 404 character not found; 400 for the v4 keyword list
   (`already in`, `no linked database-backed vault`, `Unsupported MIME
   type`, `Uploaded image is empty`, `not an image`, `not found`,
   `empty bytes`); 500 otherwise.
2. `GET /api/v1/characters/{id}?action=export&format=png` →
   `200 image/png` bytes, `Content-Disposition: attachment;
   filename="<name>.png"`.
3. `POST /api/v1/characters?action=import` — multipart (`file`: a .png
   ST card or a .json ST card) → `201 {character: {id, name,
   description, defaultImageId, createdAt, updatedAt, _count: {chats}}}`;
   400 `Invalid SillyTavern PNG file` on parse failure.

If any shape must change, BOTH orders change and the change is reported
at unification.
