### The v4 dialect (what "byte-faithful" means — the gate's spec)

- **The serializer is `MarkdownBridgePlugin`**
  (`components/chat/lexical/plugins/MarkdownBridgePlugin.tsx`, 269
  lines):
  - `COMPOSER_TRANSFORMERS` (:67-87) **excludes `ITALIC_STAR` and
    `BOLD_ITALIC_STAR`**, includes `ITALIC_UNDERSCORE` +
    `BOLD_STAR` + `BOLD_UNDERSCORE`. Italic is `_text_`. The
    *why*-comment (:60-66): single `*` is a roleplay narration
    delimiter and must survive as literal text. This matches
    `lib/chat/annotations.ts:44` (`MARKDOWN_FORMATS` italic `_`/`_`).
  - `stripMarkdownEscapes(markdown, chars)` (:128-137) strips
    Lexical's auto-escapes on export (regex `\\([*_\`~])` → `$1`);
    `DEFAULT_PRESERVED_MARKDOWN_CHARS = ['*','_','\`','~']` (:120);
    the four `preserve*` props default true (:143-151).
  - Export: `$convertToMarkdownString(COMPOSER_TRANSFORMERS,
    undefined, true)` → `normalizeExportMarkdown`.
- The other v4 plugins (for scoping the port): `ComposerSyncPlugin`
  (143 — decoupled hasContent/draft-debounce; the editor owns live
  text, send reads the handle), `KeyboardPlugin` (153 —
  Enter=submit / Shift+Enter=newline chat mode; Cmd/Ctrl+Enter
  document mode; code-block escape on blank trailing line),
  `ImagePastePlugin` (80 — clipboard image →

  `FormattingCommandPlugin` (236 — bold/italic/headings/lists/

  word-boundary autocorrect), the custom multiline

  mentions plugin, no slash-command plugin exist** — don't invent
  them.

### Quirks the port must not miss

1. The dialect is the CONTRACT: `_italic_`, `**bold**`, literal
   `*`/`_`/`` ` ``/`~` unescaped, v4's transformer scope
   (headings, lists, checklists, blockquote, code fences; tables via
   the custom transformer are tier 2).
2. Non-markdown files NEVER touch the rich editor (v4 parity — the
   byte-fidelity concession is v4's own).
3. Frontmatter stays split; only the body is edited; recombine
   exactly `${rawBlock}${body}`.
4. The raw-source toggle (v4 `showSource`) ships WITH the adoption,
   not after — it's the user's escape hatch when the dialect
   surprises them.
5. Send reads markdown from the editor handle at submit time (v4's
   decoupled ComposerSyncPlugin posture) — no per-keystroke
   serialization; `hasContent` gating only.
6. Roleplay delimiters insert as LITERAL text (v4
   FormattingCommandPlugin) — the editor must not smart-format a
   user-typed `*narration*` into emphasis on input either
   (inputrules must respect the excluded ITALIC_STAR).
7. Paste-image, Enter-vs-Shift+Enter, and the focusout flush are
   behavior contracts with existing specs — they keep passing
   unmodified or the specs are updated in the same commit with the
   reason recorded.
8. `computeAbsorbNext` goes live when `USES_RICH_MARKDOWN_EDITOR`
   flips — the first save after opening a doc may legitimately
   absorb a serializer-normalization diff ONCE; spec that behavior
   (that's what the flag was built for), and byte-noise beyond the
   first absorb is a gate FAILURE, not something to absorb
   repeatedly.
