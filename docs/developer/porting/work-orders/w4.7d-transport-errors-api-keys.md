## 1. The `api_keys` table port (the last unported repo)

Facts the survey established:

- **No dedicated v4 repository.** The `api_keys` collection is hand-rolled
  INSIDE `ConnectionProfilesRepository` via `getApiKeysCollection()`
  (`ensureCollection('api_keys', ApiKeySchema)`) — it does NOT ride the
  base-repository `_create/_update/_delete`. Port it as a v5 `db::api_keys`
  module (the marshaling boundary is the table; note v4's hosting in a
  comment).
- **Plaintext.** `key_value` holds the raw secret; the old AES-GCM columns
  were dropped by migration (`decrypt-api-key-values.ts` is history, not
  live code). No read-time decryption anywhere. The DB cipher is the only
  protection — differential fixtures use SYNTHETIC keys only, and the
  harness table dumps will contain them; never put a real key in a fixture.
- Schema: `id`/`userId`/`label`/`provider` (⚠️ FREE-FORM string, not an
  enum — `ProviderEnum = z.string().min(1)`; matching everywhere is exact
  string equality)/`key_value`/`isActive` (boolean default true)/`lastUsed`
  (nullable-optional)/timestamps. DDL has `isActive INTEGER DEFAULT 1`,
  `lastUsed TEXT` nullable.
- Methods to port: `getApiKeysByUserId` (⚠️ per-row `safeParse` that DROPS
  invalid rows and returns `[]` on error — port the drop),
  `findApiKeyById` (UNSCOPED — no ownership check), `findApiKeyByIdAndUserId`
  (the primary resolver — `findOne({id, userId})`), `createApiKey` (mints
  id + timestamps → the minted-values remap tier-2 form), `updateApiKey`
  (read-modify-write preserving `id`/`createdAt`, minting `updatedAt`),
  `deleteApiKey`, `recordApiKeyUsage` (sets `lastUsed` THROUGH
  `updateApiKey`, so it also bumps `updatedAt`).
- The user-scoped wrapper semantics (`UserScopedConnectionsRepository`):
  `findApiKeyById` re-routed to the scoped variant; update/delete pre-check
  ownership; `userId` stripped from update payloads. Port these as the
  service-facing functions.
- **Close the resolver seams** with `services::api_key_service`:
  `get_api_key_for_connection_profile(profile_id, user_id)` and
  `get_api_key_for_cheap_llm_selection(selection, user_id)` (v4
  `api-key.service.ts` — the cheap variant returns `Some("")` for local
  models, `None` otherwise). Then swap the injected `ApiKeyResolver` seams
  to the real reads at each composition point (W4.2 danger routing,
  `cheap_llm_exec`, the image handler's profile key, embeddings' profile
  key, web search's `getAllApiKeys` + `isActive` scan). Note the TWO
  distinct lookup styles: moderation auto-detect matches connection-PROFILE
  provider then resolves `apiKeyId`; web search scans `getAllApiKeys()`
  for `provider === X && isActive` — do NOT unify.
- Tracked deferrals: `lib/api-keys/auto-associate.ts` (settings-tab
  feature, Phase-4 route surface) and the three UNSCOPED `findApiKeyById`
  call sites (`enrichment.ts`, `ndjson-writer.ts`, `auto-configure`) —
  all in unported Phase-4 surfaces; port the unscoped method (it exists on
  the repo) but nothing consumes it yet.

Differential: standard tier-2 (`api_keys_tier2_equivalence`) driving v4's
REAL repository methods over create/update/delete/recordUsage + the reads
(incl. an invalid-row-drop case for `getApiKeysByUserId` — seed a
malformed row raw), minted-values remap form.

## 2. The error taxonomy (`lib/llm/errors.ts` — the unported half)

Already ported (in `services::primary_stream`): the predicate/parse
functions (`is_token_limit_error` / `is_content_limit_error` /
`is_tool_unsupported_error` / `is_recoverable_request_error` /
`parse_token_limit_error` / `parse_content_limit_error`). Still unported:

- The 8 error classes (`LLMProviderError` base carrying
  provider/originalError; `APIKeyError`, `RateLimitError` (+retryAfter),
  `NetworkError`, `ModelNotFoundError`, `InvalidRequestError`,
  `TokenLimitError` (+requested/max), `ContentLimitError`
  (+limitType/limitValue/maxValue)) — a Rust enum with the same data.
- `handleProviderError` — the string-based normalizer (unauthorized/
  invalid api key/authentication/401 → APIKey; rate limit/too many
  requests/429 → RateLimit; network/econnrefused/timeout/enotfound →
  Network; model-not-found; token-limit; invalid/400 → InvalidRequest;
  else generic). Keep the MATCH ORDER — it is precedence-bearing.
- `getUserFriendlyError` — the per-class user-facing formatter,
  byte-exact strings.

Differential: a tier-1 `llm_errors_equivalence` driving v4's REAL
`handleProviderError` + `getUserFriendlyError` over a message corpus (one
row per branch + precedence-collision rows, e.g. a message matching both
401 and 429 patterns); the already-ported predicates get regression rows in
the same case file.

## 3. Non-streaming `send_message` + `validateApiKey` / `getAvailableModels`

Every provider implements `sendMessage(params, apiKey) -> LLMResponse`
alongside `streamMessage` (same params). v4's non-streaming call sites are
the cheap-LLM executor + the one-shot services + the connection-test route
— i.e. v5's `CompletionProvider` seam becomes REAL here.

- Port sans-IO: the non-streaming RESPONSE parsers per wire family
  (chat-completions JSON, responses-API JSON, anthropic message, google
  generateContent, ollama non-stream) producing the `LLMResponse` shape
  (`content`/`finishReason`/`usage`/`toolCalls`/`reasoningContent`/
  `thoughtSignature`/`cacheUsage`/`raw`) — the request side already exists
  (W4.7c `build_request`). Reuse the W4.7b recorder pattern: committed
  response payloads captured from the real plugins with fetch/SDK mocked;
  diff the parsed `LLMResponse`.
- `validateApiKey(apiKey) -> bool` + `getAvailableModels(apiKey) ->
  Vec<String>` (+ the optional `getModelsWithMetadata`): port as request
  builders + response parsers per provider (models-list endpoints; ollama
  uses `GET /api/tags` for both). Tier-1 over canned payloads.

## 4. The `ProviderTransport` trait + host impl

The IO boundary everything above plugs into: `execute(BuiltRequest) ->
Response` (non-streaming) + `execute_stream(BuiltRequest) -> byte/frame
stream` (feeding the W4.7b decoders), abort + timeout capable.

- **v4 baseline (survey-confirmed): NO timeout, NO abort, NO retry exists
  at v4's provider tier.** The SDKs' silent defaults apply (openai/
  anthropic SDK `maxRetries: 2`, ~10-min timeout); ollama's raw fetch is
  unbounded; cancellation is only stop-iterating-the-generator. The v5
  trait therefore carries timeout/abort/retry as HOST policy knobs with
  defaults matching the SDKs' observable behavior (retries re-send the
  same built request); none of this is oracle-checkable — transport is
  integration-smoke tier, no differential.
- Per-provider construction facts the impl must carry: the User-Agent
  header (`getQuilltapUserAgent()` shape) on every provider; openrouter's
  `HTTP-Referer` from `BASE_URL` (default `http://localhost:3000`) +
  `X-Title`; the baseUrl `rewrite_localhost_url` call at CONSTRUCTION time
  (ported in W4.7a — the host injects the gateway), matching v4's
  registry-level `resolveBaseUrl` (plugins receive an already-rewritten
  URL).
- **The google config→wire framing (the W4.7c deferral) closes HERE**:
  reproduce the genai SDK's split of the flat `config` — sampling/output
  fields (`temperature, topP, topK, candidateCount, maxOutputTokens,
  stopSequences, responseLogprobs, logprobs, presencePenalty,
  frequencyPenalty, seed, responseMimeType, responseSchema,
  responseJsonSchema, responseModalities, mediaResolution, speechConfig,
  thinkingConfig, imageConfig, enableEnhancedCivicAnswers`) nest under
  `request.generationConfig`, while `systemInstruction, safetySettings,
  tools, toolConfig, cachedContent, serviceTier` stay at the request root;
  the `functionCall` part is REBUILT field-by-field in the order
  `id? → args → name` (the `{name,args}`→`{args,name}` reorder), and
  `partialArgs`/`willContinue` THROW. Verify byte-exact with a recorded
  wire capture (fetch-intercept under the real SDK — extend
  `record-request-envelopes.mjs`); this completes
  `request_builder_google_equivalence` to full wire bytes.
- **Placement decision:** the trait lives in `quilltap-core::model::
  transport`; the reqwest impl goes behind a NON-DEFAULT cargo feature
  (e.g. `native-transport`) so the default core build stays IO-free —
  expect it to migrate to the CLI/host crate when one exists. If the
  feature-gated dep fights the workspace (build times, feature unification),
  STOP and put the impl in a new tiny `quilltap-transport` crate instead —
  do not let reqwest into the default core dependency graph either way.

## Watch-outs

- Synthetic keys only, everywhere (fixtures, canned seams, recorded
  envelopes). The recorded-envelope fixtures from W4.7c already follow
  this — reuse their conventions.
- `recordApiKeyUsage` bumps `updatedAt` (it rides `updateApiKey`) — the
  differential must prove it.
- Per-provider `cacheKey` semantics diverge (`text.ts:103–115`: OpenAI/
  Grok `prompt_cache_key`, DeepSeek `user_id`, compat/Z.AI/OpenRouter
  `user`, Anthropic/Ollama ignore) — W4.7c's builders carry this; the
  non-streaming path must route through the SAME builders, not re-derive.
- OpenAI is the Responses API (`input`/`instructions`/
  `previousResponseId`), not chat-completions — its non-streaming parse is
  the responses-API family.
- The openai-compatible provider is the canonical base deepseek extends —
  port the shared parse once, flavor the differences (the W4.7b `Flavor`
  precedent).
