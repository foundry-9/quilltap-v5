## Shared contract (BINDING — reproduced verbatim in all three orders)

Five new `Request` variants land in `crates/quilltap-core/src/api/types.rs`
(lane A owns the Rust side). The SPA lanes define matching LOCAL request types
in their own api modules (cast at the call site) — **neither SPA lane touches
`core-contract.ts`**; the unifier folds the types into the `CoreRequest`
union at unification (the P4.6ao precedent). Wire encoding is the standing
one: requests internally tagged (`#[serde(tag = "type", rename_all =
"camelCase")]`, fields camelCase); responses adjacently tagged
(`{"type": …, "data": …}`).

### §1 — the llm-logs verbs (lane A ⇄ lane B)

```rust
/// v4 `GET /api/v1/llm-logs` (all filter branches).
#[serde(rename_all = "camelCase")]
LlmLogsList {
    #[serde(default)] message_id: Option<String>,
    #[serde(default)] chat_id: Option<String>,
    #[serde(default)] character_id: Option<String>,
    /// v4's `type` query param. Wire name `logType` — a field literally
    /// named `type` would collide with the internally-tagged envelope key.
    /// The REST edge maps `?type=` onto it. NOT validated (v4 casts).
    #[serde(default)] log_type: Option<String>,
    #[serde(default)] standalone: bool,
    #[serde(default)] include_messages: bool,
    /// Raw query strings; the HANDLER ports v4's parseInt/Math.min body
    /// (including the NaN no-slice quirk) so dispatch and REST agree.
    #[serde(default)] limit: Option<String>,
    #[serde(default)] offset: Option<String>,
},
/// v4 `GET /api/v1/llm-logs/[id]`.
#[serde(rename_all = "camelCase")]
LlmLogGet { id: String },
/// v4 `DELETE /api/v1/llm-logs/[id]`.
#[serde(rename_all = "camelCase")]
LlmLogDelete { id: String },
```

Response payloads (the `data` member):

- `llmLogsList` → `{ "logs": [...], "count": n, "total": n, "limit": n,
  "offset": n }` — v4's exact envelope: `total` pre-slice, `count`
  post-slice.
- `llmLogGet` → the raw log object itself (v4 `successResponse(log)`, no
  wrapper key).
- `llmLogDelete` → `{ "success": true, "deletedId": "<id>" }`.

Lane B's client sends exactly what v4 `useLLMLogs` sends:
`{ type: "llmLogsList", chatId, includeMessages: true }` — nothing else.
Response-variant Rust names follow the existing camelCase-tag convention so
the wire tags read `llmLogsList` etc.; lane B mocks against these tags and
the unifier's activation must not need renames.

### §2 — the system image-aesthetics verbs (lane A ⇄ lane C)

```rust
/// v4 `GET /api/v1/system/image-aesthetics?kind=lantern|aurora`.
#[serde(rename_all = "camelCase")]
SystemImageAestheticsGet { kind: String },
/// v4 `PUT /api/v1/system/image-aesthetics?kind=…`; empty or absent
/// content deletes the file (restores fallback).
#[serde(rename_all = "camelCase")]
SystemImageAestheticsSet {
    kind: String,
    #[serde(default)] content: Option<String>,
},
```

Responses mirror the `ProjectAestheticGet`/`Set` pair byte-for-byte:
get → `{ "content": "<markdown or ''>" }`; set → `{ "success": true }`.

Pinned error semantics (both transports): invalid kind → badRequest
`'Query param "kind" must be "lantern" or "aurora"'`; GET with no general
store → success `{content: ''}`; PUT with no general store → serverError
`'Quilltap General document store is not available'`; malformed PUT body →
content `''` → deletes the file.
