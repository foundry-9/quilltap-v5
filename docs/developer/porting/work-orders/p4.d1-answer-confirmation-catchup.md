## Mandate

Catch the ported answer-confirmation service (W4.3,
`quilltap-core::services::answer_confirmation`) up to v4 commit `a7b1398d`
("keep answer-confirmation amendments in the current conversation"), and
regenerate its differential green against v4 HEAD. The change: the
re-affirmation pass now receives (a) the replying character's name and (b) a
compact transcript of the recent live conversation, and its prompts were
rewritten so a correction stays anchored to the current scene instead of
drifting into an older conversation quoted by the reference material.

## The v4 delta (read `git show a7b1398d` in the v4 checkout — it is the spec)

All in `lib/services/chat-message/answer-confirmation.service.ts` +
`message-finalizer.service.ts`:

1. **New pure function `buildRecentConversationContext(messages,
   participants, participantCharacters) -> string | null`.**
   - Filter: `type === 'message'`, no `systemSender`, not `isSilentMessage`,
     `content` a non-empty-after-trim string. Empty result → `null`.
   - Keep the LAST `RECENT_CONTEXT_MAX_MESSAGES = 20`.
   - Each line: `` `${name}: ${content.trim()}` `` where `name` =
     `getParticipantName(m.participantId, participantCharacters, participants)`
     falling back to `'User'` when `String(role).toUpperCase() === 'USER'`
     else `'Character'`. (`getParticipantName` is v4
     `lib/chat/context/message-attribution.ts` — it is already ported in the
     Phase-1 per-character context shaping; locate and REUSE the ported
     function, do not re-implement.)
   - Join with `'\n\n'`; if the transcript exceeds
     `RECENT_CONTEXT_CHAR_BUDGET = 8_000` **UTF-16 units**, keep the TAIL
     (`transcript.slice(len - 8000)` — JS `.length`/`.slice` are UTF-16, use
     the `jsstr` primitives) and prefix
     `` `[…earlier conversation truncated…]\n` `` (note: single `\n`, and the
     prefix is added AFTER the slice so the result exceeds 8 000 by the
     prefix length — faithful).
2. **`buildReaffirmationSystemPrompt(characterName?)`** — rewritten bytes.
   `` `${you}You are reconsidering …` `` where `you` =
   `` `You are ${characterName}. ` `` when a name is given, else `''`. The
   body is multi-paragraph new text ("Stay in the current scene. …") —
   byte-exact. If the ported prompt bodies live in a generated `prompt_text`
   submodule with a checked-in generator, regenerate through the generator;
   otherwise port the template faithfully (it has one interpolation point).
   `CONSISTENCY_SYSTEM_PROMPT` is UNCHANGED — do not touch it.
3. **The re-affirmation user message restructure.** Now built from
   `reaffParts`: when `conversationContext` is non-empty, prepend
   `'=== The conversation so far (this is the scene you are in) ==='`, the
   transcript, and `''`; then the relabeled sections
   (`'=== Your draft reply — the next thing you were about to say ==='`, the
   reworded flagged-conflicts line, `'=== What you actually recalled and
   looked up this turn (your background knowledge — NOT the conversation)
   ==='`, and the rewritten closing instruction). Join `'\n'`. Transcribe
   every string byte-exact from the v4 source at `a7b1398d`.
4. **`RunAnswerConfirmationOptions`** gains `characterName?: string` and
   `conversationContext?: string | null`; both consumed only by the
   re-affirmation pass (the consistency check is unchanged).
5. **The finalizer threading** (`message-finalizer.service.ts`): inside the
   active-confirmation branch, build
   `conversationContext = buildRecentConversationContext(priorEvents,
   chat.participants ?? [], participantCharacters)` and pass it +
   `characterName: character.name` into `runAnswerConfirmation`. Mirror this
   in `quilltap-core::services::message_finalizer` at the same point (the
   v5 finalizer already holds the prior events and the participant-character
   map for the whisper scan — reuse them; check exactly which message list v4
   passes: `priorEvents` is the conversation up to but NOT including the
   draft reply).
