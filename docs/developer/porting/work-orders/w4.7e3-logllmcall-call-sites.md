## What to port

1. Each closure calls the ported `log_llm_call` with v4's exact argument
   construction (messages/temperature/maxTokens/tools into
   `summarize_request`; content/error/finishReason/toolCalls into
   `summarize_response`; usage/cacheUsage/rawProviderUsage/requestHashes
   only when present; `durationMs` from the INJECTED clock —
   `now_ms`-before/after around the provider call, matching v4's
   `Date.now()` pair; `LogContext::none()` on every request-path site).
   Fire-and-forget fidelity: v4 either `.catch`es or awaits per site —
   the writer never throws, so awaiting is safe everywhere (the watermark
   precedent); match each site's error-swallow shape.
2. The `is_logging_enabled` gate runs INSIDE the writer (already ported) —
   call sites do not pre-check. The llm-logs write lands on the llm-logs
   partition via the writer task; differentials must open the fixture with
   the llm-logs partition attached (or a main-only instance's
   `PartitionUnavailable` swallowed — check what v4's fixtures do and match;
   the cleanest form is a three-DB fixture like `state_sql_tools`').

## The regeneration plan (serialize; each step commit-able)

For each affected differential: un-mock `logLLMCall` on the v4 oracle side,
add the `llm_logs` table dump (minted `id`/`createdAt`/`updatedAt`
placeholdered or remapped per that differential's existing form;
`durationMs` diffs EXACTLY because both clocks are pinned), and re-run
green. Order (smallest/most-isolated first):

1. **`compression_tier3`** — the writer's through-a-real-call-site proof
   (the W4.7e order named it; the cheap_llm_exec closure fires
   `CONTEXT_COMPRESSION` rows).
2. **`danger_gatekeeper_tier3`** — `DANGER_CLASSIFICATION` rows (the
   moderation-path cases write none — bank the absence).
3. **`answer_confirmation_tier3`** — `ANSWER_CONFIRMATION` rows via the
   executor map (check + re-affirmation both).
4. **`image_generation_tier3`** — the four-site matrix incl. the post-hoc
   reroute legs (a failure row THEN a success row).
5. **`avatar_job_tier3`** + **`story_background_job_tier3`** — the job-path
   rows; these also prove the cheap-LLM task rows for
   `derive-scene-context` (`SUMMARIZATION`) and
   `craft-story-background-prompt` (`IMAGE_PROMPT_CRAFTING`) alongside
   `APPEARANCE_RESOLUTION`.
6. **`primary_stream_tier3`** — `CHAT_MESSAGE` with the requestHashes
   computed at the wire (the hash inputs are the formatted messages + the
   reshaped tools — assert the tier fields against the ported
   `compute_request_prefix_hashes` output).
7. **`memory_processor_tier3`** + **`context_summary_service_tier3`** —
   their cheap-LLM calls now write rows; regenerate with the dump added.

**Degradation plan:** if the session runs long, land the closures + steps

**Explicitly NOT regenerated:** `orchestrator_tier3` — its corpus fires

## Watch-outs

- `durationMs` is the one wall-clock-shaped field — both sides must derive
  it from the pinned/ticking oracle clock (the +1 ms/read orchestrator
  precedent) or it diffs. If a differential's existing clock is frozen (not
  ticking), `durationMs` is 0 on both sides — fine, bank it.
- The task→type map's `|| 'SUMMARIZATION'` default is load-bearing for any
  task string not in the table — do not "fix" an unmapped task to a nicer
  type.
- `is_logging_enabled` logs BY DEFAULT — corpora with no `chatSettings`
  row will write rows; corpora that must NOT write need an explicit
  `llmLoggingSettings: {enabled: false}` (bank one such case somewhere to
  prove the gate).
- **Parallel-round contention:** this unit touches `cheap_llm_exec.rs`,
  `primary_stream.rs`, the gatekeeper, `answer_confirmation.rs`,
  `generate_image.rs`, and the two W4.9c job handlers — NONE of the four
  spine files, no overlap with W4.5's carina modules or W4.7e2. Safe in
  parallel with W4.4b / W4.5 / W4.7e2; if W4.4b's finalizer work collides
  with the answer-confirmation regeneration, hand THAT ONE regen to the
  round's unification pass.
