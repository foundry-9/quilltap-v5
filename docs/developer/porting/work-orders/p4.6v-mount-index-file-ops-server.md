### Quirks the port must not miss

1. **Dual write/delete surfaces.** `write-file`/`delete-file` exist both as
   `?action=` verbs AND as PUT/DELETE on the catch-all. v4's SVAR adapter
   uploads via the action verb (multipart) but deletes files via the
   catch-all DELETE, and folders via `?action=delete-folder`. Variants are
   behavior-keyed (one variant per behavior); the web edge maps BOTH v4 route
   shapes onto them. Preserve both HTTP shapes — the CLI + next round's SPA
   use both.
2. **`joinPath` malformed percent-encoding → `FileOpError('INVALID_PATH')`**
   (400, not 500) — `files/[...path]/route.ts:40`.
3. **Descriptions are blob-only** — PATCH description on a text document
   400s (:283). Rename runs before description so the update lands on the
   new path (:264).
4. **Reindex is synchronous in-request; embed is async jobs** — deliberate
   split, keep it.
5. **Capabilities are derived, never persisted** — mirror
   `handleConvert`/`handleDeconvert` guards; mid-conversion quiesces every
   verb; `canConvert` refuses while scanning.
6. **`resolveFsAbsolute` boundary-escape guard** and `isPathSafe` are
   security-load-bearing — port with their exact refusals and unit-pin them.
7. **Blob routes fall back to `doc_mount_documents`** on GET/DELETE when no
   blob row matches.
8. **`FileOpResult.strategy` + sha pair** is contract surface (the SVAR
   adapter's `reindexAfterCopy` keys on `strategy === 'byte-copy'` + dest ext
   ∈ {pdf,docx}) — serialize it faithfully.
9. **fs listing merges on-disk dirs** so empty folders show
   (`listFilesystemFolders` honors `excludePatterns`).
10. **`storeMountFile` refuses a background-job child context** — in v5 the
    single-writer ownership already enforces this; carry the why-comment.
