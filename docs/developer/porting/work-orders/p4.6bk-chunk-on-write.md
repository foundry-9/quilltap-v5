## Mandate

Close a real v5 gap discovered by the P4.9G5 restore differential and recorded
there as a deliberate tripwire: **v5 never chunks a database-backed document as
it is written, where v4 always does.** Every database-store write — character
vault provisioning and update, project stores, group stores, scenarios, the
Document-Mode operator surface, the doc-edit tools — leaves the document
semantically unsearchable in v5 until something explicitly reindexes it.

Deliver the chunk-on-write pass at both v5 write sites, prove it with a
differential that actually dumps the chunk tables, and **remove the tripwires**
that currently assert the gap.

**Do NOT touch:** `apps/web/**` (E2B), `services/quilltap_import/**` or
`api/system_qtap.rs` (G4), `services/announcer/**` / `api/chat_post_office.rs` /
`api/types.rs` (E2A). **`api/types.rs` is FROZEN for this lane.**

## Survey-verified starting points (2026-07-25 @ v4 `e646f58b` — do not re-derive)

### The v4 behavior, in full (`lib/mount-index/database-store.ts:133-155`)

```ts
  // Chunk the just-written content so it is immediately searchable. The write
  // above only records the document + link row (chunkCount 0); without this the
  // embedding scheduler triggered by emitDocumentWritten below would find no
  // chunks, and the document would stay unsearchable until a manual rescan.
  // reindexSingleFile reads the content back from doc_mount_documents and
  // (re)builds the link's chunks, so an overwrite re-chunks too.
  //
  // Parent-only: inside the forked job child this write is buffered (read-your-
  // writes does not hold), so the content reindexSingleFile would read isn't
  // committed yet. In-child writers (doc_write_file in autonomous turns) leave
  // chunking to the next database rescan, as before. Bridge writers
  // (conversation summaries, avatars) already run this on the parent via
  // host-RPC, so their documents chunk here.
  if (process.env.QUILLTAP_JOB_CHILD !== '1') {
    try {
      const { reindexSingleFile } = await import('@/lib/doc-edit/reindex-file');
      await reindexSingleFile(mountPointId, rel, '');
    } catch (chunkErr) {
      logger.warn('Failed to chunk database document after write', { … });
    }
  }
```

Four facts to carry, not three: it runs **after** `linkDocumentContent`; it is
**best-effort** (a chunk failure never fails the write, only warns); it
**re-chunks on overwrite**; and the `QUILLTAP_JOB_CHILD` guard exists **only**
because v4's forked job child buffers writes so read-your-writes does not hold.

**That second sentence is the whole story of why this gap was invisible.** The
oracles were run with v4's chunk pass switched OFF, so every characters / vault /
groups / projects differential compared a chunk-free v4 against a chunk-free v5
and went green. Fixing the port therefore means **un-pinning the oracle side and
regenerating**, not just adding Rust.

**Classify all 38 sites explicitly and record the classification in the lane
record** — if a site does not fit the rule, say why rather than bending it.

### Two port judgments this lane must MAKE and RECORD (do not decide them silently)

1. **The layering inversion.** `db/database_store.rs` is the data layer;
   `reindex_single_file` lives at `crates/quilltap-core/src/services/mount_index/
   reindex_file.rs:75`. A `db` → `services` call inverts the layering and may not
   even compile as a plain call. v4 sidesteps it with a dynamic `import()` at the
   call site — which is a Node cycle-breaker, not a design. Pick v5's answer (an
   injected seam / callback parameter, or relocating the chunker) and write down
   why. Whatever you pick, `reindex_single_file`'s existing signature is
   `(conn, mount_point_id, relative_path, absolute_path, &dyn
   DocumentTextExtractor)` and `absolute_path` is `""` for database-backed
   stores.
2. **The `QUILLTAP_JOB_CHILD` guard has no v5 analogue.** v5's job runner is
   **in-process by locked decision** (memory note
   `job-runner-fork-ipc-non-port`), so there is no forked child and no buffered
   write — the exact condition the guard exists to dodge. The likely correct port
   is therefore "always chunk", which makes v5 chunk in cases where v4 skips
   (`doc_write_file` in autonomous turns). **That is a behavioral divergence** —
   state it plainly, decide it deliberately, and if you conclude it needs a human
   ruling, say so in the lane record and land the rest.
