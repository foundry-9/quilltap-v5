## The drift, classified (surveyed 2026-08-04)

**`4bbeab47` "feat(salon): pick a roleplay template when creating a
chat"** (16 files, +626/−13) — the New Chat form gains a Roleplay
Template dropdown beneath Play As, pre-selected with what the chat would
have gotten anyway (project default > user/global default > No Template,
that option labelled `(default)`), hidden when no templates exist.
`POST /api/v1/chats` accepts a **tri-state `roleplayTemplateId`**:
present (even as `null`) beats both defaults, omitted keeps the old
default chain, an unresolvable id is a 400. The client sends the value it
displayed but **omits the key when the settings/templates/project fetches
failed**, so a read error can't masquerade as a deliberate "no template".
Reference-data reloads (adding a character, switching projects) re-seed
the default only until the user picks by hand
(`roleplayTemplateTouched`). Riders: `help/chats.md` +
`help/templates-in-chats.md` (→ the `p4.9i2` bank; v5 has no help
surface).
