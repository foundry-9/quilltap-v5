## Mandate

Port v4's dedicated tool-result renderer — the collapsible Tool
Request / Tool Response card with the Success/Failed badge, tool-icon
header, and attribution line — so a `role === 'TOOL'` message stops
rendering as a raw-JSON whisper bubble. Rendering/affordance only: the
whisper-gate sets (`ALWAYS_PRIVATE_TOOLS` / `VAULT_READ_TOOLS` in
`tool_execution.rs`) and the client whisper filter are already ported
faithfully and MUST NOT change. No server surface changes; no new
dispatch verbs.

## Survey-verified starting points (2026-07-24, v4 `e646f58b`)

### v4 — the component to port

**`components/chat/ToolMessage.tsx`** (whole file, 677 lines) — the
byte-fidelity source for every label and behavior:

- **Envelope parse** (`:216-232`): `JSON.parse(message.content)` into the
  `ToolResult` shape (`:55-75` — `toolName`/`tool` [old/new normalization
  `:221`], `initiatedBy`, `operatorName`, `private`, `delegatedDisplay`,
  `success`, `result`, `arguments`, `prompt`, `provider`, `model`,
  `images`); parse-failure fallback `{toolName:'unknown', success:false,
  result:'Unable to parse tool result'}`.
- **Collapse state** (`:212-213`): two independent booleans
  (`showRequest`/`showResponse`), both default collapsed, local state
  only — **no persisted setting anywhere** (searched: none exists; §3 of
  the survey). Port as local component state; do NOT invent a setting.
- **Tool Request section** (`:476-509`): only when
  `arguments || prompt`; `▶`/`▼` glyph + `Tool Request` label; collapsed
  one-line preview (`getPreviewText` `:174-178` — first line sliced to 80
  chars + `...`); expanded `<pre>` of `formatRequestContent` (`:183-188` —
  the `prompt`, else `JSON.stringify(arguments, null, 2)`); copy button
  (tooltip `Copy request`, toasts `Request copied to clipboard` /
  `Failed to copy to clipboard`, `:337-349,492-495`).
- **Tool Response section** (`:513-601`): when `result` (or
  `generate_image` with image attachments); same disclosure idiom, label
  `Tool Response`, tooltip `Copy response`; expanded body
  `formatResultContent` (`:193-209` — pretty-print JSON, honor
  `result.formattedText`) in a `<pre>` tagged `tool-response-content`;
  image thumbnails for `generate_image`.
- **Header** (`:424-473`): display-name + emoji icon from the `toolInfo`
  map (`:243-324`; fallback ⚙️ + raw toolName `:326-330`); Success/Failed
  badge (`:464-472`, classes `qt-badge-success`/`qt-badge-destructive`);
  attribution `"<actor> ran <toolName>"` (`:438-461`, actor
  `operatorName || 'You'` for user-initiated else the character name);
  italic `whisper` tag when the row is itself a whisper (`:432-436`).
- **Wardrobe notice** (`:90-146`, rendered `:412-421`): human-readable
  action line above the card for `wardrobe_*` tools.
- **`delegatedDisplay` short-circuit** (`:367`): render NOTHING when

- **Layouts:** `embedded` (inside an assistant bubble, no avatar) vs

### v5 — the gap and the slot-in points

- **No tool branch exists anywhere.** A TOOL row flows:
  `salon-conversation.ts:1009-1026` (`displayMessages`, whisper filter —
  tool whispers correctly pass, `whisper-visibility.ts:43-59`) →
  `chat-view-model.ts:161-190` (`buildRenderItems` — TOOL rows are NOT
  filtered by `splitSwipeGroups`'s `role !== 'SYSTEM'` and have no
  `systemSender`, so they become plain `{type:'message'}` items) →
  `message-list.ts:69-90` → `message-row.ts`.
- **The raw-JSON symptom:** `message-row.ts:139` passes
  `message().content` verbatim to `qt-message-content` (markdown), and
  `variant()` (`:450-455`) returns `'whisper'` on any
  `targetParticipantIds`, printing the hardcoded label at `:105`
  (`Private whisper` — note v4's label is dynamic, `whispered to <names>`,
  `MessageRow.tsx:321-327`).
- **Natural insertion:** a tool-result branch either as a new
  `RenderItem` variant in `buildRenderItems` or at
  `message-row.ts:138-140` (`@if (isToolResult()) { <qt-tool-message …> }
  @else { … }`). The grouping transform (embedded placement) belongs in
  the view-model layer beside `buildRenderItems`.
- **Streaming path:** live tool calls already render a minimal transient
  affordance (`streaming-message.ts:76-99` — `qt-chat-tool-embedded`,
  wrench icon + name + status); settled rows re-enter via
  `buildStreamRenderItems` (`message-list.ts:330-347`) → the same
  `buildRenderItems`, so one fix covers both paths. The stream reducer
  never mints TOOL DTOs (`streamMessageToMessageDto` emits ASSISTANT
  only) — the canonical TOOL rows arrive on the post-dispatch refetch.
- **Reusable idioms:** the collapsible = `thinking-block.ts`
  (`<details>/<summary>` + chevron — mirror it rather than porting
  `useState` toggles, but keep v4's `▶`/`▼` glyphs and default-collapsed
  behavior); icons = `qt-icon` (`copy`, `wrench` already registered);
  verify `qt-badge-success`/`qt-badge-destructive` exist in v5's theme
  (they are v4 tokens; add the CSS if missing, matching v4's `_chat.css`
  bytes).
