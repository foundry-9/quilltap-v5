## Survey-verified starting points (2026-07-13 @ `dd0d9ff5`, do not re-derive)

### 1. The codec (the load-bearing unit)

**v4 `lib/embedding/float32-conversion.ts` (+270).** The
self-describing header (little-endian):

```
[0]      magic   = 0xEB
[1]      version = 0x01
[2]      dtype   : 0x01 = int8-symmetric, 0x02 = float16
[3..6]   dim     : uint32
int8: [7..10] scale : float32 (dequant f = int8 * scale)
      [11..11+dim)  int8 body      → total = 11 + dim
f16 : [7..7+2*dim)  float16 body   → total = 7 + 2*dim
```

- int8 math: `scale = maxAbs/127` (guarded to `1` for all-zero /
  non-finite maxAbs); `q = clamp(round(v/scale), -127, 127)`.
  **⚠ Pin JS `Math.round` semantics** (round-half-toward-+∞) — Rust
  `f32::round` is half-away-from-zero and differs at negative
  halves; the Phase-1 JS-number-fidelity ports are the precedent.
- f16 fallback: manual IEEE-754 half conversion
  (`float32ToHalfBits`/`halfBitsToFloat32`, round-to-nearest-even,
  subnormals + Inf/NaN).
- `isQuantizedEmbeddingBlob`: `len>=7` AND `[0]==0xEB && [1]==0x01`
  AND declared dim is byte-length-consistent; anything else decodes
  as legacy raw Float32.
- Signature facts: `float32ToBlob` now WRITES QUANTIZED
  (`EMBEDDING_STORAGE_DTYPE = INT8` is the single switch); new
  `float32ToQuantized`/`quantizedToFloat32`/`float32ToBlobRaw`;
  `blobToFloat32`/`blobToEmbedding` header-aware;
  `parseLegacyEmbeddingText` unchanged.
- v4's own test pins: per-element error ≤ scale; mean cosine ≥ 0.999
  (int8) / ≥ 0.9999 (f16); top-10 retrieval overlap ≥ 0.95 on a
  clustered corpus; sizes `11+dim` / `7+2*dim`; legacy raw decodes
  bit-exactly.

**v5 target: `crates/quilltap-core/src/embedding_blob.rs`** —
currently raw-Float32 ONLY. The write policy decision is MADE:
**v5 writes quantized too, byte-identical to v4** (v5 is a peer
writer of the shared synced DB; a mixed-format corpus and diverging
tier-2 blob dumps are both unacceptable; feature 5.1 builds on this
codec). Keep the function names (`blob_to_float32` /
