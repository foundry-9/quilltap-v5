## The drift, classified (surveyed 2026-08-01)

v4's wardrobe is tri-tier (character vault / project stores / Quilltap
General). The UI and every in-chat wardrobe tool already merged all three;
the two server paths that dress characters AT CHAT START read the vault
only. `8bb1a958` fixes seven defects — **and the survey confirmed v5
currently shares the design-time four** (vault-only pools, no component
hydration, `&[]` passed to the preview resolve) **and lacks all three
live-run fixes** (serial consults, no provider bound, no deliberate-nudity
flag):

1. `llm_choose` couldn't pick shared items (candidate list from
   `findByCharacterId` alone; validator dropped outside ids; shared-only
   wardrobe failed the non-empty guard so the LLM was never called).
2. `default` mode disagreed client↔server (client decided over the merged
   list, server resolved from the vault).
3. The creation dialog's outfit preview missed the project tier (no
   `projectMountPointIds` into `resolveEquippedOutfitForCharacter`).
4. A shared composite resolved to nothing (`resolve-equipped` seeded its
   item map from vault + equipped ids; shared components emitted as
   unknown leaves and dropped).
5. Serial consults (a chat took 2m32s to open) → resolve every character
   CONCURRENTLY (`Promise.allSettled`), commit SERIALLY (`setEquippedOutfit`
   is a read-modify-write of one JSON column keyed by character).
6. No provider bound → `OUTFIT_LLM_TIMEOUT_MS = 60_000`, then defaults
   (request abandoned, not aborted — still billed, still logged).
7. "Naked" and "I failed" were the same answer → the prompt asks for
   `"deliberate": true` alongside empty slots; `chooseLLMOutfit` returns
   `{slots, deliberatelyUnclothed}`; only a real boolean counts (stringy
   `"true"` rejected).

**Locked merge rules (from the feature doc + tests):** merge FULL pools
first, filter `isDefault` LAST (a personal `isDefault:false` copy shadows a
shared default — the opt-out; filtering first hides it); precedence
character > project > general, last project mount wins, archived dropped
(archiving a personal override lets the shared item resurface); personal +
shared defaults LAYER in the same slot ordered `createdAt` asc (undated
last) on server AND client; callers resolve `projectMountPointIds`, the
callee receives it REQUIRED; the shared pool is fetched once per call,
lazily (a manual/none batch pays nothing).
