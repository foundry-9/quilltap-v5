## Survey-verified starting points (dated 2026-07-16 @ v4 `a33ac8b8` — do not re-derive)

### v4 bug 1 — the sync trigger (`6c59b1ca`)

`ensureHelpDocsSynced()` gated on `if (existing.length > 0) return` (old
`lib/help/help-doc-sync.ts:224`). It is the only sync trigger outside
`EMBEDDING_REINDEX_ALL`, so a doc added to `help/` after the first sync
never got a row — eleven shipped docs (answer-confirmation,
brahma-console, custom-tools, post-office among them) were invisible in
the Guide. It now gates on
`existing.length > 0 && !helpDocsDivergeFromDisk(existing)`.

### v4 bug 2 — the unregistered blob column (`6c59b1ca`) — CONTEXT ONLY, NOT v5 WORK

Mechanism: `lib/database/backends/sqlite/backend.ts:662`
`registerBlobColumns(tableName, columns)` merges into
`this.collectionBlobColumns`; `getCollection(name)` (`:668-680`)
snapshots that set into a new `SQLiteCollection`. The set drives both
directions — **write**: `documentToRow(doc, jsonColumns, this.blobColumns)`
(`:126/159/168` → `json-columns.ts:284`); a registered column takes
`embeddingToBlob`, an unregistered one falls through to `JSON.stringify`,
and `JSON.stringify(Float32Array)` yields an index-keyed object
`{"0":0.1,...}` stored as TEXT. **read**: `hydrateRow` (`:379-394`) —
only `this.blobColumns.has(key)` reaches `parseLegacyEmbeddingText`;
unregistered, the TEXT lands in the Zod-validated field as a string,
fails validation, and the row is **silently dropped from `findAll()`**.

`manager.ts:113-121` registers known blob columns at backend construction
"regardless of which repository is accessed first" — but `help_docs` was
NOT on that list. It alone relied on `HelpDocsRepository` registering
lazily and caching `private blobColumnsRegistered = false` **on the
instance**. A repository OUTLIVES the backend it first ran against
(reconnect, dev-server reload), so the stale flag left the fresh backend
with no blob handling for `help_docs`. The sync rewrote 28 rows; all 28
vanished from `/api/v1/help-docs`.

**The insight:** the "legacy" JSON-text embeddings were NEVER legacy. An
unregistered blob column was MINTING them on every write.
`lib/startup/repair-text-embeddings.ts` (every-boot repair over
`vector_entries`, `memories`, `help_docs`, `conversation_chunks` —
`EMBEDDING_TABLES` at `:41-46`) plus read-side recovery treated the
SYMPTOM, which is why it kept coming back and looked historical.

v4's fixes: `manager.ts:121` one line —
`backend.registerBlobColumns('help_docs', ['embedding'])`; and
`help-docs.repository.ts` dropped the `blobColumnsRegistered` field so
`getCollection()` re-asserts registration on EVERY call (merging is a
no-op; registration is keyed to the BACKEND, so it must be re-asserted,
not remembered). Mis-stored rows convert LOSSLESSLY to BLOB at next
startup — only the shape was wrong, no re-embedding needed.

### ⚠ Why bug 2 is NOT v5 work — the evidence, to be banked as a finding

`grep -rn "register_blob\|blob_columns\|BLOB_COLUMNS" crates/ --include='*.rs'`
returns **ZERO hits**. **v5 has no registration mechanism at all.** The
port abandoned v4's generic document-mapper architecture: there is no
`documentToRow`, no `hydrateRow`, no `JSON.stringify` fallback. Each

`db/conversation_chunks.rs:59`, `db/vector_indices.rs:69`,
`db/doc_mount_chunks.rs:80`. `embedding_blob.rs` is documented as "the
SINGLE SOURCE OF TRUTH".

**The class of bug cannot occur** — no runtime registry to forget to
populate, no cached instance flag, no stringify path a Float32 vector can
fall into. v5 correspondingly needs no `repair-text-embeddings` port:
**it cannot mint the TEXT shape.** `parse_legacy_embedding_text` IS
ported (read-side recovery for genuinely old v4 rows, covered by
`legacy_embedding_equivalence.rs`) — **that is the correct residue and
must stay.** This is the port structurally AVOIDING the bug, not
inheriting it.

**The lane's deliverable here is a banked status-log finding carrying the

### v4 `551f090b` — prune + embed (THIS is real v5 work)

- **`helpDocsDivergeFromDisk()`** (`help-doc-sync.ts:297-316`) checks
  **BOTH directions from ONE directory listing**: files with no row, and
  rows whose file is gone. **The deleted direction is load-bearing** —
  without it the prune would be dead code, since a deletion alone would
  never start a sync. Costs a `readdirSync` scan; reads no file contents;
  cost unchanged.
- **Prune** (`:224-242`): rows whose path isn't in `pathsOnDisk` get
  `helpDocs.delete(doc.id)` + `embeddingStatus.deleteByEntity('HELP_DOC',
  doc.id)`, plus a new `deleted` counter. **Guarded** — only reached
  after the help dir exists and produced ≥1 readable file, so a missing
  `help/` can never empty the table. **The lane must preserve that guard;
  it is the difference between a prune and a wipe.**
- **`enqueueMissingHelpDocEmbeddings()`** (`:327-377`) runs after the
  sync in `ensureHelpDocsSynced`. **`syncHelpDocs()` stays deliberately
  enqueue-free** — the reindex handler re-embeds everything and
  batch-inserts, so enqueueing there would RACE it; per-entity dedup in
  `enqueueEmbeddingGenerate` covers the overlap. **Carry that
  *why*-comment forward** (it is exactly the kind of invariant a port
  silently drops).
- **Read-table-once**: `findAll()` + a `Map` by path replaces a
  `findByPath` per file (~115 queries per sync); the prune needed every
  row anyway.
- `lib/background-jobs/handlers/embedding-reindex.ts:142` — one line: log
  `deleted: syncResult.deleted`.

    pub sides: u32,
    pub modifier: i64,
    pub results: Vec<i64>,
    pub subtotal: i64,
    pub total: i64,
}

/// v4 `parseDiceNotation` — the STRICT anchored form
/// (`/^\s*(\d+)?d(\d+)(?:\s*([+-])\s*(\d+))?\s*$/i`): whitespace around the
/// sign IS allowed here. `None` when unparseable OR out of bounds.
pub fn parse_dice_notation(s: &str) -> Option<DiceNotation>;

/// v4 `rollNotation` — `subtotal` = sum of faces; `total` = subtotal + modifier.
pub fn roll_notation(n: &DiceNotation, rng: &mut dyn RandomBytes) -> DiceRollResult;

/// v4 `formatDiceBreakdown` — `"3d6+2: [4, 2, 6] + 2 = 14"`;
/// modifier 0 → `"3d6: [4, 2, 6] = 12"`.
pub fn format_dice_breakdown(r: &DiceRollResult) -> String;
