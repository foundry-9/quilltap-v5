## Survey-verified starting points (2026-08-20)

- The broken spelling, verified present today:
  - `crates/quilltap-harness/tests/carina_memory_extraction_tier3_equivalence.rs:31`
    — `W=${V5W:-$HOME/source/quilltap-v5}`
  - `crates/quilltap-harness/tests/carina_query_tier3_equivalence.rs:25`
    — same.
  - (`carina_runner_tier3_equivalence.rs` already uses the safe
    spelling — leave it.)
- Why it is broken (the P4.D93 discovery, verbatim in its lane record):
  the driver injects the worktree path as `W` BEFORE the header's own
  assignment runs, so `W=${V5W:-…}` **clobbers the injection** with
  main's path and the recipe rebuilds fixtures from the WRONG tree. The
  documented immune spelling is `V5W=${V5W:-$HOME/source/quilltap-v5}`
  (the injected `V5W` wins the `:-` default). Read
  [[recipe-header-conventions]] and [[recipe-sweep-driver]] BEFORE
  editing any header; the header is executable documentation — keep
  every other byte of it intact.
- The driver wart: `harness/tools/recipe_sweep.py --run <name>` with a
  family name it does not know **exits 0**, printing nothing useful — a
  typo'd family name in a gate script reads as a pass (recorded at the
  `9125f492` unification). The driver already has an error-classing
  convention (`exit=2` records, the `--self-test` mode from P4.D45, the
  refuse-unattributable-runs rule from P4.45) — follow it: an unknown
  family must exit nonzero with a message naming the unknown family and
  (cheaply) the closest known names.
