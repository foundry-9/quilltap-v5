## The drift, classified (surveyed 2026-08-01)

**`c4d4b0de` feat(pascal): custom-tool chip labels, two-block bubbles, and
side effects** — implements
`docs/developer/features/pascal-custom-tool-enhancements.md` (`ae965a4e`).
Three features + one doctrine amendment, landing squarely on the ported
Pascal surface (P4.6ay / P4.d19 / P4.D30 / P4.d10):

1. **`chipLabel`** — optional per-run label template on a definition
   (`min(1).max(160)`, caps the TEMPLATE; the rendered result is uncapped —
   UI CSS truncates). Rendered ONCE in `executeCustomTool`, AFTER outcome
   selection, via `renderTemplate` with the same subjects as the outcome
   message; returned as `CustomToolRunResult.chipLabel?`; carried in
   `pascalMeta.chipLabel`. Never exposed to the model. `simulateOutcomes`
   ignores it. No load-time reference rule (unknown placeholders render
   verbatim); the Workbench warns only.
2. **Two-block bubble** — `buildPascalResultContent` becomes
   `heading = chipLabel?.trim() || toolTitle`; body =
   `` `🎲 **${heading}**\n\n${message.trim()}` ``. The blank line makes the
   message its own Markdown block. Old messages stay one-line (content
   frozen at post time — never retro-format).
3. **`effects`** — tool-level array (max 16) of conditional writes applied
   server-side after the run, into tiered persistent state ("write where it
   lives": chat → project → group → general, defaulting to chat) or the
   rolling character's metadata (whole-object RMW; skipped for runs nobody
   made). Effect `when` = the outcome comparator language PLUS an `outcome`
   subject (a SEPARATE `EffectWhenSchema`, not a widened `WhenObjectSchema`).
   A string `value` is ALWAYS an expression, evaluated by the new closed
   eval-free parser in `lib/pascal/expressions.ts` (arithmetic,
   concatenation, parens, literals, `{{ref}}` substitution — no
   identifiers, no calls). Parse failures reject at LOAD; eval/condition
   failures skip that effect fail-soft at RUN. Writes batch one per touched
   store, re-check the underscore guard at apply, never throw, and land in
   `pascalMeta.effects` as `{target, previous?, next, tier?}`. Applied
   BEFORE the Pascal post; bench (preview) and audit NEVER apply.
   `pascalMeta` is a JSON column — no migration, no D23 re-dump (verified
   at planning: `generateDDL` untouched across all ten commits).
